### 3.2 창고 쓰기의 원칙(SQL 검토자에게 같이 보낼 것)

- 저장 한 번은 **D1 batch 하나**(전부 되거나 전부 안 됨). 부모 갱신은 판 번호를 조건으로 하고, 딸린 행 문장은 모두 '이번 요청이 부모를 바꿨다'는 **쓰기 표(`write_token`, 요청마다 새 무작위 값)**를 조건으로 건다 — 판 번호만으로 걸면 같은 판에서 출발한 두 요청이 겹칠 때 진 쪽의 딸린 행이 이긴 쪽을 덮는다.
- 딸린 행은 JSON 한 덩어리(`json_each`)로 넣고 바뀐 것만 고친다(`ON CONFLICT … DO UPDATE … WHERE` 값이 다를 때) — 질의 수 상한 50과 쓰기 한도(하루 10만 행) 안에 머문다.
- 순서: 부모 → 계열 넣기 → 감정 넣기 → 칭찬감사 넣기 → 빠진 감정 지우기 → 빠진 칭찬감사 지우기 → 빠진 계열 지우기 → 만료 영수증 지우기 → 영수증 넣기. 넣고 나서 지워야 완료된 기록의 '감정 0개 금지' 자물쇠에 걸리지 않는다.
- 공백 판정은 화면·서버(JS `\S`)와 창고(SQL `trim(x, 문자들)`)가 같은 문자 집합을 쓴다 — SQLite `trim()`은 기본으로 빈칸(0x20)만 지운다. 둘이 같은지는 시험이 문자마다 대조한다.
- 완료된 기록을 고치는 batch는 끝에 `UPDATE … SET status = status`를 둔다 — 완료 조건 trigger(`BEFORE UPDATE OF status`)를 딸린 행이 다 바뀐 뒤에 다시 거치게(SQL 검토 H1, §8).
- 일기 표에 `REPLACE`/`INSERT OR REPLACE`를 쓰지 않는다 — 내부 삭제가 trigger를 건너뛰고 딸린 행을 연쇄로 지운다(SQL 검토 M1, 시험이 서버 코드를 검사).
