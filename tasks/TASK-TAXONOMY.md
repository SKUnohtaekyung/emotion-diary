### 2.1 v1 전사와의 관계 — 순서 정정

D-038 본문 마지막 줄은 "G3 taxonomy-v1(원자료 전사)은 출처 보존을 위해 그대로 선행한다"고 적었으나, 이 순서에는 **사용자 지시 근거가 붙어 있지 않다**(에이전트 판단). 사용자가 실제로 남긴 문구는 "리서치 **후** 전공자가 사용해도 이상함을 느끼지 않게"다.

정정된 이해:

| | v1 전사 | v2 리서치 (이 작업) |
| --- | --- | --- |
| 목적 | **출처 아카이빙**(PR-004) | **제품이 쓸 목록 확정** |
| 산출물 | 원자료 사진 그대로의 전사본 | 문헌 근거가 붙은 목록 |
| 게이트 | `source-fidelity`(사진과 1:1 대조) | §7 판정 기준 + D-027 |
| 선후 | v2의 **입력**이지 관문이 아니다 | v1 어휘를 재배치·삭제·최소 보충 |

두 작업은 **병렬 가능**하다. 다만 v2의 T4(항목 귀속)는 v1 전사본을 입력으로 쓰므로, T4 시작 시점까지 v1이 있어야 한다. v1이 없으면 T4에서 차단하고 v1을 먼저 끝낸다.

### 6.4 라이선스 규칙 (강행)

- **척도의 문항·어휘 목록을 제품 목록으로 이식하지 않는다.** PANAS/PANAS-X, Geneva Emotion Wheel, DES 등은 **카테고리 구조의 근거로만 읽고**, 우리 목록은 v1 어휘(사용자 원자료) + 한국어 어휘 연구로 구성한다. 이 규칙 하나로 라이선스 위험 대부분이 사라진다.
- 인용은 출처당 1개·15단어 이내. 표·목록 전체를 복제하지 않는다.
- 라이선스가 불명확한 자료는 **구조 근거로도 쓰지 않고** `미확인`에 남긴다.
- 임상 척도(PHQ-9·BDI·STAI 등)의 문항을 선별 도구처럼 차용하지 않는다(PR-001).

### 6.5 상충 문헌 처리

같은 쟁점에서 문헌이 갈리면 ① 양쪽을 모두 기록하고 ② 우선순위(§6.1) 높은 쪽을 따르며 ③ 그래도 갈리면 **원자료 v1의 배치를 유지**한다(사용자 원형 보존, PR-004). 임의 절충안을 만들지 않는다.

## 7. 판정 기준과 중단 조건 — **2026-09-04 사용자 승인 완료**

D-038의 "전공자가 봐도 어색하지 않게"는 그 자체로 판정 불가능하다. 아래로 조작화한다.

### 7.1 "어색하지 않다"의 조작적 정의

**(A) 반증 테스트 — 필수 통과.** D-038이 이미 열거한 "전공자가 바로 지적할 지점" 5건이 v2에서 각각 해소됐는지 1:1 표로 보인다.

| # | 지적 | 해소 판정 |
| --- | --- | --- |
| ① | 공포 카테고리 부재(`두려운`·`공포에 질린`이 슬픔에 있음) | 공포 계열 신설 + 해당 어휘 이동 |
| ② | 놀람이 기쁨 안에만 존재 | 놀람 어휘의 다중 배치 또는 중립 처리 근거 |
| ③ | 즐거움·기쁨 경계 중첩 | 두 계열의 구분 기준 한 문장 + 중복 어휘 각각의 귀속 근거 |
| ④ | 바램이 정서보다 동기·기대 | 유지/재정의/이동 중 하나를 축 E 근거로 결정 |
| ⑤ | 미움이 혐오 축과 어긋남 | 유지/재정의 중 하나를 축 F 근거로 결정 |

조사 중 **새로 발견한 지적사항도 이 표에 추가**하고 같은 형식으로 해소하거나 "해소하지 않음 + 이유"를 적는다.

**(B) 카테고리 기준.** 각 카테고리가 **독립 문헌 2편 이상**에서 구분되는 정서 또는 명시적 상위 범주로 다뤄진다. 미달 카테고리는 신설하지 않는다.

**(C) 항목 근거 등급.** 모든 세부 감정에 등급을 붙인다.

- `A` — 문헌이 해당 카테고리 귀속을 직접 지지
- `B` — 원자료 v1 배치 + 한국어 어휘 타당성으로 지지(문헌 직접 근거 없음)
- `C` — 근거 약함, 귀속이 자의적

**(D) C등급 상한 15%** *(승인)*. 초과하면 초과분을 보류 목록으로 내리거나 조사를 계속한다. **자유 발굴(§7.2)을 택했으므로 이 상한이 목록 품질의 주 통제 장치다** — 새로 발굴한 어휘도 같은 등급 심사를 받고 같은 15%에 포함된다. 근거 없이 늘어난 어휘는 여기서 걸린다.

**(E) 최종 검수.** D-027 — 사용자 최종 대조 또는 시간 분리 2회. **A~D를 다 통과해도 (E) 없이 `accepted`로 전환하지 않는다.**

### 7.2 중단 조건 (2026-09-04 승인)

**카테고리 단계**: §6.2의 6개 축 최소 근거를 모두 채운 뒤, **새로 읽은 문헌 2편 연속으로 카테고리 목록에 변경 제안이 없으면** 종료(포화). **문헌 상한 20편** *(승인)* — 도달했는데 포화가 아니면 멈추고 남은 쟁점을 사용자에게 보고한다.

**항목 단계 — 어휘 자유 발굴** *(승인, 초안의 "발굴 안 함"을 사용자가 기각)*. 문헌에서 좋은 어휘를 적극 추가한다. 발굴에 개수 상한은 두지 않되, 아래 네 가지가 대신 경계를 잡는다.

1. **문헌 상한이 곧 어휘 상한이다.** 추가 어휘는 §6.2 축에서 실제로 읽은 문헌(최대 20편)에서만 나온다. 문헌 밖에서 임의로 지어내지 않으므로 발굴 자체는 유한하다.
2. **추가 어휘도 §7.1(C) 등급 심사와 15% 상한을 그대로 받는다.** 근거가 약한 추가는 C로 떨어지고 상한에 걸려 잘린다.
3. **원자료 어휘를 대체하지 않는다**(PR-004). 발굴은 *추가*이며, v1 항목의 `drop`은 문헌 근거가 있을 때만 한다. 매핑표에서 추가분은 전부 `action: add`로 표시되어 나중에 되돌릴 수 있다.
4. **규모 보고 의무**: T4 완료 시 v1 대비 총 개수와 카테고리별 개수를 보고한다. **어느 카테고리든 항목이 v1의 2배를 넘으면 진행 전에 사용자에게 알린다** — D-037 소프트 리스트(초성 레일·검색·선택 트레이)가 그 규모에서 여전히 쓸 만한지 다시 봐야 한다. 아크 휠은 카테고리 수만 쓰므로 영향 없다.

**시간 상한**: 조사 실작업 세션 **3회**(문헌 20편 + 자유 발굴에 맞춰 초안 2회에서 늘림 — 사용자가 줄이라고 하면 줄인다). 초과하면 중간 산출물로 사용자 판단을 받는다.

**즉시 중단**: §6.4 라이선스 규칙에 닿는 순간, 카테고리 수가 9를 넘으려 할 때(색 창 포화 — D-038 실측), 같은 가설 2회 실패 시(AGENTS §5).

**공유 아티팩트 갱신 완료**(2026-09-04, 사용자 승인): <https://claude.ai/code/artifact/8673a33c-900c-4273-8592-0fb3bdcc36a9> 를 9계열 판으로 재발행했다. 스와치 9행·chip 예시(light/dark)·아크 휠 목록에 공포·혐오가 들어갔고 `--fear-500:#199A8C`·`--disgust-500:#918C37`를 실제 발행본에서 확인했다.

**폴백 격자 결정(2026-09-04, 사용자)**: A(4열) 기각, **B(3열, 101px 셀) 채택**. style-guide.html에 반영, 기각안은 흐리게 남겨 대조 근거로 보존.

**아크 휠 대안 탐색(2026-09-04, TASK-TAXONOMY 범위 밖 — 참고용)**: 반지름 기반이 아닌 대안을 실제 조작 가능한 시안으로 만들어 별도 아티팩트에 발행 — <https://claude.ai/code/artifact/579fe7a4-c302-43ad-b522-ebb1af797ac6>. 처음 5개(캐러셀·소형 링 다이얼·벌집 그리드·세로 피커 휠·카드 스택)에 이어 사용자 요청으로 **6번째 안(감정 색상환 다이얼)을 추가**했다 — 계열마다 실제 색상각(hue)이 있다는 점을 이용해, T5에서 ΔE≥7 분리 작업 결과 9계열이 색상환에서 이미 44·27·55·85·27·22·35·52° 간격으로 고르게 퍼져 있음을 확인하고 그 각도 그대로 고리를 그렸다(가장 좁은 간격 13°). **writer 추천을 06으로 갱신** — 04(세로 휠)와 같은 방식으로 반지름·폴백 문제를 풀면서 회전형 조작감도 지킨다. **단, 06은 연속 그라데이션을 쓰는데 DESIGN_SYSTEM §11이 그라데이션을 명시적으로 금지한다** — writer가 임의로 예외를 정하지 않고 사용자 승인이 필요한 항목으로 남겼다. 04는 이 문제 자체가 없는 안전한 대안이다.

**사용자 지적(2026-09-04, 정당함)**: "06으로 하면 색상이 어떤 감정인지 모르잖아 시각적으로 직관적으로" — 06(그리고 **02도 같은 결함**)은 색만 있고 텍스트가 없어, 처음 보는 사람은 미리 외워야만 알 수 있었다. 01·03·04·05는 전부 항목마다 텍스트 라벨이 항상 보였는데 06·02만 중앙에 선택된 것 하나만 텍스트가 뜨는 예외였다. DESIGN_SYSTEM이 이미 지키던 원칙("카테고리 색 점을 항상 텍스트와 함께 둔다")과도 어긋났다. **조치**: 06 고리 바깥에 짧은 글자 라벨(2~3자)을 9개 위치 모두 항상 표시하도록 고쳤다. 좌우 앵커(start/center/end)를 각도의 sin 부호로 자동 판정한다. **02는 아직 고치지 않았다** — 같은 결함이 남아 있다.

**검증 중 발견한 별개 버그 2건, 함께 고쳤다**: ① `setPointerCapture`가 합성 포인터 이벤트에서 `NotFoundError`를 던지는 걸 발견해(실제 터치·마우스는 문제없음) 04·05·06 전부 try/catch로 방어 처리. ② **03(벌집 그리드)의 가운데 줄 `translateX(41px)`가 375px 실사이즈 뷰포트에서 body 가로 스크롤을 유발**하고 있었다(오늘 작업과 무관한 기존 버그) — `translateX(20px)`로 줄여 해소. 로컬 raw 파일은 뷰포트 meta가 없어 처음엔 못 잡았고, 아티팩트가 자동으로 붙이는 meta를 테스트 사본에만 추가해 375px 실측으로 재확인했다. 최종 375px에서 overflowsX=false, 10개 각도 스냅 정확도 재확인 완료. **이 결정 전체는 D-037 소유자(TASK-DESIGN)가 확정해 DESIGN_SYSTEM §6.2에 반영해야 한다** — 이 파일은 §3 색 표만 소유한다.

**2차 탐색 — HCI 관점 5개 추가(2026-09-04)**: 사용자가 "UI/UX·HCI 전공자로서 사용자 흐름이 깨지지 않는 안"을 요청해, 앞의 6개("뭐가 재미있나")와 다른 축으로 5개를 더 만들었다 — **07 고정 3×3 격자**(Fitts's Law + 공간 기억), **08 최근 3개 우선**(Zipf 법칙), **09 정서가 2단계 분기**(Hick's Law, T2가 이미 조사한 Posner 외 2005 circumplex 모형을 그대로 UI로 옮김), **10 목록 패턴 재사용**(Jakob's Law — 세부 감정 단계와 같은 위젯), **11 스마트 기본값**(GOMS/최소 상호작용, PR-001 때문에 "확정"이 아니라 "제안" 문구 필수). 전부 탭 전용으로 만들어 드래그 계열 버그(setPointerCapture 등)를 원천적으로 피했다. writer 판단: 순수 흐름 보존 기준으로는 **10**이 가장 안전(배울 게 0)하지만, 실사용은 **11+07 조합**(대부분 탭 0~1번, "바꾸기"는 고정 격자)을 권한다. 앞의 6개(재미 축)와 이번 5개(흐름 보존 축)는 서로 다른 제품 방향에 대한 답이라 writer가 최종 선택을 대신하지 않는다.
