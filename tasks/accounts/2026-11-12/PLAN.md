## 1. 목표와 범위

**목표**: 접근 열쇠 대신 카카오·구글 계정으로 다른 사람이 가입한다. 가입한 사람은 한 편을 쓰고, 내보내고, 탈퇴할 수 있다. 이 모든 동안 사람마다 기록이 완전히 나뉜다(work-graph `accounts` outputs: 'people other than the owner can sign up, write, export, and leave').

**포함**
- 소셜 로그인(카카오·구글), 가입(부를 이름 + 필수 동의 + 건강정보 별도 동의), 만 14세 확인.
- 로그아웃, 탈퇴(두 단계 + 완료), 접근 열쇠 길 퇴역.
- 세션 주체 바꾸기(A-1), 사람별 분리 재검증(`owner-isolation`), 사람별 요청 한도.
- 시안의 들어오는 길(조각 10: 로그인·가입·반가워요)과 온보딩(조각 11).
- 약관·처리방침·별도 동의 문구 초안('검토 전' 표기).
- 개발용 가짜 제공자, 묶음 끝 휴대폰 확인 한 번(`mobile-accounts`, 약 20분 + 스파이크 5분).

**제외**
- Apple 로그인(스토어 때), 계정 합치기, 이메일·비밀번호 로그인.
- 운영 다인 백업·알림·공개 대상: 공개 준비에서 한다.
- AI, Android 실기기, 화면 낭독기: 공개 관문에서 본다.
- 운영 건물 반영: 이 노드에서는 개발용까지만 한다. 운영에 올리는 것은 공개 준비 단계에서, 사용자 확인 뒤에 한다.

## 3. 정할 것: 사용자(질문 창으로 한 번에)

REQUESTS §4의 Q1~Q4다. 답은 REQUESTS '사용자 결정' 절과 `docs/DECISIONS.md` 새 행에 적는다. 아래 계획은 **추천안 기준**으로 썼다. 다른 답이 나오면 아래처럼 고친다.

- **Q1(서버가 못 읽게)**: 범위가 크게 바뀐다. 기기 안 암호화, 통계를 기기에서, 복원을 다시 설계해야 한다. 이 계획을 버리고 다시 쓴다. 그 경우 이 노드를 둘로 나누는 안을 먼저 묻는다.
- **Q2(지금 외부 검토)**: AC-8을 AC-3 앞으로 당기고, 검토 답이 올 때까지 AC-6의 문구 칸은 자리표시로 둔다.
- **Q3(둘러보기만)**: AC-4·AC-6에 '동의 없음' 상태와, 기록 경로를 막는 서버 검사가 더해진다(403 `consent_required`).
- **Q4(지금 사기)**: AC-1에서 도메인을 연결하고 개발용 주소를 바꾼다. 휴대폰의 개발용 앱은 다시 설치한다.

## 5. 데이터·경로 한 장(초안 — AC-3에서 확정)

```text
accounts            (id UUID PK, created_at, status 'active')
account_identities  (provider 'kakao'|'google'|'dev', subject_hash, account_id → accounts ON DELETE CASCADE, created_at,
                     UNIQUE(provider, subject_hash))
account_consents    (account_id → accounts ON DELETE CASCADE, item, doc_version, agreed_at, PK(account_id, item))
sessions            (subject 길이 1~64로 다시 만들기, 나머지 그대로)
owner_settings·diary_*·idempotency_records  — owner_key = accounts.id (구조 그대로)
```

| 경로 | 로그인 | 하는 일 |
| --- | --- | --- |
| `GET /api/auth/:provider/start` | 없음 | `state`·PKCE cookie → 제공자로 302 |
| `GET /api/auth/:provider/callback` | 없음 | 코드 → 사용자 번호 → 있는 계정이면 세션 발급 후 `#/today`로, 없으면 가입 대기 cookie 후 `#/auth/join`으로 |
| `POST /api/account` | 가입 대기 cookie | 이름(1~12자)·동의 넷 검사 → 계정·연결·동의 한 batch → 세션 발급. 멱등 영수증 |
| `GET /api/session` | 세션 | 지금 것에 `provider`(수단 이름) 한 칸을 더한다 |
| `POST /api/session/logout` | 세션 | 그대로 |
| `DELETE /api/account` | 세션 | A-5 |
| `POST /api/session`(열쇠) | — | 개발용·로컬만(A-10) |

## 6. 순서: 단계마다 산출물·검증·멈출 조건

단계마다 하는 일:
1. 관련 시험(Vitest 서버·화면)을 돌린다.

## 11. 지난 실수 목록(이번에 피할 것)

- **사본 지우기 함수를 지우기가 아닌 동작에 썼다**(TASK-JOURNAL-01 마감 검토 1, `dropSession`). 탈퇴·로그아웃 경로를 더할 때 D-123의 '사본을 지우는 셋'과 다시 대조한다.
- **새 주소를 `client/src/lib/routes.ts`의 ROUTES·RETURNABLE에 넣지 않아** 오늘로 튕겼다(J-9). 새 화면마다 같은 커밋에 등록한다.
- **CRLF 파일을 문자열 치환이 조용히 놓쳤다**(J-6·J-9). scratchpad 편집 스크립트는 줄 끝을 맞추고, 찾지 못하면 throw한다.
- **bash `node -e`에 한국어·backtick을 넣어 세 번 깨졌다.** 편집은 `.js` 파일로 한다.
- **시험 단언이 흐름 표시만 봐서** 결함 주입 하나를 놓쳤다(J-10). 동작의 결과(행 수·기록 칸 수)를 본다.
- **바쁠 때 화면 시험이 흔들렸다.** 비동기 그리기는 `vi.waitFor`로 기다린다.
- **확인 창 문구와 실제 동작이 달랐다**(완료 취소). 탈퇴·로그아웃 확인 문구를 쓸 때 서버가 실제로 지우는 표 목록과 한 줄씩 대조한다.
