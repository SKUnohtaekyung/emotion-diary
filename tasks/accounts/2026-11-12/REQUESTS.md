## 2. 사실

### 2.1 확인한 것 (2026-11-12, 파일·줄)

**세션·주체**
- 세션 주체는 `OWNER_SUBJECT`(접근 열쇠로 로그인하면 세션에 담는 값 — '본인 1명이라 하나 — D-025')다(`app/worker/src/context.ts` 8~9줄). 요청마다 `OWNER_ALLOWLIST`(쉼표 구분)와 대조한다(10~11줄).
- `Session.owner`는 '세션의 주체 = owner_key(본인 1명 모드)'다(41~42줄).
- 비밀값 넷(`ACCESS_KEY_HASH`·`ACCESS_KEY_SALT`·`SESSION_SECRET`·`APP_LOCK_SECRET`) 중 하나라도 없으면 어떤 요청도 받지 않는다(78~85줄). 접근 열쇠를 퇴역하면 이 검사도 바뀐다.
- `sessions` 표: `subject TEXT NOT NULL CHECK (length(subject) BETWEEN 1 AND 32)`, `key_login_at`(열쇠로 들어온 시각 — D-112 ⑧의 10분 규칙이 쓴다), `locked`(`app/migrations/0002_sessions.sql`).

**owner_key가 있는 표**
- `owner_key`가 있는 표는 `owner_settings`(0003)·`diary_entries`와 딸린 표(0006)·`idempotency_records`(0007)다.
- `auth_failures`(0001)·`client_errors`(0004)에는 owner가 없다(DATA_MODEL §8 291줄 — 그래서 모든 기록 지우기가 지우지 않는다).
- 마이그레이션은 0001~0008이다.

**모든 기록 지우기**
- 이미 있다: `app/worker/src/routes/dataControl.ts`의 `deleteAll`. 기록·설정·다른 세션을 batch 하나로 지우고, `sessions.data_epoch`로 날아오던 쓰기를 막는다(DATA_MODEL §8 291줄).
- 탈퇴는 이 위에 '이 세션도·연결 행도·동의 기록도'를 더하면 된다.

**API 입구**
- `GET·POST /api/session`은 로그인 확인 전에 따로 처리한다(`app/worker/src/app.ts` 1·52줄 주석).
- 잠긴 세션이 부를 수 있는 경로는 넷이다(46줄).

**시안(`web/`)**
- 가입 `#/auth/join`: 나의 돌 아래 이름 칸 + 필수 동의 셋(만 14세 이상·이용약관·개인정보), 그 밖의 정보는 묻지 않는다('최소만' — `web/js/views/auth.js` 4줄).
- 로그인의 시안 상태:
  - `?s=left`: 다른 기기에서 탈퇴됨
  - `?s=loggedout`: 로그아웃 직후
  - `?last=`: 지난번에 쓴 방법 표시
  - `#/auth/join?via=…&s=fail`: 가입 저장 실패
  - 모두 7~8줄.
- 약관 시트는 '시안이에요. 실제 약관은 법률 검토를 거쳐 채워요.'(121줄), 14세 미만 시트는 '보호자 동의 절차는 아직 정하지 않았어요.'(211줄)다.
- 탈퇴 두 단계(`#/settings/leave` → `?step=confirm`):
  - '탈퇴 계속하기'는 회색 버튼이다.
  - 확인 문구 '계정 탈퇴'를 입력해야 빨간 '탈퇴하기'가 풀린다.
  - 떠나는 이유는 고르지 않아도 된다(`web/js/views/settings.js` 285~356줄).
- 탈퇴 완료 화면은 `web/js/views/settings-data.js` 138줄이다.
- 온보딩은 `web/js/views/welcome.js`(492줄), 로그인·가입은 `auth.js`(266줄)다.

**앱의 지금 들어오는 길**
- 열쇠 화면 `#/auth`, 부를 이름 `#/auth/name`, 반가워요 `#/welcome`. 모두 평면이다(MAP §4.6 표 145~147줄).
- TASK-JOURNAL-01은 이 셋을 옮기지 않았다(그 PLAN §1 제외 — U-2).

**관문 라벨 정의(EVAL_PLAN §14 391~397줄)**
- `social-login`: 카카오·구글로 가입·로그인·로그아웃, 홈 화면 앱에서 로그인 유지(S-02와 같은 확인), 접근 열쇠 길 퇴역.
- `age-14-check`: 만 14세 이상이 아니면 가입하지 않는다.
- `consent-and-policy`: 약관·처리방침·건강정보 별도 동의를 가입 흐름에, 거부했을 때의 동작이 정해져 있다.
- `account-withdrawal`: 탈퇴가 모든 기록·설정·세션·소셜 연결을 지우고, 다시 오면 빈 상태다.
- `owner-isolation`: 시험 계정 둘 이상으로 모든 `/api/*`에서 남의 것을 읽거나 바꿀 수 없다(서버 시험 + 개발용 원격 검사).
- `mobile-accounts`: iPhone 홈 화면 앱에서 가입 → 한 편 → 완전히 닫았다 열기 → 탈퇴, 약 20분.

**로그인 유지 규칙(D-112)**
- 마지막 사용부터 30일이고, 서버 세션 기록이 있다.
- 앱 잠금은 서버가 확인한다.
- 열쇠로 방금 들어온 직후에는 잠금 비밀번호를 묻지 않고, 10분 안에는 비밀번호 없이 다시 정할 수 있다.
- 이 중 '열쇠로'는 소셜 로그인으로 바뀐다.

### 2.2 확인하지 않은 것 (착수 때 공식 문서·실제 런타임으로 확인 — AGENTS §3 마지막 규칙)

- **카카오 로그인**: 앱 등록에 필요한 것, workers.dev 주소를 사이트 도메인·redirect URI로 받는지, 토큰으로 사용자 번호를 받는 방법, 연결 끊기 API, 심사·비즈 앱 전환이 필요한 조건.
- **구글 로그인**: OAuth 동의 화면의 '테스트' 상태로 몇 명까지 되는지, '게시'에 심사가 필요한 범위, ID 토큰 검증(JWKS)을 Workers의 WebCrypto로 하는 방법, 권한 회수 API.
- **법 해석**: 개인정보보호법의 만 14세 미만 처리(법정대리인 동의), 민감정보(건강) 별도 동의와 감정 일기가 그 대상인지, 처리방침 필수 항목, 국외 이전(Cloudflare) 고지. **이 문서는 법 판단을 하지 않는다.** R-2의 답에 따라 공식 법령·고시를 읽거나 외부 검토를 받는다.
- **홈 화면 앱과 OAuth**: 홈 화면 앱에서 외부 로그인 화면으로 갔다가 돌아올 때 같은 앱(standalone)으로 돌아오는지, 아니면 Safari에 쿠키가 생기는지. Safari와 홈 화면 앱은 로그인을 따로 가진다(D-112 근거 — 실측 S-01). 이것은 실기기로만 확인된다 — 스파이크 AC-1의 휴대폰 5분 항목.
- **도메인 가격**: 사기 전에 확인한다(U-16).

## 3. 이미 정해진 것(다시 묻지 않는다)

**정책**
- 웹앱으로 먼저 공개하고 스토어는 나중이다(U-11).
- 첫 공개는 AI 없이 한다(U-14).
- 로그인은 소셜이다(U-15). 카카오·구글로 하고, Apple은 스토어 때 더한다(ROADMAP 116줄).
- 가입은 만 14세 이상만 받는다(U-13).
- 작은 비용은 쓰기 전에 묻고 허용한다(U-16).

**가입에서 받는 것**
- 가입은 최소만 받는다: 부를 이름(1~12자)과 필수 동의. 이메일·전화·성별·생년·직업은 받지 않는다(D-104 ②, ARCHITECTURE §6 '원시 이메일은 필요하지 않으면 저장하지 않는다').

**그대로 쓰는 것**
- 저장 계약(하루 1편·판 번호·멱등 영수증·`data_epoch`), 내보내기·모든 기록 지우기는 그대로다. 사람별로 쓰일 뿐이다.
- 시안의 들어오는 길 장면(언덕·흰 길·나의 돌·ink 이름 칸)과 탈퇴 두 단계는 2026-09-27에 승인됐다(D-104).

**구조**
- 서버·DB·운영 건물은 그대로 두고 그 위에 짓는다(U-3).
- 창고 구조를 바꾸기 전에 내보내기 + 백업하고, 바꾼 뒤 복원을 확인한다(RK-045).

**이번에 다시 짓지 않는 것**
- CSP(style 속성·innerHTML 금지), 위 줄·버튼 줄 고정 금지(D-123), `#app`만 스크롤(D-125), 화면은 Preact(D-127).

## 4. 질문 창 초안 (착수 때 한 번에, 4개)

추천안은 맨 앞에 둔다. 추천의 근거는 각 질문의 설명에 넣는다(질문 창만 봐도 판단할 수 있게).

**Q1 일기를 서버가 읽을 수 있게 둘까요?** (R-1)
- **지금처럼 둔다(추천)**: 서버는 읽을 수 있다. 저장 암호화는 Cloudflare가 하고, 운영자 접근은 규칙·기록으로 막고, 처리방침에 그대로 밝힌다.
  - 이렇게 하면 통계·내보내기·복원·기기 바꾸기가 지금처럼 된다.
  - 대가: '운영자도 못 본다'고 약속할 수 없다.
- **서버가 못 읽게**: 기기 안 암호화를 한다.
  - 기기를 잃으면 복구할 수 없다.
  - 통계를 기기에서 다시 짓고, 백업·내보내기 설계를 새로 한다. 이 노드가 크게 늘어난다.

**Q2 약관·처리방침·건강정보 동의를 법률 검토 받을까요?** (R-2)
- **초안은 에이전트가 쓰고, 공개 전에 외부 검토(추천)**: 이번 노드는 '검토 전' 표기로 개발용에서만 쓴다. 검토 비용은 공개 준비 때 견적을 받아 묻는다.
- **지금 외부 검토를 먼저**: 문구가 정해진 뒤 짓는다. 비용이 지금 든다.
- **검토 없이 공식 가이드 기준으로 직접**: 비용 0. 공개 시 위험은 사용자가 진다.

**Q3 건강정보 별도 동의를 거부하면?** (R-3)
- **가입하지 않고 이유를 한 줄로 안내(추천)**: 이 앱의 기능이 모두 그 정보를 다룬다. 거부해도 불이익이 없게 언제든 다시 올 수 있다.
- **기록 없이 둘러보기만**: 온보딩·위기 안내만 보인다.
- **법 검토 답을 보고 정한다**: 그동안 시안 안 둘 다 그린다.

**Q4 workers.dev 주소로 소셜 로그인 등록이 안 되면?** (R-4)
- **그때 도메인 가격을 확인해 다시 묻는다(추천)**: 스파이크에서 먼저 확인한다.
- **지금 도메인을 사도 된다(공개 때 어차피 필요)**: 가격은 살 때 알린다.
- **workers.dev로 되는 제공자만 먼저**.
