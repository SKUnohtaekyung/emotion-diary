## 이번에 묻지 않은 것(새 세션에서 묻는다 — PLAN §5.1)

- 화면을 만드는 도구(프레임워크)와 만드는 방식 — 조사 없이는 추천할 수 없다. 조사 뒤 비교와 추천을 붙여 묻는다.
- 개발용 서버를 실제로 만드는 것 — 만들기 직전에 바뀌는 것·요금·되돌리는 법을 보이고 다시 묻는다(Q2는 방향만 정했다).
- 휴대폰에 개발용 열쇠를 넣는 방법, 연습용 서버를 지울지, 운영 열쇠를 전달하는 방법(운영은 T3 밖).

## 사용자가 앞 작업(T2)에서 지정한 진행 방식 — T3에도 이어 쓴다

아래는 사용자가 **T2 요청에서** 말한 것이다(원문은 [../2026-10-14/REQUESTS.md](../2026-10-14/REQUESTS.md)). T3에 대해 따로 다시 말한 것은 아니고, 같은 방식을 이어 쓰는 것은 에이전트의 판단이다 — 새 세션은 시작할 때 한 줄로 알린다.

- 사용자가 정할 것(보안, 개인정보·삭제, 제품 범위, 요금, 되돌리기 어려운 일)만 질문 기능으로 한 번에 묻고, 고르면 어떻게 되는지와 추천을 붙인다. 에이전트가 정한 것은 이유를 한 줄로 남긴다.
- 멈추는 경우는 셋뿐이다: 사용자 결정이 필요할 때, 요금이 생기거나 되돌리기 어려운 일일 때, 두 문서가 달라 근거로 가릴 수 없을 때. 문서 하나를 끝냈을 때·검증이 실패했을 때·답을 기다릴 때·남은 항목이 있을 때는 멈추지 않는다.
- 하나 끝날 때마다 quick 검증과 짧은 보고, 마지막에 새 맥락의 읽기 전용 검토자 한 명(전부 보고·심각도) → 반영 → full.
- "확인됨"에는 어디서 확인했는지를 같이 적는다. 사용자가 직접 말한 것만 사용자 결정이다. 답은 받는 즉시 요청 문서에 적는다. 같은 숫자는 사실표에서 옮겨 적는다.
- 공식 문서 확인은 조사 담당 하위 에이전트에게 맡기고 요약과 출처만 받는다.
- 개발 용어 없이 하나의 비유로, 결과부터 말한다. 커밋과 푸시는 사용자가 말할 때만.
