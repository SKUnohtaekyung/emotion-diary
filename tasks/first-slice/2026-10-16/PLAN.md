## 3. 작성 흐름 상태 설계 (한 장)

### 3.1 흐름이 들고 있는 것

```
FlowState
  date        그 글의 날짜(서버가 센 오늘, 또는 이어 쓰는 지난 날)
  mode        "draft"(새 글·임시저장) | "edit"(완료한 기록 고치기)
  base        서버에서 마지막으로 확인한 { revision | null, status }
  input       지금 화면의 글 전체(DiaryInput에서 revision을 뺀 것)
  step        ResumeStep (+ details이면 categoryCode)
  seq         글·단계가 바뀔 때마다 1씩 오르는 순번
  savedSeq    서버가 받았다고 답한 마지막 순번
  pending     날아가는 요청 하나 { key, seq, baseRevision, body } | null
  save        saved | dirty | saving | offline | failed | conflict | held
              (held = 잠김·로그인 풀림·새 버전으로 보내기를 멈춤)
  touched     edit 모드에서 실제로 고쳤는가
```

화면 쪽 기억은 언제든 사라질 수 있다(RK-034). 정본은 서버, 그다음은 기기 사본(U-2), 메모리는 그 둘의 사본이다.

### 3.2 단계

| 단계 | 주소 `step` | `다음`을 막는 것과 안내 | 비고 |
| --- | --- | --- | --- |
| 있었던 일 | `event` | 비면 '한 줄만 적어도 충분해요.'(A-6) | 날짜 칸 없음 |
| 마음 고르기 | `feelings` | 0개면 '가까운 마음을 하나 고르면 다음으로 갈 수 있어요.' | 여러 개 |
| 세부 감정(고른 계열마다, 고른 순서) | `details&c=<계열>` | 그 계열 0개면 '가까운 말을 하나 고르면 다음으로 갈 수 있어요.' | `이 마음은 빼기`, '슬픔 · 1/3' |
| 크기 | `intensity` | 대표 크기 없는 계열이 있으면 시트 '크기를 정하지 않은 마음이 있어요' → `정하러 가기` | D-079 ① |
| 이유 | `reason` | 막지 않는다(남길 때 확인) | 고른 마음 이름 목록 |
| 칭찬 | `praise` | 막지 않는다 | '선택이에요. 비워 두어도 괜찮아요.' |
| 감사 | `gratitude` | 막지 않는다 | 같은 틀 |
| 검토(편지의 평면판) | `letter` | `남기기`/`저장하기`에 빠진 것이 있으면 시트 '남기려면 이것이 필요해요' → `채우러 가기`·`편지로 돌아가기` | 부분별 `고치기` |
| 완료 | `#/done/<날짜>` | — | A-7 |

막힌 `다음`은 `aria-disabled`로 흐리되 초점을 받고, 누르면 고를 자리 바로 위에 ink 안내 한 줄과 `aria-live`(D-098 ③). 검토의 `고치기`로 들어온 단계는 `다음`이 `편지로 돌아가기`가 된다.

### 3.3 일이 생길 때

| 일 | draft 모드 | edit 모드 |
| --- | --- | --- |
| 입력 | seq+1, 300ms 뒤 기기 사본, 800ms 멈추면 보낸다 | seq+1, touched, 300ms 뒤 기기 사본(보내지 않는다) |
| 단계 옮김(`다음`·`이전`·밀기) | 방문 기록 push/back, 단계도 저장 내용이라 곧 보낸다 | 기기 사본만 |
| 화면이 숨음 | 곧 보낸다(사본은 이미 있다) | 사본만 |
| 200·201 | base 갱신, savedSeq = 보낸 seq, savedSeq = seq면 사본 지움, 남은 변경이 있으면 다음 요청 | `저장하기`의 답일 때만 — 사본 지우고 기록 보기로 |
| 연결 끊김(응답 없음) | save=offline, 같은 열쇠로 다시(A-11) | `저장하기` 때만 같음 |
| 401 | save=held, '다시 들어와야 해요' 시트 → 열쇠 화면 → 같은 주소로 돌아와 사본에서 되살려 보낸다(F-22) | 같음 |
| 423 | save=held, 잠금 층(글이 보이지 않는다), 풀리면 보낸다 | 같음 |
| 409 `revision_conflict` | 다른 곳의 고침 — A-13(세션 안에서는 같은 열쇠로만 다시 보내므로 우리 요청이 아니다) | `저장하기` 때 같음 |
| 422 `not_today` | A-12 | 해당 없음 |
| 422 `incomplete` | 해당 없음(임시저장은 완료 검사를 하지 않는다) | 빠진 것 시트 |
| 422 `invalid_*`·400 | 화면 결함 — 오류 번호, 사본 유지, 보내기 멈춤 | 같음 |
| 새 버전(`compat`↑) | A-14 | 같음 |
| × | 보낼 것이 있으면 보내기를 걸어 둔 채(사본 유지) 바로 오늘로, 흐름 기록 되감기 | touched면 '고친 내용을 저장하지 않고 나갈까요?' |
| `남기기` | 남은 변경을 먼저 보내고 → `complete {revision}` → `#/done/<날짜>`로 되감아 바꿈 | `저장하기` = PUT(완료 조건 재검사) → 기록 보기로 되감아 바꿈 |
| 이 글 지우기 | 2단계 확인 → 날아가는 요청을 기다림 → `DELETE {revision}` → 사본 지움 → 오늘로 되감기 + 토스트 | 메뉴에 없다 |
| 같은 주소로 새로 열림 | 서버 기록 + 사본: 사본이 같은 판에서 출발해 앞서 있으면 사본, 아니면 서버. 단계는 주소의 `step`이 지금 내용에 맞으면 그것, 아니면 서버의 쓰던 단계 | 사본이 있으면 고치던 내용으로, 없으면 완료 기록 그대로 |
| 아이콘으로 새로 켬(`#/today`) | 오늘 화면이 '이어서 써요 · <단계> 중'을 보이고 누르면 쓰던 단계. 못 보낸 사본이 있으면 켜자마자 보낸다 | 사본이 있으면 기록 있음 줄에 '고치던 내용이 있어요' |

### 3.4 기기 사본(U-2)의 한 생

`입력` → (300ms) **쓴다** → `보냄` → `200/201(그 순번까지)` → **지운다**. 그 사이 연결 끊김·401·423·새 버전·앱 꺼짐이 끼면 사본이 남고, 다음에 켜거나 연결되면 사본부터 보낸다(날아가던 요청은 같은 열쇠로 — 이미 반영됐으면 서버가 영수증으로 같은 답을 돌려준다). 처음 판 번호가 서버와 다르면 덮지 않고 A-13. 로그아웃은 '아직 보내지 못한 글이 있어요' 시트를 먼저 보이고, 그래도 나가면 지운다. 저장소가 막혀 있으면(비공개 창 등) 사본 없이 동작하고 상태 문구는 그대로다(`storage.ts`의 try/catch).
