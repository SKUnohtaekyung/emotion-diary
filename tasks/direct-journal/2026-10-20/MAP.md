# direct-journal 착수 준비 — 변경 지도 (2026-10-20)

다음 노드 `direct-journal`(쓰면서 시안 이식, D-116)을 시작하기 전에 **지금 앱(평면) → 옮길 것(승인된 시안) → 근거**를 화면·부품마다 한 장에 놓고, 이식 순서와 조각마다의 위험을 적는다. 값은 [FACTS.md](FACTS.md), 사용자에게 한 번에 물을 것은 [QUESTIONS.md](QUESTIONS.md)에 있다.

- **이 문서는 계획(PLAN)이 아니다.** 질문의 답을 받은 뒤 `tasks/direct-journal/<날짜>/PLAN.md`(체크리스트이자 유일한 진행 기록, D-118)를 쓴다. 코드·`docs/*`·`harness/*`는 이번에 고치지 않았다 — personal-start가 진행 중이다.
- 읽은 것: `docs/SERVICE_WHY.md` 전문, `AGENTS.md`, `harness/work-graph.yaml` `direct-journal`, `docs/STATUS.md` §4-7, `docs/DECISIONS.md`(D-116·D-123·D-125와 관련 행), `docs/UX_SPEC.md`, `docs/DESIGN_SYSTEM.md`, 시안 `web/`(HTML·CSS·`js/views/*.js`·`js/components/*.js` — 동작은 핸들러까지), 앱 `app/client/src/`(views·ui·styles·router·write·lib), 서버 경로 목록(`app/worker/src/app.ts`), 감리 `tasks/review/2026-10-14/REPORT.md` §3.3·§5.3.
- '추정'은 이번에 실물(코드 실행·실기기·공식 문서)로 확인하지 않은 것이다.

## 0. 한눈에

1. **앱은 기능이 거의 다 있고 모양만 평면이다.** 작성 흐름·저장·기기 사본·충돌·기록 보기·내보내기·지우기·잠금·위기 안내가 돌아간다. 이식의 대부분은 **저장·흐름 코드는 그대로 두고 그 위에 시안의 부품과 장면을 입히는 일**이다(§2 R4·R5).
2. **그러나 순수한 화면 일만은 아니다.** 시안에 있는 두 화면이 서버 경로가 없다 — **달력의 한 달 목록**과 **완료 취소**(FACTS §9). 둘 다 새 계약이라 ARCHITECTURE §5·DATA_MODEL·TRACEABILITY·EVAL을 같은 변경에서 고쳐야 한다(AGENTS §4).
3. **시안 코드는 그대로 붙지 않는다.** 앱의 세 규칙에 걸리는 곳이 정해져 있다 — ① 보안 정책(style 속성·innerHTML 금지) ② 문서 고정·`#app`만 스크롤(D-125) ③ 버튼 줄·위 줄을 화면에 고정하지 않음(D-123). 걸리는 파일과 줄은 §3.
4. **순서**: 기초 → 작성 흐름 네 조각 → 편지·완료 → (Preact 관문 재기) → 기록 메뉴 → 달력·하단 탐색 → 설정 → 오늘 숲·로딩·잠금 → 들어오는 길 → 온보딩. **오늘 숲은 달력·설정 뒤**다 — 오늘 화면 아래 버튼 줄(도움·잠금·내보내기·지우기·로그아웃)이 옮겨 갈 설정과, `지난 기록` 알약이 갈 달력이 먼저 있어야 한다(§5).
5. **통계는 이 노드 밖이다**(`dashboard-reminder`). 그래서 하단 탐색의 통계 칸과 완료 화면의 `통계 보기`를 어떻게 둘지 정해야 한다(Q2).

## 1. SERVICE_WHY §20 점검

승인된 시안을 옮기는 일이라 새 기능은 없다. 옮길 때 지킬 것만 적는다.

| 질문 | 이식에서 지킬 것 |
| --- | --- |
| 1 정의 대신 이해 | 친구·조약돌은 사용자가 쓴 글에 반응하지 않는다(표정·대사·크기 변화 없음 — DESIGN_SYSTEM §8.1). 장면 설명 줄은 격려·평가가 아니다(UX_SPEC §6.1) |
| 2 판단은 사용자 | AI 줄·AI 분석 항목은 옮기지 않는다(D-120·D-121, 원칙 8) |
| 3 감정은 신호 | 감정 색·조약돌 크기로 좋고 나쁨·강도를 그리지 않는다(D-050·D-067) — 크기는 숫자와 열 점으로만 |
| 4 기록 강제 없음 | 연속 기록·보상·수집 장치를 옮기지 않는다. 작성 알림은 이 노드에서 두지 않는다(A-2) |
| 5 데이터가 가치로 | 달력은 '좋은 날 지도'가 아니다 — 칸에 감정 색·빛을 쓰지 않는다(DESIGN_SYSTEM §6.7) |
| 6 선택·행동으로 | 이 노드가 직접 닿는 일은 없다(감리 REPORT §3.2) — 30일 뒤 결정(STATUS §4-9) |
| 7 통제권 | 지우기·내보내기·완료 취소가 화면에서 닿는다(조각 6·8) |

매일 반복해 보는 연출(돌 흰빛 1.2s·봉투 2.4s·봉인 약 1.3s)이 부담이 되는지는 시안 승인으로 정해진 것을 바꾸지 않고, 감리가 권한 '주 1회 5분 소감'(REPORT §3.3 5단계)으로 본다(Q5).

## 7. 이식하며 같은 변경에서 고칠 정본

- **UX_SPEC**: §2 '첫 버전에서 시안과 다른 곳' 문단(뼈대 화면이 최소 모양이라는 문장), §3 '도움이 필요할 때 보기'의 '오늘 화면 아래 버튼 줄' 문장(D-125 — 설정이 생기면 옮긴다), §3·§11 오늘 기록이 있는 날 돌을 누르면 열리는 것(Q4 답), §3 로딩의 'D-058로 미정' 문구(FACTS §12-10), §4-2 '자동 전환은 아직 없다'(시안에 이미 있다 — FACTS §12-19), §13 '첫 구현' 문단, §16 '온보딩을 누구에게 다시 보일지'(Q6 답).
- **ARCHITECTURE §5**: 한 달 목록·완료 취소 두 행(조각 6·7), `GET /api/today`의 첫 기록일(A-7). **DATA_MODEL §5**: 완료 취소의 경로. **TRACEABILITY**·**EVAL §5**: 새 검증 항목, F-21의 '통계'(Q1·Q2 답에 따라 관문 `core-product` 조정 — `harness/quality-gates.yaml`).
- **DESIGN_SYSTEM**: FACTS §12의 4~11·16·20~23번(옛 서술이 남은 곳). 토큰을 더하거나 이름을 바꾸면 `design/tokens.json`·`style-guide.html`·`check-contrast`(DESIGN_SYSTEM §12).
- **DECISIONS**: Q1~Q6의 답, D-066 상태(Q3).
- **work-graph·STATUS §4·ROADMAP Phase 3·4**: Q1 답(달력이 두 곳에 적혀 있다 — FACTS §12-1), '별자리' 표현(FACTS §12-15).

## 8. 멈추는 경우(셋)와 지난 실수에서 배운 것

멈추는 경우: ① 제품 범위·안전·개인정보를 바꾸는 사용자 결정이 새로 필요할 때 ② 운영의 실제 일기에 닿는 되돌리기 어려운 일(창고 구조 변경 — 그 전엔 내보내기 + 백업, 뒤엔 복원 확인, RK-045) ③ 두 정본이 근거로 가려지지 않을 때(FACTS §12에 이미 적은 것은 근거가 있다).

이번에 피할 것:
- '지금 동작'을 CSS만 보고 적음 → 핸들러(JS)까지 읽고 파일:줄로.
- 작업자 보고를 그대로 믿음 → 메인이 새 캡처 프로필·2배 확대로 다시 잰다(헤드리스 캡처는 프로필 캐시가 옛 화면을 찍는다).
- 브라우저 도구로 Enter·Space가 `<button>`을 누르지 못하는 것을 결함으로 오진 → 키보드 활성화는 사용자 확인 항목.
- 사용자 그림을 다시 그림 → 원본을 줄이기만.
- 운영에 개발용 습관 → 운영 명령은 `ALLOW_PROD=1`, 실제 일기가 있는 운영에 지우는 명령을 쓰지 않는다(DEPLOY §8).
- 같은 숫자가 문서마다 다름 → 숫자는 STATUS §1, 값은 이 폴더의 FACTS가 아니라 각 출처를 고친다.
