# R-ZERO(백지 설계가) 보고 — 원문

2026-10-14 · 모델 Opus 5.5·추론도 high · 에이전트 형 `Plan`(쓰기 도구 없음) · 읽기 제한: `docs/SERVICE_WHY.md`, `PRD.md`, `FACTS.md` §A만. 메인이 받은 마지막 답장을 고치지 않고 옮겼다(맨 끝의 'Critical Files' 목록만 뺐다). 이 보고는 검토자의 주장이다 — 메인의 재확인은 `../REPORT.md` §7.

## 1. 요약

이미 있는 것은 이렇다. 접근 열쇠 로그인·세션·앱 잠금까지 된 앱 뼈대(시험 241건 통과), 사용자가 승인한 화면 시안, 검수를 마친 감정 분류표 v2, 무료 개발용 서버(Worker+D1). 일기를 저장하는 기능은 아직 없다(FACTS §A 19행). 그래서 백지에서 다시 그리면 첫 목표는 하나로 좁힌다. **'오늘 일기 한 편을 쓰고, 다시 열고, 내 손으로 내보내고 지울 수 있다'를 실제 서버와 iPhone에서 처음부터 끝까지 한 번에 뚫는 것**이다. 화면·대시보드·알림을 층층이 먼저 쌓지 않는다. 실제 데이터를 넣기 전에 내보내기·삭제·복구를 먼저 갖춘다(§20-7). 기록률을 재촉하는 장치(streak·알림)는 사용자가 켤 때만 동작하게 한다(§11·P4). 구간 1은 본인 전용이든 공개든 거의 같다. 두 경우가 갈라지는 곳은 **AI 경로**다. 공식 문서상 구독 로그인(`claude -p`)은 다른 사람의 요청을 처리하는 데 쓸 수 없다. 그래서 공개 여부는 'AI 작성 보조를 짓기 전'까지만 정하면 비용이 작다.

## 2. 구간 1 — 본인이 매일 쓰는 첫 버전

|---|---|---|---|---|---|
| 1-0 정리 | 커밋 안 된 뼈대를 확정하고, 운영 서버를 만들지 결정 | 자동 시험 통과, 개발 서버 원격 점검 통과 | 0회 | 정리 단계가 문서 작업으로 길어지는 것 | 문서 정비 전부 |

| 1-4 실사용 2주 | 쓰면서 걸리는 점을 모으는 기간. 새 기능은 만들지 않음 | 사용자가 매주 3문장 소감(무엇이 귀찮았나, 무엇을 다시 보고 싶었나, 그만두고 싶었던 순간) | 주 1회 5분 | 기록하지 못한 날에 죄책감이 생기는 것(§11) → 오늘 화면에 빈 날 표시·숫자를 두지 않음 | 모든 새 기능 |
| 1-5 돌아보기 조각 | 달력(빈 날은 중립 표시, 실패 표시 없음) + 지난 기록 상세 + 단순 빈도 통계(n 표시) | 시험: 완료 기록만 집계, 기록 없는 날은 missing으로 처리(0이 아님) | 1회 10분 | 통계가 '평가'처럼 읽히는 것 | Welch t 검정 비교, 친밀도 |
| 1-6 선택 장치 | 알림(인앱, 기본 꺼짐), streak(기본 꺼짐, 켜면 이틀 이상일 때만 표시) — §11·§19.12·P4 | 꺼진 상태에서 어떤 재촉 문구도 나오지 않는다는 시험 | 켤지 1회 선택 | — | 전부 미뤄도 됨 |

**본인 전용 / 공개 차이:** 1-1~1-5는 같다. 공개 가능성이 있으면 1-1에서 딱 두 가지만 지킨다. 모든 표 모든 행에 owner를 붙이고, 데이터 층에서 '열쇠는 하나'라고 가정하지 않는다. 비용은 거의 0이다. 1-3의 위기 연락처 검토는 공개라면 필수, 본인 전용이면 사용자가 위험을 알고 받아들이는 것으로 갈음할 수 있다(추론).

## 3. 구간 2 — AI 작성 보조, 근거 기반 분석(RAG), 공개

| 단계 | 목적 / 만드는 것 | 완료 기준 | 사용자 할 일 | 가장 큰 위험 | 미뤄도 되는 것 |
|---|---|---|---|---|---|
| 2-0 **갈림길 결정** | 공개 가능성을 열어 둘지 결정(아래 4절) | 사용자 답 1개 | 1회 10분 | 결정을 미루다 구독 경로에 깊이 묶이는 것 | — |
| 2-1 AI 작성 보조(세로 조각) | 대화 → **후보만** 제안 → 사용자가 하나씩 고름 → 기존 임시저장에 합침. AI 출력은 사용자가 승인한 칸에만 들어가고 대화 원문은 저장하지 않음(P1·P5). AI 호출은 '작업 큐 + 처리기' 하나로 감싸, 처리기를 PC 구독에서 API 키로 바꿔 끼울 수 있게 함 | 자동 시험: 승인 없이 저장되는 칸 0, 단정 표현 금지 목록 위반 0, AI가 꺼져 있을 때 직접 작성으로 넘어가는지. 사용자: 실제 3회 사용 | 주 1회 소감 | 응답 10~38초 지연(§A 22행)이 쓰기 흐름을 끊는 것 → 질문 하나마다 '건너뛰고 직접 쓰기' 버튼 | 음성 |
| 2-2 결정론적 회고 강화 | 기간 비교, 계열별 평균(n≥3) — AI 없이 계산 | 같은 입력이면 같은 출력이 나오는 시험 | — | 수치가 판정처럼 읽히는 것 | 통계 검정 |
| 2-3 근거 기반 분석(작게) | 데이터 **8주 이상** 쌓인 뒤. 근거 카드는 사람이 고른 30~50장, 벡터 DB 없이 태그로 찾기. 출력은 관찰·근거·한계·질문 네 칸 고정. 결과마다 '맞지 않음/지우기' 버튼(§20-7, P5) | 정답 세트 20건으로 평가: 근거 없는 문장 0, 단정 0, 진단어 0. 사용자가 4주 써 보고 '도움이 됐나' 판단 | 카드 검수 1회 30분, 주 1회 소감 | 분석이 사용자를 '정의'하게 되는 것(§12) | 벡터 검색, 자동 장기 기억 |
| 2-4P 공개 준비(공개일 때만) | 계정 인증(패스키 등), 행 단위 격리 재검증, 개인정보 처리방침, 위기 흐름 임상 검토, AI를 API 키(유료)나 사용자 본인 키로 전환, 운영자가 일기를 읽을 수 있는지에 대한 입장 | 외부 보안 검토, 격리 침투 시험, 법 검토 | 결정 여러 번, 외부 비용 발생 | 청소년 대상(§5)이면 만 14세 미만 동의 절차(미확인) | — |

**본인 전용:** 2-1은 PC 구독 경로로 충분하다. 2-4P는 없다.
**공개:** 2-1의 처리기를 처음부터 API 경로로 시험하고 비용 상한을 둔다. 무료 Workers는 하루 10만 요청이고, 넘으면 1027 오류가 난다. 공개 규모에서는 유료 전환을 가정해야 한다.

## 4. 갈림길과 결정 시점

| 갈림길 | 늦어도 언제 | 지금 정하면 / 늦게 정하면 |

| G2 **공개 가능성 여부** | 2-1(AI) 시작 전 | 공식 문서상 구독 로그인 경로로는 다른 사용자 요청을 대신 처리할 수 없다(아래 6절 URL). 공개 가능성이 있으면 AI는 API 키 경로로 지어야 하고 유료다. 이는 '유료 API 없음' 원칙(사용자 결정 D-019, FACTS §A 14행)과 충돌하므로 사용자 결정을 다시 열어야 한다 — 권고만 함 |

| G4 다른 사람 한 명이라도 초대 | 초대 전 | 공유 열쇠 하나로는 격리가 안 됨. 열쇠를 나눠 주는 순간이 하드 스톱 |
| G5 근거 카드의 출처·이용 허락 | 2-3 시작 전 | 본인 전용이면 느슨해도 되고, 공개면 허락 확인이 필요 |

권고: **공개 여부는 1-4(실사용 2주)가 끝날 때 묻는다.** 그 전에는 G1만 지키면 어느 쪽으로 가도 잃는 것이 없다. 결정 문구는 개발 용어 없이 이렇게 묻는다. "다른 사람도 쓰게 할 가능성이 1년 안에 있나요? 있으면 AI 기능에 월 비용이 생깁니다."

## 5. 이상적인 일하는 방식(1인 + AI 에이전트, 사용자는 비개발자)

**문서로 남길 것(네 가지만):** SERVICE_WHY(고치지 않음) / 짧은 PRD(사용자가 휴대폰에서 할 수 있는 일, 2쪽 이내) / 결정 기록(한 줄 결정 + 누가 정했나 + 다시 열 조건) / '지금 내 휴대폰에서 되는 것' 표 하나.

세부 명세는 시험이 대신한다. 문서는 '왜'만 남기고, '어떻게'는 코드와 시험에 둔다. 문서 분량에 상한을 두는 것을 제안한다(PRD가 요구사항 15개, 하위 정본 여러 개를 참조하는 지금 규모는 1인에게 크다 — 추론).

**시험으로 지킬 것(불변 조건):** 하루 1개 / owner 격리 / 저장 실패 시 입력 유지 / 완전 삭제 / 내보내기 왕복 / AI 출력은 승인 없이 저장하지 않음 / 단정·진단 표현 금지 목록 / 재촉 장치는 기본 꺼짐. 원칙별로 시험 하나씩을 '원칙 시험'으로 묶어, 원칙이 깨지면 빌드가 실패하게 한다.

**실기기로 확인할 것:** 출시마다 10항목 점검표를 사용자가 5~10분에 통과한다. 화면을 캡처해 기록한다.

**사용자에게 묻는 법:** 제품·가치 선택만 묻는다. 기술 선택은 묻지 않는다. 선택지는 2~3개로 내고, 각 선택지가 '휴대폰에서 어떻게 보이나'와 추천안을 붙인다. 질문은 주 1회 한 번에 묶는다. 승인은 '써 보고 괜찮음'으로 받는다.

**검토:** 독립 검토자는 갈림길(G2·G3), 실제 데이터 투입 직전, 공개 직전에만 둔다. 단계마다 두지 않는다.

**원칙이 낳은 선택:** §11·P4 → 알림·streak 기본 꺼짐, 빈 날 중립 표시, 실사용 소감에 '그만두고 싶던 순간' 질문 / §12·P1 → AI는 후보·질문만 내고 칸별로 승인받음, 금지 표현 시험 / P5·§20-7 → 실제 데이터 전에 내보내기·삭제·복구 먼저, AI 결과마다 '맞지 않음/지우기' / §20-5 → RAG는 8주 데이터 뒤에, 데이터를 늘리는 것 자체를 목표로 두지 않음.

## 6. 가정한 것과 확인하지 못한 것

**사실(공식 문서, 2026-10-14 확인):**
- D1 무료: 읽기 하루 500만 행, 쓰기 10만 행, 저장 5GB. 넘으면 다음 초기화까지 쿼리 오류 — https://developers.cloudflare.com/d1/platform/pricing/
- D1 Time Travel: 무료 7일, 유료 30일 — https://developers.cloudflare.com/d1/reference/time-travel/
- Workers 무료: 하루 10만 요청, 요청당 CPU 10ms, 넘으면 1027 오류 — https://developers.cloudflare.com/workers/platform/limits/
- 구독 경로 제한: Anthropic은 Free·Pro·Max 자격으로 다른 사용자 요청을 대신 보내는 것을 허용하지 않고, 제품은 API 키를 쓰라고 함 — https://code.claude.com/docs/en/legal-and-compliance

**추론:** 구간 1은 두 경우에 같다. 시안을 옮기는 일이 가장 큰 일정 위험이다. 8주·카드 30~50장·점검표 10항목·사용자 시간(분) 숫자는 내가 정한 추정치다.

**미확인:** 열쇠·PIN 해시가 무료 CPU 10ms 안에 드는지(스파이크가 통과했다고 문서에 적혀 있을 뿐, 이번에 다시 재지 않음) / 감정일기가 개인정보보호법상 민감정보에 해당하는지, 만 14세 미만 동의 요건 / 구독 한도가 매일 쓰기에 충분한지(B-06 보류) / 현재 PRD의 하위 정본(ARCHITECTURE·DATA_MODEL 등)이 이 순서와 맞는지 — 읽기 제한으로 열지 않음 / 기존 공정표와 얼마나 다른지 — 비교하지 않음.
