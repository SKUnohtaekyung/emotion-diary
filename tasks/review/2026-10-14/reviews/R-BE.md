# R-BE(서버) 보고 — 원문

2026-10-14 · 모델 Sonnet·추론도 high · 에이전트 형 `Plan`(쓰기 도구 없음) · 도구 53회. 메인이 받은 마지막 답장을 고치지 않고 옮겼다(맨 끝의 'Critical Files' 목록만 뺐다). 이 보고는 검토자의 주장이다 — 메인의 재확인은 `../REPORT.md` §7.

범위: Worker 하나+Static Assets, 인증, 직접 쓴 경로 표, AI 경로. 읽기 전용으로 했고 원격 명령은 돌리지 않았다. `npx vitest run --project worker`는 5파일 67건이 통과했고, `npm run typecheck`도 통과했다(둘 다 이 세션이 돌린 결과).

## 1. 판정 표

표기는 대상 | 판정(본인 전용 / 공개) | 근거 | 바꾸는 비용 | 미루는 비용 순이다. 사실·추론은 근거 칸에 표시했다.

1. **Worker 하나+Static Assets+`/api/*` (D-111, 사용자 결정)**
   - 판정: 유지 / 유지(트래픽이 늘면 Paid 전환).
   - 근거(사실): 정적 파일 요청은 "free and unlimited"이다. `run_worker_first`에 걸리는 요청은 Worker 요금으로 잡히고, 무료 한도를 넘으면 정적 파일로 빠지지 않고 429가 된다(developers.cloudflare.com/workers/static-assets/billing-and-limitations, 2026-10-14). Workers Paid는 월 $5에 요청 1천만 건 포함이다(…/workers/platform/pricing).
   - 바꾸는 비용: 큼(DB 계층 재작성). 미루는 비용: 없음.
2. **직접 쓴 경로 표·요청 순서 (`router.ts` 67줄, `app.ts` 98줄)**
   - 판정: 유지 / 유지(Hono는 선택).
   - 근거(사실): 서버 코드는 847줄이고 런타임 의존성이 0개다. 순서 401→403→423→404/405는 `app.ts`에서 확인했고 `router-and-race.test.ts`가 시험한다. Hono는 `hono/tiny`가 14kB 미만이고 Workers를 지원하며, Body Limit과 Secure Headers 미들웨어가 있다. CSRF 미들웨어가 있는지는 확인하지 못했다(hono.dev/docs).
   - 판단(추론): 경로가 15개 안팎이면 직접 쓴 쪽이 낫다. 경로가 30개를 넘거나 여러 사람이 코드를 만지게 되면 Hono를 다시 따진다.
   - 바꾸는 비용: 하루 안팎. 미루는 비용: 경로가 늘수록 서서히 커진다.
3. **접근 열쇠 + 서버 세션 기록 + `__Host-` cookie + CSRF (D-112·D-025)**
   - 판정: 유지 / 바꿈.
   - 근거(사실, 코드): HMAC 비교는 상수 시간이다. 시도를 대조 전에 예약해서 병렬로 몰아 맞혀 보는 길을 막는다. 로그아웃하면 서버 기록이 지워진다. CSRF는 header+Origin+Sec-Fetch-Site 세 겹이다. 열쇠는 본문으로만 받는다. 응답 헤더와 오류 처리도 갖췄다.
   - 본인 전용에서는 설계가 건전하다. 공개 서비스에는 단일 열쇠 방식이 맞지 않는다(ARCHITECTURE §6 '공개 전환'이 이미 인정한다).
   - 바꾸는 비용: 공개 전환 때 1~2주(추론). 미루는 비용: 본인 전용이면 없음.
4. **D1 전역 틀린 열쇠 잠금 (60초 10번→5분)**
   - 판정: 고침(작게) / 바꿈.
   - 근거(사실): 주소만 아는 누구나 5분마다 틀린 열쇠 10번을 보내 주인의 새 로그인을 계속 막을 수 있다(RK-001이 인정한 위험). 열쇠가 DEPLOY §6 기준으로 최소 약 70비트(휴대폰용 12자)이고 기본은 43자다. 그러면 잠금이 보안에 주는 이득은 거의 없고, 막힘 위험만 남는다.
   - 제안(추론): 잠금 시간을 60초 안팎으로 줄인다. 상수는 `shared/api.ts` 한 줄이고 시험 값도 같이 바꾼다. 어차피 소용없는 추측 시도를 계속 막을 이유가 없다.
   - 공개에서는 IP·계정별 제한과 WAF가 필요하다. Workers Rate Limiting은 위치별·"permissive, eventually consistent"라서 경계가 될 수 없다(공식 문서, 2026-10-14).
   - 바꾸는 비용: 작음. 미루는 비용: 새 기기에서 로그인해야 하는 날 공격이 겹치면 그날 일기를 못 쓴다.
5. **무료 요청 한도 소진 공격 — 위험 대장에 없다**
   - 판정: 고침(작게: 위험 등록 정도) / 바꿈.
   - 근거(사실+추론): `/api/*`는 하루 10만 건이 넘으면 429가 된다. 앱 화면은 그대로 열리는데 API만 죽는다. 주소를 아는 사람이 초당 약 1.2건만 보내도 하루 한도를 채운다. `grep`으로 RISK_REGISTER를 찾아도 이 위험은 없다(RK-003은 D1 한도만 다룬다).
   - 본인 1명의 평소 사용량은 하루 수백 건이라 한도의 100분의 1 아래다(추론).
   - 바꾸는 비용: 등록은 분 단위. 막으려면 Access나 자체 도메인+WAF가 필요한데 둘 다 D-019·D-021의 "무료만"에 걸린다. 미루는 비용: 주소가 퍼지면 하루 단위로 먹통이 된다.
6. **앱 잠금 PIN 4자리·서버 확인 (D-106·D-112 ③)**
   - 판정: 유지 / 바꿈.
   - 근거(사실): 틀린 횟수를 서버가 세고(5번→30초), 병렬 요청도 5번만 대조한다. 숫자 4자리는 지속 공격으로 평균 약 8시간 안에 뚫리지만, 공격자가 유효한 세션을 갖고 있어야 하므로 실질 위험은 낮다(추론).
   - 접근 열쇠를 가진 사람은 PIN 없이 풀린 세션을 받고, 10분 안에 PIN을 끌 수 있다. 이 점은 RK-002에 이미 적혀 있다. 즉 PIN은 "옆 사람이 화면을 보는 것"만 막는다.
   - 바꾸는 비용: 없음. 미루는 비용: 없음.
7. **Cloudflare Access 미사용 (D-108 ③, 사용자 결정)**
   - 판정: 유지 / 판단 보류.
   - 근거(사실): Access는 workers.dev URL에 붙일 수 있다(…/configuration/routing/workers-dev). 무료여도 결제수단 입력이 필요하다는 문장을 다시 확인했다("this step is still needed but you will not be charged", …/cloudflare-one/setup).
   - 공식 문서로는 50명 무료를 확인하지 못했다. 제3자 요약은 50명이라고 한다.
   - iPhone 홈 화면 앱에서 Access 로그인 왕복이 되는지, 만료 때 fetch가 302로 깨지는지는 미확인이다(추론: 깨질 가능성).
   - 공개 서비스에서는 사람 수만큼 요금이 붙는 구조라 맞지 않는다(제3자 요약 기준 1인 $7/월, 미확인).
   - 바꾸는 비용: 실기기 검증 필요. 미루는 비용: 5번 항목 위험이 그대로다.
8. **서버 시험이 Node에서 돌아감**
   - 판정: 유지 / 고침(작게).
   - 근거(사실): 시험은 `getPlatformProxy`가 띄운 로컬 D1(workerd)로 돌고, 런타임 차이는 개발용 건물의 원격 검사 34건이 메운다(STATUS §6). 이번 세션은 원격 검사를 돌리지 않았다.
   - 공개에서는 Workers 런타임 안에서 도는 시험이 필요하다. 지금 공식 플러그인은 Windows 지원이 미확인이다.
   - 바꾸는 비용: 중간. 미루는 비용: 작음.
9. **호스팅 대안 (Vercel Hobby, Netlify Free, Deno Deploy Free)**
   - 판정: 유지 / 해당 없음.
   - 근거(사실): Vercel Hobby는 "non-commercial, personal use only"이고 Function 호출 100만 건이 포함된다(vercel.com/docs/plans/hobby). Netlify Free는 월 300 크레딧 hard limit이며 한도 초과 때 동작은 확인하지 못했다. Deno Deploy Free는 월 요청 100만 건, 한도 초과 동작은 미확인이다.
   - 셋 다 D1 기반 SQL·batch 계약을 DB부터 다시 지어야 한다. 한도 수치만 보면 Cloudflare 쪽이 더 넉넉하다.
   - 바꾸는 비용: 큼. 미루는 비용: 없음.
10. **AI 경로: 본인 PC worker + `claude -p` 구독 로그인 (D-019·D-029·D-110, 사용자 결정)**
    - 판정: 유지(후행·기본 비활성) / 불가.
    - 근거(사실): 공식 문서는 제3자가 사용자 대신 Free/Pro/Max 자격으로 요청을 보내는 것을 허용하지 않는다고 한다. 이 문서는 AI 기능을 공개할 때 구독 경로가 막힌다는 사실의 직접 근거다(code.claude.com/docs/en/legal-and-compliance).
    - `--bare`는 구독 로그인을 읽지 않으며 "will become the default for `-p`"라고 예고되어 있다(…/headless). RK-035가 사실로 확인됐고, 업데이트 한 번에 조용히 AI가 멈출 수 있다.
    - 한도에 걸린 호출이 약 46번이라는 기록이 있다(runtime-profile). 이 구독 한도는 사용자가 매일 하는 개발 작업과 공유될 수 있는데 비율이 미측정이다(B-06 보류).
    - 바꾸는 비용: 대안 항목 참조. 미루는 비용: AI 단계 착수 전까지는 없음.

## 2. 영역 결론

본인 1명이 쓰는 지금 단계에서 서버 뼈대는 크게 잘못된 곳이 없다. 구성이 단순하고(847줄, 의존성 0), 병렬 공격·cookie 사본·잠금 되돌림 같은 어려운 경계를 시험이 실제로 잡는다. 판정은 유지 위주다. 손볼 것은 작은 둘이다. 첫째, 전역 열쇠 잠금은 보안 이득이 작고 막힘 위험만 남으니 잠금 시간을 줄이는 쪽이 낫다. 둘째, "요청 한도 소진으로 API가 하루 먹통이 되는 위험"이 위험 대장에 빠져 있다. 막는 수단이 없으니 인지된 위험으로 등록만 해도 된다. 공개 서비스는 인증·다중 사용자 분리·요율 제한·AI 경로를 거의 새로 지어야 한다. 구독 로그인 AI 경로는 공개로는 쓸 수 없다. 본인 전용인 지금은 이 구조를 바꿀 이유가 없다. 다만 일기 저장 코드가 아직 없어서, 이 검토는 인증 뼈대만 본 것이다.

## 3. 대안

- **(권고만, 사용자 결정 D-019)** AI 대화 단계 착수 시점에 "유료 API 없음"을 다시 열어 볼 만하다. 같은 모델을 Messages API로 직접 부르면 `claude -p`의 약 2.6만 토큰 오버헤드가 사라지고, 지연이 줄고(추론), 구독 한도·정책 회색지대·`--bare` 변경 위험이 없어진다.
  - 비용 추정(추론): Sonnet 5는 입력 $2/출력 $10 per MTok(platform.claude.com/docs/en/about-claude/pricing, 2026-10-14)이다. 한 턴을 입력 3천·출력 6백 토큰으로 가정하면 약 $0.012이고, 하루 5턴이면 월 약 $1.8이다. Opus 5 검증 호출은 한 번에 약 $0.03이다. 본인 1명이면 월 $2~4 수준이다.
  - 잃는 것: "추가 지출 0원" 원칙이다.
- **Workers AI 무료 할당(10,000 neurons/일)**(…/workers-ai/platform/pricing): 한국어 품질, 구조화 출력, 위기 감지 독립 검증은 미확인이다. 쓰려면 기존 평가 세트로 먼저 재 봐야 한다.
- **Passkey/WebAuthn**: 공개로 갈 때 접근 열쇠를 대체한다. 본인 전용에서는 지금 방식이 실기기 검증을 마쳤으므로 바꿀 필요가 없다.
- **공개 서비스로 갈 때 다시 지을 것(추정 규모는 추론)**:
  - 인증(가입·복구·이메일 또는 OAuth): 1~2주
  - 다중 owner 분리와 시험: 1~2주
  - 요율 제한(D1 또는 DO 카운터): 며칠
  - Workers Paid: 월 $5부터
  - AI API 비용: 위 단가로 사용자 1,000명, 월 150턴이면 월 약 $1,800이다. Haiku 5.5($0.10/$0.50)로 내리면 대폭 줄지만 품질은 미검증이다.
  - 이용 정책: Anthropic AUP는 18세 미만 대상 제품에 추가 지침을 요구하고, 정신건강 분야의 AI 권고에는 자격 있는 사람의 검토와 AI 고지를 요구한다(anthropic.com/legal/aup, 2026-10-14 요약). SERVICE_WHY가 청소년·청년을 대상으로 삼으므로 정면으로 걸린다. 이 기능이 '권고'에 해당하는지는 법률 검토가 필요하다(미확인).
  - 개인정보 처리 법규: 확인하지 못했다.

## 4. 확인하지 못한 것

- 일기 저장·내보내기·삭제 경로가 아직 없어서 데이터 무결성 쪽은 코드로 볼 수 없었다.
- 원격 검사(`remote-check`)는 금지 명령이라 돌리지 않았고, 개발용 건물 실측도 못 봤다.
- Access를 홈 화면 앱에서 쓸 수 있는지 확인하지 못했다.
- Workers Rate Limiting의 무료 플랜 제공 여부는 공식 문서에서 찾지 못했다.
- Zero Trust 무료 50명은 공식 문서로 확인하지 못했다.
- Netlify·Deno의 한도 초과 동작은 확인하지 못했다.
- Workers AI 모델별 한국어 품질과 neuron 소모는 확인하지 못했다.
- 개인정보 법규는 보지 않았다.
- workers.dev 주소가 외부에서 쉽게 발견되는지는 확인하지 못했다.

## 5. 메인이 다시 잴 곳

1. **무료 한도 소진 시 동작**: https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/ 에서 `run_worker_first`와 429, 그리고 https://developers.cloudflare.com/workers/platform/limits/ 의 하루 10만 건과 Error 1027. 5번 판정의 근거다.
2. **전역 잠금 상수와 열쇠 길이**: `app/shared/api.ts` 38~42줄(KEY_FAIL_MAX 등)과 `app/worker/src/routes/session.ts`의 `login`(약 47~100줄). DEPLOY §6의 열쇠 길이(약 70비트, 기본 43자)와 함께 4번 판정이 맞는지 확인한다.
3. **`--bare` 기본값 예고**: https://code.claude.com/docs/en/headless 의 "Start faster with bare mode" 절. 구독 로그인을 읽지 않는다는 문장이 지금도 있는지 확인한다.
4. **제3자 구독 자격 사용 금지 문장**: https://code.claude.com/docs/en/legal-and-compliance 의 "Authentication and credential use" 절. 공개 서비스에서 AI 경로가 불가하다는 판정의 근거다.
5. **Access 결제수단 문장**: https://developers.cloudflare.com/cloudflare-one/setup/ 에서 "payment details" 문장이 지금도 있는지, 그리고 `docs/DECISIONS.md` D-108 ③의 서술과 일치하는지 확인한다.
