## 8. 멈추는 경우 / 멈추지 않는 경우

- **멈추고 묻는다**: 점검 범위를 넘는 일(코드·정본·서버 변경)이 필요해 보일 때, 비밀·개인정보·요금·되돌리기 어려운 일이 걸릴 때, 사용자만 아는 사실(예: 공개 계획의 시점·의도, 예산 한계)이 판정을 좌우할 때 — 이때도 질문은 모아서 한 번에.
- **멈추지 않는다**: 단계 하나를 끝냈을 때(짧게 보고만), 검토자 결과를 기다릴 때(다른 단계 먼저), 검토자끼리 부딪힐 때(메인이 근거로 판정).
- 일시적 도구 실패는 두 번까지 재시도. 같은 가설로 두 번 실패하면 가설을 버린다(AGENTS §5).

## 9. 작업 규칙과 함정(이 저장소·이 PC)

- **줄바꿈**: 문서 대부분이 CRLF다. 이 폴더의 새 문서도 CRLF로 쓴다(Write 도구로 쓴 뒤 변환하거나 기존 CRLF 파일을 Edit 도구로). 고친 뒤 LF 수 = CRLF 수를 바이트로 센다.
- **셸과 백틱**: 백틱·작은따옴표가 든 글을 Bash 명령(`node -e "…"`, heredoc) 안에 넣지 않는다 — 셸이 명령으로 해석해 낱말이 사라지거나 파일이 명령으로 실행되려 했다(2026-10-14 두 번). 그런 글은 Edit 도구나 스크래치패드의 스크립트 파일로만.
- **Write 경로**: 파일 경로는 저장소나 스크래치패드 안인지 쓰기 전에 본다(2026-10-14 잘못된 경로에 빈 파일을 만든 일).
- **작업 트리**: `app/scaffold`에 커밋 전 변경이 있다. 건드리지 않는다. 검토자도 읽기만.
- **개발용 건물**: 읽기 전용으로도 원격 명령은 쓰지 않는다(로그인 만료·실수 위험). 상태는 `harness/runtime-profile.json`과 `tasks/mobile/2026-10-14-t3/PLAN.md` 5·6단계 기록으로 본다.
- **하위 에이전트**: 보고를 그대로 믿지 않고 결론을 좌우하는 주장은 메인이 다시 잰다. 같은 영역 재작업은 두 번까지(AGENT_WORKFLOW §10). Workflow 도구는 사용자가 명시적으로 원할 때만 — 이번에는 Agent 도구로 background 병렬(일곱 명, medium 규모 안).
- **'확인됨'**에는 어디서(명령·파일·URL+확인일) 확인했는지를 같이 적는다. 연습용·개발용 결과를 실제 앱의 통과로 옮기지 않는다.
- **사용자에게**: 개발 용어 없이 비유로, 결과부터. 사용자가 정할 것만 묻고 추천을 붙인다. 휴대폰 조작 같은 사용자 부담을 늘리는 권고는 그 부담을 숫자(분·횟수)로 적는다.
