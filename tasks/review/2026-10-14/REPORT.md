## 1. 한 장 요약

### 1.1 결론 다섯 줄

1. **자재와 공법(기술 스택)은 본인 전용 기준으로 맞다 — 유지.** 창고(D1)·건물 하나(Worker)·도구 없이 짓는 화면은 지금 바꿀 이유가 없고, 바꾸는 값이 지금이 가장 싸다는 것까지 재 봤다(§5). 손볼 것은 작다: 틀린 열쇠 잠금이 **맞는 열쇠까지 막아 주인을 계속 내쫓을 수 있는 구조**를 고치고, '무료 요청 한도를 남이 다 써 버리면 그날 앱이 멈춘다'는 위험을 등록한다.
2. **가장 크게 바꿀 것은 공정 순서다.** 지금 공정표는 '서버 → 화면 전부 → 통계 → 출시' 층 쌓기라 실제로 매일 쓰기 시작하는 날이 가장 늦고, 가장 큰 위험(화면이 통째로 새로 열려 쓰던 글이 사라짐, 자판이 버튼을 가림)을 화면 10단계를 다 옮긴 뒤에야 휴대폰에서 본다. **'오늘 한 편 쓰기 → 다시 열기 → 내보내기·지우기 → 되살리기'를 휴대폰까지 먼저 뚫고 그날부터 실제로 쓰고**, 통계는 데이터가 쌓인 뒤 만든다(§3). 실사용을 앞당기는 만큼 '실제 일기가 아직 바뀌는 창고 구조 위에 놓이는 위험'이 생기므로 구조를 바꿀 때마다 백업을 먼저 하는 규칙을 함께 둔다.
3. **AI 경로는 다시 판정할 새 사실이 나왔다.** 2026-10-07부터 Claude **Max·Team 요금제에 월 API 크레딧**(Max 5x $100, Max 20x $200, 결제수단 불필요, 다 쓰면 청구 없이 멈춤)이 들어 있다(공식 문서 확인). Max라면 '본인 PC + `claude -p`' 대신 서버가 Claude API를 직접 부르는 길이 **추가 비용 없이** 열려 PC를 켜 둘 필요와 정책 회색지대가 사라지고, 지연도 줄어들 공산이 크다(미측정). 단 이 크레딧은 약관 동의·조직 연결이 필요한 **프로모션 혜택**이라 없어질 수 있다 — 그때는 지금 경로로 돌아갈 수 있게 짓는다. **요금제 종류는 사용자만 안다**(§5.4, 질문 1).
4. **데이터 안전의 약점은 창고가 아니라 그 둘레다.** 백업·재수입·복원 연습 코드가 0줄이고(사실), '화면이 통째로 새로 열린 뒤 복구'(F-24)는 위험 중 가장 높은데(RK-034 높음/높음) **어느 출시 관문에도 들어 있지 않다**(사실, grep 0건). 둘 다 실제 일기를 넣기 전 조건으로 삼는다(§3, §6).
5. **현장 규칙은 효과가 확인된 셋을 지키고 무게를 덜어 낸다.** 효과가 기록으로 남은 것은 새 맥락 검토자·기계 검사·실기기 확인이다(실제 결함·가짜 통과를 잡음 — 이번 점검에서도 반대 입장 검토가 메인 초안의 잘못된 고침을 잡았다). 비용은 같은 사실을 변경 하나에서 정본 7~11개에 손으로 옮겨 적는 데 몰려 있고, 그 결과 이번에만 불일치 9건이 나왔다. '사실은 한 곳에' 원칙으로 바꾸고, 소유 파일 확인 훅은 여러 작업자가 동시에 쓸 때만 켜고, 사용자에게 묻는 수는 줄이되 에이전트가 정한 것은 지금처럼 '에이전트 결정'으로 표시한다(§4).

- 기존 계획을 그대로 둘 때의 장점: 설계도·관문을 다시 쓸 필요가 없고, 실제 일기는 구조가 다 굳은 뒤에 들어간다. 단점은 위 '얻는 것'의 반대다.

## 5. 기술 스택(자재와 공법)

### 5.1 창고 — Cloudflare D1

- **정할 때의 기준**: D-032(사용자 결정) — 직접 쓴 백엔드 + 무료 클라우드, BaaS는 과하다. D-024 — 대화형 트랜잭션 없이 조건부 UPDATE·CHECK·trigger·batch로 규칙을 지킨다.
- **기준이 지금도 맞나**: '무료'와 '복구'로 다시 보면 더 맞다. 한도를 넘어도 과금 없이 질의만 막히고(사실, 공식 문서), 무료 복구 기간이 7일로 대안(Turso 1일, Neon 6시간, Supabase 무료 자동 백업 없음 — R-DB가 인용한 공식 페이지, 메인 미재확인)보다 길다. 원자성·동시성은 원격 실측했다(사실).
- **대안과 바꾸는 비용**: 지금 표가 4개뿐이라 지금이 가장 싸다(Turso는 같은 SQL 방언). 그러나 바꿀 이유가 없다. 기기 안 저장을 **주 저장소**로 쓰는 안(+ 동기화)은 홈 화면 앱 저장 공간이 지워질 수 있고 AI 경로와 충돌해 권하지 않는다(짧은 임시 보관용 사본은 별개 — §3.3 2단계).
- **서버가 못 읽는 암호화**: **판단 보류**. 열쇠를 잃으면 일기를 영영 잃고(SERVICE_WHY §11의 '돌아올 수 있음'과 부딪힘), AI·서버 통계와 맞지 않는다. 그러나 사용자의 데이터 통제권(§20-7)과, 공개 뒤에 붙이면 거의 다시 짓는다는 점(§5.6)을 생각하면 공개 갈림길에서 꼭 다시 묻는다. 본인 전용 동안 '나중에 열쇠를 나눌 수 있는 저장 형태'의 비용은 이번에 재지 못했다(§8).
- **판정**: 본인 **유지** / 공개 **유지**(규모가 커지면 유료 전환, 행마다 owner는 이미 설계). 둘레는 **고침**: 백업·재수입·복원 연습을 사용 시작 조건으로, 근거 카드(Evidence)는 일기 창고 밖(저장소 파일)으로, 내보내기 CPU 실측.
- **나중에 커지는 비용**: 일기 표 위에 코드가 쌓이면 Turso로도 '작음', Postgres로는 '중간'(R-DB). 공개 때 '지운 기록을 행 단위로 즉시 파기'는 Time Travel 구조상 어렵다(판단 보류 — 법률 미확인).

### 5.2 서버 — Worker 하나 + 직접 쓴 경로 + 열쇠 로그인

- **정할 때의 기준**: D-111(사용자 결정) — 화면과 `/api/*`를 같은 주소에 둬야 iPhone 홈 화면 앱에서 로그인 cookie가 산다(규격에서 끌어낸 판단, 분리 구성은 재 보지 않음). D-112(굵은 글 사용자 결정) — 열쇠 로그인 30일·서버 세션 기록·잠금 서버 확인. D-115(에이전트 결정) — 프레임워크 없는 경로 표.
- **기준이 지금도 맞나**: 맞다. 서버 847줄·런타임 의존성 0, 순서(401 → 403 → 423 → 404/405)와 경쟁 조건을 시험이 잡는다(사실, R-BE가 시험 67건 PASS). 정적 파일 요청은 무료·무제한이다(사실).
- **대안**: Hono는 경로가 30개를 넘거나 여러 사람이 고칠 때 다시 본다(하루 안팎). Vercel·Netlify·Deno는 창고부터 다시 지어야 하고 한도도 좁다. Cloudflare Access는 결제수단 입력이 필요하고 홈 화면 앱에서 로그인 왕복이 되는지 미확인.
- **판정**: 본인 **유지**, 단 두 가지 **고침(작게)**:
  1. **틀린 열쇠 잠금 구조**(에이전트 설계 — `app/worker/src/routes/session.ts` 38~75줄, `app/shared/api.ts` 34~37줄, 메인 원문 확인): 틀린 횟수를 **전 세계 공용 1행**으로 세고 잠긴 동안에는 **맞는 열쇠도 429**다. 그래서 주소만 아는 누구라도 잠금 시간마다 틀린 열쇠 10번을 보내면 주인을 계속 내쫓을 수 있다 — 잠금 시간을 줄여도 공격 간격만 짧아질 뿐 막히지 않는다(초안의 '1분으로 줄이기'는 틀렸다 — §7.4 R-RED #1). 열쇠가 약 70비트(12자)~43자라 맞혀 보는 공격은 처음부터 성립하지 않으므로(추론: 무료 한도 하루 10만 번을 다 써도 2^70에 견줄 수 없다) 잠금이 실제로 막는 것은 주인뿐이다. **고칠 방향: 맞는 열쇠는 잠금과 상관없이 통과시키고 틀린 시도만 막는다**(대조는 지금처럼 상수 시간). 대안은 요청한 곳(IP)별로 세기.
  2. `/api/*` 무료 한도(하루 10만)를 남이 채우면 그날 API가 429로 멈춘다(사실, 공식 문서) → 위험 기록에 등록(막을 무료 수단은 없다 — 주소를 퍼뜨리지 않는 것이 완화).
- 공개 **바꿈** — 가입·복구·사용자별 분리·요율 제한(1~2주씩, R-BE 추정).

### 5.3 화면 — 도구 없는 TypeScript + Vite + 해시 주소 + 홈 화면 앱(service worker 없음)

- **정할 때의 기준**: D-114(**사용자 결정**: 도구 없이) — 더 받는 무게 0, 한글 입력에 도구가 끼지 않음, 시안과 같은 방식. D-047(사용자 결정) — 시안 코드는 버리고 구조만 옮긴다.
- **기준이 지금도 맞나**: 대체로 맞다. 남은 화면의 어려운 점(방문 기록 규칙·한글 조합·iOS 자판·움직임·새로 열림 복구·앱 전환 때 신호 없음)은 어느 도구도 대신 풀어 주지 않는다(R-FE 추론, 메인 동의). 화면을 그리는 보안 정책(CSP)을 느슨하게 하지 않아도 된다는 이점도 있다.
- **대안과 바꾸는 비용**: 지금 바꾸면 도구에 묶이는 코드 약 1,400줄(메인 측정 1,397줄), 시안을 옮긴 뒤 바꾸면 약 4,400줄(R-FE 추정) — 결정 시점은 '작성 흐름을 옮기기 전'. 네이티브 래퍼는 Mac과 유료 개발자 계정이 필요하다. service worker는 Web Push를 할 때만 필요해지고(공식 WebKit 글) 지금은 필요 없다 — 사용자가 켜고 끄는 알림이라면 SERVICE_WHY(§19.12)와도 부딪히지 않는다.
- **판정**: 본인 **유지** + **고침(작게)**: 시안을 옮기기 전에 '작성 흐름 상태 설계 한 장'(단계는 주소에, 저장은 입력 멈춤마다, 한글 조합 중 값 건드리지 않기, 버튼은 본문 흐름, 단계 계산은 순수 함수), R-FE의 관문(작성 흐름을 먼저 옮겨 보고 기준을 넘으면 그때 Preact). 공개 **유지 + 관문**(접근성 정적 검사가 닿지 않는 점은 공개 때 다시 본다), 웹폰트 2.0MB는 공개 직전에 조각화.

### 5.4 AI 경로 — 본인 PC + `claude -p` 구독 로그인 (D-019·D-029, **사용자 결정**)

- **정할 때의 기준**: D-019 — 유료 API를 쓰지 않는다, 구독 자원으로 되는 경로만. D-029 — 그래서 본인 PC의 Claude Code를 구독 로그인으로 부른다.
- **기준이 지금도 맞나 — 새 사실 셋(메인이 2026-10-14 공식 문서로 확인)**
  1. `--bare`는 구독 로그인을 읽지 않으며 앞으로 `-p`의 기본값이 될 예정이다(code.claude.com/docs/en/headless). 그날 지금 경로는 멈춘다. 다만 실패는 결과로 드러나므로(같은 문서) worker의 실패 전환(B-06에서 확인)이 받아 '조용히' 깨지지는 않는다. 기본값이 바뀐 뒤 명시 옵션으로 되돌릴 수 있는지는 미확인.
  2. 개발자가 사용자 대신 Free·Pro·Max 자격으로 요청을 보내는 것은 허용되지 않는다(code.claude.com/docs/en/legal-and-compliance) — 공개 서비스에선 이 경로를 쓸 수 없다.
  3. **Max 5x·Max 20x·Team 요금제에 월 API 크레딧($100·$200·좌석당, Team은 최대 $500)이 포함**된다(공지일 2026-10-07 — support.claude.com/articles/15036540의 공지 줄. 조건은 platform.claude.com/docs/en/about-claude/api-credits-for-subscribers). 내 앱에서 Claude API를 쓰는 데 쓸 수 있고, 결제수단을 넣지 않아도 되며, 크레딧이 떨어지면 요청이 멈출 뿐 요금제에 청구되지 않는다(따로 산 크레딧·자동 충전이 없을 때). **조건**: Claude Console 조직을 만들어 요금제에 연결하고 프로그램 약관에 동의해야 한다, 연결한 조직은 본인이 바꿀 수 없다, 신규 가입자는 7일 뒤부터, Pro·Free는 대상이 아니다, 콘솔에 '프로모션 크레딧'으로 분류된다 — **없어지거나 바뀔 수 있는 혜택**이다.

### 7.5 이 검토의 한계

- 검토자 일곱과 메인 모두 같은 회사 모델이다(Opus·Sonnet·Fable). 완전한 독립은 아니다(PLAN §6.1).
- 영역 검토자 다섯과 백지 설계가는 같은 브리프·잣대를 받았다 — 수렴의 일부는 잣대가 유도했을 수 있다(R-RED #14).
- 검토자는 쓰기 도구가 없는 형으로 띄웠고 원격 명령(개발용 건물)은 아무도 돌리지 않았다 — 개발용 건물의 현재 상태는 T3 기록에 기댄다.
- 세션 시간·토큰 비용은 기록에 접근할 수 없어 파일 수·바이트·건수로만 쟀다.

## 8. 확인하지 못한 것

- 사용자의 Claude 요금제 종류(Max/Team/Pro) — §5.4 판정이 여기에 달려 있다(Q-A).
- `--bare`가 기본값이 된 뒤 명시 옵션으로 구독 로그인 동작을 되돌릴 수 있는지.
- Playwright WebKit 같은 PC 도구가 iPhone 홈 화면 앱의 동작(새로 열림, 앱 전환 신호)을 어디까지 대신하는지.
- WebKit 322900이 사용자 기기(iOS 26.5.2)에서도 나는지(보고는 iOS 27).
- Android 에뮬레이터·빌린 기기를 증거로 인정할 수 있는지(공개 때).
- 법률: 본인 전용에서도 건강 민감정보 별도 동의가 필요한지, 만 14세 미만 동의, 공개 때 파기 의무와 Time Travel 보존의 관계.
- Cloudflare Time Travel 이력이 물리적으로 지워지는 시점, Cloudflare 직원의 데이터 접근 정책(공식 문서에 없음 — R-DB).
- 서버가 못 읽는 암호화를 나중에 붙일 수 있게 지금 저장 형태를 잡는 비용.
- 잠긴 동안의 시도가 D1 '쓰기 행' 한도에 세어지는지(R-RED — 읽기 한도 소모는 확실).
- 내보내기 CPU, Workers 런타임 안 시험(일기 코드가 없어 잴 수 없음).
- Cloudflare Access가 홈 화면 앱에서 로그인 왕복이 되는지, Zero Trust 무료 인원(공식 문서로 확인 못 함 — R-BE).
- Workers AI의 한국어 품질·구조화 출력.
- 공개 저장소의 작성자 메일이 사용자의 주 메일인지(도메인 종류만 분류했다).
- Turso·Neon·Supabase의 무료 조건은 R-DB가 인용한 공식 페이지이고 메인이 다시 열지 않았다(결론에 영향 없음 — 바꾸지 말자는 판정이라).
- 작업 크기(세션 수)·일정은 추정하지 않았다.
