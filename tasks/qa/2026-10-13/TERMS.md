# 용어 통일 (2026-10-13 사용자 승인, 반영 완료)

2026-10-13 작성 흐름 밖 문구 점검에서 나온 것. UX 라이팅 원칙 7(같은 것은 같은 말로)에 걸리는 곳만 모았다. 사용자 승인 뒤 코드에 반영했다. 정본은 `docs/UX_SPEC.md` §6.1의 용어표다. 줄 번호는 점검 시점의 것이다.

## 1. 지우기 / 삭제

| 지금 | 어디 | 모을 말 |
| --- | --- | --- |
| 이 글 지우기 · 지우기 · 쓰던 글을 지웠어요 | 작성 ⋯ 메뉴, 달력의 쓰던 글 | 그대로(**지우기**) |
| 삭제 · 삭제하기 · "…기록을 삭제할까요?" · "정말 삭제할까요?" · "삭제하면 되돌릴 수 없어요." | 기록 메뉴(`tabs.js` 290~299) | **지우기** · "…기록을 지울까요?" · "정말 지울까요?" · "지우면 되돌릴 수 없어요." |
| 기록만 지우기 → 모든 기록 삭제 → 모든 기록 영구 삭제 → "모든 기록을 영구 삭제할까요?" → 모두 삭제했어요 | 설정(`settings.js`·`settings-data.js`) | 기록만 지우기 → **모든 기록 지우기** → (마지막 확인만) "모든 기록을 영구히 지울까요?" → **모두 지웠어요** |
| 보관과 삭제 · "삭제 전에 내 기록 내보내기로…" | 개인정보 안내·삭제 화면 | **보관과 지우기** · "지우기 전에 내 기록 내보내기로…" |

기준: 동사는 '지우기' 하나. '영구'는 되돌릴 수 없는 마지막 확인 한 곳에만 쓴다. 문서·정책 이름(영구 삭제, hard delete)은 그대로다.

## 2. 편지 / 기록

| 지금 | 어디 | 모을 말 |
| --- | --- | --- |
| "10월 3일의 편지"(상세 제목)와 "10월 3일의 기록"(같은 화면 ⋯ 시트) | `tabs.js` 351·287 | 시트도 **"10월 3일의 편지"** |
| "이 날의 편지가 없어요" / "남긴 기록이 없어요" | `tabs.js` 311·163 | 둘 다 **"남긴 기록이 없어요"**(없는 것은 기록이다) |

기준: 저장된 대상은 '기록', 그것을 읽는 모습(카드·봉투)은 '편지'. 한 화면에서 같은 것을 두 말로 부르지 않는다.

## 4. 일기 / 기록 / 글

| 지금 | 어디 | 모을 말 |
| --- | --- | --- |
| "직접 쓴 일기를 자동으로 분석하거나 지켜보지 않아요" | 온보딩 시작하기 전에(`welcome.js` 91) | "직접 쓴 **기록**을 자동으로 분석하거나 **들여다보지** 않아요" |
| "직접 쓴 일기를 … 감시하지 않아요" | 설정 개인정보 안내(`settings.js` 224) | 위와 같은 문장 |
| 쓰던 글 / 임시저장 | 달력·오늘·작성 / 달력 범례·기록 메뉴 | 사람에게 하는 말은 **쓰던 글**, 상태 이름(범례·'임시저장 상태로 돌려요')은 **임시저장** 그대로 |

기준: 완료해 남긴 것은 '기록', 쓰는 중인 것은 '글'. 서비스 이름(감정일기) 밖에서는 '일기'를 쓰지 않는다.

## 5. 닫는 버튼

## 판단이 남은 것

- 통계의 '친구·친밀도·다녀갔어요'와 작성 흐름의 '마음' — D-064로 정한 은유라 이번에는 건드리지 않는다.
- 통계 빈 상태 "기록이 더 필요해요" — 부품 명세(empty-state)가 '탓하지 않는 중립 사실'로 정한 말이라 그대로 두었다.
- 가입의 "보호자가 함께 동의해야", 삭제 확인의 "문구를 그대로 입력해요" — 법·안전 때문에 필요한 말이라 원칙 1의 예외로 둔다.
- 위기 안내 "혼자 견디지 않아도 돼요" — 안전 문구. 임상·안전 검토(출시 차단 항목)에서 함께 본다.
