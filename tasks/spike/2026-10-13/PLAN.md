## `app-scaffold`를 열 수 있는가

**열 수 있다.** `app-scaffold`의 선행은 `hosting-identity-spike`(B-02·B-03·B-08)와 `data-store-spike`(B-04·B-05) 둘이고, 다섯 게이트가 모두 pass라 두 노드를 `done`으로, `app-scaffold`를 `ready`로 바꿨다. B-06 보류와 B-07은 AI·RAG 단계의 선행이라 여기를 막지 않는다. 다만 착수 전에 정해야 할 것이 둘 있다. 첫째, 이 판정은 전부 **Worker 하나가 화면과 `/api/*`를 함께 내는 구성**에서 나왔고 정본(D-032)이 적고 있는 Pages+Workers 분리 구성은 한 번도 검증된 적이 없다 — TASK-MOBILE 제안을 받으면 그대로 착수할 수 있고, 분리 구성을 고집하면 B-08을 그 구성으로 다시 재야 한다. 둘째, 판정은 **본인 1명** 전제다 — 여러 사람이 쓰는 서비스로 간다면 로그인 방식·사람별 데이터 분리·AI 비용을 다시 검증해야 하고 이번 pass는 그 경우를 보장하지 않는다.

- 실패 원인: 형식을 맞춘 답은 내부적으로 한 번 더 주고받는데(`num_turns` 2), `--max-turns 1` 제한에 걸리는 때가 있다. 같은 문장을 다시 부르면 된다 — 재시도 상한 2가 이 경우를 받는다.
- **모델만으로는 위기 흐름을 보장할 수 없다.** 위기 문장에서 호출이 실패하면 지금 설계로는 '직접 쓰기로' 돌아가고 위기 안내가 뜨지 않는다. `docs/AI_RAG_SPEC.md` §5.2가 이미 "모델의 신호는 단독 근거가 아니라 Safety Validator의 규칙 검사와 결합"이라고 적고 있다 — 스파이크는 그 규칙 검사를 만들지 않았다. Phase 3에 넘길 것: 규칙 검사는 모델 호출과 따로, 호출이 실패해도 돈다.
- `possible_crisis`인데도 모델이 사건 칸을 채워 보낸 경우가 3건(X1·X2·M2). **draft를 바꾸지 않는 것은 모델이 아니라 서버가 지켜야 한다**(같은 절이 이미 요구). 스파이크 서버는 draft 반영 자체를 구현하지 않았다.
- 모호 3건은 모두 `possible_crisis` 쪽으로 기울었다. 과한지 적절한지는 사람이 판정한다(EVAL §7) — 사용자 판정 대기.

**E-3 생성과 분리된 독립 검증 호출(Opus)**

- 생성 호출 1회 → 그 출력과 고정 주장 4개를 **다른 프로세스·다른 prompt·도구 없음·기록 없음**으로 검증 5회. 세션 ID 6개가 모두 다르다(문맥을 공유하지 않는다).
- 판정: 범위 안 → `supported`, 일반화·인과 → `too_strong`, 카드에 없음 → `unsupported`, 진단·치료 단정 → `safety_prohibited`, 생성 출력 → `supported`. **기대와 5/5 일치**, 출력은 판정과 사유 코드뿐.
- 걸린 시간(3개 동시): 12.5 ~ 16.6초. 근거 카드는 합성이다(실제 연구 요약이 아니다).

**E-5 실패 분류**

- 1.5초 제한 → `timeout`(1.7초에 프로세스 정리), 깨진 형식 정의 → `nonzero_exit`, 로그인 만료 → `auth_expired`(앞 절). 거절(`refusal`)·끊긴 출력(`incomplete`)은 분류 코드는 넣었으나 **재현하지 못했다**.

**지연 — 9월과 다르다**

- 위기 문장 호출: 첫 실행(3개 동시) 16.7 ~ 25.4초, 후속(하나씩) 20.4 ~ 38.0초. 평범한 문장 1회는 11.7초. 9월 실측은 p50 8.4초 / p95 12.1초였다.
- 조건이 다르다(문장 종류, 동시 실행, 표본 수). 같은 조건(대기열 경유, 평범한 문장, 하나씩 10회)으로 다시 재는 것을 E-2에 넣는다. **지금 숫자로는 '20초 지나면 직접 쓰기로' 전제가 위기 문장에서 자주 걸린다.**

### A-5 Claude 구독 경로의 보존·학습 설정 [B-06]

출처: https://code.claude.com/docs/en/data-usage

- 개인 구독(Free·Pro·Max)은 '모델 개선에 내 데이터 사용' 설정을 고를 수 있고 Claude Code 사용에도 그대로 적용된다. **켜 두면 5년 보존, 끄면 30일 보존.** 바꾸는 곳: https://claude.ai/settings/data-privacy-controls
- `claude`는 대화 기록을 이 PC의 `~/.claude/projects/` 아래에 **평문으로 30일**(기본값, `cleanupPeriodDays`) 남긴다. 9월 스파이크의 PC worker는 이 기록을 끄지 않았다.
- 실제 도구 확인: `claude --help`에 `--no-session-persistence`("sessions will not be saved to disk … only works with --print")가 있다. 실제로 기록이 안 남는지는 E 묶음에서 실행으로 확인한다.
- 사용 지표·오류 보고는 `DISABLE_TELEMETRY=1`·`DISABLE_ERROR_REPORTING=1`로 끈다. 문서상 지표에는 코드·프롬프트가 들어가지 않는다.
- 사용자 계정의 설정값: 켜져 있었고 사용자가 2026-10-14에 껐다고 알림(에이전트는 설정 화면을 보지 못했다)(E-6).
