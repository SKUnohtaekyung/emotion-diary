## 진행 방식(사용자 지정)

1. 먼저 문서와 `work/spikes/`를 읽고 게이트별로 "이미 확인된 것 / 남은 것 / 확인 방법 / 사용자가 직접 해야 하는 것"을 표로 보인다. 그 전에는 아무것도 실행하지 않는다. → 2026-10-13 완료.
2. 정하지 못한 것은 질문 기능으로 한 번에 묻는다. 다 정해지면 `tasks/` 아래에 요청·계획 문서를 MD로 남기고(`tasks/qa/2026-10-13/`와 같은 방식) 계획을 보며 하나씩 진행한다.
3. 게이트 하나를 끝낼 때마다 근거(실행한 명령과 결과, 캡처)를 계획 문서에 적고 사용자에게 보고한 뒤 다음으로 간다.
4. 사용자가 직접 해야 하는 확인(실기기 등)은 "무엇을 어떤 순서로 누르고 무엇을 알려 주면 되는지"를 **개발 용어 없이** 적는다. 사용자는 개발 용어를 모른다.

## 지켜야 할 것(사용자 지정)

- Cloudflare 자원을 새로 만들거나, 요금이 생길 수 있거나, 되돌리기 어려운 일은 하기 전에 반드시 먼저 묻는다. 비밀번호·토큰은 채팅에 쓰지 않는다.
- 확인하지 않은 것을 pass로 적지 않는다. 실기기가 없어 못 한 것은 못 했다고 그대로 남긴다.
- 외부 서비스의 기능·한도는 기억으로 답하지 않고 지금 시점의 공식 문서와 실제 실행으로 확인한다.
- 실제 일기 내용이나 개인정보를 테스트 데이터·로그에 넣지 않는다.
- 토큰은 최소로, 효과는 최대로. 읽을 문서는 필요한 절만 읽는다.
- 판정이 끝나면 `docs/STATUS.md` §3 표, `work-graph`, `loop-state`, 관련 결정 문서를 같은 변경에서 맞춘다.
- 커밋과 푸시는 사용자가 말할 때만 한다.
