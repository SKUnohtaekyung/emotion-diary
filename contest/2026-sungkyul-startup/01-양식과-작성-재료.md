## 2. 구성원 명단 (첨부 1)

연번 1~10, 성명 / 학과 / 학년 / 학번 / 연락처(휴대폰) / E-mail. 아래에 총원과 학년별 인원(4학년 ·3학년 ·2학년 ·1학년)을 적는다.

## 3. 사업계획서 (첨부 2)

표지에 팀명, 아이템명, 아이템 분야, 대표자(팀장). 본문은 아이템명 한 줄과 네 칸이다. 칸마다 가운뎃점(·) 세 개가 미리 찍혀 있다. **개조식으로 서너 항목씩** 쓰라는 뜻으로 읽힌다. 분량 제한은 적혀 있지 않다.

아래는 칸마다 쓸 수 있는 재료와 그 출처다. 문장은 아직 쓰지 않았다.

### 3.1 아이템의 소개 — 무엇인가, 지금 어디까지 됐나

| 재료 | 출처 |
| --- | --- |
| 한 문장 정의: "AI가 수많은 답을 만들어주는 시대, 감정을 기록하며 나를 이해하고 내 삶의 기준을 만들어가는 자기이해 서비스" | [SERVICE_WHY](../../docs/SERVICE_WHY.md) §16 |
| 하루 한 편. 사건 → 감정과 강도 → 이유 → 칭찬 3 → 감사 3 순서로 쓴다 | [PRD](../../PRD.md) PR-003, [STATUS](../../docs/STATUS.md) §2 |
| 감정 9계열, 세부 감정 194개, 강도 1~10. 여러 감정을 함께 고를 수 있다 | STATUS §2 (taxonomy v2) |
| 감정 계열마다 친구 캐릭터 9종, 기록이 조약돌로 남는 숲 | [BRAND_STORY](../../docs/BRAND_STORY.md) |
| 설치형 홈 화면 웹앱(iPhone 확인). 서버와 DB를 직접 만들어 무료 클라우드에서 운영 | STATUS §1·§2 |
| 현재 단계: 화면 시안 전체 완성, '오늘 한 편' 쓰기·수정·내보내기·전체 삭제·백업 복원이 운영 환경에서 동작, 제작자 본인이 실제로 쓰기 시작하는 단계 | STATUS §1 (2026-10-20 기준) |
| 자동 시험 508건, 실제 브라우저 시험 20건 통과 | STATUS §1 숫자 표 (2026-10-20) |

"아이디어만 있는 팀"이 아니라 **돌아가는 앱이 있다**는 점이 이 칸의 핵심이다. 화면 캡처 두세 장을 넣을 수 있으면 넣는다. 숫자는 날짜와 함께 쓴다. STATUS가 10-20 기준이라 제출 전에 한 번 다시 확인하면 좋다.

쓰면 안 되는 것: 사용자 수, 재방문율 같은 지표. 쓰는 사람이 본인 한 명이라(D-108) 그런 숫자가 없다.

### 3.2 아이템의 가치 — 왜 필요한가, 무엇이 다른가

| 재료 | 출처 |
| --- | --- |
| AI가 답을 만들어 줄수록 무엇을 고를지 정하는 자기 기준이 필요하다 | SERVICE_WHY §1~§4 |
| WEF 2025: 기업이 꼽은 핵심 역량에 동기·자기인식 52% | SERVICE_WHY §2 |
| 청년 번아웃 경험 32.2%, 그 이유 중 진로불안 39.1% (2024 청년의 삶 실태조사, N=15,098) | SERVICE_WHY §6 |
| 청소년 스트레스 인지율 남 32.9%·여 50.3% (2025 청소년건강행태조사) | SERVICE_WHY §6 |
| 감정에 이름 붙이기(affect labeling), 감정 세분화(emotional granularity) 연구 | SERVICE_WHY §8 |
| 차별점: AI가 사용자를 판정하지 않고 후보와 질문만 낸다. 기록하지 않은 날을 실패로 만들지 않는다. 기분 한 번 누르는 트래커가 아니라 이름을 붙이는 기록이다 | SERVICE_WHY §12·§17, DECK_PLAN §1 '기록 깊이' |
| 경쟁 서비스 61개를 여섯 갈래로 정리한 자료, 시장에서 드문데 우리가 이미 명세한 것 | [benchmark-analysis](../../docs/research/benchmark-2026-09-analysis.md) §2.1·§3.3, [competitors](../../docs/research/benchmark-2026-09-competitors.md) |

인용할 때 지킬 선(SERVICE_WHY §19):

- 번아웃·스트레스 통계는 "이 시기에 이런 부담이 함께 있다"까지만 쓴다. "자기를 몰라서 힘들다"로 잇지 않는다(§19.6).
- affect labeling은 실험실 연구다. "일기를 쓰면 뇌가 안정된다"로 넓히지 않는다(§19.10).
- "AI가 일자리를 대체한다"가 아니라 "역할이 바뀐다"(§19.1).

## 4. 비어 있는 재료 — 사업성

지금까지 이 프로젝트는 "본인 한 명이 쓰는 도구"로 지었고(D-108), 투자 덱 계획에서도 팀·수익 모델·트랙션은 일부러 뺐다(DECK_PLAN §1). 그래서 이 대회가 묻는 사업성에 답할 결정이 없다. 아래는 초안 전에 정해야 하는 것이다. 정본 문서의 제품 결정을 바꾸는 게 아니라 **대회용 사업 가설**로 따로 적으면 된다.

1. **첫 고객이 누구인가.** WHY는 청소년·청년을 말하지만 사업계획서에는 더 좁은 한 집단이 필요하다. 예: 진로를 고민하는 대학생.
2. **누가 무엇에 돈을 내나.** 개인 구독인지, 학교·상담센터 같은 기관 대상인지. 경쟁 서비스 가격은 competitors §6에 있다.
3. **시장 규모.** 큰 산업 통계를 가져오기보다 "대상 수 × 쓸 비율 × 가격"으로 쌓는 쪽이 방어하기 쉽다. 넣을 숫자와 계산 틀은 [04](04-시장-수치.md)에 있다. "쓸 비율"은 근거를 찾지 못해 가정으로 둬야 한다.
4. **수요 근거.** 인터뷰나 설문이 없다. 오늘 주변 대학생 다섯 명에게 10분씩 물어볼 수 있으면 그것만으로 "5명 중 몇 명이 무엇을 했다"를 쓸 수 있다. 질문은 [02](02-사업계획서-작성법.md) §4.3. 못 하면 없다고 쓰고 "대회 뒤 몇 명에게 써 보게 한다"는 검증 계획을 적는다. 지어낸 숫자보다 낫다.
5. **공개까지의 길.** 지금은 1인용이다. 여러 사람이 쓰려면 가입·개인정보 동의·위기 대응 검토가 먼저다(ROADMAP). 이걸 로드맵으로 보여 주면 약점이 계획으로 바뀐다.
6. **팀.** 누가 무엇을 맡는지.

WHY와 부딪히지 않게 볼 것: 연속 기록 보상으로 붙잡아 두는 모델, 기록 양을 늘리는 것 자체가 목표인 모델은 §11·§20에 어긋난다. 수익 가설을 고를 때 이 선을 넘는지 본다. 넘는 안이 필요하면 추측으로 정하지 말고 따로 결정한다(AGENTS §1).
