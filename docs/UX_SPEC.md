# 모바일 UX 명세

## 1. 책임

이 문서는 사용자가 보는 화면, 상태, 상호작용과 접근성의 정본이다. 제품 범위는 [../PRD.md](../PRD.md), 저장 완료조건은 [DATA_MODEL.md](DATA_MODEL.md), AI 안전 문구는 [SAFETY_POLICY.md](SAFETY_POLICY.md)를 따른다.

## 2. 정보 구조

하단 탐색은 최대 네 항목을 사용한다.

1. 오늘 — 작성 시작/오늘 기록
2. 달력 — 달력과 과거 기록
3. 통계 — 대시보드와 근거 기반 분석
4. 설정 — 알림, 내보내기, 개인정보 안내

탭 이름은 그 화면에 무엇이 있는지 그대로 말한다(D-035). 이전 이름 "기록"과 "돌아보기"는 둘 다 과거를 가리켜 구분되지 않았다. 제품 문서에서 이 영역을 개념으로 부를 때는 "돌아보기"를 쓰되, 화면 라벨은 "통계"다.

로그인/접근 오류와 온보딩은 탐색 밖의 진입 화면이다. 작은 화면에서 핵심 저장 동작을 화면 하단의 안전영역 위에 둔다.

## 3. 온보딩과 시작

- 첫 화면은 “감정을 진단하지 않고 내가 선택한 표현을 기록한다”는 목적을 짧게 설명한다.
- 민감한 의료/심리 치료 기록이나 PHI를 입력하는 용도가 아님을 알린다.
- 오늘 날짜와 `직접 작성`, `AI와 대화하며 작성`을 같은 위계로 제공하되 직접 작성을 먼저 배치한다.
- 오늘 기록이 있으면 새 일기를 만들지 않고 `이어 쓰기` 또는 `기록 보기/수정`을 보여 준다.

## 4. 직접 작성 흐름

한 화면의 긴 폼 또는 단계형 화면을 선택할 수 있으나 다음 순서와 저장 구조는 유지한다.

1. 날짜: 기본 오늘, 미래 금지, 과거 선택 가능
2. 사건: “무슨 일이 있었나요?”
3. 감정: 7개 상위 카테고리 토글 → 세부 감정 복수 선택. 세부 감정 목록이 크므로 한글 텍스트 검색(초성·부분 일치), 카테고리 필터, `최근 사용` 묶음을 제공한다(결함 I-14). 카테고리가 다르면 같은 표기의 감정이 둘 다 나타날 수 있으므로 항목에 카테고리 색·label을 함께 표시한다(D-022)
4. 강도: 선택한 각 세부 감정마다 1~10과 1/5/10 앵커
5. 이유: “왜 이런 감정이 들었다고 느끼나요?”
6. 칭찬 3개: 항상 세 슬롯, 선택 입력
7. 감사 3개: 항상 세 슬롯, 선택 입력
8. 검토: 원형 순서의 전체 요약과 수정 링크
9. 완료 저장

자동 임시저장은 입력 중임을 방해하지 않는 `저장 중/저장됨/저장 실패` 상태로 보여 준다. 저장 실패에도 입력을 지우지 않는다. revision 충돌은 어느 쪽도 자동 덮어쓰지 않고 선택 가능한 차이를 보여 준다.

## 5. AI 대화형 작성 흐름

AI는 인터뷰어가 아니라 사용자가 말하기 쉽게 돕는 보조자다.

1. AI가 한 번에 한 가지 열린 질문으로 사건을 묻는다.
2. 사용자의 표현을 짧게 반영하고, 감정 단어가 필요할 때 2~5개 후보를 질문형으로 제시한다.
3. 사용자가 세부 감정을 복수 선택하고 각각 강도를 직접 정한다.
4. 이유를 묻고, 선택 항목인 칭찬/감사는 건너뛸 수 있게 한다.
5. AI가 구조화 초안을 원형 순서대로 보여 준다.
6. 사용자가 각 필드를 수정하고 명시적으로 완료한다.

AI는 “당신은 분노한 것 같아요”처럼 확정하지 않고 “분노, 답답함 중 가까운 표현이 있나요? 다른 표현도 괜찮아요”처럼 말한다. 말하지 않은 사람·사건·원인·칭찬·감사를 채우지 않는다. 전체 대화가 영구 보존되지 않고 구조화 draft만 복구됨을 흐름 시작에 알린다.

AI 오류·지연·거부 시 현재 draft를 유지하며 `직접 작성으로 계속`을 항상 제공한다.

이 흐름은 후행 단계다(D-018). 구독 기반 모델 경로가 확인되지 않은 배포에서는 `AI와 대화하며 작성` 진입점을 숨기거나 "현재 제공되지 않음"으로 비활성 표시하고 직접 작성만 제공한다(D-019).

위기 전환(D-020): AI 응답의 `safetySignal`이 `possible_crisis`이면 대화 UI를 멈추고 짧은 안전 확인 문구, 한국 기준 검증된 연락처, `지금은 여기까지 저장하고 나가기`, `직접 작성으로 계속`을 보여 준다. 캐릭터 애니메이션과 감정 후보 제안은 표시하지 않고, draft는 그대로 보존한다. 직접 작성 흐름에는 이런 자동 전환이 없으며, 온보딩과 설정의 개인정보 안내에 "직접 작성한 일기는 자동으로 분석·감시되지 않습니다"와 위기 연락처를 정적으로 제공한다.

## 6. 날짜·하루 한 기록·완료

- 날짜를 바꾸면 기존 record 여부를 서버에서 확인한다.
- 같은 날짜 record가 있으면 새 생성 대신 그것을 연다.
- 미래 날짜는 선택할 수 없다.
- 과거 날짜에는 “기록에는 반영되지만 이미 끊긴 작성 streak를 되돌려 채우지는 않아요”라고 표시한다.
- 핵심 필드가 없으면 완료 버튼에서 누락 필드로 초점을 이동하고 구체적으로 설명한다.
- 칭찬/감사 빈 슬롯에는 오류를 표시하지 않는다.

## 7. 기록과 수정·삭제

- 달력은 `없음/draft/completed`를 색만이 아닌 아이콘/텍스트로 구분한다.
- 상세 화면은 원형 순서를 유지하고 emotion label+intensity를 함께 표시한다.
- 완료 기록 수정 시 “기존 분석이 최신이 아니게 될 수 있음”을 알리고 저장 후 분석에 stale badge를 표시한다.
- 완료 기록을 수정하는 동안 상태는 `completed`로 유지된다(D-023). 화면은 "완료된 기록을 수정 중"으로 표시하고, 저장 시 완료조건을 다시 검사해 미충족이면 저장을 막고 누락 필드를 안내한다. `완료 취소`는 별도의 명시적 동작이며 확인 문구에 "이 기록은 임시저장 상태가 되어 통계·분석에서 빠집니다"를 포함한다.
- 삭제는 날짜와 복구 불가를 명시하는 2단계 확인을 거친다. 삭제 직후 되돌리기 토스트를 제공하지 않는다.

## 8. 색상과 캐릭터

구체 색 값·글자·간격·구성요소 규칙은 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)와 `design/tokens.json`이 정본이다. 이 절은 원칙만 둔다.

- 흰색/중립 배경을 기본으로 하고 원자료의 7개 색 계열을 semantic token으로 정의한다.
- 색은 감정의 좋고 나쁨, 진단, 위험 수준을 뜻하지 않는다.
- 캐릭터는 해당 카테고리를 친근하게 찾는 보조 수단이며 alt text/label을 갖는다.
- 복수 감정은 한 배경에 색을 섞기보다 독립 tag/card로 보여 준다.
- 모든 상태와 차트는 색 외에 label, pattern, icon 또는 수치를 제공한다.

## 9. 대시보드와 분석

### 결정론적 영역

- 기간 선택: 최근 7일/30일/사용자 지정
- 날짜별 강도 추세(기록 없는 날은 빈 값)
- 상위 감정 비중과 세부 감정 빈도
- 평균 강도와 표본 수
- 현재 작성 streak

차트의 분모·기간·기록 수를 근처에 표시한다. 적은 데이터에서는 추세를 과장하지 않고 “기록이 더 필요함”을 보여 준다.

### AI 분석 영역

- 사용자 기록에서 계산된 `관찰`, 연구가 설명하는 `가능한 해석`, `한계`, `성찰 질문`, `근거`를 시각적으로 분리한다.
- Gate/Verifier 실패나 근거 부족이면 분석 카드 대신 보류 이유와 결정론적 통계만 보여 준다.
- 심리 상태 점수, 병명, 성격 label, 치료 권고처럼 보이는 UI를 만들지 않는다.

## 10. 알림

- 설정에서 on/off, 시간, timezone을 제공한다.
- background 알림을 실제로 검증하기 전에는 푸시를 약속하지 않는다.
- MVP fallback은 사용자가 앱을 열었고 당일 미완료일 때 보이는 인앱 reminder다.
- 권한 거부를 반복해서 요구하지 않는다. completed 후 같은 날 reminder를 중단한다.

## 11. 상태 설계

모든 주요 화면은 다음을 갖는다.

- initial loading과 skeleton
- 빈 상태와 다음 행동
- validation 오류와 field association
- network/server 오류, 재시도, 안전한 fallback
- AI pending/withheld/stale
- 접근 거부/세션 만료
- 중복 탭/revision conflict
- offline 감지와 저장되지 않았다는 명확한 표시

## 12. 접근성·모바일 검증

- WCAG 2.2 AA를 목표로 한다.
- 최소 터치 영역 44×44 CSS px, body text 확대, 키보드 초점, visible focus, semantic heading/label을 보장한다.
- intensity slider만 제공하지 말고 숫자 선택/입력 대안을 제공한다.
- 스크린리더가 emotion label, category, intensity, 선택 상태를 한 단위로 읽을 수 있어야 한다.
- iPhone Safari와 Android Chrome, 360px 폭, 화면 키보드, safe-area, 세로/가로 회전, 큰 글자에서 핵심 흐름을 실제 기기로 검증한다.
- 애니메이션은 `prefers-reduced-motion`을 존중하고 캐릭터 움직임은 필수가 아니다.

## 13. 내보내기와 영구 삭제 (설정)

결함 I-12에 따라 모바일 브라우저에서의 내보내기 경로를 명시한다.

- 설정 탭에 `내 기록 내보내기(JSON)`와 `모든 기록 영구 삭제`를 분리해 배치하고, 삭제는 시각적으로 구분되는 위험 동작으로 둔다.
- 내보내기는 서버가 `application/json; charset=utf-8`과 `Content-Disposition: attachment; filename="emotion-diary-<YYYY-MM-DD>.json"`으로 응답하고 `Cache-Control: no-store`를 붙인다. 응답은 짧은 수명의 1회성 URL이 아니라 인증된 요청에 대한 직접 응답이다.
- iPhone Safari에서는 다운로드가 `파일` 앱 또는 공유 시트로 열리고, Android Chrome은 다운로드 폴더에 저장된다. 화면에 "저장 위치 확인" 안내와 파일 이름을 표시하고, 다운로드 실패 시 재시도 버튼을 둔다.
- 내보내기 직전 화면에 포함 범위(모든 completed/draft 기록, 선택 시 분석 결과)와 제외 항목(비밀값, 내부 owner key, AI 대화 전문)을 표시한다.
- 홈 화면 바로가기(standalone)에서 다운로드가 동작하지 않는 플랫폼이면 "브라우저에서 열기" 대안을 안내한다. 실제 동작은 EVAL §6 모바일 실기기 검증 항목이다.
- 영구 삭제는 §7의 2단계 확인과 동일한 강도로, 전체 삭제는 사용자가 확인 문구를 직접 입력하게 한다. 삭제 후 백업·공급자 보존 지연 고지를 다시 보여 준다.
