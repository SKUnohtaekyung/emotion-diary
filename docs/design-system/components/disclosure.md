# 펼치기 글자 버튼

기본 부품 · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건**(2026-09-26 D-099로 2건을 위임 판단으로 정함 — 각 항목의 '정함'을 보라). 크기 화면에서 "세부 감정도 크기를 정하고 싶어요"를 눌러 세부 강도 슬라이더를 펼치는 글자 버튼이다(`.link.int-more`, `web/js/components/slider.js:205-210`, `web/css/write.css:118-120`).

## A. 쓰임

- **쓸 때**: 기본으로는 접혀 있고, 필요할 때만 더 자세한 조작 칸(세부 감정별 크기)을 펼쳐 보일 때. 지금 시안에는 이 한 자리뿐이다(§6.4).
- **쓰지 않을 때**: 다른 화면으로 이동 → 목록 줄·버튼. 펼쳐도 접어도 값이 사라지면 안 되는 자리에만 쓴다(아래 G) — 접으면 값이 없어지는 것처럼 보이는 곳에는 쓰지 않는다.
- 옛 명세에는 이 패턴 자체에 이름이 없었다("글자 버튼"으로만 불림, INVENTORY) — 이 문서가 "펼치기 글자 버튼"이라는 이름과 규칙을 처음 정한다.

## B. 구조

- 필수: 글자 라벨("세부 감정도 크기를 정하고 싶어요") + 방향을 바꾸는 화살표(`::after`, 아이콘 파일이 아니라 CSS 테두리로 그린 쉐브런).
- 펼쳐지는 영역(`#intdet-<cat>`)은 이 부품이 아니라 이 부품이 여닫는 대상이다.

## C. 변형

변형 없음 — 한 가지 모양뿐이다.

## D. 크기

- `min-height 44`·`min-width 44`(`.link` 공통값, `base.css:96`), 좌우 여백 `space.2`(8).
- 화살표: 8×8, 선 2px(`emphasis`), 45°/−135° 회전으로 아래/위를 가리킨다.
- 너비: 내용 맞춤(글자만큼).

| 속성 | 값 |

| 글자 단계 | `label`(14) + `fw-body-strong`(600) |
| 밑줄 | 있음(`.link` 공통값 — 이 부품은 [버튼](button.md)의 `text` 변형과 달리 항상 밑줄이 있다), `text-underline-offset 3px` |

- **결정(D-099) F1 — 누름 반응을 어느 쪽 공식으로 만들지**: §5.1은 "알약 모양"(97%로 작아짐)과 "줄 모양"(ink 6% 덮음+98.5%)만 정했는데, 이 부품은 pill도 목록 줄도 아니라 밑줄 있는 글자 버튼이다(같은 클래스 `.link`를 쓰는 다른 글자 버튼들도 마찬가지 — 버튼의 `text` 변형과는 달리 `.btn`이 아니라 `.link` 클래스라 §5.1의 어느 공식도 자동으로 적용되지 않는다). *(추천: "줄 모양"에 가까운 옅은 밑줄-글자 눌림(ink 6% 덮음, 배경 없이 글자 영역만)을 새로 정한다 — pill처럼 작아지면 밑줄 있는 텍스트가 뭉개져 보인다. §5.1의 "글자 버튼" 세 번째 공식으로 다음 라운드에 편입하는 것을 제안한다.)* → **정함(D-099, 위임 판단)**: 줄 모양 규칙을 쓴다(옅은 면 ink 6% + 98.5%). 밑줄 글자는 작아지면 뭉개져 보인다. §5.1에 '배경 없는 글자 줄 버튼은 줄 모양'을 더한다.

## G. 동작

- 누르면 `aria-expanded`를 뒤집고 펼쳐지는 영역(`hidden` 속성)을 열고 닫는다. **닫아도 세부 강도 값은 사라지지 않는다** — 다시 펼치면 그대로 남아 있다(`slider.js:206-209`).
- 펼치는 순간에만 `requestAnimationFrame`으로 안의 슬라이더들을 다시 그린다(접혀 있는 동안 폭이 0이라 그리지 못했던 것을 그린다, `slider.js:209`).
- **결정(D-099) G1 — 펼침 상태가 새로고침에도 남아야 하는지**: 지금은 모듈 변수(`expanded` Set, `slider.js:15`)에만 있어 같은 페이지가 떠 있는 동안(다른 계열 화면을 오가도)은 유지되지만 새로고침하면 모두 접힌 채로 돌아간다. 완료된 기록을 고치러 다시 들어왔을 때도 항상 접힌 채로 시작해야 하는지, 마지막으로 펼쳤던 계열은 열린 채로 보여줘야 하는지 결정이 없다. *(추천: 그대로 둔다(항상 접힌 채 시작) — 세부 강도는 "필요할 때만 보는" 보조 정보라는 §6.4의 전제와 맞고, 기록을 다시 열 때마다 이전 세션의 펼침 상태를 기억하려면 저장할 자리가 늘어난다(§4 "영구적인 판단"에 비해 이득이 작다).)* → **정함(D-099, 위임 판단)**: 접힌 채 시작하되, 세부 크기를 따로 정한 값이 하나라도 있으면 펼친 채 시작한다 — 사용자가 정한 값을 접어 숨기지 않는다(SERVICE_WHY §17 원칙 5). 펼침 상태 자체는 저장하지 않는다.

## H. 배치·묶음

- 계열 패널 안에서 대표 강도 무대 바로 아래, 펼친 세부 강도들 바로 위에 하나(`slider.js:216`).

## I. 문구

- 문장형 라벨 "세부 감정도 크기를 정하고 싶어요"(동사로 끝나지만 [버튼](button.md)의 "할 일 명령"과는 결이 다르다 — 청유형에 가깝다). 펼친 뒤에도 같은 문구를 유지한다(화살표 방향만 바뀐다, "접기"로 바뀌지 않는다).

## J. 움직임

화살표 회전만 `dur-base`로 전환된다(`write.css:119`). 펼쳐지는 영역 자체의 나타남 애니메이션은 없다(`hidden` 속성만 토글, 즉시 나타남/사라짐).

## K. 접근성

- `<button aria-expanded aria-controls>`. 펼쳐지는 영역은 `id`로 연결된다(`intdet-<cat>`).
- 화살표(`::after`)는 장식이라 별도 텍스트가 없다 — 방향은 `aria-expanded` 값으로 전해진다(스크린리더가 "펼쳐짐/접힘"을 읽는다).

## L. 화면 폭·기기

- 360~480px에서 글자가 한 줄에 들어간다(실측 필요 — 미확인, 큰 글자(200%)에서 두 줄로 넘칠 수 있다).

## M. 장면 위에서

해당 없음 — 크기 화면은 흰 종이 바탕뿐이라 감정 색 면 위에는 나오지 않는다.

## N. 하지 말 것·근거

- 접었을 때 값을 지우지 않는다(위 G).
- "닫기"라는 반대말 대신 같은 문구를 유지한다 — 화살표만으로 상태를 보여준다(§2-4 "색 외 단서"와 같은 원칙의 연장 — 다만 이 부품은 형태(방향) 하나로 충분하다).
- 근거: D-059(대표/세부 이원화).
