# 바텀시트

기본 부품 · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건**(2026-09-26 D-099로 2건을 위임 판단으로 정함 — 각 항목의 '정함'을 보라). 아래에서 "값"은 `web/js/components/sheet.js`·`web/css/base.css`를 읽고 잰 것이고, 시안과 옛 명세(§6.11 "바텀시트 radius 16, 손잡이, 배경 dim 40%")가 다른 곳은 시안을 기준으로 적고 그 사실을 남겼다. 확인 대화상자를 별도 부품으로 두지 않고 이 시트의 위험 변형(`danger:true`)이 그 역할을 한다(INVENTORY §1 바텀시트 행) — 이 문서가 확인 대화상자 명세를 겸한다.

## A. 쓰임

- **쓸 때**: 위험 동작 확인(글 지우기·완료 취소·기록 삭제, 2단계), 선택지 목록 제시(⋯ 메뉴 — 고치기·완료 취소·삭제), 정보 부족을 짚어 주기(크기 미입력 안내, 남기기의 빠진 항목 안내), 접근 만료 재진입 안내.
- **쓰지 않을 때**: 사라져도 되는 결과 알림 → [토스트](toast.md). 화면에 계속 떠 있어야 하는 상태 안내(오프라인·저장 실패·수정 중) → [안내 띠](banner.md). 여러 화면으로 이동하는 긴 목록(선택지가 많음) → 지금 시안에는 그런 자리가 없다(드롭다운·메뉴·팝오버 미사용, INVENTORY §2).
- **위험 동작의 확인 자리**(button.md A 참조): 삭제·완료 취소·지우기는 버튼 하나로 끝내지 않고 이 시트를 거친다(UX_SPEC §7). 확정 버튼이 `danger` 변형이다.

## B. 구조

- 필수: 손잡이(`.sheet-grab`, 장식 막대, `aria-hidden`), 제목(`h2`, `aria-labelledby`로 연결), 버튼 영역(1~2개 버튼 **또는** 메뉴 행 목록).
- 선택: 본문(문단 하나·목록·요약 줄). 메뉴 변형은 본문 자리에 `.menu-row` 버튼들이 온다.
- 순서: 손잡이 → 제목 → 본문 → 버튼(세로로, **확정 버튼이 위**) — button.md H "위아래로 쌓을 때 주 버튼이 위"와 같다.
- 시트는 **한 종류의 UI만** 연다 — 시트 안에 다른 시트를 열지 않는다(위험 확인의 2단계는 첫 시트를 **닫은 뒤** 다음 시트를 여는 순차 호출이다, `tabs.js` `del1`→`del2`, `write.js` `discard1`→`discard2`).

## C. 변형

| 변형 | 쓰는 곳 | 버튼 구성 |
| --- | --- | --- |
| 확인 시트 | 완료 취소, 접근 만료 재진입, 지난 날 마무리 안내류 | 확정(주 또는 danger) + 그만두기(글자) |

## D. 크기

- 폭 100%, 최대 `content-max-width`(480)에서 가운데 정렬.
- 높이: **내용 맞춤**, 상한 `88dvh`. 내용이 상한을 넘으면 시트 안이 스크롤된다(`overflow:auto`) — 끌어 올리기(사용자가 손으로 늘리는 handle drag)는 없다.
- 반경: 위 두 모서리만 `radius.sheet`(16), 아래는 0(화면 아래에 붙는다).
- 손잡이: 40×5px, 반경 3px(다섯 반경 값 밖의 장식용 리터럴 — 카드·시트 반경과 무관한 작은 막대이므로 O 검수에서 다시 본다).
- 버튼: `btn big`(56px, button.md D) 그대로 쓴다. 메뉴 행 최소 높이 60px.

## G. 동작

- **여는 법**: 트리거(⋯ 버튼, 삭제 버튼 등)를 누르면 `openSheet()`가 호출된다.
- **닫는 법**(CHECKLIST §3): ① 확정(primary/danger) 버튼 클릭 → 그 동작을 실행하고 닫힘 ② 그만두기(secondary) 버튼 클릭 → 아무 것도 실행하지 않고 닫힘 ③ **바깥(dim) 클릭** → 아무 것도 실행하지 않고 닫힘 ④ **Esc** → 아무 것도 실행하지 않고 닫힘. **끌어서 닫기(스와이프 다운)는 없다** — 손잡이는 장식이고 드래그 핸들러가 없다.
- **위험 동작의 확인 규칙**: 바깥 클릭·Esc로는 위험 동작이 **절대 실행되지 않는다** — 확정은 반드시 `danger` 버튼을 눌러야 일어난다(button.md G와 동일).
- **초점**: 열릴 때 첫 포커스 가능한 요소로 초점이 가고(없으면 시트 자체), 시트 안에서 Tab이 순환한다(초점 가두기, `sheet.js` `onKey`). 닫히면 시트를 연 요소로 초점이 돌아온다.
- **결정(D-099) G1 — 시트가 열려 있는 동안 새 시트 요청이 오면**: 지금 코드에는 이를 막는 장치가 없다(같은 화면에서 두 트리거가 동시에 시트를 열 수 없어 지금까지 드러나지 않았을 뿐이다). ① 무시(이미 열린 시트가 있으면 새 요청을 무시) ② 열린 시트를 닫고 새 시트로 교체 ③ 지금처럼 가드를 두지 않고 호출부가 겹치지 않게 관리한다(현행 유지). *(추천: ③ — 지금 겹치는 실제 경로가 없고, AI 대화 등 새 진입점이 생기면 그때 ①로 막는다.)* → **정함(D-099, 위임 판단)**: 한 번에 하나 — 새 시트를 열면 열려 있던 시트를 먼저 닫고 연다. 지금은 겹칠 경로가 없지만 규칙으로 막아 둔다.
- **결정(D-099) G2 — 기기·브라우저 뒤로가기로 닫히는가**: 시트는 주소(history)를 바꾸지 않는다(`history.pushState`/`replaceState` 호출 없음) — 안드로이드 뒤로가기 제스처나 브라우저 뒤로 가기 버튼을 누르면 시트를 지나쳐 이전 화면으로 가 버릴 수 있다(실기기 미확인). ① 시트를 열 때 가짜 history 항목을 넣어 뒤로가기가 시트만 닫게 한다 ② 지금처럼 두고 Esc·바깥 누르기만 지원한다(데스크톱 관례). *(추천: 실기기로 확인하기 전에는 정하지 않는다 — TASK-MOBILE 실기기 스파이크와 함께 본다, button.md H4와 같은 유보 사유.)* → **정함(D-099, 위임 판단)**: 잠정 — 기기 뒤로가기로 시트가 닫히게 한다(시트를 열 때 기록 항목 하나). 뒤로가기가 시트 대신 화면을 떠나면 안드로이드에서 쓰던 내용을 잃을 수 있다. 해시 라우팅과 부딪히는지는 **실기기 확인**(TASK-MOBILE B-08)에서 본다.

## H. 배치·묶음

- 화면 하단에 붙어 위로 올라온다. dim은 전체 화면을 덮는다.
- z-index: CSS는 `var(--z-sheet, 30)`을 쓰는데 `tokens.js`가 `--z-sheet` 변수를 실제로 설정하지 않는다 — 항상 CSS 쪽 대체값(30)이 적용되고, 이 값이 `tokens.json`의 `z.sheet`(30)과 우연히 같을 뿐 토큰에 실제로 연결돼 있지 않다(O 검수 참조).
- 시트 안에서 손잡이 아래 여백 `space.4`(16), 본문과 버튼 사이 `space.5`(20), 버튼 사이 `space.1`(4, button.md H와 동일).

## I. 문구

- 제목은 질문형 해요체("이 글을 지울까요?", "정말 지울까요?", "완료를 취소할까요?") — button.md I의 동사 규칙은 시트 제목이 아니라 시트 안 버튼 라벨에 적용된다.
- 메뉴 행: 명사(고치기·완료 취소·삭제) + 보조 설명 한 줄(`small`, muted) — 무엇이 일어나는지 미리 말한다("완료된 기록을 수정해요. 저장하면 분석이 최신이 아니게 될 수 있어요.").
- 위험 확인 2단계 제목은 "정말 ~할까요?"로 짙어지고, 본문에 되돌릴 수 없음을 다시 말한다("삭제하면 되돌릴 수 없어요. 삭제한 뒤에 되돌리는 버튼도 없어요.").

## J. 움직임

- 열림: dim 페이드인(`motion.duration.base` 200ms), 시트는 아래에서 24px 올라오며 페이드인(`motion.duration.slow` 320ms).
- 닫힘: **전환 없이 즉시 제거**된다(`close()`가 `dim.remove()`를 바로 호출) — 열림과 닫힘이 비대칭이다.
- 움직임 줄이기: dim·시트 애니메이션 모두 없음(`base.css:145`).

## K. 접근성

- `role="dialog"` `aria-modal="true"` `aria-labelledby="sheetTitle"`(제목과 연결). 본문 문단은 별도 `aria-describedby` 연결이 없다(미확인 — 스크린리더가 다이얼로그에 들어가면 문서 순서대로 이어 읽어 실사용에 문제가 없는지는 실기기로 확인하지 못했다).
- 초점 가두기: Tab/Shift+Tab이 시트 안 포커스 가능 요소 사이에서만 순환한다.
- 열릴 때 배경 스크롤 잠금(`document.body.style.overflow = "hidden"`), 닫히면 해제.
- 위험 버튼 대비·크기는 button.md K를 그대로 따른다.

## L. 화면 폭·기기

- 360~480: 폭 100%. 480보다 넓은 창에서는 `content-max-width`로 가운데.
- 홈 화면 앱: 시트 아래 패딩이 안전 영역(`env(safe-area-inset-bottom)`)을 비운다.
- 글자 200%: 본문·제목이 늘어난 만큼 시트 전체가 스크롤된다(D 참조) — 손잡이·제목이 별도로 고정(sticky)되지 않으므로 글자를 키우면 제목도 스크롤에 들어간다.

## M. 장면 위에서

- 시트는 어떤 배경(어두운 숲 포함) 위에서 열려도 항상 `neutral.bg`의 밝은 면으로 뜬다 — 장면 색을 받지 않는다.
- 시트 안 초점 링은 표준 `focus`(파랑)이다 — 장면별 대체 색(어두운 숲의 mint, 초록 언덕의 ink)이 시트 안에는 적용되지 않는다(시트가 항상 밝은 면이라 파랑 링의 대비가 이미 충분하기 때문).

## N. 하지 말 것·근거

- 위험 동작을 이 시트 없이 버튼 하나로 끝내지 않는다(UX_SPEC §7).
- 바깥 누르기·Esc로 위험 동작을 실행하지 않는다 — 닫기만 한다(`sheet.js`).
- 삭제·완료 취소 뒤 되돌리기 토스트로 대체하지 않는다(UX_SPEC §7, button.md G).
- 근거: UX_SPEC §7(기록과 수정·삭제), DESIGN_SYSTEM §6.11, D-098(§5.1 상태 공통 규칙).

## O. 검수

- 전시장 상태표: 4단계에서 `design/style-guide.html`에 변형 4(확인·위험 확인·안내·메뉴) × 열림 상태를 둔다.
- 하네스: 토큰 밖 값 검사에 손잡이 반경(3px)과 dim 50%(명세 40%와의 차이)를 포함한다. `--z-sheet` CSS 변수가 `tokens.js`에서 설정되지 않는 점도 하네스가 잡아야 한다(H 참조).
- 캡처: 360px, 글자 200%에서 시트 제목이 스크롤에 들어가는 모습.
