# 텍스트 입력 (줄 노트 textarea · 3칸 슬롯 · 필드 오류)

기본 부품 · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건**(2026-09-26 D-099로 2건을 위임 판단으로 정함 — 각 항목의 '정함'을 보라). DESIGN_SYSTEM §6.5는 이 부품에 "명세 있음"이라 적었지만 실제로는 라벨·자리표시자·오류만 정했고 도움말 자리·글자 수 표시는 정하지 않았다(INVENTORY의 측정된 빈틈 그대로다).

## A. 쓰임

- **쓸 때**: 사건("오늘 있었던 일")·이유·칭찬·감사처럼 사용자가 직접 글을 쓰는 모든 자리.
- **쓰지 않을 때**: 선택지 중 고르기 → 알약·chip. 숫자 하나 → 강도 선택기. 날짜·시각 → 기기 기본 선택기(`native-picker`).
- 두 형태가 있다: **줄 노트**(사건·이유, 자동 높이 조절 `<textarea>` 하나, `ruled()`) / **3칸 슬롯**(칭찬·감사, `<input>` 세 개를 한 `<fieldset>`으로 묶음, `slots()`).

## B. 구조

`web/js/views/write.js:28-39`(`ruled`/`slots`), `web/css/base.css:102-111`(`.field`/`.field-label`/`.ruled`/`.field-error`).

- **줄 노트**: `<div class="field">` 안에 `<label class="field-label">`(라벨, 항상 보임) → `<textarea class="ruled">`(자리표시자로 안내 문구를 보여줌, 값이 없으면 안내가 곧 자리표시자다) → `<p class="field-error">`(기본 `hidden`).
- **3칸 슬롯**: `<fieldset class="field slots-field">` 안에 `<legend>`("칭찬할 점, 세 가지까지") → 안내 캡션("선택이에요. 비워 두어도 괜찮아요.") → `<input>` 3개, 각각 자리표시자 "칭찬 1"/"칭찬 2"/"칭찬 3".
- 이유·오늘 있었던 일·칭찬·감사 화면은 이 입력을 **종이·언덕 장면**에 얹는다(M 참고) — 입력 자체의 마크업은 같고 장면 쪽 CSS가 배경·기울기·자리만 덮어 쓴다.

## C. 변형

| 변형 | 쓰는 곳 | 필수 여부 |
| --- | --- | --- |
| 줄 노트(`ruled`) | 사건, 이유 | 필수(완료 시 확인) |
| 3칸 슬롯(`slots`) | 칭찬, 감사 | 선택 — 전부 비워도 됨 |

## D. 크기

- 줄 노트: 자동 높이(`autoGrow`, `write.js:27` — `scrollHeight`만큼 늘어남), 최소 5줄(`rows=5`), 글자 `fs-heading`(18)·줄 높이 2rem(줄 종이의 가로줄과 맞춘다).
- 3칸 슬롯: 입력 한 칸 최소 높이 `3.25rem`(52px, `notes.css:97`) — 누르는 영역 44px 기준을 넘는다.
- 줄 노트 입력 폭은 종이 좌우 여백까지 넓혀 눌러도 글쓰기가 시작되게 한다(`.rs-note .ruled{width:calc(100% + sp-4*2)...}`, `reason.css:19`).

## E. 값

| 속성 | 값 |
| --- | --- |
| 배경 | `surface`(장면 밖) / `paper`(이유·오늘 있었던 일·칭찬·감사 장면 안, §3.5) |
| 테두리 | 1px(장면 밖 기본 입력 규칙, §6.5) — 줄 노트·슬롯 자체는 테두리 없이 종이의 가로줄이 경계를 대신한다 |
| 초점 | `focus` 2px(장면 밖) / 초록 언덕 위 ink 3px(이유·오늘 있었던 일 장면, `reason.css:23`) |
| 글자 | 16px 이상(iOS 자동 확대 방지, §4) |
| 라벨 | `fs-label`(14)·`fw-body-strong`, 장면 안에서는 `paper-ink` 색 |
| 오류 문구 | `fs-label`(14)·`danger`, 앞에 "! " 표지(`.field-error::before`) |

## F. 상태

| 상태 | 값 |
| --- | --- |
| 기본 | 위 E, 자리표시자는 `subtle`(장면 밖)/`muted`(장면 안, `.ruled::placeholder`) |
| 초점 | §9의 바탕별 초점 색(장면 밖 `focus`, 초록 언덕 위 ink 3px) |
| 채움(입력 중) | 값이 있으면 `input` 이벤트에서 오류를 즉시 지운다(`write.js:31` `if (ta.value.trim()) ...Error.hidden = true`) |
| 비활성 | 해당 없음 — 이 부품이 잠기는 화면이 없다 |
| 필수 오류(아직 누를 수 없음이 아니라 **완료를 눌렀는데 빈 칸**) | `.field-error`가 나타나고 §5.1의 구분대로 **빨간 색**(`danger`)이다 — "아직 고르지 않음"의 ink 안내(§5.1 blocked-hint)와는 다른 경우다. 감정 색 면(계열 300) 위에서는 `danger` 원색이 대비 미달이라 **중립 `text` 글자 + 굵기**로 바꾼다(`[data-theme-cat] .field-error`, `base.css:110`) — §5.1이 정한 "감정 300 위에서는 중립 글자로 오류를 알린다" 규칙과 일치한다 |
| 선택 | 해당 없음 |
| 로딩 | 해당 없음(자동 저장 상태는 이 부품이 아니라 화면 상단 줄이 알린다, §6.6) |
| 상태가 겹칠 때 | 오류가 뜬 채로 다시 입력하면 그 즉시(첫 글자 입력 시) 오류가 사라진다 — 오류+입력 중이 함께 보이는 순간은 없다 |

## G. 동작

- 저장은 즉시가 아니라 상태(state.draft)에 반영되고 화면 상단의 자동 저장 줄이 결과를 알린다(§6.6) — 이 부품 자체는 "저장" 개념이 없다.
- 완료(다음/남기기)를 누를 때만 필수 칸을 검사한다(§6.5 "필수 필드 누락은 완료 시점에만 표시"). 입력 중에는 오류를 앞서 보여주지 않는다.
- 3칸 슬롯은 빈 슬롯에 오류를 표시하지 않는다(전부 선택 사항).

## H. 배치·묶음

- 줄 노트: 화면 세로 흐름 안에 있어(`position:fixed`로 화면을 덮지 않음) 모바일 키보드가 올라와도 입력 칸을 가리지 않는다(§6.5, D-069 ②).
- 3칸 슬롯(칭찬): 세 쪽지가 세로로 쌓이고 좌우로 어긋난다(`.nt-slips`, `notes.css:89`).
- 3칸 슬롯(감사): 세 카드가 끈에 꿴 듯 세로로 이어진다(`.nt-tags`, `notes.css:110`).

## I. 문구

- 라벨은 **항상 보인다**(자리표시자와 별개로 `<label>`이 위에 고정) — CHECKLIST §3 질문 "라벨은 늘 보이나"의 답은 **그렇다**.
- 자리표시자는 안내 문구를 겸한다(예: "있었던 일을 떠오르는 대로 적어요.") — 값을 입력하면 사라지는 임시 안내다.
- **글자 수 표시는 없다** — `maxlength` 속성도, 카운터 UI도 시안에 없다(줄 노트·슬롯 모두).
- 오류 문구는 필드 바로 아래 caption + "! " 표지(색 외의 단서, §2-4).

**결정(D-099) I1 — 글자 수를 보여줄지**: CHECKLIST §3이 명시적으로 묻는 항목인데 시안에 없다. 짧은 일기 앱 성격상 글자 수 표시를 아예 안 둘지(자유롭게 쓰라는 메시지), 너무 길어질 때만(예: 500자 이후) 안내할지. *(추천: 두지 않는다 — SERVICE_WHY §11 "기록은 많을수록 좋은 것이 아니다"와 같은 결로, 글자 수 압박이 성찰을 방해할 수 있다.)* → **정함(D-099, 위임 판단)**: 보이지 않는다(지금대로) — 글자 수는 쓰는 양에 압박을 준다(SERVICE_WHY §11·§17 원칙 4).

## J. 움직임

- 줄 노트: 값이 늘어나면 `autoGrow`가 높이를 즉시(전환 없이) 늘린다.
- 장면 안(이유·오늘 있었던 일·칭찬·감사): 초점이 들어온 쪽지·카드만 곧게 펴진다(`nt-slip:focus-within{transform:rotate(0deg)}`, `notes.css:138`) — 글 내용이 아니라 초점에만 반응한다(장면 규칙, §6.15).
- 움직임 줄이기: 위 회전 전환이 꺼진다(`notes.css:162`).

## K. 접근성

- 줄 노트: `aria-describedby="${id}Hint ${id}Error"`, `aria-required="true"`(`write.js:29`). **`${id}Hint` id를 가진 요소가 실제로 없다** — 안내 문구는 자리표시자로만 존재해 `aria-describedby`가 존재하지 않는 id를 가리킨다(스크린리더는 이 부분을 조용히 무시한다). 아래 "예상 밖 발견" 참고.
- 3칸 슬롯: `<fieldset>`+`<legend>`로 묶고 각 입력에 `aria-label`("칭찬 1" 등)을 따로 준다.
- 오류는 `id="${id}Error"`로 연결되지만 위 Hint 문제와 별개로 오류 자체의 연결은 정상이다(요소가 실제로 존재).

**결정(D-099) K1 — 자리표시자 안내를 스크린리더가 안정적으로 읽지 못한다**: 자리표시자는 값이 없을 때만 보이고 스크린리더마다 읽는 방식이 다르다(값이 생기면 사라져 다시 못 듣는다). 안내 문구를 위해 화면에는 보이지 않는 실제 `${id}Hint` 요소를 추가해 `aria-describedby`가 실제로 가리키게 할지, 지금처럼 자리표시자로만 둘지. *(추천: 추가한다 — `aria-describedby`가 이미 그 id를 참조하도록 코드가 의도했던 것으로 보이고, 시각적으로는 자리표시자만 보여도 스크린리더용 요소는 `.sr`로 숨겨 함께 둘 수 있다.)* → **정함(D-099, 위임 판단)**: 고친다 — `aria-describedby`가 가리키는 `<id>Hint`를 화면에 보이지 않는 안내 글로 실제로 만든다. 지금은 없는 id를 가리킨다(`write.js:29`).

## L. 화면 폭·기기

- 360~480: 줄 노트·슬롯 모두 폭 가득, 좌우 여백은 종이 여백(`space.4`)을 따른다.
- 큰 글자(200%): 라벨·자리표시자 모두 rem 기반이라 함께 커진다(실측은 하지 않았다 — 미확인).
- 홈 화면 앱: 차이 없음.

## M. 장면 위에서

- **이유**(§6.5): 줄 노트가 −0.6° 기운 종이(`paper` 배경 + 가로줄)에 오른쪽 위 민트 테이프. 아래 초록 언덕에 고른 친구들이 선다. 언덕은 버튼 줄 뒤에 sticky로 남아 키보드가 올라와도 따라온다.
- **오늘 있었던 일**(§6.15): 종이가 +0.5° 기울고 왼쪽 위에 날짜 탭(민트 테이프). 아래는 이른 아침 풍경(해·흰 길·시작하는 돌).
- **칭찬**: 3칸 슬롯이 −1.5°/+1°/−0.5°로 어긋난 크림빛 쪽지 셋, 각각 민트 테이프+접힌 모서리.
- **감사**: 3칸 슬롯이 끈에 꿴 카드 셋(±0.6°), 각 카드에 구멍+줄 하나.
- 장면 위 오류 문구 색: 이유·오늘 있었던 일 화면은 종이 위라 `danger` 원색 그대로 4.5:1 이상(§9 "이유 노트 위 안내·오류 글자 4.5:1 이상"). 계열 300 배경(세부 감정 화면 자체는 텍스트 입력이 없어 해당 없음)과는 다른 조건이다.

## N. 하지 말 것·근거

- 빈 슬롯(칭찬·감사)에 오류를 표시하지 않는다(UX §6).
- 도움말 자리를 오류 문구가 밀어내며 레이아웃을 흔들지 않는다 — 오류는 `hidden` 토글로만 나타나고 자리는 항상 있다(`.field-error`가 값 없이도 DOM에 존재).
- 근거: D-069(장면 얹기)·D-053(계열 300 위 오류 색 규칙).

## O. 검수

- 전시장 상태표: 4단계에서 줄 노트·3칸 슬롯 × 상태(기본·초점·채움·오류) 표를 `design/style-guide.html`에 둔다.
- 하네스: D-ti-2가 해결되면 `aria-describedby` 참조 무결성(가리키는 id가 실제로 존재하는지)을 자동 검사에 추가한다.
- 캡처: 360px, 오류 문구가 뜬 상태(레이아웃 밀림 확인), 장면 안/밖 각각.
