# 로딩·오류·연결 끊김 상태

기본 부품 · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건**(2026-09-26 D-099로 1건을 위임 판단으로 정함 — 각 항목의 '정함'을 보라). 아래에서 "값"은 `web/js/dom.js`(`renderStatus()`)·`web/css/base.css`(`.status-block*`)와 실제 호출부(`today.js`·`tabs.js`·`stats.js`)를 읽고 잰 것이다. 옛 명세(§6.12·UX_SPEC §11)와 시안이 다른 곳은 없다 — 다만 호출부마다 "다시 시도" 버튼을 붙이는 기준이 갈려 있어(F1) 결정 대기로 남겼다.

## A. 쓰임

- **쓸 때**: 화면이 데이터를 불러오는 동안(로딩), 불러오지 못했을 때(오류), 오프라인일 때(연결 끊김) — 오늘·달력·통계·기록 상세 네 화면이 이 부품을 갖췄다(D-083 ①).
- **쓰지 않을 때**: 데이터는 불러왔지만 보여줄 내용이 없을 때 → [빈 상태](empty-state.md). 동작이 끝난 뒤의 성공/실패 화면 → [결과 화면](result.md).
- 오늘 화면은 이 부품을 **돌 자리**에 놓는다(장면 안에 놓이므로 `tone="dark"`를 쓴다, M 참조) — 나머지 세 화면은 밝은 배경 그대로(`tone="light"`, 기본값).

## B. 구조

- 로딩: 스크린리더 전용 텍스트("불러오는 중이에요") + 옅은 막대 3개(`<i>`, 장식).
- 오류·연결 끊김: 제목(`status-title`) + 설명(`status-detail`) + 재시도 버튼(선택, `button.md`의 `secondary` 변형 재사용).
- 필수 부분은 로�딩=막대, 오류/연결 끊김=제목+설명이고, 재시도 버튼은 호출부가 `onRetry`를 넘길 때만 있다(F1).

## C. 변형

| kind | 제목(기본값) | 설명(기본값) | role |
| --- | --- | --- | --- |
| `loading` | 없음(막대만) | 없음 | `status`(스크린리더 텍스트만) |
| `error` | "불러오지 못했어요" | "잠시 뒤 다시 시도해 주세요." | `alert`(끼어들며 읽힘) |
| `offline` | "연결이 끊겼어요" | "연결되면 다시 불러올게요." | `status`(차례를 기다려 읽힘) |

- 제목·설명은 호출부가 `title`/`detail`로 덮어쓸 수 있다(오늘 화면은 "잠시 뒤 다시 시도해 주세요." 대신 "연결되면 돌을 누를 수 있어요."처럼 화면 맥락에 맞는 문구로 바꾼다).

## D. 크기

- 안쪽 여백 상하 `space.6`(24), 좌우 `space.4`(16), 요소 사이 간격 `space.2`(8).
- 로딩 막대: 높이 14px, 반경 7px — **둘 다 다섯 반경/간격 값 밖의 리터럴**(O 검수 참조). 폭은 첫 줄 100%·둘째 줄 72%·셋째 줄 48%(내용의 들쭉날쭉한 줄 길이를 흉내낸다).
- 재시도 버튼: button.md의 `secondary` 크기(48px) 그대로, 위 여백 `space.2`(8) 추가.

## F. 상태

| 상태 | 값 |
| --- | --- |
| 로딩 | 막대 3개가 1.6초 주기로 `opacity .6↔1` 맥박(펄스) — 스피너를 쓰지 않는다(INVENTORY §2, `스피너` 미사용 근거와 일치) |

| **결정(D-099) F1 — 연결 끊김에 재시도 버튼을 항상 둘지**: 오늘 화면(`today.js`)은 오류·연결 끊김 모두에 재시도 버튼을 준다. 달력·통계(`tabs.js`·`stats.js`)는 **오류에만** 재시도를 주고 연결 끊김에는 주지 않는다(`onRetry: kind === "error" ? ... : undefined`) — 오프라인은 재시도해도 안 될 거라는 판단인지, 빠뜨린 것인지 코드만으로는 알 수 없다. ① 모든 화면의 연결 끊김에도 재시도 버튼을 둔다(오늘 화면과 통일) ② 지금처럼 화면마다 다르게 둔다 ③ 연결 끊김에는 재시도 버튼 대신 온라인 복귀를 자동 감지해 다시 불러온다. *(추천: ① — UX_SPEC §11이 모든 주요 화면에 "network/server 오류, 재시도"를 공통 요구 조건으로 두고 있고 오늘 화면이 이미 그 기준을 보여준다. 다만 이것이 의도적 생략인지 구현 누락인지 사용자 확인이 필요하다.)*  → **정함(D-099, 위임 판단)**: 모든 화면에 둔다 — 연결 끊김에도 오늘·달력·통계·기록 상세 모두 '다시 시도'를 준다. UX_SPEC §11이 공통으로 요구하고, 지금 달력·통계만 빠져 있다. |

## G. 동작

- 재시도 버튼을 누르면 그 화면을 다시 불러온다(`navigate(현재 화면)` 재호출 — 자동 재시도·타임아웃은 없다).
- 로딩 상태에 최대 대기 시간이나 자동 오류 전환이 없다 — 실제 데이터 요청이 끝날 때까지 그대로 맥박친다.

## H. 배치·묶음

- 화면 본문 영역을 통째로 대신한다(그 화면의 다른 내용과 함께 나오지 않는다) — 로딩·오류·연결 끊김은 서로 배타적이다.
- 오늘 화면에서는 돌·조약돌·문구 자리를 이 부품이 대신 채운다(§6.12 상태표).

## I. 문구

- 해요체, 사실을 말하고 다음 행동을 알린다("잠시 뒤 다시 시도해 주세요", "연결되면 다시 불러올게요").
- 오늘 화면은 기본 문구 대신 그 화면에 맞는 문구로 덮어쓴다(C 참조) — 버튼을 누르는 대상이 "돌"이라는 것까지 알려준다.

## J. 움직임

- 로딩 막대의 맥박(1.6s, ease-in-out, 무한 반복)뿐 — 등장·퇴장 전환은 없다(다음 상태로 즉시 바뀐다).
- 움직임 줄이기: 맥박 없음(`base.css:160`) — 막대는 고정된 옅은 색으로만 보인다.

## K. 접근성

- 로딩: 시각 요소(막대)는 장식, 스크린리더는 `<span class="sr">불러오는 중이에요</span>`만 읽는다.
- 오류: `role="alert"` — 끼어들며 즉시 읽힌다(F9 "끼어들기"). 연결 끊김·로딩: `role="status"` — 차례를 기다려 읽힌다("차례 기다리기").
- 재시도 버튼은 `<button>`이라 키보드로 도달·실행된다(button.md K 참조).

## L. 화면 폭·기기

- 360~480: 가운데 정렬, 제목·설명이 폭 안에서 자연히 줄바꿈된다.
- 글자 200%: `min-height`만 쓰는 재시도 버튼(button.md K)과 같은 이유로 잘리지 않는다(미확인 — 이 부품만의 200% 캡처는 없다).

## M. 장면 위에서

- 어두운 숲(오늘 화면) 위에서는 `tone="dark"`를 쓴다 — 글자는 `neutral.bg`(흰색), 설명은 흰색 78% 섞음, 로딩 막대는 흰색 14% 섞음(§9 대비 검사 대상). 다만 이 두 곳(돌 아래 문구 92%, AI 안내 62%)의 실제 대비 측정은 아직 없다고 DESIGN_SYSTEM §9가 밝히고 있다 — 이 부품의 `dark` 문구 대비도 같은 미측정 범위에 든다(미확인).

## N. 하지 말 것·근거

- 스피너를 쓰지 않는다 — 로딩은 옅은 막대 맥박 하나로 통일한다(INVENTORY §2).
- 오류 상태에서 확인 없이 새 기록을 시작하게 두지 않는다 — 오늘 화면은 오류·연결 끊김일 때 돌 자체를 비활성으로 둔다(D-077 ⑧·D-083 ①, 하루 하나 규칙 보호).
- 근거: D-083 ①(로딩 뼈대·재시도 공통화), UX_SPEC §11.

## O. 검수

- 전시장 상태표: 4단계에서 `design/style-guide.html`에 kind 3 × tone 2(light/dark) 표를 둔다.
- 하네스: 토큰 밖 값 검사에 로딩 막대 높이(14px)·반경(7px)을 포함한다.
- 캡처: 360px에서 각 kind, 오늘 화면(dark)에서의 오류·연결 끊김.
