# 아이콘 버튼

기본 부품 · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건**(2026-09-26 D-099로 3건을 위임 판단으로 정함 — 각 항목의 '정함'을 보라). 아래 "값"은 시안에서 재서 확인한 것이다. 이 부품은 뒤로가기·닫기(×)·더보기(⋯)·달력 넘김(‹›)의 네 뜻을 아이콘 하나로 전하는 44px 버튼이다.

## A. 쓰임

- **쓸 때**: 화면 위쪽에서 뒤로 가거나 닫거나 메뉴를 열 때(뒤로·닫기·더보기), 달력에서 달·주를 옮기거나 펼친 줄을 닫거나 그 날의 메뉴를 열 때.
- **쓰지 않을 때**: 글자 라벨이 있는 동작 → [버튼](button.md). 여럿 중 하나를 고르는 것 → [세그먼트](segmented.md)·[고르기 알약](radio-pill.md). 강도의 증감(−/+)은 이 부품이 아니라 [강도 선택기](intensity.md)의 증감 버튼이다(모양은 비슷하지만 값을 하나씩 옮기는 다른 부품이다).
- **두 변형의 경계(시안이 이미 일관되게 쓰고 있다)**: 면 없는 변형은 화면 맨 위 정보 줄(뒤로·닫기·더보기)에 쓴다(`tabs.css:50` `.info-top .back`, `write.css:6` `.write-top .back`). 옅은 원판 배경 변형은 달력의 월·주 이동과 펼친 줄 안의 닫기·더보기에 쓴다(`tabs-mood.css:26` `.cal-arrow`, `tabs-mood.css:52` `.cal-close-btn`·`.cal-more-btn`) — 아이콘이 콘텐츠(달력 격자·날짜) 사이에 놓일 때는 배경으로 눌리는 자리를 알리고, 글 위 정보 줄에서는 배경 없이 가볍게 둔다.

## B. 구조

- 필수: 아이콘 하나(svg). 선택: 없음 — 글자 라벨을 두지 않는다(이름은 `aria-label`로만 전한다).
- 아이콘은 가운데 정렬(`display:grid;place-items:center`).

## C. 변형

| 변형 | 면 | 쓰는 곳 |
| --- | --- | --- |
| plain(면 없음) | 없음, 아이콘 `service.ink` | 정보 줄의 뒤로·닫기(×)·더보기(⋯) |
| soft-circle(옅은 원판) | `neutral.surface-soft`, 아이콘 `service.ink` | 달력 월·주 이동(‹›), 펼친 줄의 닫기(×)·더보기(⋯) |
| soft-circle-small(작은 보이는 크기) | soft-circle과 같음, 보이는 크기만 36px | 펼친 달력 줄 안(`.cal-close-btn`·`.cal-more-btn`)에서만 |

- **결정(D-099) D1 — 작은 보이는 크기(soft-circle-small)를 정식 크기 변형으로 인정할지**: 지금은 펼친 달력 줄 하나에서만 44→36px로 줄이고 `::after`로 누르는 자리 44px를 지킨다(`tabs-mood.css:52-53`). 다른 화면에도 이 작은 크기가 필요해질 수 있다. *(추천: 아직 정식 변형으로 규칙화하지 않는다 — 지금 이 한 곳뿐이고, 다른 자리에서 필요해지면 그때 폭 좁은 줄 안이라는 조건과 함께 규칙화한다.)* → **정함(D-099, 위임 판단)**: 달력 전용 예외로 남긴다 — 쓰는 곳이 한 곳뿐이다. 두 번째 쓰임이 생기면 정식 크기로 올린다.

## D. 크기

- plain: 44×44(`size.touch-target-min`), 아이콘 22px·선 2.4.
- soft-circle(월·주 이동): 44×44, 아이콘 20px·선 2.4.
- soft-circle-small(펼친 줄): 보이는 36×36, 아이콘 18px, 누르는 자리는 `::after{inset:-4px}`로 44×44.
- 너비: 내용 맞춤(정사각형 고정), 나란히 배치일 때도 서로 늘어나지 않는다.

## F. 상태

| 상태 | 값 |
| --- | --- |
| 기본 | 위 E |
| 누름 | **시안은 아직 반응이 없다**(`web/css/tabs.css`·`write.css`·`tabs-mood.css`에 `:active` 규칙 없음) — §5.1 "누름 반응이 없는 기본 부품은 두지 않는다"에 어긋난다. §5.1의 알약 모양 규칙(97%로 작아짐, 120ms, 움직임 줄이기에서는 ink 8% 면)으로 바꾼다. → **시안 반영(2026-09-26)**: 뒤로·닫기·⋯·달 넘김·편지 화살표 모두 97% |
| 초점 | 전역 규칙(§9) 그대로 — 흰 바탕 `focus` 2px, offset 2px. 이 부품만의 별도 값은 없다(세그먼트처럼 안쪽으로 당기지 않는다). |
| 비활성 | soft-circle의 달력 월·주 이동에서만 나온다(경계에 닿으면, 예: 미래 달로 못 감). 시안은 `opacity:.35` + HTML `disabled` 속성(`tabs.css` `.cal-arrow:disabled`, `tabs.js:159-165`)이다 — §5.1의 색-섞기 규칙(바탕에 ink 12%/50%)과도, `aria-disabled`로 초점을 유지하는 규칙과도 다르다. plain 변형(뒤로·닫기·더보기)에는 비활성이 없다 — 항상 누를 수 있다. → **시안 반영(2026-09-26)**: `aria-disabled`로 바꿨고(초점 유지, 누르면 무시) 모습은 면 그대로 + 아이콘 바탕+ink 50% |
| 선택 | 해당 없음 — 이 부품은 상태를 갖지 않는다(현재 탭 표시는 하단 탐색이, 고른 날은 달력 칸이 맡는다). |
| 로딩 | 해당 없음 — 누르면 즉시 화면이 바뀌거나 시트가 열린다, 기다리는 로딩이 없다. |
| 상태가 겹칠 때 | 비활성+누름: 시안은 `disabled` 속성이라 클릭 자체가 브라우저에서 막힌다(무반응). → **시안 반영(2026-09-26)**: `aria-disabled`라 초점은 남고 누름은 핸들러가 무시한다(작아지지도 않는다) |

- **결정(D-099) K1 — 비활성 표현을 무엇으로 통일할지**: 같은 "경계에서 비활성"인데 달력 월·주 이동은 실제 `disabled` 속성(포커스를 잃음)을, 강도 선택기의 증감 버튼([intensity.md](intensity.md))은 `aria-disabled`(포커스 유지)를 쓴다 — 같은 아이콘 버튼 계열인데 접근성 동작이 다르다. *(추천: `aria-disabled`로 통일한다 — §5.1이 일반적으로 `aria-disabled`를 선호하고(포커스를 잃지 않음), 증감 버튼이 이미 그렇게 하고 있다. 달력 화살표만 실제 `disabled`를 쓰는 것은 옛 구현이다.)* → **정함(D-099, 위임 판단)**: `aria-disabled`로 통일한다 — 초점을 잃지 않고, 증감 버튼·주 버튼과 같은 방식이다(§5.1). 모습은 바탕에서 만든 색.

## G. 동작

- 한 번 누르면 한 번 실행 — 즉시 화면 전환(뒤로·닫기) 또는 시트 열기(더보기)다. 저장처럼 기다리는 동작이 없어 다시 누르기를 막을 필요가 없다.
- 더보기(⋯)는 [바텀시트](../../DESIGN_SYSTEM.md#611-내비게이션시트토스트)를 연다 — 열리면 초점이 시트로 옮겨 가고 닫히면 원래 자리로 돌아온다(§6.11).
- 달력 월·주 이동은 그 자리에서 격자를 다시 그린다(화면 전환 없음). 펼친 줄의 날짜 칸은 재도약(`tb-pop`)하지 않는다 — 처음 들어올 때만 튀어 들어온다(§6.7).
- 닫기(×, 펼친 달력 줄)는 그 줄을 접어 한 달 보기로 돌아간다(같은 화면 안에서 접힘/펼침만 바뀐다).

## H. 배치·묶음

- **정보 줄(값)**: 왼쪽 끝에 뒤로 또는 닫기 하나, 오른쪽 끝에 더보기(있으면). 가운데는 제목(h1)이 가변으로 차지한다(`.info-top`·`.write-top` 순서 그대로).
- **달력 큰 제목(값)**: 제목 글자 양옆에 월 이동 화살표를 하나씩 둔다(`이전 달` 왼쪽, `다음 달` 오른쪽). 제목 글자와의 간격 16px(§6.7 — 전에는 8px이라 아이콘이 글자에 붙어 보였다).
- **펼친 줄(값)**: 왼쪽 닫기(×) → 날짜+예시 태그 → (완료한 날이면) 오른쪽 끝 더보기(⋯). 간격은 §6.7의 펼친 윗줄 규칙을 따른다.

## I. 문구

- 라벨 없음. 접근 가능한 이름만 있다 — 동사·명사 혼용이 허용된다("이전 화면"·"닫기"·"메뉴"/"더보기"·"이전 달"/"다음 달"·"한 달 보기로 닫기"). 길이 상한은 해당 없음(화면에 보이지 않는다).
- 이름은 맥락을 담는다 — 같은 뒤로가기라도 "달력으로"·"통계로"·"설정으로"처럼 도착지를 말한다(`settings.js:66` 등). 순수 방향만 말하는 "이전 화면"은 엔트리 화면(`entry.js:7`)처럼 도착지가 명확하지 않을 때만 쓴다.

## J. 움직임

없음(위 F의 누름 반응 결함 참고 — §5.1로 바꾸기 전까지는 나타남·사라짐 연출도 없다).

## K. 접근성

- `<button type="button">` + `aria-label` 필수(아이콘만 있어 이름 텍스트가 없다).
- **결정(D-099) K2 — 더보기(⋯) 버튼에 `aria-haspopup="menu"`를 붙일지**: 지금은 `aria-label`만 있고 이 버튼이 메뉴(시트)를 연다는 표시가 없다(`write.js:346`·`tabs.js:401`). *(추천: 붙인다 — 시트가 열리기 전 스크린리더 사용자가 "메뉴 버튼"임을 미리 알 수 있다. §6.11의 시트 초점 이동 규칙과 함께 쓰면 예측 가능성이 올라간다.)* → **정함(D-099, 위임 판단)**: 붙이되 `menu`가 아니라 `aria-haspopup="dialog"`를 붙인다 — ⋯는 메뉴 목록이 아니라 시트(dialog)를 연다.
- 대비: ink 아이콘이 흰 바탕·`surface-soft` 원판 모두에서 4.5:1 이상(중립 색 조합, `check-contrast`의 중립 검사 범위).
- 글자 200%: 아이콘 버튼은 글자를 포함하지 않아 확대의 영향을 받지 않는다.

## L. 화면 폭·기기

- 360~480px에서 크기·자리가 바뀌지 않는다(고정 44px, 정보 줄·달력 제목의 좌우 끝에 고정).
- 홈 화면 앱: 안전 영역 위쪽(정보 줄이 sticky일 때)이 잘리지 않는다(`write-top`의 `sticky top`).

## M. 장면 위에서

- 세부 감정 화면(감정 300 면) 위: `.write-top`이 `--tint`로 물들지만 아이콘 버튼 자체(`.back`)는 색을 바꾸지 않는다 — ink 아이콘 그대로다(300 위 ink 대비 6.48:1 이상, §9).
- 마음 고르기(초록 언덕) 위: 같은 규칙, 초점 링만 ink 3px로 바뀐다(§6.2, 공통 규칙이지 이 부품만의 값은 아니다).
- 어두운 숲(오늘 화면): 이 부품을 쓰지 않는다 — 오늘 화면에는 아이콘 버튼이 없다(§6.12, 조작은 가운데 돌 하나뿐).

## N. 하지 말 것·근거

- 아이콘 옆에 글자 라벨을 붙이지 않는다(라벨이 필요하면 [버튼](button.md)을 쓴다).
- 그림자를 주지 않는다(§2-6).
- 근거: D-076(오늘 화면 탐색 제거로 이 부품이 오늘 화면에서 빠짐), D-080(달력 아이콘 색 파기 규칙), D-090 ③(펼친 줄 닫기 원 축소).
