# 달력 날짜 칸

기본 부품(장면 부품 예외 포함) · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건**(2026-09-26 D-099로 1건을 위임 판단으로 정함 — 각 항목의 '정함'을 보라). **선택(고른 날) 표현은 장면 부품 예외로 자기 방식(민트 띠+ink 고리)을 유지한다** — §5.1이 "달력 칸의 민트 띠+고리"를 장면 부품의 예외로 이름 붙였다(DESIGN_SYSTEM §5.1). 이 부품은 밝은 화면(달력)에서만 쓰이고 감정 색·장면 색 위에 놓이지 않는다.

## A. 쓰임

- **쓸 때**: 달력의 한 달(또는 접힌 한 주)에서 그 날의 기록 상태를 보여주고 고르는 자리.
- **쓰지 않을 때**: 범례의 견본(`mini`, 눌리지 않는 `<span>`)이나 "이번 주 길"(지금은 쓰지 않음) 같은 정적 표시.

## B. 구조

`web/js/components/day.js`(`dayCell`), `web/css/tabs.css:10-37`.

- `<button class="day <status>">` 안에 숫자(`.day-num`)와, 임시저장이면 연필 아이콘(`pencil`).
- 상태 모양은 모두 `::before`(둥근 blob 반경, `radius.blob`) 하나의 배경/테두리로 그린다 — 별도 배지 요소가 아니다.
- 오늘이면서 완료/임시저장이면 `::after`로 안쪽에 한 겹 더(mint 칸 위에 그 날의 상태 모양을 얹음, `tabs.css:18-20`).
- 고른 날은 `::before`의 `inset`을 7px로 좁히고 `box-shadow`(민트 4px 띠)+`outline`(ink 2px 고리)을 더한다(`tabs.css:30`).

## C. 변형

| 상태 | 뜻 | 모양(`tabs.css`) |
| --- | --- | --- |
| `completed` | 완료 | ink 채움 blob |
| `draft` | 임시저장 | ink 50% 점선 윤곽 + 연필 |
| (없음, 기본) | 기록 없음 | 빈 자리(hairline만) |
| `today` | 오늘 | mint 배경 + ink 2px 테두리(그 위에 그날 상태를 겹쳐 그림) |
| `future` | 미래 | `opacity:.4`, 테두리 투명, `disabled`(F1 참고) → **시안 반영(2026-09-26)**: 글자 바탕+ink 50%(`color-mix`), 투명도 없음 |
| `blank` | 그 달 밖의 빈 칸(요일 맞춤용) | `::before` 자체를 숨김 |
| `mini` | 범례 견본 | 24×24, 숫자 없음 |

색만으로 구분하지 않는다 — 모양(채움/점선/빈칸)과 연필 아이콘이 함께 다르다(§6.7 "색만으로 구분하지 않는다").

## D. 크기

- 셀은 `min-height: touch`(44px 이상), 폭은 7열 그리드에서 `1fr`(고정 폭이 아님, `tabs.css:8`) — 360px 화면에서 45.7×44px가 나와 44px 기준을 넘으면서 가로 스크롤이 생기지 않는다(D-036, 실측).
- 범례 견본(`mini`)만 24×24 고정.
- 누르는 영역 = 보이는 셀 그대로(버튼 자체가 셀 전체).

## E. 값

| 속성 | 값 |
| --- | --- |
| 완료 면 | `service-ink`, 글자 `neutral-bg`, `fw-body-strong` |
| 임시저장 테두리 | `emphasis`(2px) dashed, ink 50% |
| 오늘 면 | `service-mint`, 테두리 `emphasis` solid ink |
| 고른 날 띠·고리 | `box-shadow 0 0 0 4px mint` + `outline emphasis solid ink`(고리 바깥 끝이 칸 안 1px, §6.7) |
| 셀 배경 반경 | `radius.blob`(유기형 — 다섯 고정 반경 값의 예외, §5) |

## F. 상태

| 상태 | 값 |
| --- | --- |
| 완료/임시저장/기록 없음/오늘 | 위 C·E |
| 선택(고른 날) | 장면 부품 예외 — §5.1 공통 규칙(ink 면+흰 글자) 대신 자기 표현(민트 띠+ink 고리) 유지. `aria-pressed="true"` |
| 미래(비활성) | `disabled` 속성(네이티브) + `opacity:.4` + 테두리 투명(`tabs.css:21-22`) → **시안 반영(2026-09-26)**: `opacity` 대신 글자 바탕+ink 50%(`tabs.css` `.day.future`). `disabled` 속성은 그대로(이 칸은 아이콘 버튼이 아니라 K1 범위 밖) |

**결정(D-099) F1 — 미래 날짜의 비활성 표현이 §5.1과 다르다**: §5.1은 "투명도로 흐리게 하지 않는다 — 바탕에서 색을 만든다(`color-mix`)"고 정했지만, 미래 날짜는 지금도 `opacity:.4`(옛 방식)를 쓴다(button.md의 다른 기본 부품들은 이미 `color-mix`로 바꿨다). 달력 칸을 §5.1의 새 규칙(`color-mix` 기반 비활성)으로 맞출지, 아니면 이 부품 전체(선택 표현처럼)를 장면 부품 예외로 넓혀 지금 표현을 유지할지. *(추천: `color-mix`로 맞춘다 — 미래 날짜의 "비활성"은 버튼의 비활성과 같은 성격(만질 수 없음)이라 선택 표현과 달리 예외로 둘 이유가 약하다.)* → **정함(D-099, 위임 판단)**: 맞춘다 — 미래 날짜는 §5.1의 바탕에서 만든 색(글자 바탕+ink 50%)으로 흐리게 하고 투명도를 쓰지 않는다. 날짜 칸의 선택 표현(민트 띠+고리)은 장면 부품 예외 그대로다.

## G. 동작

- 누르면 그 날짜로 즉시 `replaceState`(뒤로 가기 기록을 쌓지 않음, `tabs.js:301`)하고 그 주가 접히며 아래에 내용이 열린다(§6.7).
- 미래 날짜는 `disabled`라 눌러도 반응이 없다(안내 문구도 없음 — "경계가 스스로 이유를 말하는 곳", §5.1의 "안내 없이 비활성만" 예).
- 날짜를 바꾸면(달 넘김 포함) 격자 전체가 다시 튀어 들어오지 않고, **누른 칸 하나만** 420ms 동안 좌우로 까딱인다(`cal-wiggle`, `tabs-mood.css:35-36`) — 처음 진입할 때만 칸 전체가 `tb-pop`으로 튀어 들어온다.

## H. 배치·묶음

- 7열 그리드(`grid-template-columns: repeat(7,1fr)`), 열 간격 0·줄 간격 `space.1`(4px, D-036).
- 처음 진입 시 줄마다 50ms·같은 줄 안에서 칸마다 12ms 간격으로 튀어 들어온다(`--tb-d`, `tabs.js:179`).
- 조약돌 모양(`::before`)은 줄마다 좌우/상하로 뒤집혀(`nth-child(3n)`/`nth-child(4n+2)`) 손으로 놓은 느낌을 낸다(`tabs.css:31-32`).

## I. 문구

해당 없음 — 숫자만 표시하고 별도 라벨 문구가 없다(접근 가능한 이름은 K 참고).

## J. 움직임

- 첫 진입: `tb-pop`(340ms, spring) — 줄·칸 지연은 H 참고.
- 재진입(달 넘김·펼치기 등)은 애니메이션 없음(`cal-settled`가 끈다).
- 날짜 선택: `cal-wiggle`(420ms, 좌우 회전) 한 번.
- 움직임 줄이기: 위 둘 다 없음(`tabs-mood.css:141`).

## K. 접근성

- `role` 없이 `<button>` 그대로(네이티브 버튼 시맨틱), `aria-current="date"`(오늘)·`aria-pressed`(고른 날)·`data-iso`(값 없음, 내부 참조용).
- 접근 가능한 이름은 숫자 텍스트(`.day-num`)뿐 — 상태(완료/임시저장 등)는 이름에 포함되지 않는다. **미확인**: 스크린리더가 상태를 별도로 안내받는지(예: "완료, 25일") 검증하지 않았다 — 지금 코드로는 시각 모양만 상태를 전하고 접근 가능한 이름에는 상태가 없다(예상 밖 발견 참고).
- 미래 날짜는 `disabled`라 Tab 순서에서 빠진다(§5.1의 "아직 누를 수 없는 주 버튼"과 달리 `aria-disabled`가 아니라 진짜 `disabled` — 초점도 받지 않는다).

## L. 화면 폭·기기

- 360~480: `1fr` 그리드라 폭에 맞춰 셀이 늘어난다(고정 폭 아님).
- 글자 확대 200%: 숫자만 커지고 셀 크기는 그대로 → 미확인(넘침 여부 실측하지 않음).

## M. 장면 위에서

해당 없음 — 달력 화면은 밝은 바탕이고(§6.7 "어두운 숲은 오늘 화면 한 곳뿐") 이 부품은 감정 색 면·초록 언덕·어두운 숲 위에 놓이지 않는다.

## N. 하지 말 것·근거

- 감정 색으로 상태를 칠하지 않는다(D-053·D-071) — 서비스 색(ink/mint)과 조약돌 모양만 쓴다.
- 달력에 빛(§8.3)·친구를 남기지 않는다 — "달력은 기록의 지도이지 좋은 날의 지도가 아니다"(§6.7).
- 근거: D-050(조약돌 크기 원칙)·D-067(원근 크기, 이 부품에는 적용 안 됨 — 모든 날짜 칸은 같은 크기)·D-096 ①(펼침 동작)·D-098(상태 공통 규칙, F1의 대상).

## O. 검수

- 전시장 상태표: 4단계에서 6개 상태(완료·임시저장·없음·오늘·미래·선택) 표를 `design/style-guide.html`에 둔다.
- 하네스: F1이 해결되면 비활성 색 산출 방식(`color-mix` 사용 여부)을 검사에 추가한다.
- 캡처: 360px, 한 달 보기(진입 연출 포함)와 접힌 주(선택 상태 포함) 각각.
