# 세그먼트

기본 부품 · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건**(2026-09-26 D-099로 1건을 위임 판단으로 정함 — 각 항목의 '정함'을 보라). 통계 화면의 기간(최근 7일/30일) 하나를 고르는 부품이다(`.segmented`, `web/css/base.css:97-100`).

## A. 쓰임

- **쓸 때**: 화면 안에서 보여 줄 기간·범위를 둘 중 하나로 즉시 바꿀 때(지금은 최근 7일/30일 하나뿐).
- **쓰지 않을 때**: 세 개 이상의 선택지 → [고르기 알약](radio-pill.md)(`role=radio`, flex-wrap으로 줄바꿈). 여러 개를 고르는 것 → [선택 chip](choice-chip.md). 다른 화면으로 이동 → 하단 탭·목록 줄.
- 지금 시안에는 통계 화면(첫 화면·친구 상세) 한 곳에만 있다(`stats.js:99,276`). 세그먼트가 늘어나 세 개 이상이 되면 고르기 알약으로 바꾸는 것을 검토한다 — 이 부품은 "둘 중 하나, 폭이 좁아도 나란히"를 전제로 값(D)이 정해졌다.

## B. 구조

- 필수: 버튼 N개(지금은 2개), 각 버튼은 글자 라벨 하나("최근 7일"·"최근 30일").
- 컨테이너 하나(`role="group"`)가 버튼들을 감싸고 옅은 면 하나로 묶는다. → **시안 반영(2026-09-26)**: `role="radiogroup"` + 버튼 `role="radio"`·`aria-checked`, ← →로 옮기며 고른다(K1)

## C. 변형

- 변형 없음 — 한 가지 모양뿐이다. 한 화면에 세그먼트는 하나만 둔다(둘 이상이면 어느 것이 무엇을 바꾸는지 헷갈린다 — 지금 시안은 이미 화면당 하나다).

## D. 크기

- 컨테이너: 안쪽 여백 `space.1`(4), 버튼 사이 간격 `space.1`(4), 반경 `radius.chip`(999).
- 버튼: `min-height 44`, 좌우 여백 `space.4`(16), 반경 `radius.chip`(999). 너비: `grid-auto-columns:1fr`로 버튼들이 컨테이너 폭을 균등하게 나눠 채운다(내용 맞춤이 아니라 항상 가득 채움).

## G. 동작

- 누르면 즉시 그 값으로 바뀐다(저장 없음, 되돌리기 없음) — 화면 안 표시만 바뀌는 필터라 실행 취소가 필요 없다.
- 값이 바뀌면 다른 세그먼트 버튼의 `aria-pressed`를 false로, 누른 버튼만 true로 바꾸고 `aria-live`로 "최근 N일 통계"를 읽는다(`stats.js:100`). → **시안 반영(2026-09-26)**: `aria-checked`와 roving `tabindex`로 바뀌었다(`stats.js` `periodPicker`)
- 주소 표시줄에 `?p=`로 남아 뒤로 가기·새로고침에도 유지된다(`history.replaceState`, 쌓지 않는다).
- 친구 상세 화면(`stats.js:276`)에서 기간을 바꾸면 걷는 애니메이션을 다시 재생하지 않는다(§6.9 — 통계는 반복 움직임이 없는 정적 화면).

## H. 배치·묶음

- 화면 위쪽, 요약 통계 칸 앞에 하나(`stats-screen .segmented{margin-top:...}`). 친구 상세는 가운데 정렬 + 최대 폭 15rem(`stats.css:78`).
- 버튼 순서는 값이 작은 것이 왼쪽("최근 7일" 왼쪽, "최근 30일" 오른쪽) — 시간이 짧은 것에서 긴 것 순.

## I. 문구

- 명사형 라벨("최근 7일"), 동사로 끝나지 않는다(버튼의 "할 일" 규칙과 달리 이 부품은 상태를 나타내는 값 이름이다).
- 한 줄에 들어가게 쓴다. 글자 확대 200%에서 넘칠 만큼 긴 라벨은 아직 없다(지금은 "최근 N일" 짧은 문구뿐) — 늘어나면 [버튼](button.md) I2의 위아래 쌓기와 같은 방식을 검토한다.

## J. 움직임

없음(위 F의 누름 반응 결함 참고).

## K. 접근성

- 컨테이너 `role="group"` + `aria-label="기간"`. 각 버튼은 `<button aria-pressed>`. → **시안 반영(2026-09-26)**: `radiogroup`/`radio`로 바꿨다(K1)
- **결정(D-099) K1 — role을 그대로 둘지, `radiogroup`/`radio`로 바꿀지**: §5.1은 세그먼트를 고르기 알약과 함께 "하나 고르기"로 분류하는데(같은 선택 표현 규칙을 쓴다), 고르기 알약은 `role="radio"`+`aria-checked`([radio-pill.md](radio-pill.md))를 쓰고 세그먼트는 `role="group"`+`aria-pressed`(토글 버튼 묶음)를 쓴다 — 같은 "하나 고르기"인데 스크린리더에 다르게 읽힌다(라디오는 "n개 중 1번, 선택됨"을, 토글 버튼은 "눌림/안 눌림"을 말한다). *(추천: `radiogroup`/`radio`로 바꾼다 — 실제로 "여러 값 중 하나"를 고르는 동작이고 고르기 알약과 짝이 맞는다. 지금의 `aria-pressed`는 "켜짐/꺼짐을 토글한다"는 뜻이라 실제 동작과 어긋난다.)* → **정함(D-099, 위임 판단)**: `radiogroup`/`radio`로 바꾼다 — 여럿 중 하나를 고르는 동작이고, 고르기 알약과 같은 '하나 고르기'(§5.1 ④)로 묶인다. 방향키로 옮겨 다닌다.
- 대비: 컨테이너 위 muted 글자, 고른 버튼의 ink 면 위 흰 글자 모두 4.5:1 이상(중립 조합).

## L. 화면 폭·기기

- 360~480px에서 버튼들이 `1fr`로 균등하게 줄어들며 라벨이 잘리지 않는다(짧은 라벨이라 여유가 있다).
- 글자 200%에서도 지금 라벨 길이로는 넘치지 않는다(실기기 확인은 미확인).

## M. 장면 위에서

- 해당 없음 — 세그먼트는 통계 화면(밝은 바탕)에만 있고 감정 색 면·장면 색 위에는 나오지 않는다(§3.3 적용 제외 화면 목록에 통계가 포함된다).

## N. 하지 말 것·근거

- 그림자를 주지 않는다.
- 근거: D-070(통계는 밝은 화면), D-091 ①(친구 상세도 같은 세그먼트 재사용).
