# 날짜·시각 입력(기기 기본)

기본 부품 · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098, 이 부품은 브라우저 기본 UI를 그대로 써서 §5.1이 적용되지 않는다 — 아래 F 참고) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건**(2026-09-26 D-099로 2건을 위임 판단으로 정함 — 각 항목의 '정함'을 보라). 이 앱은 직접 만든 달력·시계 선택기를 두지 않고 기기(브라우저) 기본 `<input type="date">`/`<input type="time">`를 그대로 쓴다는 결정이 코드에만 있고 문서에는 없었다(INVENTORY). 이 문서가 그 결정을 처음 옮겨 적는다.

## A. 쓰임

- **쓸 때**: 날짜 하나 또는 시각 하나를 입력받아야 할 때, 기기가 이미 가진 선택기(달력 팝업·시계 다이얼)를 그대로 빌려 쓴다.
- **쓰지 않을 때**: 값이 미리 정해진 몇 개 중 하나 → [고르기 알약](radio-pill.md)(지금 알림 시각·하루 기준 시각이 실제로 쓰는 방식). 이 부품은 그 알약 목록에 없는 "다른 시각"을 고를 때만 뒤에서 열린다.
- **지금 실제로 살아 있는 것은 시각(`type="time"`) 하나뿐이다**: 설정의 "다른 시각…" 알약이 여는 시간 선택기(`settings.js:119-121`). 날짜(`type="date"`)는 스타일(`notes.css:53-55`)만 남아 있고 호출부가 없다 — 아래 결정(D-099) C1.

## B. 구조

- 필수: 네이티브 `<input type="date">` 또는 `<input type="time">` 하나. 이 부품 자체에는 라벨·오류 문구가 없다(부르는 화면이 감싼다).
- 시각(현재 살아 있는 형): 화면에 보이지 않는 숨은 input 하나(`.st-time-native`) + 그것을 여는 눈에 보이는 트리거([고르기 알약](radio-pill.md)의 "다른 시각…").

## C. 변형

| 변형 | 보임 | 여는 방법 | 쓰는 곳 |
| --- | --- | --- | --- |
| 숨김형(트리거로 연다) | input 자체는 1×1px·투명·화면 밖(`settings.css:59`) | 알약을 누르면 `showPicker()` | 알림 시각의 "다른 시각…"(살아 있음) → **시안 반영(2026-09-26)**: `showPicker()`가 없으면 그 자리에 보이는 입력 칸(`.st-time-native.is-revealed`)으로 드러내고 초점을 준다(G1) |
| 인라인형(그대로 보인다) | input이 줄 종이 탭 안에 그대로 보인다(`notes.css:53`) | 사용자가 직접 누른다(브라우저 기본) | 없음(스타일만 있고 호출부가 없다 — 아래 C1) |

- **결정(D-099) C1 — 인라인형(날짜)을 되살릴지, 지우고 숨김형 하나로 통일할지**: `notes.js`의 `renderEventScene({dateField})`는 `dateField`가 있으면 종이 탭 안에 넣게 돼 있지만, 실제 호출부(`write.js:307`)는 항상 `dateField: null`을 넘긴다(D-082 — "새 기록은 그날만 쓴다"가 날짜 칸 자체를 없앴다). `notes.css:53-55`의 스타일만 죽지 않고 남아 있다. *(추천: 지운다 — D-082 이후로 이 앱에는 날짜를 사용자가 고르는 화면이 없다(작성 흐름은 항상 오늘, 지난 글 마무리는 그 글이 시작된 날짜를 그대로 쓴다). 스타일이 남아 있으면 다음 작업자가 "쓰는 곳이 있나 보다"고 오해하기 쉽다. 날짜를 고르는 화면이 실제로 필요해지면(예: 지난 날 기록을 새로 시작) 그때 이 인라인형을 다시 쓸지 정한다.)* → **정함(D-099, 위임 판단)**: 지운다 — 날짜 인라인형은 D-082가 새 기록의 날짜 칸을 없애며 남은 흔적이다. 기기 선택기는 숨김형(시각) 하나로 둔다. 시안 반영 때 CSS를 지운다.

## D. 크기

- 숨김형: 1×1px(화면에 없음). 트리거(알약)의 크기는 [고르기 알약](radio-pill.md)의 값을 따른다.
- 인라인형(죽은 코드): 폭 100%, 글자 `heading`(18/600). 달력 아이콘 자체의 누르는 자리는 `::-webkit-calendar-picker-indicator`에 `padding: space.3`(12)을 줘 약 40px로 넓혔다(`notes.css:55`) — **WebKit 전용 의사 요소라 Firefox 등에는 적용되지 않는다**(미확인 — 다른 브라우저의 실제 터치 목표 크기를 재지 않았다).

## E. 값(부품 토큰 — 4단계에서 `tokens.json`에 올린다)

이 부품은 브라우저가 그리는 선택기 UI 자체(색·모양)를 우리 토큰으로 바꾸지 않는다 — 트리거(알약)만 우리 값을 쓴다. 숨김 input 자체는 값이랄 것이 없다(보이지 않음).

## G. 동작

- **즉시 적용**: 값을 고르면(또는 선택기를 닫으면) `onchange`가 그 값을 바로 상태에 반영한다(`settings.js:120`) — 저장 버튼이 없다(§6.16 전제 그대로).
- **여는 법**: `showPicker()`(지원 브라우저)를 우선 부르고, 실패하면(구식 브라우저·권한 예외) `.focus()`로 대신한다(`settings.js:121`). → **시안 반영(2026-09-26)**: `.focus()` 대신 입력 칸을 드러낸다(G1)
- **결정(D-099) G1 — `showPicker()`를 지원하지 않는 브라우저의 fallback이 사실상 보이지 않는다**: `.focus()` fallback은 화면 밖(`left:-9999px`)·1×1px·투명한 input에 키보드 초점만 옮긴다 — **선택기 자체가 뜨지 않는 브라우저에서는 사용자가 아무것도 보지 못한 채 화면 밖 보이지 않는 칸에 초점만 가 있는 상태**가 된다(마우스 사용자는 무엇을 눌러야 값이 바뀌는지 알 방법이 없고, 키보드 사용자는 숫자를 타이핑해 시각을 입력할 수는 있으나 안내가 없다). *(추천: fallback 경로에서 `showPicker`가 없거나 실패하면 숨김 input을 그 순간만 화면에 보이는 자리로 옮기거나(예: 알약 바로 아래에 임시로 보이는 네이티브 input을 놓는다), 최소한 "시각을 입력해 주세요" 같은 화면에 보이는 안내를 그 순간 띄운다 — 지금은 이 갈래를 시험한 흔적이 없다(아래 미확인).)* → **정함(D-099, 위임 판단)**: `showPicker()`가 없으면 그 자리에 기기 입력 칸을 보이게 드러내고 초점을 준다 — 눌러도 아무 일이 없어 보이는 상태를 두지 않는다.

## H. 배치·묶음

- 숨김형은 트리거(알약) 바로 뒤에 문서상 위치만 차지한다(`settings.js:134`, 시각 `st-pills` 컨테이너의 마지막 자식).

## I. 문구

- 이 부품 자체는 문구를 갖지 않는다 — 트리거의 문구([고르기 알약](radio-pill.md) I 참고)와 브라우저가 그리는 선택기 UI의 문구(운영체제 언어를 따름, 우리가 바꿀 수 없다)로 나뉜다.

## J. 움직임

해당 없음(브라우저 기본 선택기의 열림·닫힘 애니메이션은 OS·브라우저의 몫이다).

## K. 접근성

- 숨김형 input은 `tabindex="-1"` + `aria-hidden="true"`(`settings.js:119`) — Tab 순서에 끼지 않고 트리거(알약)만 초점을 받는다. `display:none`을 쓰지 않는다 — 그러면 `showPicker()`가 "렌더링되지 않음" 오류를 낸다(주석, `settings.css:58`).
- 스크린리더 사용자에게는 트리거(알약)의 이름과 상태만 들린다 — 선택기 안의 읽기는 브라우저·OS가 맡는다.

## L. 화면 폭·기기

- 브라우저·OS마다 실제로 뜨는 선택기 UI 모양이 다르다(iOS 휠, Android 다이얼로그, 데스크톱 팝업 등) — 이 앱은 그 차이를 흡수하지 않는다(의도된 위임).
- 미확인 — 실제 iOS Safari·Android Chrome에서 `showPicker()` 성공률과 fallback 발생 빈도를 재지 않았다.

## M. 장면 위에서

## N. 하지 말 것·근거
