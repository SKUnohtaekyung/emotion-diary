# 페이지 점·넘김 화살표 (편지 카드)

기본 부품 · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건**(2026-09-26 D-099로 1건을 위임 판단으로 정함 — 각 항목의 '정함'을 보라).

## A. 쓰임

- **쓸 때**: 편지(검토·기록 상세, §6.14)의 카드 여러 장을 옆으로 넘길 때 — 스와이프만 두지 않고 화살표·점을 함께 둔다(WCAG 2.5.1, `letter.js:1-3` 주석).
- **쓰지 않을 때**: 달력의 달 넘김(‹ ›만 있고 점이 없다 — 아이콘 버튼)이나 세부 감정의 계열 간 이동(이전/다음 버튼, 점 없음)에는 이 부품을 쓰지 않는다.

## B. 구조

`web/js/components/letter.js:109-137`, `web/css/write.css:207-215`.

- 카드 묶음(`.pager`, 실제 스크롤 컨테이너) 아래 18px에 **넘김 줄**(`.letter-nav`)이 따로 있다: 왼쪽 이전 화살표(`.ar`) → 가운데 점 묶음(`.dd`, 카드 수만큼) → 오른쪽 다음 화살표(`.ar`).
- 점은 장식(`aria-hidden`), 화살표만 실제 버튼.
- 봉투가 닫혀 있는 동안은 `.letter-nav` 자체가 `visibility:hidden`이라 화면에 없고 Tab으로도 닿지 않는다(봉투를 열어야 나타난다).

## C. 변형

| 변형 | 차이 |
| --- | --- |
| 편지(검토·기록 상세, `scene:true`) | 봉투 열림 연출 뒤에 나타남, 카드 묶음 위 책상 장면 포함 |
| 달력 인라인(`scene:false`, `letter.js:126-129`) | 봉투 없이 곧장 `opened` 상태로 시작 — 넘김 줄 구조·동작은 같다 |

카드 수는 계열 수(감정 카드, 9개 넘으면 "이어지는 카드"로 더 늘어남) + 이야기 카드(사건·이유) + 있으면 칭찬·감사 카드다 — 최소 2장(감정 카드 없이 이야기 카드만 있는 경우는 없다: 계열을 하나 이상 고르지 않으면 편지 단계로 오지 않는다).

## D. 크기

- 화살표: 44×44 원형(`surface-soft` 면, `write.css:212`).
- 점: 꺼짐 7×7 원형 → 켜짐 20×7 알약(폭만 늘어남, `.dd i.on`).
- 점 사이 간격 8px, 화살표-점 묶음 간격 12px(`write.css:209`, 둘 다 토큰 값 `space.2`/`space.3`과 일치).
- 넘김 줄 자체 높이 36px, 카드 아래 18px 지점에 위치.
- 카드 자체 크기(참고): 328×(376~448)px, 화면 높이에 따라 `clamp()`로 변한다(§6.14, D-079 ③) — 이 값은 [tag.md](tag.md)·편지 장면 쪽 소관이라 여기서는 참고만 한다.

## G. 동작

- 화살표: 누르면 한 칸씩 `scrollTo({behavior:"smooth"})`로 이동(움직임 줄이기에서는 `"auto"`, 즉시 이동).
- 스크롤: `scroll-snap-type:x mandatory`로 카드 하나씩 딱 맞게 멈춘다. 스크롤이 끝나면 `scroll` 이벤트로 점·화살표 상태를 다시 그린다(`paint()`, `letter.js:133-134`).
- 키보드: 카드 묶음(`.pager`) 자체가 `tabindex="0"`이고 `ArrowLeft`/`ArrowRight`로 화살표 클릭과 같은 동작을 한다(`letter.js:137`).
- 열릴 때 초점은 카드 묶음(`.pager`)으로 옮겨간다(봉투가 사라지며 초점을 잃지 않도록, `letter.js:150`).

## H. 배치·묶음

- 카드 묶음 바로 아래(18px) 가운데 정렬로 붙는다 — 카드와 독립된 자리라 카드 높이(`--card-h`)가 화면마다 달라져도 항상 카드 아래에 있다.
- 화면이 낮으면(`max-height:660px`) 봉투 열기 전 캡션(`.envcap`) 위치만 조정되고 넘김 줄 자체 위치는 바뀌지 않는다.

## I. 문구

해당 없음 — 점·화살표 모두 글자가 없다(접근 가능한 이름은 K).

## J. 움직임

- 점 폭 변화(7→20px 등): `width .25s, background .25s`(전환).
- 화살표 자체의 등장/사라짐 전환은 `.letter-nav{opacity 0 → 1, transition .4s}`(봉투가 열릴 때).
- 카드 스크롤 자체는 `scrollTo` 기반이라 브라우저의 기본 스무스 스크롤(사용자 에이전트 정의 곡선)을 쓴다 — 토큰화된 `easing`이 아니다.
- 움직임 줄이기: 스크롤은 `"auto"`(즉시)로 바뀌지만, 점 폭 전환(`transition: width .25s`)에는 별도의 reduced-motion 예외가 없다 — 아래 "예상 밖 발견".

## K. 접근성

- 카드 묶음: `role="region"` `aria-roledescription="carousel"` `aria-label="오늘의 편지"`, 각 카드는 `aria-label="N / 전체, 이름"`.
- 화살표: `aria-label="이전 장"`/`"다음 장"`.
- 점: `aria-hidden`(장식) — 현재 위치는 카드 자체의 `aria-label`(예: "2 / 5, 이유")로 전해진다.
- 넘칠 때만 스크롤되는 카드 내부 글 영역(`.lt-scroll`)은 넘칠 때만 `tabindex="0"`을 받는다(`markScrollers`, `letter.js:145`).

**결정(D-099) K1 — 장을 넘겨도 스크린리더에 새로 알리지 않는다**: 화살표를 누르거나 스와이프해도 `aria-live` 알림이 없다 — 스크린리더 사용자는 카드 묶음에 다시 초점을 옮기거나 카드 자체를 읽어야 몇 번째 장인지 안다. 카드를 넘길 때마다 "N / 전체, 이름"을 `aria-live="polite"`로 알릴지, 지금처럼 조용히 둘지(자동 알림이 잦은 편지 읽기 흐름을 방해할 수 있다는 반론도 있다). *(추천: 알린다 — 봉투를 처음 열 때는 이미 `announce()`로 "편지를 열었어요"를 알리고 있어(`letter.js:150-153`) 같은 패턴을 넘김에도 쓰면 일관된다.)* → **정함(D-099, 위임 판단)**: 알린다 — 장을 넘기면 '3장 중 2장'을 `aria-live="polite"`로 읽는다. 봉투를 열 때 이미 비슷하게 알린다.

## L. 화면 폭·기기

- 360~480: 카드 폭 328px 고정, 좌우 16px(달력 인라인은 화면 padding이 대신 그 자리를 준다, `write.css:152` 주석).
- 글자 확대 200%: 화살표·점은 px 고정이라 커지지 않는다 — 카드 안 글자만 커진다(미확인 — 실측하지 않음).

## M. 장면 위에서

- **편지(숲 속 빈터, D-085)**: 넘김 줄은 장면 자체와 분리된 흰 배경 없는 투명 줄이라 뒤 장면(빈터 바닥·빛 알갱이)이 그대로 비친다 — 화살표 면(`surface-soft`)만 불투명해 눈에 띈다.
- **달력 인라인**: 장면이 없어(순수 흰 화면) 이 문제 자체가 없다.

## N. 하지 말 것·근거

- 스와이프만 두지 않는다(화살표·점을 항상 함께 둔다, WCAG 2.5.1).
- 옆 카드가 살짝 보이는 엿보기·가장자리 흐림 마스크를 다시 쓰지 않는다 — 카드는 한 장만 보인다(D-096 ②, 엿보기가 배경에 묻힌 느낌을 만들었다).
- 근거: D-063(편지 검토)·D-079 ③(카드 높이 범위)·D-096 ②(엿보기 제거).

## O. 검수

- 전시장 상태표: 4단계에서 카드 3장짜리 예시로 처음/가운데/끝 장 상태(화살표 비활성 포함) 표를 `design/style-guide.html`에 둔다.
- 하네스: 해당 없음(스크롤 기반 동작이라 정적 스냅샷 검사의 이점이 적다).
- 캡처: 360px, 봉투 닫힘/열림 각 1장, 끝 장에서 화살표 비활성 확인.
