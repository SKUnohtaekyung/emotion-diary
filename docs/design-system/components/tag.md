# 태그 (고치기 · 시안 · 따로 정함)

기본 부품 · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건**(2026-09-26 D-099로 2건을 위임 판단으로 정함 — 각 항목의 '정함'을 보라). 이름은 하나지만 시안에는 뜻이 다른 세 가지 작은 라벨이 섞여 있다 — 이 문서가 셋을 갈라 정리한다.

## A. 쓰임

세 가지는 겉모양은 비슷해도(작은 알약/딱지 모양) 쓰임이 다르다.

| 종류 | 클래스 | 누르나 | 뜻 |
| --- | --- | --- | --- |
| **고치기**(edit-tag) | `.edit-tag` | 그렇다 — 버튼 | 편지 카드에서 그 카드가 나온 입력 단계로 돌아간다 |
| **시안**(proto-tag) | `.proto-tag` | 아니다 — 표시만 | "이 화면/숫자는 아직 실제로 동작하지 않는다"는 표식(`시안`/`예시`) |
| **따로 정함**(own-tag) | `.own-tag` | 아니다 — 표시만 | 세부 감정 크기를 대표 크기와 다르게 정했다는 표식 |

- **쓸 때**: 편지 카드마다 원본 입력으로 가는 손잡이가 필요할 때(고치기) · 시안 전용 화면·숫자에 "진짜 데이터가 아니다"를 알릴 때(시안) · 크기 선택기에서 개별 값이 대표값과 달라졌음을 알릴 때(따로 정함).
- **쓰지 않을 때**: 여러 개 중 하나를 고르는 것 → 선택 chip. 감정 표시 → [감정 chip](../../DESIGN_SYSTEM.md#631-감정-chip-표시용)(§6.3.1, 다른 부품).

## B. 구조

`web/js/components/letter.js:14`(`editTag`), `web/js/dom.js:60-64`(`protoButton`이 감싸는 `.proto-tag`)·`web/js/views/settings.js:87`(단독 `.proto-tag`), `web/js/components/slider.js:195`(`own-tag`).

- **고치기**: `<button class="edit-tag">` 안에 테이프 장식(`<i class="tape">`) + 연필 아이콘 + "고치기" 글자. 카드 오른쪽 위(기본 top 14px) 또는 이야기 카드의 소제목 줄 옆(top −4px, `letter.js:94`)에 절대 위치.
- **시안**: `<span class="proto-tag">` 글자만("시안"/"예시"), 문장 중간이나 화면 상단 안내 줄에 인라인으로 낀다.
- **따로 정함**: `<span class="own-tag">` 글자만("따로 정함"), 세부 감정 이름 뒤에 붙고 바로 옆에 "대표 크기와 같게"(되돌리는 실제 버튼)가 따로 있다.

## C. 변형

| 변형 | 자리 |

| 고치기 — 카드 오른쪽 위 | 감정 카드(`t1`/`t1-more`) |

| 시안 — 화면 상단 안내 줄 | 설정·통계·달력의 "이 화면의 동작은 자리만 있고…" 문장 앞 |

| 반경 | **9px**(`write.css:159`) | `radius-chip`(999, `base.css:53`) | `radius-chip`(999, `write.css:124`) → **시안 반영(2026-09-26)**: 고치기 태그 `radius.control`(8) |

**결정(D-099) E1 — 고치기 태그의 반경이 토큰 다섯 값 밖이다**: DESIGN_SYSTEM §5는 "모서리는 컨트롤 8·카드 12·시트 16·chip 999·차트 막대 4, 이 다섯 값 밖의 반경은 쓰지 않는다"고 정했지만 `.edit-tag`는 9px을 쓴다(`write.css:159`). 가장 가까운 토큰인 `radius.control`(8px)로 맞출지, 이 태그만의 예외(딱지 느낌을 살리는 값)로 남길지. *(추천: `control`(8px)로 맞춘다 — 9px과 8px의 시각 차는 거의 없고, 다섯 값 규칙을 지키면 토큰 밖 값 검사(§12)에 새 예외를 추가하지 않아도 된다.)* → **정함(D-099, 위임 판단)**: 맞춘다 — 고치기 태그 반경을 `radius.control`(8)로. 1px 차이라 모습은 거의 같다.

## G. 동작

- 고치기: 누르면 그 카드가 속한 입력 단계로 이동(`onEdit`), 고친 뒤 "편지로 돌아가기" 버튼으로 편지로 되돌아온다(`state.fromReview`, `write.js:357`).
- 시안: 화면 상단 안내 줄의 것은 순수 표시. `protoButton()`으로 감싼 것은 버튼 전체가 `aria-disabled`이고 누르면 "○○: 시안이라 동작하지 않습니다"를 안내한다(태그 자체가 아니라 버튼이 하는 일).
- 따로 정함: 태그 자체는 누를 수 없다 — 바로 옆의 "대표 크기와 같게" 버튼을 눌러야 값이 대표를 다시 따라간다(`e.own = null`, `slider.js:196`).

**결정(D-099) G1 — "따로 정함" 태그와 되돌리기 버튼이 분리돼 있다**: 태그 자체를 누르면 바로 대표값으로 되돌아가게(태그=버튼) 합칠지, 지금처럼 "정보 표시(태그)"와 "동작(옆의 글자 버튼)"을 분리해 둘지. *(추천: 분리를 유지한다 — 태그를 눌러 되돌리는 것은 "그 배지를 눌렀더니 값이 바뀌었다"는 뜻밖의 부작용으로 읽힐 수 있고, 지금처럼 버튼 글자("대표 크기와 같게")가 하는 일을 그대로 말해 주는 쪽이 명확하다.)* → **정함(D-099, 위임 판단)**: 지금대로 분리한다 — 표시를 누르면 값이 바뀌는 것은 뜻밖이다. 되돌리기는 옆의 글자 버튼('대표 크기와 같게')이 맡는다.

## H. 배치·묶음

- 고치기: 카드마다 하나, 절대 위치(오른쪽 위 또는 소제목 옆) — 카드 안 다른 요소와 겹치지 않게 좌표를 카드 CSS가 고정한다.
- 시안: 문장 안 인라인, 또는 화면 상단 안내 줄의 첫 요소.
- 따로 정함: 세부 감정 이름 바로 뒤, 한 줄 안(`sl-name` 옆).
- 한 화면에 소품(스티커·테이프·태그)을 세 곳 넘게 붙이지 않는다는 원칙(D-061 ①)과 관련 — 편지 카드 하나에는 고치기 태그 하나만 있어 이 제한에 걸리지 않는다.

## I. 문구

- 고치기: 글자 "고치기" 고정, 접근 가능한 이름만 카드마다 다르다(예: "슬픔 고치기", "칭찬 고치기").
- 시안: "시안" 또는 "예시" 두 단어뿐, 다른 문구를 쓰지 않는다(일관성).
- 따로 정함: "따로 정함" 고정.

## J. 움직임

- 고치기: 나타남·사라짐 연출 없음(카드 진입 연출에 얹혀 함께 나타날 뿐 자기 애니메이션은 없다).
- 시안·따로 정함: 애니메이션 없음. 따로 정함은 `hidden` 토글이 즉시 적용(전환 없음).

## K. 접근성

- 고치기: `aria-label`로 "○○ 고치기" 전체를 읽는다(보이는 "고치기" 글자보다 구체적) — 좋은 패턴.
- 시안: 장식이 아니라 실제 정보(이 화면이 가짜라는 것)라 `aria-hidden`을 주지 않고 평문으로 읽힌다(확인함, `dom.js:63`에 `aria-hidden` 없음).
- 따로 정함: 마찬가지로 평문(스크린리더가 "따로 정함"을 그대로 읽는다). 다만 별도 `aria-label`이 슬라이더 쪽에 있어 "따로 정함" 자체가 무엇을 뜻하는지 태그 단독으로는 설명하지 않는다 — 옆 슬라이더의 `aria-describedby` 문구(대표 강도 안내)가 맥락을 보완하는지는 미확인.

## L. 화면 폭·기기

- 360~480: 셋 다 텍스트 길이만큼 자연스럽게 배치, 좁은 화면에서 잘리는지는 실측하지 않았다(미확인).

## M. 장면 위에서

- **고치기**: 편지 카드(감정 카드=계열 300 면, 이야기 카드=`paper`, 칭찬·감사 카드=`service-light`) 위에 놓이지만 태그 자신의 면은 항상 흰색(`neutral-bg`)이라 카드 색과 무관하게 일정한 대비를 갖는다 — 카드가 무슨 색이든 태그는 늘 "흰 딱지"로 보인다.
- **시안·따로 정함**: 흰 화면(설정·통계·달력·크기 선택기)에서만 쓰이고 장면 위에 놓이지 않는다.

## N. 하지 말 것·근거

- "시안" 표를 여러 다른 문구로 바꿔 쓰지 않는다(항상 "시안" 또는 "예시" 둘 중 하나, 일관성이 신뢰를 만든다).
- 근거: D-063(편지 카드의 고치기)·D-079(카드 알약·조약돌 배치, 고치기 좌표와 겹치지 않게 조정한 이력).

## O. 검수

- 전시장 상태표: 4단계에서 세 종류를 나란히 `design/style-guide.html`에 둔다(상태가 거의 없어 표는 간단히).
- 하네스: E1이 해결되면 토큰 밖 반경 값 검사(§12)에 이 부품이 걸리는지 확인한다.
- 캡처: 360px, 감정 카드 위 고치기 태그(계열별 대비 확인), 세부 감정 화면의 따로 정함 태그.
