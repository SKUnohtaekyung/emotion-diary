# 토스트

기본 부품 · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건.** 아래에서 "값"은 `web/js/dom.js`(`toast()`)·`web/css/base.css`를 읽고 잰 것이다. 옛 명세(§6.11)의 "토스트는 상단, 4초, 되돌리기 없음"은 시안과 같다 — 값으로 그대로 옮긴다.

## A. 쓰임

- **쓸 때**: 되돌릴 수 없는 동작이 막 끝났음을 짧게 알릴 때(기록 삭제, 글 지우기) — 사용자가 답하지 않아도 되는 **완료 확인**.
- **쓰지 않을 때**: 사용자가 반드시 봐야/답해야 하는 것 → [바텀시트](sheet.md). 조건이 풀릴 때까지 계속 알려야 하는 상태 → [안내 띠](banner.md). 아래 표 참조.
- 삭제 뒤 **되돌리기(실행 취소) 동작을 토스트에 두지 않는다**(UX_SPEC §7) — 삭제는 이미 2단계 확인 시트를 거쳤으므로 토스트는 결과만 알린다.

## B. 구조

- 필수: 글자 한 줄(`role="status"`).
- 선택: 없음 — 아이콘·동작 버튼·닫기 버튼을 두지 않는다(D 참조).
- 한 줄 안에서 가운데 정렬, 길면 자연히 줄바꿈된다(말줄임 없음).

## C. 변형

변형 없음 — 토스트는 한 모양뿐이다. 위험/성공을 색으로 나누지 않는다(모두 `service.ink` 면 + 흰 글자, 뜻은 글 내용이 말한다).

## D. 크기

- 위치: 화면 위쪽 가운데, `top: space.4(16) + env(safe-area-inset-top)`.
- 폭: 내용 맞춤, 최대 `min(440px, 100vw - space.4×2)`.
- 안쪽 여백: 상하 `space.2`(8), 좌우 `space.4`(16).
- 반경: `radius.chip`(999, 알약).
- **동작 버튼을 두지 않으므로 터치 영역 규칙이 따로 없다** — 토스트 자체는 누를 수 없다.

## E. 값(부품 토큰 — 4단계에서 `tokens.json`에 올린다)

| 속성 | 값 |
| --- | --- |
| 면 | `service.ink` |
| 글자 | `neutral.bg`(흰색), `typography.label`(14/20) + `body-strong` 굵기(600) |
| z-index | 코드는 리터럴 `250` — `tokens.json`의 `z.toast`(40)와 연결돼 있지 않다(변수도 쓰지 않는다). O 검수 참조 |

## F. 상태

| 상태 | 값 |
| --- | --- |
| 나타남 | 위에서 8px 내려오며 페이드인(J 참조) |
| 머무름 | **고정 4000ms** — 내용 길이·동작 버튼 유무와 무관하게 항상 같다(동작 버튼이 없으므로 "버튼이 있으면 더 길게" 규칙이 적용될 자리가 없다) |
| 사라짐 | 전환 없이 즉시 제거(J 참조) |
| 겹침 | **최대 1개** — 새 토스트가 오면 이전 토스트를 즉시 없애고 새로 띄운다(대기열 없음, `dom.js` "새 토스트가 오면 앞의 것을 바꾼다") |

## G. 동작

- `toast(text)` 호출 한 번으로 뜨고, 4초 뒤 스스로 사라진다. 사용자가 직접 닫을 수 없다(닫기 버튼 없음).
- 동작 버튼을 두지 않는다(A·UX_SPEC §7) — 삭제 되돌리기·"실행 취소" 같은 2차 동작이 없다.

## H. 배치·묶음

- 화면 위쪽 고정(`position:fixed`), 하단 탐색·시트보다 항상 위에 뜬다(단, z-index가 토큰에 연결되지 않은 리터럴이라 다른 z-index 변경 시 함께 깨질 수 있다 — O 참조).
- 한 번에 하나만 존재한다(F 참조) — 쌓임(스택)이 없다.

## I. 문구

- 한 줄, 완료된 사실만 말한다("쓰던 글을 지웠어요.", "9월 3일 기록을 지웠어요.") — 사과·설명·다음 행동 유도를 더하지 않는다.
- 해요체, 완료형 동사로 끝맺는다.

## J. 움직임

- 나타남: `opacity 0→1` + `translate 0 -8px → 0`(`toast-in`, `motion.duration.base` 200ms).
- 사라짐: **애니메이션 없음** — `setTimeout` 뒤 DOM에서 즉시 제거된다. 나타남·사라짐이 비대칭이다(사라짐에 미리보기 없이 뚝 끊긴다).
- 움직임 줄이기: 나타남 애니메이션도 없음(`base.css:164`).

## K. 접근성

- `role="status"`(암묵적 `aria-live="polite"`, `aria-atomic="true"`) — 스크린리더가 현재 읽는 것을 끊지 않고 차례를 기다려 읽는다(F9, 끼어들지 않는다).
- 닫기·동작 버튼이 없으므로 키보드 조작 대상이 아니다(포커스를 받지 않는다).
- 대비: 흰 글자 on `service.ink` — button.md K의 주 버튼과 같은 조합, WCAG AA 이상.

## L. 화면 폭·기기

- 360~480: 폭이 좁으면 최대폭 계산식이 좌우 여백을 32px(16×2)만 남기고 줄인다.
- 홈 화면 앱: 위쪽 안전 영역(`env(safe-area-inset-top)`)을 비운다.

## M. 장면 위에서

- 오늘 화면(어두운 숲) 위에서도 같은 `service.ink` 면 + 흰 글자를 그대로 쓴다 — 어두운 배경 위에서 ink 면 토스트의 경계가 흐려 보이는지는 **미확인**(실기기·눈 검수 필요, 지금 시안에서 오늘 화면 경로로 토스트가 뜨는 사례를 찾지 못했다).

## N. 하지 말 것·근거

- 삭제 뒤 되돌리기 토스트를 두지 않는다(UX_SPEC §7, button.md G).
- 동작 버튼·닫기 버튼을 더하지 않는다(A).
- 여러 토스트를 쌓지(스택) 않는다 — 새 토스트가 이전 것을 바꾼다.
- 근거: UX_SPEC §7, DESIGN_SYSTEM §6.11.

## O. 검수

- 전시장 상태표: 4단계에서 `design/style-guide.html`에 짧은 글/긴 글(줄바꿈) 두 예시를 둔다.
- 하네스: 토큰 밖 값 검사에 `z-index: 250`(토큰 `z.toast=40`과 불일치, 변수 미사용)을 포함한다.
- 캡처: 360px에서 두 줄로 줄바꿈되는 예시.

## 토스트·안내 띠·시트를 가르는 기준

CHECKLIST §3의 물음("저절로 사라져도 되나 × 반드시 답해야 하나")에 답한다.

| | 저절로 사라지는가 | 답해야 하는가 | 계속 보여야 하는 조건이 있는가 | 쓰는 곳 |
| --- | --- | --- | --- | --- |
| **토스트** | 그렇다(4초 뒤 자동) | 아니다 — 정보 확인용, 무시해도 된다 | 없다 — 한 번 뜨고 끝 | 삭제·지우기 완료 알림 |
| **안내 띠**(banner.md) | 아니다 — 조건이 풀릴 때까지 그대로 있다 | 아니다 — 답하지 않아도 계속 작업할 수 있다(단, 저장 실패는 "다시 시도"로 스스로 해소해야 사라진다) | 있다 — 수정 중·오프라인·저장 실패 같은 **상태**가 유지되는 동안 | 완료 기록 수정 중, 오프라인, 저장 실패, 지난 날 마무리 중 |
| **바텀시트**(sheet.md) | 아니다 — 사용자가 닫아야 사라진다(버튼·바깥·Esc) | **그렇다** — 확정하거나 그만두거나, 둘 중 하나를 골라야 다음으로 간다(단, 바깥·Esc로 "그만두기"를 고른 것과 같은 효과를 낼 수 있다) | 없다 — 한 번의 결정을 위해 뜬다 | 위험 동작 확인, 메뉴, 미입력 안내 |
