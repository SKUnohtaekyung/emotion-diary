# 버튼

기본 부품 · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건**(2026-09-26 D-099로 5건을 위임 판단으로 정함 — 각 항목의 '정함'을 보라). 아래에서 "값"은 시안에서 재서 확인한 것이고, 시안과 옛 명세(§6.1)가 다른 곳은 시안을 기준으로 적고 그 사실을 남겼다.

## A. 쓰임

- **쓸 때**: 지금 화면에서 행동을 시작하거나 확정할 때(다음, 이대로 남길게요, 삭제).
- **쓰지 않을 때**: 다른 화면으로 가는 목록 항목 → [목록 줄](list-row.md). 켜고 끄는 설정 → [스위치](switch.md). 여럿 중 고르기 → 고르기 알약·선택 chip. 아이콘만 있는 동작(뒤로·닫기·⋯) → [아이콘 버튼](icon-button.md).
- **위험 동작**(삭제·완료 취소·지우기)은 버튼 하나로 끝내지 않고 확인 시트를 거친다(UX §7). 확인 시트 안의 확정 버튼이 `danger` 변형이다.

## B. 구조

- 필수: 글자 라벨. 선택: 없음 — 버튼 안에 아이콘을 넣는 곳은 지금 없다. *아이콘+글자 버튼이 필요해지면 이 항목을 채운다.*
- 한 줄 가운데 정렬.

## C. 변형

| 변형 | 쓰는 곳 | 면 / 글자 |
| --- | --- | --- |
| 주(`primary`) | 화면의 다음 행동 하나 | `service.ink` / `neutral.bg` |
| 보조(`secondary`) | 주 버튼과 나란히 있는 다른 길(예: 완료 화면의 '달력 보기') | `neutral.surface-soft` / `service.ink` |
| 글자(`text`) | 덜 중요한 행동(이전, 취소, 나중에) | 없음 / `service.ink` |
| 위험(`danger`) | 확인 시트 안의 삭제 확정에만 | `semantic.danger` / `neutral.bg` |

- 크기 두 단계: 기본 48, **큰 버튼**(`big`) 56 — 작성 흐름의 아래 버튼 줄·완료 화면·시트 안은 큰 버튼.
- 감정 색 면(§3.3) 위에서도 주 버튼은 계열 색이 아니라 ink다(D-054 — 감정 색은 분위기, ink는 행동).
- **결정(D-099) C1 — 한 화면의 주 버튼 수**: 지금은 모든 화면이 1개다. 규칙으로 "주 버튼은 화면에 하나, 시트 안은 시트 기준 하나"를 적을지. *(추천: 적는다 — 세 공개 시스템이 모두 1~2개로 제한하고, 우리 시안은 이미 1개다.)* → **정함(D-099, 위임 판단)**: 적는다 — 주 버튼은 화면에 하나, 시트 안은 시트 기준 하나. 시안이 이미 그렇고 세 공개 시스템 모두 1~2개로 제한한다.

## D. 크기

- 높이: 기본 `min-height 48`, 큰 버튼 `56`. 누르는 영역 = 보이는 크기(44 이상).
- 좌우 안쪽 여백 `space.6`(24). *옛 명세 §6.1은 16이라 적었으나 시안은 24다 — 시안을 기준으로 적는다.*
- 반경 `radius.chip`(999, 알약). *옛 명세 §5는 컨트롤 8이라 적었으나 버튼은 알약이다(D-054 ink 알약).*
- 너비: 버튼 줄(`step-footer`·`done-bar`) 안에서는 칸을 가득 채운다(두 개면 균등 폭, 하나면 전체). 시트 안에서는 가득. 그 밖의 자리에서는 내용 맞춤.

## F. 상태

| 상태 | 값 |
| --- | --- |
| 기본 | 위 E |
| 누름 | §5.1 알약 모양 — 97%로 작아짐, 120ms. 움직임 줄이기에서는 옅은 면(주·위험은 흰색 14%, 보조·글자는 ink 8%) |
| 초점 | `focus` 2px 링, 간격 2px(바탕별 초점 색은 §9). 초록 언덕·노트 장면 위에서는 ink 3px(시안 `notes.css:43`) |
| 비활성 | §5.1 — 바탕에서 만든 색(면 바탕+ink 12%, 글자 바탕+ink 50%). 주 버튼이 못 누르는 상태면 `aria-disabled`로 두고 누르면 같은 자리 안내(§5.1) |
| 로딩(저장 중) | 글자를 "남기는 중…"으로 바꾸고 `aria-disabled`로 다시 누르기를 막는다(`write.js` `saving`). **결정(D-099) F5**: ① 로딩 중 버튼 폭을 그대로 유지할지(글자가 길이만큼 폭이 바뀌지 않게) ② 글자만 바꿀지, 점·막대 같은 표시를 더할지. *(추천: 폭 유지 + 글자만 — 로딩이 짧고(2초 안쪽), 스피너는 쓰지 않는 원칙(INVENTORY §2))*  → **정함(D-099, 위임 판단)**: 폭을 유지하고 글자만 바꾼다("남기는 중…"). 버튼은 누르기 전 폭을 최소 폭으로 잡아 글자 길이로 흔들리지 않게 하고, 스피너·점은 더하지 않는다 — 저장은 2초 안쪽이고 로딩 표현은 스켈레톤 하나로 둔다(INVENTORY §2). |
| 선택 | 해당 없음 — 버튼은 상태를 갖지 않는다. 켜짐/꺼짐은 스위치, 고르기는 알약·chip |
| 오류 | 해당 없음 — 오류는 버튼이 아니라 입력 칸 아래에 알린다(§6.5) |
| hover | **결정(D-099) F2**: 옛 명세는 "hover(데스크톱만)"라 했으나 시안의 버튼에는 hover가 없다(목록 줄·하단 탭에는 있다). *(추천: 두지 않는다 — 손가락 화면 우선이고 누름 반응이 있다. 명세에서 지운다)*  → **정함(D-099, 위임 판단)**: 알약 모양(버튼)에는 hover를 두지 않는다. 손가락 화면에서 hover가 눌린 뒤에도 남는 문제를 피하고 누름 반응으로 충분하다. 줄 모양(목록 줄)과 하단 탭의 hover는 `@media (hover:hover)`에서만 둔다(§5.1). 옛 명세의 'hover(데스크톱만)'는 지운다. |
| 상태가 겹칠 때 | 로딩+누름: 누름 반응 없음(`aria-disabled`). 비활성+누름: 누름 반응 없음, 주 버튼이면 안내만 |

## G. 동작

- 한 번 누르면 한 번 실행. 저장처럼 시간이 걸리는 동작은 끝날 때까지 다시 누르기를 막는다(위 로딩).
- 위험 동작은 확인 시트를 거친다. 확인 시트는 Esc·바깥 누르기로 **아무것도 실행하지 않고 닫힌다**(`sheet.js`) — 확정은 위험 버튼을 눌러야만 일어난다.
- 되돌리기 토스트는 두지 않는다(UX §7, §6.11).

## H. 배치·묶음

- **순서(값)**: 나란히 둘 때 **주 버튼이 오른쪽**(이전 | 다음, 달력 보기 | 통계 보기), 위아래로 쌓을 때 **주 버튼이 위**(시트: 확정 → 취소). 시안 전체가 이미 이 규칙이다.
- 버튼 줄 간격: 나란히 `space.3`(12), 시트 안 세로 `space.1`(4), 시트 본문과의 간격 `space.5`(20).
- 화면 아래 고정 버튼 줄: 좌우 `space.4`, 아래 `space.4` + 안전 영역(`env(safe-area-inset-bottom)`), 앱 열 폭(`content-max-width` 480) 안에 가운데.
- **결정(D-099) H4 — 키보드가 올라올 때**: 작성 흐름의 글 입력 중 아래 버튼 줄을 키보드 위로 따라 올릴지, 가려지게 둘지. *(실기기 확인이 필요한 항목 — TASK-MOBILE 실기기 스파이크와 함께 본다)* → **정함(D-099, 위임 판단)**: 잠정 — 따라 올리지 않는다. 글을 쓰는 동안 아래 버튼 줄이 키보드에 가려져도 되고, 키보드를 내리면 다시 보인다. 따라 올리려면 visualViewport 계산이 필요한데 iOS 홈 화면 앱에서의 동작을 아직 모른다. **실기기 확인**(TASK-MOBILE B-08)에서 입력 칸이 버튼 줄에 가려지는 경우가 나오면 다시 정한다.

## I. 문구

- 해요체, **할 일을 말하는 동사**로 끝낸다("이대로 남길게요", "다음", "지울게요"). 명사만 쓰는 버튼은 탐색성 이동에만("달력 보기", "통계 보기").
- 한 줄에 들어가게 쓴다. **결정(D-099) I2 — 넘칠 때**: 글자 확대 200%에서 두 버튼 줄이 넘치면 ① 두 줄로 줄바꿈 ② 위아래로 쌓기(주 버튼 위) 중 무엇으로 할지. *(추천: ② 위아래로 쌓기 — 순서 규칙(H)을 그대로 쓰고 버튼 글자가 잘리지 않는다)* → **정함(D-099, 위임 판단)**: 위아래로 쌓는다(주 버튼 위) — 순서 규칙(H)을 그대로 쓰고 글자가 잘리지 않는다. 두 버튼의 글자가 한 줄에 들어가지 않을 때만 쌓는다.

## J. 움직임

§5.1의 누름만. 나타남·사라짐 연출은 없다.

## K. 접근성

- `<button type="button">`. 이름은 보이는 글자 그대로(아이콘만 있는 버튼은 [아이콘 버튼](icon-button.md)).
- 비활성은 `disabled` 속성이 아니라 `aria-disabled="true"` — 초점을 받고, 주 버튼이면 누를 때 안내를 준다(§5.1).
- 대비: 주 ink 위 흰 글자, 보조 surface-soft 위 ink 글자 모두 WCAG AA 이상(`check-contrast`).
- 글자 200%에서 높이가 늘어나고 글자가 잘리지 않는다(`min-height`만 쓰고 고정 높이를 쓰지 않는다).

## L. 화면 폭·기기

- 360~480: 버튼 줄은 폭을 가득 쓴다. 480보다 넓은 창에서는 앱 열 폭에 가운데(`flow.css:6`).
- 홈 화면 앱: 아래 버튼 줄이 안전 영역을 비운다(위 H).

## M. 장면 위에서

- 감정 색 면(300) 위: 주 버튼 ink 그대로. 초점 링은 ink 2px(§9).
- 초록 언덕·노트 장면 위: ink 알약만 올린다(`land` 토큰 주석 — 흰 글자·회색 글자 금지). 초점 ink 3px.
- 편지 검토 화면: 버튼 줄 바탕을 불투명 흰색으로 둬 카드가 밑으로 지나가도 글자가 겹치지 않는다(`letter-scene.css:123`).
- 어두운 숲(오늘 화면): 버튼을 두지 않는다 — 시작은 가운데 돌, 이동은 '지난 기록' 알약(§6.11·§6.12).

## N. 하지 말 것·근거

- 감정 색으로 버튼을 칠하지 않는다(D-054, §2-1). 그림자를 주지 않는다(§2-6).
- 위험 버튼을 확인 없이 두지 않는다(UX §7). 되돌리기 토스트를 두지 않는다.
- 근거: D-054(ink 알약), D-078(완료 화면 두 버튼), D-082·D-083(작성 흐름 버튼 줄), D-098(상태).
