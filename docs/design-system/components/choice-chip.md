# 선택 chip

기본 부품 · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건(완료).** 세부 감정 화면(계열마다 화면 하나, §6.3)에서 여러 개를 고르는 pill이다(`.choice`, `web/css/write.css:82-87`). 옛 명세 §6.3이 이미 이 부품을 값까지 정해 둔 몇 안 되는 부품이라 시안과 크게 어긋나지 않는다.

## A. 쓰임

- **쓸 때**: 계열 화면 안에서 그 계열의 세부 감정을 **여러 개** 고를 때뿐이다(`web/js/components/detail.js:23-34`).
- **쓰지 않을 때**: 하나만 고르는 것 → [고르기 알약](radio-pill.md). 이미 고른 것을 보여만 줄 때(누르는 동작 없음) → [표시용 chip](chip.md). 다른 화면으로 이동 → 목록 줄.
- **표시용과의 경계(CHECKLIST §3)**: 이 부품은 `<button aria-pressed>`로 세부 감정 고르기 화면에만 있고, 색 배색도 다르다(아래 E) — 화면 전체가 그 계열 300으로 물든 위에 놓이므로 흰 반투명 면을 쓴다. 고른 결과를 다른 화면(선택 트레이·기록 카드·통계)에 보여줄 때는 이 부품이 아니라 [표시용 chip](chip.md)(fill 100/border 300/text 900)을 쓴다 — 바탕이 흰색이라 배색 자체가 다르다.
- 하나만 고르나 여럿 고르나(CHECKLIST §3): **여럿** 고른다(§6.3, 최소 1개 필요).

## B. 구조

- 필수: 체크 자리(`.ck`, 24px 원) + 글자 라벨. 선택: 없음.
- 여러 chip을 담는 pill 구름(`.cloud`)은 `flex-wrap`으로 가나다순 흐른다.

## C. 변형

변형 없음 — 한 가지 모양뿐이다.

## D. 크기

- `min-height 44`(`var(--touch)`), 좌우 여백 `space.4`(오른쪽 16) `space.2`(왼쪽 8, 체크 자리가 있어 왼쪽은 좁다), 반경 `radius.chip`(999).
- 체크 자리(`.ck`): 24×24 원형, 안쪽 글자(✓) 14px.
- 너비: 내용 맞춤, 줄바꿈 허용(가나다순 pill 구름, 계열당 3~53개).

## E. 값(부품 토큰 — 4단계에서 `tokens.json`에 올린다)

| 속성 | 기본 | 고름 |
| --- | --- | --- |
| 면 | 흰색 74% 반투명(`color-mix(bg 74%, transparent)`, §6.3 "300 위 흰 반투명 알약 72~74%") | `service.ink` |
| 글자 | `service.ink` | `neutral.bg` |
| 안쪽 윤곽선 | 1px `color-mix(ink 18%, transparent)`(선이며 그림자가 아니다) | 없음(면 자체가 경계를 만든다) |
| 체크 자리(`.ck`) 면 | `color-mix(ink 12%, transparent)`, 글자 색 투명(보이지 않음) | `service.mint`, 글자 색 `service.ink`(✓가 보인다) |

## F. 상태

| 상태 | 값 |
| --- | --- |
| 기본 | 위 E |
| 누름 | **시안은 아직 반응이 없다**(`write.css`에 `.choice:active` 없음) — §5.1의 알약 모양 규칙(97%, 120ms)으로 바꾼다. → **시안 반영(2026-09-26)**: 97%로 작아진다(`base.css` 상태 표현 절) |
| 초점 | 전역 규칙(§9)을 따르되 이 부품은 늘 계열 300 면 위에 있으므로 실제로는 항상 **ink 2px**다(`[data-theme-cat]{--focus:var(--service-ink)}`, `base.css:31`). |
| 비활성 | 해당 없음 — 이 부품에 비활성 상태가 없다. 화면 안의 모든 세부 감정은 항상 고를 수 있다(검색으로 줄일 수 없어 다 보인다, D-065 ③). |
| 선택 | ink 면 + 흰 글자 + **민트 체크**(§5.1 "여럿 고르기"에만 체크를 더한다 — 고르기 알약·세그먼트의 "하나 고르기"와 다른 점). 색만으로 전달하지 않는다(면 전환 자체가 형태 변화이고 체크가 더해진다, §2-4). |
| 로딩 | 해당 없음. |
| 상태가 겹칠 때 | 해당 없음(비활성·로딩이 없다). |

## G. 동작

- 누르면 즉시 토글되고(`toggleEmotion`, `state.js:56-62`) 그 계열 조약돌이 바구니로 미끄러져 담기거나 빠진다(장식, `pile.js` — 이 부품의 소유가 아니다).
- 토글마다 `aria-live="polite"`로 "<이름> 선택됨/선택 해제됨, <계열>에서 N개 선택"을 알린다(`detail.js:31`).
- 저장·확인 단계 없음 — 바로 `state.draft.emotions`에 반영된다. 최소 1개를 고르지 않고 다음으로 넘어가려 하면 인라인 오류(`.field-error`)가 뜬다(§6.3, 이 부품이 아니라 화면의 몫).

## H. 배치·묶음

- 가나다순으로 `flex-wrap` 구름을 이룬다(정렬 순서는 화면의 몫, 이 부품은 순서를 정하지 않는다).
- 체크 자리가 왼쪽, 글자가 오른쪽(`.choice{gap:space.2}`, 체크 먼저 오는 순서는 §6.3이 정한 값이다 — 고른 것이 왼쪽에서부터 눈에 띈다).

## I. 문구

- 명사(감정 이름) 하나뿐 — 버튼과 달리 동사로 끝나지 않는다.
- 한 글자~여러 글자까지 다양한 한글 낱말이 그대로 들어간다(줄바꿈은 pill 자체가 아니라 구름의 `flex-wrap`이 맡는다 — pill 하나 안에서 줄바꿈하지 않는다).

## J. 움직임

없음(위 F의 누름 반응 결함 참고). 고를 때 조약돌이 바구니로 담기는 애니메이션은 chip이 아니라 바구니(`pile.js`)의 움직임이다.

## K. 접근성

- `<button aria-pressed>`. 체크 표시(`.ck`)는 `aria-hidden="true"`(장식) — 상태는 `aria-pressed`가 전한다.
- 묶음은 `role="group"` + `aria-label="<계열>의 세부 감정, 여러 개 선택"`(`detail.js:21`).
- 대비: 300 면 위 흰 반투명 pill의 ink 글자, 고른 상태의 ink 면 위 흰 글자 모두 §9가 검사한다(세부 감정 화면의 연한 배경 위 pill 대비 11.2:1 이상).

## L. 화면 폭·기기

- 360~480px에서 pill이 줄바꿈해 넘치지 않는다(가나다순 구름, 계열당 최대 53개까지 스크롤).
- 글자 200%: 미확인 — 긴 세부 감정 이름이 확대 시 pill 안에서 줄바꿈되는지 실기기 확인이 없다.

## M. 장면 위에서

- **이 부품은 항상 감정 300 면 위에만 있다**(세부 감정 화면 전용) — 값(E)이 이미 그 전제로 정해져 있다. 다른 장면(어두운 숲·초록 언덕·편지)에는 나오지 않는다.

## N. 하지 말 것·근거

- 검색·초성 필터를 두지 않는다(D-065 ③).
- 그림자를 주지 않는다(안쪽 윤곽선은 `box-shadow` 문법을 쓰지만 §2-6의 그림자 금지 예외가 아니라 1px 선이다, §6.3 원문).
- 근거: D-059(계열별 화면), D-037(pill 구름이 1열 리스트를 대체), D-071(연한 배경 규칙).

## O. 검수

- 전시장 상태표: 4단계에서 기본·고름 두 상태를 `design/style-guide.html`에 둔다(계열 300 면 배경 안에서).
- 하네스: 4단계에서 §5.1 누름 반응 반영 여부를 검사에 추가한다.
- 캡처: 360px, 계열마다 다른 배경색에서 최소 하나씩.
