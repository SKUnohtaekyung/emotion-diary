# 목록 줄

기본 부품 · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건**(2026-09-26 D-099로 2건을 위임 판단으로 정함 — 각 항목의 '정함'을 보라). 설정 화면(`web/js/views/settings.js`, `web/css/settings.css`)의 `.st-row`가 대상이다. 통계 화면의 `.sxd-day-row`("함께한 날" 줄)는 같은 눌림 결(면+scale)을 흉내 내지만 클래스가 다르고(`.sxd-day-row`) 화살표가 없어(§6.9 "구분선과 ›는 없다") 이 부품에 넣지 않았다 — 참고로만 남긴다.

## A. 쓰임

- **쓸 때**: 설정 목록에서 다른 화면·시트로 가거나(이동 줄), 그 자리에서 즉시 켜고 끄거나(스위치 줄), 설명만 보여줄 때(안내 줄).
- **쓰지 않을 때**: 여러 개 중 하나를 고르는 것 → 고르기 알약(`role=radio`). 감정을 여러 개 고르는 것 → 선택 chip. 화면 맨 위의 큰 진입(나의 기록 공간, `.st-me`) → 이 부품과 결은 같지만 클래스가 다른 별도 요소(56px 돌 그림 포함, 72px)라 이 문서 범위 밖이다.
- 삭제(영구) 전용의 빨간 글자 줄(`.st-delete-row`)은 이 부품의 변형 중 하나로 다룬다(C 참고).

## B. 구조

`web/js/views/settings.js:41-52`(`navRow`/`switchRow`), `web/js/views/settings.js:187-189`(`infoRow`).

- 왼쪽: **아이콘 칸**(40×40, 조약돌 모양 `surface-soft` 면 + 위에 겹친 ink 선 아이콘 22px). 면은 줄마다 `scaleX`/`scaleY`로 뒤집혀 손으로 놓은 느낌을 내고(`settings.css:31-34`, 규칙: 3의 배수째 줄은 좌우 반전, 4n+2째 줄은 상하 반전), 아이콘 자체는 뒤집지 않는다.
- 가운데: **이름**(`.st-row-name`, `flex:1 1 auto`, `min-width:120px`) — 명사구, 본문 굵게.
- 오른쪽: **꼬리**(`.st-row-trail`, `margin-left:auto`) — 지금 값(muted, `aria-hidden`) + 화살표(18px), 또는 스위치, 또는 없음(안내 줄).
- 선택: 이름 아래 설명 두 줄(안내 줄 변형만, `.st-info-body`).
- `flex-wrap:wrap`이라 이름이 길거나 화면이 좁으면 꼬리(값+화살표)가 다음 줄로 내려가 오른쪽에 붙는다(`settings.css:19` 주석 — 큰 글자에서 잘림 없음이 완성 기준).
- 줄 사이 구분선은 아이콘 칸+간격 뒤(왼쪽에서 52px)에서 시작하는 hairline이다(`settings.css:17`) — 아이콘 칸 밑을 지나지 않아 "박스가 아니라 텍스트 열의 경계"로 읽힌다.

## C. 변형

| 변형 | 만드는 함수 | 오른쪽 꼬리 | 전체가 눌리나 |
| --- | --- | --- | --- |
| 이동 줄(nav row) | `navRow` | 값(선택)+화살표 | `<button>`, 줄 전체 |
| 스위치 줄 | `switchRow` | 스위치(또는 "준비 중" 글자) | 아니다 — `<div>`이고 스위치만 별도 `<button role="switch">` |
| 안내 줄(info row) | `infoRow` | 없음(이름 아래 설명 두 줄) | 아니다 — `<div>`, 클릭 불가 |
| 삭제 줄 | 인라인(`settings.js:107`) | 화살표만(아이콘 칸 없음) | `<button>`, 줄 전체, 빨간 글자(`danger`) |

한 화면의 삭제 줄은 하나뿐이고 맨 아래 화면 폭 전체다(§6.16). 이동 줄 수는 제한이 없다(설정 묶음마다 1~2개).

## D. 크기

- 최소 높이 56px(하위 화면), **설정 목록 화면에서는 60px**(`.screen.settings .st-row`, `settings.css:102`).
- 아이콘 칸 40×40, 화살표 18×18, 스위치 트랙 64×36·손잡이 28·누르는 자리 64×44(`tabs.css:56-58`).
- 누르는 영역 = 보이는 줄 전체(높이 56/60, 폭 화면 가득) — 44px 기준을 넉넉히 넘는다.
- 너비: 화면 좌우 여백(`screen`의 `sp-5`)까지 가득.

## F. 상태

| 상태 | 값 |
| --- | --- |
| 기본 | 위 E |
| 누름(설정 목록 화면 안에서만, 아래 참고) | `::after`로 좌우 10px 밖까지 번진 `surface-soft` 면이 나타나고(반경 14px) 줄이 `scale(.985)`로 눌린다(`motion.duration.fast`) — §5.1의 "줄 모양" 규칙과 결이 같다(면+살짝 눌림) |
| hover(데스크톱만, 같은 범위) | 같은 면 60%(`@media (hover:hover)`) |
| 꺼짐(`is-dim`, 예: 알림이 꺼지면 "알림 시각" 줄) | 줄 전체 `opacity:.42`, 화살표에 다시 `opacity:.7`을 얹는다(`settings.css:28-29`) — **§5.1은 투명도가 아니라 바탕에서 만든 색(`color-mix`)을 쓰라고 정했다. 이 줄은 아직 옛 표현(투명도)이다 — §5.1로 바꾼다.** 또한 화살표의 두 번째 `opacity:.7`은 부모의 `.42`와 곱해져(0.42×0.7≈0.29) 오히려 나머지 글자보다 더 흐려진다 — 의도(화살표를 덜 흐리게)와 실제 결과가 반대다(아래 "예상 밖 발견") → **시안 반영(2026-09-26)**: 이름·값·›·아이콘 바탕+ink 50%, 서비스 색 조약돌 면은 중립 회색. 투명도 없음(`settings.css`) |
| 선택 | 해당 없음 — 이 부품에는 켜짐/눌러진 채로 남는 상태가 없다(스위치의 켜짐/꺼짐은 [스위치](switch.md) 몫) |
| 로딩 | 해당 없음 — 목록 줄은 즉시 이동/전환이고 기다리는 동작이 없다 |
| 상태가 겹칠 때 | 꺼짐+누름: 알림 시각 줄은 꺼진 채로도 눌려 알림 화면으로 간다(막지 않는다) — `is-dim`은 시각적 표시일 뿐 `aria-disabled`가 아니다 |

**결정(D-099) F1 — 눌림 반응이 화면마다 다르다**: 누름 면·scale·hover 규칙이 `.screen.settings button.st-row`(설정 **목록** 화면)에만 걸려 있다(`settings.css:106-112`). 하위 화면(`.screen.settings-sub`)에서 같은 `navRow`로 그리는 "시간대" 줄(`settings.js:138`)은 이 선택자에 걸리지 않아 **눌러도 아무 반응이 없다**(면도, scale도, hover도 없음). 눌림 규칙을 모든 하위 화면의 `.st-row`에도 적용할지. *(추천: 적용한다 — 같은 부품이 화면에 따라 다르게 반응하면 "훑어 찾기" 신뢰가 깨진다.)* → **정함(D-099, 위임 판단)**: 넣는다 — 설정 하위 화면의 줄도 목록 화면과 같은 누름 반응(§5.1 줄 모양)을 받는다. 지금은 선택자 범위(`.screen.settings`) 때문에 빠진 결함이다.

## G. 동작

- 이동 줄: 누르면 즉시 그 화면/시트로 간다(저장 확인 없음).
- 스위치 줄: 스위치를 누르면 즉시 적용(그 자리에서 켜짐/꺼짐 다시 그림) — [스위치](switch.md) 참고.
- 삭제 줄: 누르면 삭제 확인 화면(`settings/delete`)으로 이동할 뿐, 그 자리에서 삭제하지 않는다.
- 실패 시 되돌림: 해당 없음(시안은 모두 로컬 상태라 실패 경로가 없다).

**결정(D-099) G1 — 화살표가 "다른 화면" 말고 "시트 열기"에도 쓰인다**: "접근 끊기" 줄(`settings.js:105`)은 값 "로그아웃"과 화살표를 보이지만 눌러도 다른 화면으로 가지 않고 확인 시트가 뜬다(`openAccessSheet`, CHECKLIST §3 목록 줄 질문 "오른쪽 화살표는 '다른 화면으로 간다'만 뜻하나"의 답이 "아니다"). 시트로 여는 줄에도 같은 화살표를 쓸지, 다른 표시(예: 화살표 없이 값만, 또는 다른 아이콘)를 쓸지. *(추천: 같은 화살표를 유지한다 — 사용자에게는 "이 줄을 누르면 다음 단계가 열린다"는 뜻만 전하면 충분하고, 그 다음 단계가 화면인지 시트인지는 규칙을 늘릴 만큼 중요하지 않다.)* → **정함(D-099, 위임 판단)**: 화살표를 유지하고 뜻을 '누르면 다음 화면이나 시트가 열린다'로 정한다. 누르는 즉시 적용되는 줄(스위치)에는 화살표를 두지 않는다.

## H. 배치·묶음

- 여러 줄은 `.st-rows`(세로 flex)로 묶이고, 묶음(`.st-group`)마다 위에 [섹션 머리글](section-header.md)이 붙는다.
- 묶음 사이 간격은 이 부품이 아니라 섹션 머리글·화면 쪽 규칙이다(설정 목록 화면은 폭 전체 12px 옅은 띠, §6.16) — 자세한 값은 [section-header.md](section-header.md) H 참고.
- 화면 하단 고정: 해당 없음(목록 줄은 스크롤되는 본문 안에 있다).

## I. 문구

- 이름은 **명사구**(예: "알림 시각", "개인정보 안내") — 동사로 끝나는 버튼과 다르다.
- 값은 지금 상태를 한 줄로(예: "오후 10시", "기기 시간대 · 서울") — 길면 `flex-wrap`으로 다음 줄에 오른쪽 정렬(잘라내거나 말줄임하지 않는다, `settings.css:19`).
- 안내 줄의 설명은 두 줄까지(자연 줄바꿈, 말줄임 없음).

## J. 움직임

§5.1의 "줄 모양" 누름(면+`scale(.985)`)만 D-list-1의 범위(현재는 설정 목록 화면)에서 재생된다. 나타남·사라짐 연출은 없다. 움직임 줄이기에서는 scale을 끄고 면만 남긴다(`settings.css:112`).

## K. 접근성

- 이동 줄: `<button type="button">`, 접근 가능한 이름은 "이름, 값"(값이 있으면, `settings.js:42`) — 화면에 보이는 값 span은 `aria-hidden`이라 이중으로 읽히지 않는다.
- 스위치 줄: 줄 자체는 `<div>`(초점 없음)이고 스위치만 `role="switch"` + `aria-checked`.
- 안내 줄: `<div>`, 이름·설명이 평문으로 읽힌다(별도 role 없음).
- 삭제 줄: `<button type="button">`, 이름은 보이는 글자 "모든 기록 영구 삭제" 그대로.
- 화살표(`.st-chev`)는 장식이라 별도 `aria-hidden`을 주지 않았다(SVG 자체가 `aria-hidden`, `settings.js:29`) — 확인함.

## L. 화면 폭·기기

- 360~480: 줄 폭 가득, `flex-wrap`으로 좁을 때 값+화살표가 다음 줄로.
- 글자 확대 200%: 이름이 길어지면 `min-width:120px`만 지키고 나머지는 줄어들다 줄바꿈 — 실측은 INVENTORY의 "375 실측: 이름 시작 x 73px·값 끝 x 354px" 참고.
- 홈 화면 앱: 차이 없음(이 부품은 화면 하단 고정이 아니다).

## M. 장면 위에서

해당 없음 — 이 부품은 설정 화면에서만 쓰이고, 설정에는 "친구·장면을 두지 않는다"(§6.16)는 규칙이 있어 감정 색 면·초록 언덕·어두운 숲 위에 놓이지 않는다.

## N. 하지 말 것·근거

- 아이콘 모양을 다른 뜻에 재사용하지 않는다(§6.16 "아이콘은 한 모양 한 뜻").
- 회색 바탕 위 흰 카드 짜임(다른 디자인 시스템에서 흔한 모양)을 쓰지 않는다 — 묶음 구분은 띠(배경 단계)로 한다(D-061 원칙 6).
- 근거: D-091 ④⑤⑥(설정 목록 재구성), D-098(상태 공통 규칙).

## O. 검수
