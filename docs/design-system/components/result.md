# 결과 화면 (완료·내보내기 성공/실패·삭제 완료)

기본 부품 · 틀은 [CHECKLIST.md](../CHECKLIST.md) · 상태 공통 규칙은 [DESIGN_SYSTEM §5.1](../../DESIGN_SYSTEM.md)(D-098) · 측정 기준 시안 `1bfd066`

**상태: 결정 대기 0건**(2026-09-26 D-099로 3건을 위임 판단으로 정함 — 각 항목의 '정함'을 보라). 아래에서 "값"은 `web/js/views/write.js`(`renderDone`)·`web/js/views/settings-data.js`(내보내기 성공/실패·삭제 완료)·`web/css/scene.css`·`web/css/settings-data.css`를 읽고 잰 것이다. INVENTORY가 "여러 곳에 반복되지만 공통 구조가 없다"고 적은 그대로다 — 네 화면 모두 "그림 → 제목 → 설명 → 동작"의 큰 틀은 같지만, 그림 자리·설명 두 단계 순서·버튼 배치 세 가지가 서로 다르게 구현돼 있어 그대로 옮기고 결정 대기로 남겼다.

## A. 쓰임

- **쓸 때**: 어떤 동작(작성 완료, 내보내기, 영구 삭제)이 **끝난 뒤** 그 결과만 보여주는 화면. 되돌릴 수 없는 일(완료·삭제)과 되돌릴 수 있는 일(작성 완료는 이어서 달력·통계로 이동 가능)을 함께 다룬다.
- **쓰지 않을 때**: 아직 끝나지 않은 진행 중 상태 → [로딩·오류·연결 끊김](status-block.md). 계속 확인해야 하는 상태(오프라인·수정 중) → [안내 띠](banner.md). 결과를 확인/거부해야 하는 것(위험 동작 확인) → [바텀시트](sheet.md).
- 네 예시: ① 작성 완료 화면(`write.js` `renderDone`) ② 내보내기 성공(`sd-export-done`) ③ 내보내기 실패(`sd-export-fail`) ④ 영구 삭제 완료(`sd-deleted`).

## B. 구조

공통 뼈대는 **그림/아이콘 → 제목(h1) → 설명(1~2단계) → 동작**이다. 그림 자리만 두 가지로 갈린다.

| | 그림 자리 | 뒤로가기(‹) |
| --- | --- | --- |
| 완료 화면 | **장면**(흰 하늘·색 언덕·흰 길, 그날 고른 친구·조약돌이 선다 — §6.13) | 없음(닫기 ×가 상위 화면에 있다) |
| 내보내기 성공/실패 | **아이콘 배지**(64×64 유기형 면, 체크/경고 선 아이콘) | 있음(`.info-top .back`, 설정으로) |
| 삭제 완료 | **아이콘 배지**(체크, `neutral` 톤 — 좌우 반전으로 변화만 준다) | **없음**(되돌릴 수 없는 일이 끝난 화면이라 뒤로 가면 삭제 확인으로 돌아가는 모순이 생긴다 — `settings-data.js` 주석) |

- **결정(D-099) B1 — 그림 자리를 통일할지**: 완료 화면만 실제 장면(친구·조약돌)을 쓰고 나머지 둘은 중립적 아이콘 배지를 쓴다 — 완료는 "그날 고른 마음"이라는 고유한 내용이 있어 장면이 자연스럽지만, 셋 다 "결과 화면"이라는 같은 부류로 묶는다면 시각 언어가 갈려 보인다. ① 지금처럼 완료만 장면, 나머지는 아이콘 배지로 유지한다(완료는 그날의 기록을 담아 보여줘야 하니 성격이 다르다고 본다) ② 셋 다 아이콘 배지로 통일한다(완료 화면도 장면 대신 배지로 바꾼다 — D-061·D-078의 "친구와 조약돌만 선다"와 부딪힌다) ③ 셋 다 장면으로 확장한다(내보내기·삭제에도 장면을 넣는다 — D-091 "내보내기·삭제·위기에는 은유를 쓰지 않는다"와 부딪힌다). *(추천: ① — ②·③ 모두 이미 결정된 다른 규칙(D-061·D-078, D-091)과 충돌한다. 지금 갈림은 의도된 것으로 보고, 이 문서에 "결과 화면은 두 그림 자리 방식을 함께 쓴다"고 값으로 적어 앞으로 헷갈리지 않게 한다.)* → **정함(D-099, 위임 판단)**: 지금대로 — 완료 화면은 그날 고른 마음(친구·조약돌 장면), 내보내기·삭제는 아이콘 배지. 두 규칙 모두 이미 정해진 결정에서 나온다.

## C. 변형

| 변형 | 그림/아이콘 | 톤 | 버튼 |
| --- | --- | --- | --- |
| 완료(작성 흐름) | 장면(친구+조약돌) | — | 보조 `달력 보기` + 주 `통계 보기`(가로 2단) |
| 내보내기 성공 | 체크 아이콘 배지 | `mint`(28% 섞음) | 주 `설정으로 돌아가기` 1개(세로) |
| 내보내기 실패 | 경고(삼각형+느낌표) 아이콘 배지 | `neutral` | 주 `다시 시도` + 글자 `브라우저에서 열기`(세로) |
| 삭제 완료 | 체크 아이콘 배지 | `neutral`(좌우 반전) | 주 `처음으로` 1개(세로) |

- 경고 아이콘은 삼각형+느낌표를 **ink로만** 그린다 — 빨강을 쓰지 않는다(D-091 ⑤, 설정 결과 화면에는 위기 신호처럼 보이는 빨강을 두지 않는다).

## D. 크기

- 완료 화면: 장면 상자(360:590)가 제목·버튼 줄을 뺀 남은 자리에 통째로 들어온다(§6.13 크기 규칙 그대로).
- 내보내기/삭제: 아이콘 배지 64×64px, 위 `space.2`(8)·아래 `space.4`(16) 여백.
- 버튼: 모두 `button.md`의 `big`(56px) 크기.

## F. 상태

결과 화면 자체는 상태를 갖지 않는다(§5.1 대상 아님 — 화면 전체가 하나의 "완료됨" 상태를 보여준다). 버튼은 button.md F를 그대로 따른다.

## G. 동작

- 화면 진입 시 제목(h1)이 자동으로 초점을 받는다(공통 라우터 동작, `main.js:58` — 결과 화면도 예외 없이 적용된다).
- 완료 화면은 추가로 `announce("기록을 마쳤습니다…")`를 직접 호출해 완료 사실을 스크린리더에 다시 알린다. **내보내기 성공·삭제 완료는 이 추가 announce를 호출하지 않는다** — h1 포커스 이동만으로 알림을 대신한다(불일치, N 참조).
- 시안이라 실제로 저장·삭제·내보내지 않는다(모두 화면 전환만 한다) — 이 사실은 문서화 대상이 아니라 시안의 한계다.

## H. 배치·묶음

버튼 영역이 두 가지 다른 방식으로 구현돼 있다.

| | 배치 | 위치 | 개수 |
| --- | --- | --- | --- |
| 완료 화면(`done-bar`) | **가로 2단 그리드**(`grid-template-columns:1fr 1fr`), `gap:12` | `position:absolute`, 화면 하단에 붙음 | 2개(보조+주, button.md H "나란히 둘 때 주 버튼이 오른쪽") |
| 내보내기/삭제(`sd-actions`) | **세로 스택**(`flex-direction:column`), `gap:8`, 버튼 폭 100% | `position:sticky`, 스크롤 컨테이너 하단에 붙음 | 1~2개(주 하나, 있으면 글자 버튼 하나 더 아래) |

- **결정(D-099) H1 — 버튼 영역을 통일할지**: 완료는 "다음에 어디로 갈지" 두 갈래를 고르는 **선택형**이라 가로 2단이 자연스럽고, 설정 결과는 "이 화면을 벗어나는 길 하나"를 알리는 **진행형**이라 세로 스택이 자연스럽다 — 화면의 성격이 다르다. ① 지금처럼 화면 성격별로 다르게 유지한다(선택형=가로 2단, 진행형=세로 스택) ② 결과 화면은 항상 세로 스택으로 통일한다(완료 화면의 두 버튼도 위아래로 쌓는다) ③ 결과 화면은 항상 가로 2단으로 통일한다(설정 결과가 버튼 1개뿐이면 가로 1단으로 자연히 줄어든다). *(추천: ① — 완료 화면의 두 버튼은 대등한 선택지이고 설정 결과는 순차 진행이라 의미가 다르다. 다만 두 구현이 `position:absolute`/`position:sticky`로 서로 다른 매커니즘을 쓰는 것은 정리할 여지가 있다 — 그건 이 문서가 결정할 시각 규칙이 아니라 구현 정리다.)* | → **정함(D-099, 위임 판단)**: 지금대로 — 대등한 두 선택(완료: 달력|통계)은 나란히, 순서대로 이어지는 행동(내보내기·삭제)은 위아래. 둘 다 버튼 순서 규칙(button.md H)을 따른다.

## I. 문구

- 제목은 짧은 사실 문장("오늘의 마음을 남겼어요", "파일을 만들었어요", "모두 삭제했어요") — 칭찬·과장 없음(§6.13).
- 설명은 두 단계로 나뉜다: **큰 설명**(`.lede`, 대체로 다음에 뭘 할 수 있는지)과 **작은 설명**(`.note`, 파일명·보존 안내 같은 세부 사실).
- **결정(D-099) I1 — 두 설명의 순서**: 내보내기 성공은 note(파일명) → lede(저장 위치 안내) 순인데, 내보내기 실패·삭제 완료는 lede → note 순이다(코드 순서 그대로). ① note(사실/세부) 먼저, lede(안내) 나중으로 통일한다 ② lede(안내) 먼저, note(세부) 나중으로 통일한다(성공 화면만 고친다) ③ 지금처럼 화면마다 자연스러운 순서를 따른다. *(추천: ② — 성공/실패/삭제 셋 중 둘이 이미 "무슨 일이 있었는지 안내 → 세부 사실"순이고, 사람이 먼저 알고 싶은 것은 대체로 상황 설명이다. 성공 화면만 순서를 뒤집는다.)* → **정함(D-099, 위임 판단)**: 큰 설명 먼저로 통일한다(상황 → 세부). 내보내기 성공 화면만 순서를 바꾼다.

## J. 움직임

- `.sd-screen`(내보내기/삭제): 진입 시 260ms 위로 살짝 올라오며 나타난다(`sd-rise`), 움직임 줄이기에서 없음.
- 완료 화면: 친구가 아래에서 차례로 올라옴(§6.13 J, 0.6초+계단식), 이후 은은한 숨쉬기·해 고리 맥박. 움직임 줄이기에서 모두 멈추고 즉시 나타난다.

## K. 접근성

- 제목(h1)이 화면 진입 시 초점을 받는다(공통, G 참조).
- 완료 화면만 `announce()`로 완료 사실을 추가로 읽어준다 — 다른 세 결과 화면은 h1 포커스 이동에만 의존한다(F9 "알림 방식"의 일관성 측면에서 차이가 있다, N 참조).
- 아이콘 배지는 `aria-hidden="true"`(장식) — 뜻은 옆 제목이 맡는다.
- 완료 화면의 친구 그림은 `alt`가 이름+계열("누리, 즐거움 친구"), 조약돌은 장식(§6.13 K).

## L. 화면 폭·기기

- 완료 화면: 장면 상자가 화면 폭·높이 중 좁은 쪽에 맞춰 줄어든다(§6.13).
- 내보내기/삭제: 360~480 폭 가득, 버튼 영역이 스크롤 컨테이너 하단에 sticky로 붙어 본문이 길어져도 항상 보인다.

## M. 장면 위에서

- 완료 화면 자체가 장면(흰 하늘·색 언덕)이다 — 언덕 위 글자는 ink만 쓴다(§6.13 "글자" 항목, button.md M과 같은 원칙).
- 내보내기/삭제는 흰 배경이라 장면별 대체 값이 없다.

## N. 하지 말 것·근거

- 완료 화면에 칭찬·연속 기록·성취 표현을 넣지 않는다(§6.13 "짧은 사실 문장이고 칭찬·성장·연속 기록 표현이 없다").
- 완료 화면에 숫자·누적·점수를 넣지 않는다(친구·조약돌은 그날 고른 것만, D-050).
- 삭제 완료에는 뒤로가기를 두지 않는다(B 참조 — 되돌릴 수 없는 일 뒤에 되돌아갈 길을 보이면 모순이다).
- 설정 결과 화면에 친구·조약돌 그림을 쓰지 않는다(D-091 — 내보내기·삭제·위기에는 은유를 쓰지 않는다).
- 근거: D-061·D-078(완료 화면 구성), D-091 ⑤(내보내기·삭제 흐름), §6.13.

## O. 검수

- 전시장 상태표: 4단계에서 `design/style-guide.html`에 네 변형을 나란히 둔다(H1·I1·B1 결정이 나면 그 모습으로 갱신).
- 하네스: 완료 제목(hero, `clamp()`)과 설정 결과 제목(전역 `h1`, 굵기 800 리터럴+자간 `-.03em`)이 다른 스케일을 쓰는 점, 그리고 전역 `h1`의 굵기(800)가 `typography.display` 토큰(700)과 다른 점을 토큰 밖 값 검사에 남긴다.
- 캡처: 360px에서 네 변형, 완료 화면은 친구 1명/9명 경우 각각.
