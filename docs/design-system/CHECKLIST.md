# 부품 결정 항목 틀

기본 부품 명세(`components/<부품>.md`)가 모두 따르는 틀이다(D-097). 부품 하나를 새 화면에 **똑같이 다시 만들 수 있을 만큼** 정했는지를 이 틀로 판단한다.

- 항목마다 셋 중 하나로 채운다: **값**(토큰 이름·규칙 문장) / **해당 없음 — 이유** / **결정 대기 — 무엇을 누가**. 빈칸은 두지 않는다.
- 값은 우리 토큰 이름(`design/tokens.json`)과 4pt 간격 단계로만 쓴다. 다른 디자인 시스템의 값·문구를 옮기지 않는다(D-039).
- 틀의 항목은 Material Design 3·Apple HIG·IBM Carbon이 부품 문서에서 공통으로 다루는 범주와, TDS 문서 구조에서 관찰한 결정 종류를 교차해 **우리 문장으로** 만들었다. 관찰 기록은 [reference/](reference/)에 있다.
- 장면 부품(숲·언덕·편지·돌)은 이 틀을 따르지 않고 [DESIGN_SYSTEM.md](../DESIGN_SYSTEM.md)의 장면 절이 정한다. 다만 기본 부품이 장면 **위에** 놓일 때 바뀌는 점은 부품 쪽 M항목에 적는다.

## 1. 기초가 먼저 정해 둘 공통 규칙

부품마다 따로 정하면 어긋나는 것들이다. 부품 파일은 이 규칙을 **가리키기만** 하고 다시 정하지 않는다. 정본은 `DESIGN_SYSTEM.md`의 기초 절이다.

| # | 공통 규칙 | 정할 것 |
| --- | --- | --- |
| F1 | 상태 표현 | 누름·선택·초점·비활성·로딩·오류를 모든 부품에서 **같은 방식**으로 보이는 규칙(무엇이 바뀌나: 면·선·크기·투명도). 한 상태에 두 방식을 섞지 않는다 |
| F2 | 초점 표시 | 키보드 초점 링의 굵기·간격·색, 어두운 숲과 감정 색 면 위에서의 대체 색, 대비 3:1 이상 |
| F3 | 누르는 영역 | 보이는 크기와 누르는 영역을 따로 적는 법, 44px 미만으로 보이는 부품의 영역 넓히기 |
| F4 | 움직임 | 시간 단계·곡선, 누름 반응 시간, 움직임 줄이기(`prefers-reduced-motion`)에서 무엇을 끄고 무엇을 남기나 |
| F5 | 아이콘 | 크기 단계, 선 굵기, 선(비활성)/면(활성) 규칙, 출처와 라이선스 |
| F6 | 문구 | 해요체, 버튼은 동사로 끝냄, 길이 상한, 긴 문구 처리(줄바꿈·말줄임·배치 전환) 기본값 |
| F7 | 글자 확대 | 200%에서 가로 넘침 없음, 부품이 배치를 바꾸는 기준 |
| F8 | 화면 가장자리 | 안전 영역, 키보드가 올라올 때, 하단 탐색 위 흐림 띠와의 관계 |
| F9 | 알림 방식 | 스크린리더에 바뀐 것을 알리는 두 방식(끼어들기/차례 기다리기) 중 무엇을 언제 |
| F10 | 부품 층 토큰 | 부품 토큰 이름 짓기(`<부품>.<변형>.<상태>.<속성>`)와 기초 토큰만 참조한다는 규칙 |

## 2. 부품마다 채우는 항목

| 항목 | 정할 것 |
| --- | --- |
| **A. 쓰임** | 언제 쓰나 / 언제 쓰지 않나 / 비슷한 부품과의 경계(대신 무엇을 쓰나) |
| **B. 구조** | 필수 부분과 선택 부분, 영역 나눔(예: 왼쪽·가운데·오른쪽), 부분 사이 간격 |
| **C. 변형** | 위계·종류, 한 화면에 몇 개까지(예: 주 버튼) |
| **D. 크기** | 보이는 높이·폭, 누르는 영역, 너비 방식(내용 맞춤/가득 채움/나란히), 최소·최대 |
| **E. 값** | 상태별 면·글자·선·반경·간격을 부품 토큰으로 |
| **F. 상태** | 기본·누름·초점·비활성·선택·로딩·오류·빈 상태 가운데 이 부품에 있는 것 전부의 상태표. 없는 상태는 "해당 없음 — 이유". **비활성일 때 눌렀을 때의 반응**(무반응/이유 안내)과 **상태가 겹칠 때**(선택+비활성, 로딩+누름)도 적는다 |
| **G. 동작** | 즉시 적용인지 저장해야 하는지, 여는 법·닫는 법, 저절로 사라지는지, 로딩 중 다시 누르기 막기, 실패했을 때 되돌림 |
| **H. 배치·묶음** | 화면 안 위치, 여럿을 묶을 때 순서·간격, 하단 고정일 때 안전 영역·키보드·스크롤 |
| **I. 문구** | 라벨의 형태(동사/명사)·길이, 긴 문구일 때(줄바꿈/말줄임/세로 배치 전환), 도움말·오류 문구 자리 |
| **J. 움직임** | 나타남·사라짐·상태 전환·누름 반응, 움직임 줄이기에서의 대체 |
| **K. 접근성** | 역할(role)과 상태 속성(aria-*), 키보드 조작, 스크린리더가 읽는 문장, 대비, 글자 200% |
| **L. 화면 폭·기기** | 360~480px 폭에서의 변화, 홈 화면 앱(standalone)에서의 차이, 큰 글자 배치 |
| **M. 장면 위에서** | 어두운 숲·감정 색 면·편지 종이 위에 놓일 때 바뀌는 값(이 앱에만 있는 항목) |
| **N. 하지 말 것·근거** | 금지 사항, 관련 결정(D-번호), 참고한 관찰 |
| **O. 검수** | 전시장 상태표 위치, 하네스 검사, 캡처 기준(360px·확대) |

## 3. 부품별로 꼭 물어야 할 질문

2절의 항목만으로는 빠지기 쉬운, 참고 관찰에서 나온 질문이다. 해당 부품 파일의 A·F·G·H 항목에서 답한다.

| 부품 | 질문 |
| --- | --- |
| 버튼 | 한 화면에 주 버튼은 몇 개까지인가 · 위험 동작은 '경고에 답하는 자리'와 '스스로 고르는 자리'에서 강조를 다르게 하나 · 취소·뒤로는 어떤 경우에도 비활성으로 두지 않는가 · 할 수 없는 동작은 비활성으로 두나, 숨기나, 눌렀을 때 이유를 알려 주나 · 로딩 중 버튼 폭을 유지하고 다시 누르기를 막는가 · 두 버튼을 나란히/위아래로 둘 때의 순서 |
| 스위치 | 즉시 적용되는 설정에만 쓰는가(저장이 필요하면 다른 부품) · 적용이 실패하면 스위치를 되돌리고 알리는가 · 라벨·설명 줄을 부품 밖에서 어떻게 조합하나 |
| 선택 알약·chip | 하나만 고르나 여럿 고르나 · 선택을 색 말고 무엇으로도 보이나(형태·아이콘) · 표시용 chip과 누르는 알약의 경계 |
| 목록 줄 | 왼쪽·가운데·오른쪽 영역에 무엇이 올 수 있나 · 한 줄/두 줄일 때 글자 단계 · 오른쪽 화살표는 '다른 화면으로 간다'만 뜻하나 · 줄 전체가 눌리나, 오른쪽 부품만 눌리나 |
| 섹션 머리글 | 제목·보조 설명·오른쪽 동작의 자리, 목록과의 간격 |
| 바텀시트 | 높이 방식(내용 맞춤/고정/끌어 올림) · 닫는 법(바깥 누르기·아래로 끌기·뒤로) · 초점 가두기 · 큰 글자에서 제목이 스크롤에 들어가나 · 한 번에 하나만 |
| 확인 대화상자 | 버튼 하나/둘의 기준 · 바깥을 눌러 닫히나 · 버튼 문구가 길면 위아래로 바뀌나 · 여는 순간 초점이 어디로 가나 |
| 토스트 | 위치 · 머무는 시간(동작 버튼이 있으면 더 길게) · 동작 버튼을 허용하나 · 스크린리더 알림 방식 · **토스트·안내 띠·대화상자 가르는 기준**: 저절로 사라져도 되나 × 반드시 답해야 하나 |
| 하단 고정 버튼 | 안전 영역 여백 · 키보드가 올라오면 따라 올라가나 · 스크롤 중 숨기나 · 나타나는 때 |
| 텍스트 입력 | 라벨은 늘 보이나 · 도움말 자리를 오류 문구가 대신하나(레이아웃이 밀리지 않게) · 글자 수 표시 · 오류를 색 말고 아이콘·문구로도 알리나 |
| 강도 선택 | 값 표시 방식(움직이는 동안/고정 눈금) · 키보드 한 칸 단위 · 증감 버튼의 스크린리더 이름. *이름 주의: TDS에서 'Stepper'는 단계 진행 표시이고 숫자 증감은 다른 부품이다 — 우리는 '증감 버튼'이라 부른다* |
| 진행·로딩 | 진행률을 모를 때→알 때로만 바뀌고 거꾸로 가지 않는가 · 자리 표시(스켈레톤)는 실제 내용의 모양을 닮는가 · 로딩 문구를 읽어 주나 |
| 빈 상태·결과 화면 | 그림 → 제목 → 설명 → 동작의 순서를 고정하나 · 동작 버튼 자리가 내용이 있을 때와 같은가 |
| 하단 탭 | 현재 탭을 색 말고 형태로도 보이나 · 알림 표시를 허용하나 |

## 4. 완료의 뜻

부품 파일은 A~O가 모두 **값 / 해당 없음 — 이유 / 결정 대기** 중 하나로 채워지고, 3절의 해당 질문에 답이 있으면 완료다. "결정 대기"가 남아 있으면 그 부품은 완료가 아니다.
