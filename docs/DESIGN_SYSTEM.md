# 디자인 시스템

## 1. 책임

이 문서는 감정일기 화면의 시각 언어(색·글자·간격·구성요소·상태·접근성)의 정본이다. 화면 흐름과 정보 구조는 [UX_SPEC.md](UX_SPEC.md), 제품 범위는 [../PRD.md](../PRD.md), 색과 캐릭터의 비진단 원칙은 [SAFETY_POLICY.md](SAFETY_POLICY.md)를 따른다. 기계 판독용 값은 [../design/tokens.json](../design/tokens.json)에 있고, 이 문서와 어긋나면 tokens.json을 고친다.

## 2. 원칙

1. **감정을 판정하지 않는 색**: 7개 감정 색은 "찾기 쉽게" 돕는 라벨이지 좋고 나쁨·위험·점수가 아니다. 순위·경고·위험 표현에 감정 색을 쓰지 않는다.
2. **원자료에서 온 색**: 색 계열은 사용자 원자료의 수채 파스텔(연두, 연한 라일락, 하늘, 주황·빨강, 노랑, 분홍, 짙은 남색·보라)에서 왔고, 접근성 대비를 위해 단계(50~900)로 정규화했다. 정규화는 원자료의 밝기 관계를 지켜야 한다 — 바램은 가장 옅고 미움은 가장 짙다(D-034).
3. **흰 배경, 부드러운 강조**: 기본은 흰색/중립 배경이다. 감정 색은 chip·tag·card 테두리·차트에만 쓰고 화면 전체를 물들이지 않는다.
4. **색 외의 단서**: 모든 상태와 차트는 색과 함께 텍스트·아이콘·패턴·수치를 준다.
5. **모바일 우선, 한 손**: 핵심 저장 동작은 하단 안전영역 위, 터치 영역 44px 이상, 본문 16px 이상.
6. **평면, 얇은 선**: 그림자 없이 배경 단계와 1px 선으로 계층을 만든다.
7. **차분한 움직임**: 캐릭터 움직임은 선택 사항이며 `prefers-reduced-motion`을 존중한다.

## 3. 색

### 3.1 중립·의미 색

| 역할 | light | dark | 용도 |
| --- | --- | --- | --- |
| bg | `#FFFFFF` | `#121211` | 화면 배경 |
| surface | `#FAFAF8` | `#1B1B19` | 카드·입력 배경 |
| surface-raised | `#FFFFFF` | `#232320` | 시트·팝오버 |
| border / border-strong | `#E6E4DE` / `#C9C7BF` | `#33322E` / `#4A4842` | 구분선 / 입력 테두리 |
| text / text-muted / text-subtle | `#1F1F1D` / `#5F5E5A` / `#767570` | `#F0EFEA` / `#B5B3AA` / `#8F8E87` | 본문 / 보조 / 힌트 |
| focus | `#2F6FB5` | `#7FB3F0` | 키보드 초점 링(2px) |
| success / warning / danger / info | `#2E7D32` / `#9A5B00` / `#C62828` / `#2F6FB5` | `#7FCB84` / `#F0B54A` / `#F28B82` / `#7FB3F0` | 저장됨 / 주의 / 오류·삭제 / 안내 |

의미 색은 항상 아이콘+문구와 함께 쓴다. 위기 안내는 감정 색이 아니라 중립 배경+`danger` 테두리+명확한 문구로 표시한다.

### 3.2 감정 색 (7계열 × 6단계)

| 계열 | 50 | 100 | 300 | 500 | 700 | 900 |
| --- | --- | --- | --- | --- | --- | --- |
| 즐거움 enjoyment | `#F1F8E6` | `#DCEFC2` | `#A9D67C` | `#5E9C2E` | `#3F7A1C` | `#1F4A0E` |
| 바램 wish | `#F8EFFC` | `#EFDAF7` | `#D5A3E8` | `#A855CE` | `#7B3399` | `#48195C` |
| 슬픔 sadness | `#EAF4FB` | `#CFE6F7` | `#8FC2EA` | `#3F8FD6` | `#245F97` | `#143A5E` |
| 분노 anger | `#FDEEE7` | `#FBD5C4` | `#F5A07E` | `#E8663C` | `#A63F1E` | `#64240F` |
| 기쁨 joy | `#FFF9E0` | `#FDF0B3` | `#F8DE66` | `#E9BE1A` | `#B08A00` | `#5C4904` |
| 사랑 love | `#FDEEF4` | `#FAD3E2` | `#F29CBE` | `#E1609B` | `#A33566` | `#641C3C` |
| 미움 hate | `#ECEEF8` | `#D2D6EE` | `#98A0D4` | `#4750A6` | `#2F3878` | `#1B2049` |

사용 규칙:

- **chip(세부 감정 선택/표시)**: light는 fill 100 + border 300 + text 900, dark는 fill 900 + border 700 + text 100. 텍스트는 반드시 같은 계열의 900(dark: 100)이며 검정·회색을 감정 fill 위에 쓰지 않는다.
- **카테고리 강조(토글, 아이콘 배경, 차트 계열)**: 500(dark: 300). 예외: 기쁨(노랑)은 흰 배경에서 500이 1.77:1로 3:1에 못 미치므로 얇은 테두리·작은 아이콘·차트 선 같은 light 강조에 700 `#B08A00`(3.24:1)을 쓴다(`accent-override`). 글자를 올리지 않는 큰 면(chip fill, 차트 면, 캐릭터 배경)에는 기쁨도 500을 그대로 쓴다. 500/700 위에 텍스트를 올리지 않는다.
- **부드러운 배경(선택된 카테고리 영역)**: 50(dark: 900을 40% 투명도). 그 위 본문은 중립 text 색.
- 두 감정 이상을 한 배경에 섞지 않는다. 복수 감정은 독립 chip/card로 나열한다.
- 같은 표기의 세부 감정이 카테고리마다 있을 수 있으므로(D-022) chip에는 항상 카테고리 색과 카테고리 이름(또는 아이콘)을 함께 보여 준다.

대비: 900 텍스트를 100 fill 위에 올리면 모든 계열에서 WCAG AA 4.5:1 이상이다. 500은 흰 배경에서 큰 글자·아이콘 3:1 기준만 만족하므로 작은 글자에 쓰지 않는다. 검증 스크립트는 §9.

계열 간 분리: 같은 표기의 세부 감정을 카테고리 색으로 구분해야 하므로(D-022), 어떤 두 계열도 같은 자리에 쓰이는 단계에서 서로 구별되어야 한다. 기준은 CIEDE2000 색차 ΔE ≥ 7이며, 현재 최솟값은 chip fill 7.2 / 강조 18.8 / chip 글자 11.3 / dark 강조 13.3이다(모두 바램–미움 쌍). 값을 바꿀 때 이 여유를 줄이지 않는다.

## 4. 글자

- 글꼴: `"Pretendard Variable", Pretendard, -apple-system, "Apple SD Gothic Neo", "Noto Sans KR", "Segoe UI", Roboto, sans-serif`. **MVP는 웹폰트를 싣지 않는다**(D-034). 기기의 시스템 한글 글꼴(iOS Apple SD Gothic Neo, Android Noto Sans KR)로 렌더링되며, 첫 로드 비용과 외부 의존이 없다. 스택이 Pretendard를 먼저 찾으므로 나중에 self-host `@font-face`만 추가하면 토큰 변경 없이 전환된다. 기기별로 자모 모양이 조금 다른 것은 받아들인다.
- 크기 단계(px / 줄 높이 / 굵기): display 28/36/700, title 22/30/700, heading 18/26/600, body 16/24/400, body-strong 16/24/600, label 14/20/500, caption 12/16/400.
- 규칙: 입력 필드 글자 16px 이상(iOS 자동 확대 방지), 본문 한 줄 최대 38자, `word-break: keep-all`, 사용자 글자 확대 200%에서 가로 스크롤 없음. 숫자는 tabular figures.

## 5. 간격·모양·크기

- 간격은 4pt 단위: 4, 8, 12, 16, 20, 24, 32, 40, 48. 화면 좌우 여백 16, 카드 안쪽 16, 섹션 사이 24. 유일하게 허용하는 예외는 **선택된 chip의 좌우 패딩 11**이다 — 테두리가 1px에서 2px로 굵어질 때 chip 폭이 튀지 않게 1px을 되돌린 값이며, 이런 광학 보정 외에는 단계를 벗어나지 않는다(D-036).
- 모서리: 컨트롤 8, 카드 12, 바텀시트 16, chip 999, 차트 막대 4. 이 다섯 값 밖의 반경은 쓰지 않는다.
- 크기: 터치 영역 최소 44×44, 콘텐츠 최대 폭 480, 하단 탐색 56 + 안전영역.
- 계층: 그림자 없음. bg → surface → surface-raised 세 단계와 1px border로 표현. 강조 테두리만 2px.

## 6. 구성요소

각 항목은 "모양 / 상태 / 접근성"을 갖는다. 상태 목록은 UX §11을 만족해야 한다.

### 6.1 버튼

- 종류: primary(text 색 배경+bg 글자), secondary(surface 배경+border-strong), text(배경 없음), danger(삭제 전용, `danger` 색).
- 상태: default, hover(데스크톱만), pressed(scale 0.98 또는 배경 한 단계 어둡게), disabled(불투명도 45%, 커서 기본), loading(스피너+문구 유지).
- 높이 48, 좌우 패딩 16, label 16/600. 화면 하단 고정 저장 버튼은 안전영역 위 16px.
- 위험 동작은 secondary 위치에 두지 않고 별도 확인 단계로 분리한다(UX §7).

### 6.2 카테고리 선택기 (7개 상위 감정) — 아크 휠

D-035의 2줄 격자를 **아크 휠**로 대체한다(D-037). 항목이 7개로 고정이고 단일 선택이라 휠의 규모와 맞는다. 격자보다 세로를 2배 쓰지만 사용자가 이 조작감을 택했다.

- 세로 380, 항목은 오른쪽 기준선에 정렬하고 위아래로 곡선을 그리며 멀어진다. 반지름 460, 항목 사이 7.6°. 이 값에서 7개가 모두 화면에 있고 가운데 5개가 또렷하다(실측).
- 각 항목: 캐릭터 아이콘 48 타일(radius 16, 계열 50 배경) + 이름. 현재 항목은 계열 색 2px 테두리와 알약 라벨로 표시한다.
- **글자 회전은 접선 각도의 45%만 적용한다.** 100%로 돌리면 한글이 옆으로 누워 읽기 어렵다. 흐림은 6° 밖부터 최대 1.6px, 투명도는 `1 - 각도/36`으로 낮춘다.
- 끌어서 넘기고, 놓으면 관성으로 미끄러지다 가까운 항목에 붙는다.
- 접근성: `role="listbox"` + `aria-activedescendant`, 각 항목 `role="option"`과 `aria-selected`. `Tab`으로 포커스, `↑``↓`(`←``→`)로 이동, `Home`/`End`로 양 끝. 값이 바뀌면 `aria-live="polite"`로 "이름, n/7"을 읽는다.
- `prefers-reduced-motion: reduce`이면 회전·흐림·관성을 끄고 세로 목록처럼 동작한다. 휠의 움직임은 장식이 아니라 조작 자체이므로 컨트롤을 없애지 않고 표현만 단순화한다.
- **큰 글자 폴백(구현 필수)**: 반지름이 고정이라 글자를 확대하면 항목이 겹친다. 확대 배율이 커지면 2줄 격자(D-035 규격: 4열 고정, 칸 80, 아이콘 40)로 전환한다. §9의 200% 확대 기준은 이 폴백으로 만족시킨다.

### 6.3 세부 감정 선택기 — 소프트 리스트

세부 감정 **선택**은 chip 격자가 아니라 1열 리스트로 한다(D-037). 한글 감정 단어는 길이가 들쭉날쭉해서("멍한" ↔ "마음이 무거운") chip이나 격자에서는 줄이 어긋난다. 1열은 길이와 무관하게 가지런하고, 목록이 수십 개여도 세로로만 훑으면 된다. chip은 **표시용으로 계속 쓴다**(§6.3.1).

- **검색**(항상 위, 높이 48, radius 999): 부분 일치와 **초성 일치**를 모두 지원한다. `ㅎㅈ` → "허전한". 질의가 전부 초성이면 초성 문자열로, 아니면 공백을 제거한 부분 문자열로 맞춘다(UX §4).
- **선택 트레이**(검색 바로 아래): 고른 감정이 알약으로 쌓이고 각각 해제 버튼(×)을 갖는다. 목록을 스크롤해도 무엇을 골랐는지 항상 보인다. 비어 있으면 "고른 감정이 여기에 쌓입니다"를 회색으로 둔다.
- **행**: 전체 폭, 최소 높이 48, radius 12(카드), 간격 8. 기본은 raised 배경 + 투명 테두리, 선택 시 계열 50 배경 + 300 테두리 + 오른쪽 22px 원형 체크(계열 500 채움). 색만으로 구분하지 않는다.
- **초성 레일**(오른쪽 22px): 현재 목록에 있는 초성만 세로로 나열하고, 누르면 그 그룹으로 스크롤한다. 목록에는 초성 그룹 머리글을 sticky로 둔다. ㄲ·ㄸ·ㅃ·ㅆ·ㅉ는 ㄱ·ㄷ·ㅂ·ㅅ·ㅈ로 합친다.
- `최근 사용` 묶음을 목록 맨 위에 둔다(UX §4).
- 접근성: 목록은 `role="listbox"` + `aria-multiselectable="true"`, 행은 `role="option"`과 `aria-selected`. 스크린리더가 "카테고리, 감정 이름, 선택됨"을 한 단위로 읽도록 `aria-label`을 구성한다.

#### 6.3.1 감정 chip (표시용)

선택이 끝난 감정을 **보여 줄 때**는 chip을 쓴다 — 선택 트레이, 기록 카드(§6.8), 대시보드 범례, AI 감정 후보 제시(§6.10).

- fill 100 / border 300 / text 900. 높이 36, 좌우 12, label 14/500.
- 카테고리 색 점(8px)을 왼쪽에 두어 같은 표기의 감정을 구분한다(D-022).

### 6.4 강도 선택기 (1~10)

- **슬라이더 + 항상 보이는 숫자 + −/+ 스테퍼**로 한다(D-037). D-036의 2줄 세그먼트를 대체한다. 세부 감정마다 선택기가 하나씩 붙으므로 세로가 중요한데, 감정 3개 기준 세그먼트 536px → 슬라이더 380px로 **156px 줄어든다**(실측).
- 구성: `−` 44 원형 버튼 / 트랙 / `+` 44 원형 버튼, 오른쪽 위에 현재 값(18/700, tabular). 트랙 높이 10 radius 999, 채움은 계열 강조 색, 손잡이 30 원형(계열 색 2px 테두리, 배경 raised). 트랙 위 10개 점으로 눈금을 두어 값이 연속이 아니라 1~10 정수임을 보인다 — 채워진 구간의 점은 숨긴다.
- **스테퍼는 생략하지 않는다.** 320px 화면에서 한 단계가 약 30px이라 손가락으로 6과 7을 가려 짚기 어렵다. 스테퍼가 44 목표를 주고, 숫자 입력창이 아니라서 키보드가 올라오지 않는다. 스테퍼가 있으므로 "슬라이더만 제공" 금지(§11)에 걸리지 않는다.
- 애니메이션: 스테퍼로 바꿀 때만 손잡이와 채움에 전환을 건다(0.32s spring). **끌 때는 전환을 끈다** — 손잡이가 손가락을 못 따라와 조작감이 나빠진다.
- 앵커 문구는 **한 줄만** 둔다(D-036). 세부 감정마다 선택기가 하나씩 나오므로 3줄을 항상 띄우면 같은 문구가 화면에 반복된다.
  - 선택 전: `1 거의 스쳐 지나감 → 10 일상에 큰 영향` 한 줄(caption).
  - 선택 후: 고른 값이 속한 구간의 문구 한 줄. 1~3 "거의 스쳐 지나간 감정", 4~7 "분명히 느껴졌고 하루에 영향을 준 감정", 8~10 "매우 커서 일상 행동에 큰 영향을 준 감정". 구간 경계는 앵커 1·5·10과 어긋나지 않는다.
  - 이 문구는 `aria-describedby`로 선택기와 연결해 스크린리더가 값과 함께 읽게 한다.
- 채움과 손잡이는 해당 감정 계열의 **강조 색**(500, 기쁨은 700)을 쓴다. 채움의 *길이*가 강도를 나타내는 것은 허용하지만, 계열 안의 **색 단계(300/500/700)를 바꿔 강도를 표현하지 않는다**(색=감정, 숫자·길이=강도). §11 참조.
- 접근성: native `<input type="range">`를 실제 컨트롤로 쓰고 그 위에 시각 요소를 얹는다. 화살표 키 조작과 값 읽기가 기본으로 따라온다. `aria-label`은 "<감정> 강도, 10점 만점", 앵커 문구는 `aria-describedby`로 연결한다.

### 6.5 텍스트 입력 (사건, 이유, 칭찬·감사 슬롯)

- 배경 surface, border 1px, 초점 시 focus 2px. 글자 16. 자동 높이 조절 textarea.
- 칭찬·감사 슬롯은 항상 3칸, 자리표시자 "칭찬 1", "칭찬 2", "칭찬 3". 빈 슬롯에 오류를 표시하지 않는다(UX §6).
- 필수 필드 누락은 완료 시점에만 표시하고, 오류 문구는 필드 바로 아래 caption + `aria-describedby`.

### 6.6 자동 저장 상태

- 화면 상단 고정 줄 또는 저장 버튼 옆 caption: "저장 중…"(info 아이콘), "저장됨 · 방금"(success), "저장 실패 · 다시 시도"(danger, 버튼). 입력을 지우지 않는다.
- revision 충돌은 시트로 두 버전을 나란히 보여 주고 선택하게 한다.

### 6.7 달력 날짜 셀

- 상태: 없음(빈 셀), draft(점선 테두리+연필 아이콘), completed(채워진 점+체크), 오늘(text 색 2px 테두리), 미래(비활성, 선택 불가).
- 색만으로 구분하지 않고 아이콘/텍스트를 함께 둔다. 셀 44×44 이상.
- 7열은 **고정 폭이 아니라 `1fr`**, 열 간격 0, 줄 간격 4으로 둔다(D-036). 360px 화면에서 44px 고정 셀에 열 간격까지 주면 7열이 가로로 넘친다. `1fr`이면 셀이 45.7×44로 터치 최소를 넘기면서 가로 스크롤이 생기지 않는다(실측). 셀 사이 구분은 간격이 아니라 각 셀의 1px 테두리가 맡는다.

### 6.8 기록 카드 (상세·목록)

- 카드 12 radius, surface 배경, border 1px. 원형 순서 유지: 날짜 → 사건 → 감정 chip들(각각 "이름 · 강도 7") → 이유 → 칭찬 → 감사.
- 수정 중인 완료 기록은 상단에 "완료된 기록을 수정 중" 배지(중립 색).

### 6.9 대시보드 카드·차트

- 통계 카드: label(muted 14) + 숫자(title 22, tabular) + 분모/기간 caption. 기록이 적으면 "기록이 더 필요함" 문구.
- 차트 계열 색은 감정 500(dark 300). 세부 감정 빈도는 가로 막대, 추세는 선. 기록 없는 날은 선을 끊고 빈 값으로 표시한다(0이 아님).
- 범례는 색 사각형+이름+값. 색 외에 패턴 또는 값 라벨을 함께 둔다.

### 6.10 AI 대화·분석 표시 (후행 단계)

- AI 말풍선은 중립 surface, 사용자 말풍선은 text 색 배경. 감정 후보는 §6.3 chip으로 제시하고 "다른 표현도 괜찮아요" 문구를 붙인다.
- 상태: "생각 중"(스피너+최대 20초 안내), 응답 불가(직접 작성으로 계속 버튼), 보류(withheld: 이유와 통계만), stale(회색 배지 "최신 아님").
- 분석 카드는 관찰 / 가능한 해석 / 한계 / 성찰 질문 / 근거를 소제목으로 분리한다. 점수·병명·성격 라벨처럼 보이는 UI를 만들지 않는다.
- 위기 안내: 중립 배경 + `danger` 2px 테두리 + 제목 "지금 안전이 먼저예요" + 한국 기준 연락처 + "직접 작성으로 계속"·"저장하고 나가기" 버튼. 캐릭터·애니메이션 없음.

### 6.11 내비게이션·시트·토스트

- 하단 탐색 4개(**오늘·달력·통계·설정**, D-035), 아이콘+라벨, 현재 항목은 text 색+굵기. 높이 56+안전영역. 아이콘은 **비활성 선(outline) / 활성 면(filled)** 으로 상태를 형태로도 구분한다 — 색과 굵기만으로 현재 탭을 표시하지 않는다. 각 탭 이름이 그 화면에 무엇이 있는지 그대로 말하게 한다 — 이전 이름 "기록"과 "돌아보기"는 둘 다 과거를 가리켜 구분되지 않았다.
- 바텀시트 radius 16, 손잡이, 배경 dim 40%. 열릴 때 초점을 시트로 이동하고 닫히면 원래 위치로 복귀.
- 토스트는 상단, 4초, 삭제 후 되돌리기 토스트는 제공하지 않는다(UX §7).

## 7. 브랜드

- 앱 이름은 **감정일기**이며 홈 화면 제목과 온보딩에 그대로 쓴다. **로고·워드마크는 만들지 않는다**(D-036). 1인용 도구에 브랜드 자산은 과잉이고, 유지할 자산이 하나 늘어난다.
- PWA 아이콘처럼 정사각 이미지가 꼭 필요해지면 캐릭터 자산(§8) 중 하나를 쓰고 새로 그리지 않는다.

## 8. 캐릭터

- 원자료의 캐릭터(흰 공룡, 고양이들)는 카테고리 식별 보조다. 카테고리 토글과 기록 카드의 카테고리 표시에만 쓰고, 강도·평가·위기 화면에는 쓰지 않는다.
- 각 캐릭터에 `alt`(예: "즐거움 캐릭터")를 두고, 이미지 없이도 이름만으로 동작해야 한다.
- 원본 이미지를 그대로 자르지 않고, **원자료와 같은 손그림 수채 무드로 다시 생성한** 자산을 `design/characters/`에 versioned로 둔다(D-035). 생성기는 codex imagegen이고 프롬프트 정본은 `design/characters/prompts.json`이다. 7종은 같은 공통 프롬프트와 seed로 **한 번에** 만든다.
- 규격: 생성 원본 1024×1024(`src/<key>-1024.png`), 앱이 쓰는 파일 120×120(`<key>.png`), 둘 다 투명 배경 PNG. 화면에는 40px로 표시한다. 수채 질감은 24px에서 뭉개지므로 그보다 작은 자리에는 아이콘 대신 8px 카테고리 색 점을 쓴다.
- `node scripts/check-characters.mjs`가 파일 유무·크기·투명 배경을 검사한다(quick 하네스). 자산 미제작이면 pending으로 통과한다. 눈으로 볼 검수 항목은 `design/characters/README.md` §3.
- 자산 제작은 taxonomy v1 검수와 함께 진행한다.

## 9. 접근성 검증

- 대비: 본문 4.5:1, 큰 글자·아이콘 3:1. `node scripts/check-contrast.mjs`가 tokens.json의 chip 조합(100 위 900, dark 900 위 100)과 중립 조합을 계산해 실패 시 종료 코드 1을 반환한다. quick 하네스가 이 스크립트를 실행한다.
- 키보드: 모든 chip·토글·강도 값은 Tab/화살표로 도달, 초점 링 2px `focus` 색.
- 스크린리더: 감정 chip은 "카테고리, 이름, 선택됨/선택 안 됨", 강도는 "강도 7, 10점 만점" 형태로 읽힌다.
- 확대: 200% 글자 확대와 360px 폭에서 핵심 흐름에 가로 스크롤·가림이 없다.
- 움직임: `prefers-reduced-motion: reduce`이면 캐릭터 애니메이션을 끄고 전환은 opacity만 남긴다.

## 10. 다크 모드

**MVP는 light 전용이다**(D-034). dark 토큰은 정의를 유지하고 §9 대비 검사도 두 모드를 계속 검사하지만, 제품 화면에는 적용하지 않는다. 검증할 화면이 절반이라 릴리스가 빨라지고, 토큰이 살아 있어 나중 적용 비용도 낮다.

나중에 적용할 때의 규칙: 시스템 설정만 따르고(`prefers-color-scheme`) 앱 안에 수동 토글을 두지 않는다(설정 항목과 저장할 상태가 늘어 PRD 범위를 벗어난다). 감정 chip은 fill 900 / border 700 / text 100으로 뒤집고 차트 계열은 300을 쓴다. 적용 시점에 모든 구성요소를 dark에서 다시 확인해야 한다.

## 11. 하지 않는 것

- 감정 색으로 위험·경고·순위를 표현하기
- 감정 계열의 색 단계(300/500/700)를 바꿔 강도를 표현하기 — 슬라이더 채움의 *길이*로 나타내는 것은 허용한다(§6.4)
- 두 감정 색을 한 배경에 섞기
- 감정 fill 위에 검정/회색 글자 올리기
- 그림자·그라데이션·장식 텍스처
- 슬라이더만 있는 강도 입력(숫자와 −/+ 스테퍼를 반드시 함께 둔다)
- 위기 화면에 캐릭터·애니메이션·감정 색 사용

## 12. 변경 규칙

색·글자·간격 값을 바꾸면 `design/tokens.json`, 이 문서, `design/style-guide.html`을 같은 변경에서 고치고 대비 검사와 §3.2 계열 분리(ΔE) 확인을 다시 실행한다. 감정 계열의 의미(어떤 색이 어떤 카테고리인지)는 원자료를 따르므로 사용자 승인 없이 바꾸지 않는다(PR-010, D-033).
