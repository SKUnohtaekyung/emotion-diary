## 2. 확정된 것

- **제품**: 원형 일기 6영역(날짜·사건·감정+강도·이유·칭찬 3·감사 3), 9개 상위 감정과 세부 감정 194개(taxonomy v2, D-038), 원자료 전사본 v1의 보존, 복수 감정과 각 1~10 강도, 하루 1개·그날만 작성(D-082가 소급 작성 허용을 대체)·streak, 결정론적 대시보드(친구와의 친밀도·계열별 평균, D-064·D-086), 비진단 원칙.
- **배포(D-032, 호스팅은 D-111이 교정)**: 직접 작성한 백엔드를 무료 클라우드에 올린다 — **Cloudflare Worker 하나가 앱 화면(정적 파일)과 `/api/*`를 같은 주소에서 내고**(유일한 진입점) DB는 D1(SQLite 호환)이다. 모바일은 설치형 홈 화면 웹앱이다(service worker·오프라인 없음). 스파이크 판정도 이 구성에서 나왔다. 처음 계획했던 분리 구성(화면은 Pages, API는 Workers)은 검증한 적이 없고 채택하지 않는다 — iPhone에서 안 된다는 것은 규격에서 끌어낸 판단이다. 정본 본문은 2026-10-14 TASK-MOBILE T2에서 이 구성으로 고쳐 썼다. 쓰는 사람은 일단 본인 1명이다(D-108).
- **로그인·잠금·입구 화면(D-112, 2026-10-14)**: 로그인은 접근 열쇠로 받는 cookie 하나이고 마지막으로 쓴 날부터 30일 유지된다(틀린 열쇠는 D1 전역 잠금 — 60초에 10번 → 5분. 잠긴 동안 맞는 열쇠까지 막는 구조는 `data-foundation`에서 고친다 — RK-041). 풀리면 '다시 들어와 주세요' 뒤 있던 화면으로 돌아간다. 앱 잠금 비밀번호(D-106)는 서버가 확인한다. 첫 버전의 입구는 접근 열쇠 화면 + 부를 이름 + 반가워요이고 시안의 소셜 로그인·동의·탈퇴는 넣지 않는다. 모든 기록 지우기는 확인 문구에 더해 잠금을 켠 경우 비밀번호를 묻고, 기록과 부를 이름·앱 잠금 설정까지 전부 지운다. 접근 열쇠는 암호 보관함에 저장할 수 있게 하고, 열쇠로 방금 들어온 직후에는 잠금 비밀번호를 묻지 않는다. 계속 쓰는 동안 로그인의 끝나는 날은 없다. 화면에서 접근 열쇠는 '열쇠', 앱 잠금은 '비밀번호'라 부른다. 설치하지 않고 Safari·PC로 들어와도 쓸 수 있다. Cloudflare Access는 첫 버전에서 쓰지 않는다(D-108). 로그아웃과 잠금을 서버에서 지키려고 서버가 세션마다 기록을 둔다(스파이크는 서명만 썼다 — 이번에 더한 설계, DATA_MODEL §3.10).

## 6. 알려진 제한

- 앱 코드는 뼈대뿐이다(2026-10-14, `app/` — 로그인·세션·앱 잠금·부를 이름·화면 이동, 화면은 기능 확인용 최소 모양). 일기 저장은 서버 쪽만 있다(2026-10-15 `data-foundation` — 오늘·조회·임시저장·완료·지우기, 화면은 `first-slice`). 달력·통계는 없다(Phase 2·4). `web/`은 눌러 보는 화면 시안일 뿐 저장·인증·API가 없고, Phase 2에서 구조만 옮기고 코드는 버린다(D-047). 스파이크 코드는 `work/`(비추적)에 있다.
- 개발용 건물 `emotion-diary-dev`(Worker·D1, 가짜 데이터만)가 있다(2026-10-14, 사용자 확인 U-2). 운영 건물은 없다. 개발용 열쇠는 2026-10-14에 긴 열쇠로 바꿨고 이름·로그인 기록은 비웠다.
- 스파이크 자원(Workers·D1)에는 합성 데이터만 넣었고 2026-10-14 검증 뒤 비웠다가, 같은 날 12시간 로그인 확인(연습용 PASS)을 본 뒤 사용자 결정으로 Worker와 D1을 지웠다 — 휴대폰의 '일기 연습' 아이콘은 더 열리지 않는다. 실제 앱은 별도 Worker로 배포한다(개발용 `emotion-diary-dev`, 운영은 본인 사용 시작 전 — D-117).
- 스파이크 판정은 본인 1명 전제이고 Worker 하나 구성에서 나왔다(D-108, §3). Cloudflare Access는 문서로만 판정했고 켜 보지 않았다. Android·Pages 분리 구성·다중 사용자는 확인하지 않았다.
- 검증 하네스 `full`은 2026-10-14부터 앱의 lint·typecheck·test(서버 시험은 Node + 로컬 D1, 화면 시험은 happy-dom)·build를 함께 돈다. 서버 시험은 Workers 런타임 안이 아니라 Node에서 돈다 — 런타임 차이는 개발용 건물 원격 검사가 메운다(ARCHITECTURE §11.8). CI는 2026-10-15 PR #37에서 처음 앱 코드를 돌렸다(§1 숫자 표).
- 기계적 강제(커밋 확인, 소유 파일 확인 — 동시 작업 때만 켬(D-119), Stop 검증)는 Claude Code 세션에만 걸려 있다. Codex 세션에 걸리는 장치는 CI뿐이다(AGENTS 서두, §2.3).
