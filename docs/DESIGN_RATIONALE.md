# 디자인·브랜드 선택의 근거

## 1. 읽는 법

이 문서는 "무엇을 골랐나"가 아니라 **"왜 골랐나"**를 남긴다. 결정 자체는 [DECISIONS.md](DECISIONS.md)(D-050·D-052~D-058·D-061~D-072), 스토리는 [BRAND_STORY.md](BRAND_STORY.md), 값과 규칙은 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)에 있다. 2026-09-21 사용자와 나눈 질의응답(§3.1~§3.9)과 2026-09-21~22 무드 v4 시안 검토(§3.10)를 바탕으로 한다. §3.1~§3.9는 당시 근거를 이력으로 남기며, D-061~D-067이 대체·수정한 절에는 첫머리에 표지를 달았다.

각 항목은 같은 틀로 적는다: **결정 → 사용자의 이유 → 근거와 상태 → 검토했지만 고르지 않은 것 → 되돌리는 조건**. 누가 정했는지를 구분한다.

| 표시 | 뜻 |
| --- | --- |
| 사용자 결정 | 사용자가 골랐거나 지시한 것 |
| 사용자 위임 | 사용자가 "생각해 봐"라며 판단을 맡긴 것. 에이전트의 판단이므로 이유를 적었고 언제든 뒤집을 수 있다 |
| 에이전트 제안 | 에이전트가 낸 안을 사용자가 받아들인 것 |
| 측정 | 저장소의 값이나 자산으로 직접 잰 것(§6) |

근거의 등급은 BRAND_STORY §9와 같다 — **제품 원칙 / 측정 / 사용자 제공 요약 / 해석·디자인 판단**. 원문을 이번에 확인하지 않은 학술 주장은 해석으로만 다룬다.

## 2. 이 방향에 이른 흐름

### 사용자가 정리한 다섯 가지 이유

1. **오늘 화면이 너무 비어 있고, 캐릭터가 가지런히 줄 서 있어서** "내 노트"·"나만의 세계" 느낌이 없다고 느꼈다.
2. **감정 색과 서비스 색이 섞이면** 서비스가 감정을 평가하는 것처럼 보일 수 있다. 그래서 감정 색은 감정용, 숲색·민트는 서비스 구조용으로 나눴다.
3. **반딧불이 안내자**는 예쁘지만 앱이 사용자의 감정을 이해하는 척하는 AI의 얼굴이 될 위험이 있었다. 그래서 "나를 이끄는 캐릭터"보다 "내가 켜는 빛"으로 중심을 옮겼다.
4. **플랫하고 어린 시절 같은 시각 언어**를 원하는 이유는 유아용으로 보이려는 것이 아니라, 감정을 설명하거나 교정하기 전에 먼저 **있는 그대로 표현하자는 태도** 때문이다.
5. **조약돌**은 감정을 모아 성취하는 물건이 아니라 "오늘 있었던 마음이 사라지지 않고 남아 있다"는 **흔적**이다. 그래서 빛·숲·조약돌은 각각 행복·자유·기록의 은유로 이어졌다.

## 3. 결정별 근거

### 3.1 감정 색이 화면을 물들인다 — 세 화면에서만 (D-053)

> → D-061~D-067·D-071이 대체·수정(아래는 당시 근거). 계열 고르기는 별자리 지도 대신 친구 아홉(D-061 ②), 검토·기록 상세는 편지 카드(D-063), 완료는 초록 언덕과 그날 고른 친구(D-061 ④)가 됐다. 구현(`web/`) 기준으로 감정 색이 화면을 넓게 물들이는 곳은 세부 감정 화면(배경은 계열 100·50을 섞은 연한 면, pill은 300을 흰색에 섞은 색 — D-071이 아래의 '300 하나'를 이 화면에서 바꿨다, §3.10.12)과 편지의 감정 카드(계열 300 면, 그대로)다 — 정본은 DESIGN_SYSTEM §3.3. ink 주 버튼·비판정 원칙(PR-010)은 그대로다.

- **결정** (사용자 결정): 세 번째 무드 글의 "감정을 고르면 배경·캐릭터가 그 감정 색으로 바뀐다"를 받아들이되, 감정 고르기(계열·세부·강도)·완료·기록 상세에만 적용한다. 주 버튼은 서비스 ink. 직접 작성·통계·달력·설정·위기 안내는 제외. **면의 진하기는 계열 300**(아래 "진하기" 항목), **계열 선택은 별자리 지도를 유지하고 위쪽에 큰 친구 영역**을 둔다(사용자 결정).
- **이유**: 무드 글의 의도 — 귀여운 캐릭터가 있는 감정 앱이 아니라 **감정에 따라 앱의 환경이 바뀌는 제품**. 캐릭터가 화면의 큰 비중을 차지하는 포스터형 입구.
- **충돌하는 기존 규칙과 처리**: D-033·DESIGN_SYSTEM §2.3의 "화면 전체를 물들이지 않는다", PRD §6.3 둘째 줄의 "부드러운 강조·태그·카드", 사용자 자신의 분석 2("감정색=감정용"). 사용자가 명시적으로 번복했고 PRD 수정도 승인했다("최소 수정으로 고친다"). PRD의 "복수 감정은 배경색 혼합보다 독립 label/card"는 그대로 지켜진다.
- **측정**: 글 3의 "버튼 700 + 흰 글자"는 기쁨(노랑)이 3.2:1로 기준 4.5에 못 미친다(나머지 8계열 통과). 그래서 버튼은 서비스 ink(흰 글자 16.4:1)로 했다. 글 3의 서술은 배경 50이었고 처음에는 그대로 따랐다(50 위 중립 글자 14.3~15.6:1). 최종 300에서 중립 글자는 6.54~12.29:1, ink 글자는 6.48~12.19:1이며 흰 글자는 300 위 9계열 모두 3:1 미달이다.
- **여러 감정의 화면 비율** (사용자 위임 → 에이전트 판단): 사용자는 처음 "먼저 고른 순서대로 화면의 비율을 먹게"라고 했고, 확인 질문에서 "심리학적으로 안정감 있고 정답에 가까운 것을 생각해"라며 맡겼다. **같은 크기**로 정했다. 이유 — ① 넓은 면은 더 중요하게 읽힌다(일반적인 시각 위계 원리이며 이 저장소에서 별도 문헌을 확인하지는 않았다). ② 고른 순서는 저장하지 않는다(D-041)라 저장 뒤 기록 상세에서 같은 화면을 다시 그릴 수 없다. ③ 색이 강도·순위를 뜻하지 않는다(PR-010). ④ PRD §6.3의 독립 카드 원칙.
- **면의 진하기 — 레퍼런스와의 비교** (사용자 결정 "b." = 계열 300): 사용자가 참고 이미지 3장을 다시 보내며 "이런 스타일을 하려는 것 아니냐"고 물었다. 에이전트가 읽은 공통점은 큰 색 면·초대형 굵은 제목(화면의 약 30%)·큰 마스코트(40~50%)·큰 pill이고, 솔직히 당시의 계열 50 면은 그보다 훨씬 얌전했다. 같은 슬픔 화면을 50·300·500으로 나란히 그려 비교했다 — 명도 차 4·22·41, 500 위 흰 큰 글자(3:1)는 8/9계열 통과(기쁨 1.8:1은 ink), 500 위 ink 본문(4.5:1)은 7/9(희망·미움 미달), 300 위 흰 글자는 0/9·ink는 9/9. 사용자가 300을 골랐다. 500은 명도 차 41(기쁨 L* 79 ↔ 미움 38)이라 밝기가 좋고 나쁨으로 읽힐 위험(PR-010)과 작은 글자·목록 화면의 가독성 때문에 채택하지 않았다. 에이전트의 권고는 "입구·출구만 500, 작업 화면은 50"이었으나 사용자가 다르게 골랐다. 새 위험: 300에서는 몸 색이 면과 비슷한 친구(설이·누리·숨이)가 묻힐 수 있어 친구 뒤 밝은 유기형 면으로 분리한다.
- **에이전트 과정 오류**: 이 개편 중 하위 에이전트에게 "판단이 필요한 곳은 더 조용한 쪽으로"라고 지시했다. 목표 스타일(대담한 포스터형)과 어긋나 "조용함은 직접 작성 화면에만"으로 정정했다.
- **고르지 않은 것**: 가장 먼저 고른 감정의 테마(순서가 곧 중요도로 읽힘), 가장 강한 감정의 테마(강도 순위 — PR-010 위반), 여러 개면 흰색(테마의 맛이 약해짐), 글 3 그대로(기쁨 버튼 미달·계열마다 규칙이 달라짐).
- **되돌리는 조건**: 고른 순서를 저장하게 되고 우열 없는 표현 방법이 생겼을 때. 사용자 눈 검수에서 패널 구성이 답답하거나 "판정"처럼 읽힐 때.
- **등급**: 제품 원칙 + 측정 + 에이전트 판단.

### 3.2 서비스 색: ink · 민트 · 크림빛 (D-054)

> → D-062·D-063이 일부 수정(아래는 당시 근거). 빛의 색이 크림빛에서 흰색으로 바뀌었고(§3.3 표지), 크림빛은 지금 편지의 칭찬·감사 카드와 안내 배너에 쓰이며 오늘 화면에는 쓰지 않는다. 세 서비스 색의 값과 ΔE 근거는 그대로 유효하다.

- **결정** (사용자 결정): 강조색을 라임 `#C8F75A`에서 민트 `#62FDB4`로 바꾼다. 사용 범위는 주 버튼 채움(ink), 현재 위치·오늘 표시(mint), 달력 기록 상태(ink 단계·모양). 큰 제목 글자색은 ink로 바꾸지 않는다(선택하지 않음).
- **이유**: 서비스 색이 감정 색으로 읽히면 "서비스가 감정을 말한다"가 된다(사용자 분석 2). 라임은 즐거움 그림(시트 몸 `#D0ED56`, 조약돌 `#C4EE69`)과 ΔE 3.4·2.9로 거의 같은 색이었고, 흰 바탕에서 1.24:1로 보이지 않았다. 달력 상태를 "감정 9색은 빼고 서비스 색으로" 구분하고 싶다는 QA 요청(#7)도 반영했다.
- **어떻게 골랐나** (사용자 요청 "다른 색 추천해봐" → 에이전트 계산): 색상각 전체를 돌며 감정 토큰(100·300·500)과 그림 색 19개 모두와 가장 먼 색을 찾았다. 결과 — 민트~스프링 그린 띠(색상각 150~165°)가 ΔE 14~17로 가장 비어 있고, 앰버 13.4, 시안 9.8, 레몬 9.2, 핑크 6.8. 라임을 조금 옮기는 방식으로는 한쪽에서 멀어지면 다른 쪽(토큰 즐거움 300)에 붙어 깨끗이 풀리지 않았다. 후보 A `#62FDB4`(15.4)·B `#41FAA0`(14.9)·C `#8AFFC2`(14.8) 중 사용자가 A를 골랐다.
- **하늘색·시안을 검토하고 고르지 않은 이유** (사용자가 이미지로 `#00F7FF`·`#B0FFFA`를 제안 → 에이전트가 반대 → 사용자가 민트 유지): 하늘·시안 띠는 슬픔(파랑)과 공포(청록) 사이라 프로젝트 기준 ΔE 7을 넘는 색이 없다 — 시안 5.2(확정된 공포 조약돌과 가장 가까움), 연한 아쿠아 9.3, 전형적 하늘색 `#87CEEB` 6.5, 맑은 하늘 `#5FA8D3` 6.8, 밝은 하늘 `#7CC7FF` 3.8. 감정 테마를 채택해 슬픔·공포 화면이 그 온도의 면으로 물들기 때문에 충돌 비용이 더 커졌다. ink(색상각 219°)와 시안(202°)은 같은 색상각의 명도만 다른 단색 조합이라 "지금 여기"가 튀지 않고 네온·테크 인상이 난다. "자유=하늘" 은유는 색이 아니라 **여백**으로 살린다(스토리에서 자유를 이미 길·여백으로 정함).
- **에이전트의 정정**: 민트의 ΔE 15는 정상 시야 기준이다. 색각 이상 시뮬레이션에서는 적색맹 기쁨 100과 0.5, 녹색맹 분노 100과 2.3, 청색맹 공포 조약돌과 4.6까지 붙는다. 다만 토큰 500끼리도 적색맹에서 즐거움–혐오가 4.2로 무너지므로, 방어선은 색이 아니라 **형태 단서**(ink 위 blob·ink 테두리·채운 아이콘)다. 시안·아쿠아도 같은 조건에서 1.3·1.5로 무너져 후보를 가르는 기준은 아니었다.
- **크림빛 `#FFF3D6`**: 빛의 색. ink 위 14.85:1, 흰 바탕 위 1.10:1(그래서 흰 바탕에 빛을 두지 않는다).
- **되돌리는 조건**: 실기기에서 민트가 ink 위에서도 형광처럼 눈이 아프거나 촌스럽게 보일 때 B·C를 다시 본다. 사용자가 서비스 색을 더 넓히자고 할 때 `check-contrast`의 서비스 항목(모든 감정 색 단계와 ΔE 7)을 통과하는지부터 본다.
- **등급**: 측정 + 사용자 결정.

### 3.3 빛 — 알아차림의 빛 (D-055)

> → D-061~D-067이 대체·수정(아래는 당시 근거). 빛은 D-062 ⑥이 '작성을 시작할 때의 흰빛(가운데 돌)'으로 바꿨다 — 색은 흰색이고 저장 뒤 완료 화면의 칭찬·감사 빛은 두지 않는다. '기록으로 남기지 않는다'는 원칙과 그 이유(좋은 날 지도)는 새 빛도 지킨다(§3.10.2).

- **결정** (사용자 결정): 빛은 "알아차림의 빛"이다. 쓴 칭찬·감사 칸에 켜지고, 색 없는 크림빛이며, 순간 연출로만 나타나고 기록으로 남기지 않는다. 무대는 흰 화면 위의 숲색 큰 유기형 면.
- **이유**: 사용자 분석 3 — 안내자 대신 "내가 켜는 빛". 행복은 점수나 보상이 아니라 자연스럽게 빛나는 상태이므로 빛이 보상으로 읽히지 않아야 한다. 에이전트가 낸 조건 셋(색 없는 빛 / 쓴 것에만 켜짐 / 빛이 없는 날도 온전)을 사용자가 받아들였다. 사용자의 다른 문서에는 "노란빛·기록을 시작할 때 켜는 행복의 빛"이 있었으나 폴더 기록과 달라 사용자가 "알아차림의 빛"을 골랐다.
- **노랑을 쓰지 않는 이유** (측정): 노란 빛은 기쁨 300과 ΔE 2.2로 감정 색과 구분되지 않는다.
- **흰 바탕의 빛** (측정 → 사용자 결정): 크림빛은 흰 바탕에서 1.10:1이라 보이지 않는다. 밤 풍경을 접고 "흰 화면 + 숲색 큰 유기형 면 위에"를 골랐다.
- **기록으로 남기지 않는 이유** (사용자 결정, 에이전트 근거): 달력·통계에 빛 표시가 남으면 빛 있는 날과 없는 날이 지도로 쌓여 "좋은 날 지도"가 되고, 우울한 시기에 달력이 어둡게 보일 위험이 있다. 스트릭·성취 장치가 위기 상황과 충돌할 수 있다는 설계 판단과 같은 방향이다(해석·디자인 판단).
- **고르지 않은 것**: 행복의 빛(시작할 때 켜는 노란빛), 빛을 쓰지 않음, 달력에 남김, 완료마다 항상 켜짐(알아차림에 켜진다는 뜻이 약해짐), 밤 시냇가 풍경(PRD §6.3·D-034 예외 승인 필요, 흰 바탕 요청과 충돌).
- **되돌리는 조건**: 빛을 기록으로 남기고 싶은 명확한 사용자 가치가 생기되 "좋은 날 지도" 위험이 없다는 설계가 나올 때.
- **등급**: 제품 원칙 + 측정 + 해석·디자인 판단.

### 3.4 조약돌 — 돌 하나는 그날 고른 계열 하나 (D-050)

> → D-062·D-064·D-067·D-068이 일부 수정(아래는 당시 근거). '어두운 밤 장면 철회·바탕은 흰색·무대는 풍경이 아님'은 오늘 화면에 한해 D-062가 대체했고, 오늘 화면의 조약돌은 계열마다 하나씩 아홉 개가 원근으로 흩어진다(처음 계열마다 셋·27개로 시안을 만들었으나 사용자가 정정했다, D-067, §3.10.7·§3.10.8). 세부 감정을 켜서 담는 자리는 친구 발치의 더미에서 바구니로 바뀌었다(D-068, §3.10.9). '레벨·누적 표시 금지'와 통계 친밀도의 경계는 D-064가 정했다(§3.10).

- **결정** (사용자 결정): 조약돌을 중심 은유로 채택하고 오늘 화면의 주인공으로 삼는다. **돌 하나 = 그날 고른 계열 하나.** 확정 원본 9종은 입체 글로시 질감 그대로 쓰고, 조약돌 이미지에 한해 그라데이션 예외 조항을 둔다.
- **이유**: 조약돌은 감정을 모아 성취하는 물건이 아니라 "오늘 있었던 마음이 사라지지 않고 남아 있다"는 흔적(사용자 분석 5). 에이전트의 평가 — 빛을 켜고 줍는 쪽이 사용자 자신이라 안내자의 주체성 문제가 풀리고, 얼굴 없는 중립 사물이라 판정·페르소나·AI 얼굴 문제가 없으며, 새 캐릭터 그림이 필요 없다.
- **층위**: 원본이 9종(계열당 하나)이라 194개 세부 감정을 돌로 구분할 수 없다. 사용자가 "돌 하나 = 그날 고른 계열 하나"로 정해 스토리의 "돌 하나 = 세부 감정 하나"를 고쳤다. 세부 감정은 글자로 남는다.
- **질감 충돌**: 확정 원본은 입체 그라데이션이다(이미지로 확인). DESIGN_SYSTEM §11·§8의 "그림자·그라데이션·3D 광택 금지"와 부딪혀 사용자가 "원본 유지 + 조약돌에 한한 예외"를 골랐다. 평면 친구와 톤이 어긋나 보이는지는 실제 화면에서 눈으로 판단한다.
- **하지 않는 것과 이유**: 수집·개수·희귀도·잠금·돌탑·레벨은 스트릭·수집·성취 장치가 위기 상황과 충돌할 수 있다는 판단(제품 안전 원칙 + 설계 판단). 짐("돌덩이")·던지기(물수제비)는 감정을 무거운 짐이나 버릴 것으로 읽히게 하므로 금지. 무거운 감정도 같은 가치(PR-010).
- **밤 장면 철회**: 사용자가 흰 바탕을 요청했고 PRD §6.3("흰색/중립 배경 기본")과 같은 방향이다. 예시(`?theme=pebble`)의 밤 시냇가 풍경은 접는다.
- **되돌리는 조건**: 2주 써 보고 세부 감정 고르기·오늘 화면에서 효과가 없을 때, 또는 글로시 질감이 친구와 어긋나 화면 전체가 산만할 때.
- **등급**: 제품 원칙 + 사용자 결정 + 해석·디자인 판단.

### 3.5 친구 — 동물에서 평면 생물로 (D-048·D-051, 다른 세션에서 확정)

> → D-061 ⑤가 일부 수정(아래는 당시 근거). '쓰는 자리 네 곳 제한'을 폐지해 마음 고르기·세부 감정·크기·완료·통계·달력 요약·빈 상태·온보딩에 쓴다. 오늘 화면·위기 안내·AI 위기 전환·오류에는 나오지 않는다.

- **결정** (사용자 결정): 눈 두 점·입 없음의 평면 친구 9종을 최종 채택하고 이름을 붙였다(누리·바라·설이·타온·나래·품이·아린·숨이·가름). 크레용 동물 세트는 이력으로 보존한다. 이 개편 중 "이미지는 추후 첨부"라고 했고, 사용자가 다른 세션에서 이미지를 첨부해 확정했다.
- **근거의 종류가 바뀐다**: 크레용 동물 시스템은 "동물의 행동 근거"(§5)가 있었고, 평면 친구는 **"감정을 표정으로 단정하지 않고 자세·형태·색으로 열어 둔다"는 디자인 원칙**이 중심이다. 동물 근거는 더 이상 브랜드의 핵심 근거가 아니다.
- **표정을 고정하지 않는 이유**: 표정의 보편성은 학계에서 논쟁적이다 — Barrett 2019가 대화에서 언급됐으나 원문을 이번에 확인하지 않았다(해석). 그래서 화난 눈썹·울음·땀방울 같은 이모지 표정에 감정을 고정하지 않는다. 표정 있는 안내자를 AI의 얼굴처럼 두지 않는 이유는 제품 원칙(앱이 이해하는 척하지 않는다)이지 특정 논문이 아니다.
- **색만으로 구분하지 않는 이유** (측정): 색각 이상에서 감정 색이 무너진다(§6). 그래서 이름·실루엣·자세를 함께 쓰고 64px 미만에서는 단독으로 쓰지 않는다.
- **쓰는 자리를 네 곳으로 한정한 이유** (사용자 결정): 이번 주 길·달력, 저장 중·로딩, 알림·앱 아이콘 추가를 제안했으나 사용자가 "추가 없음"을 골랐다. 이번 주 길·달력은 D-048의 "결과·평가 화면에 쓰지 않음"과 달력을 감정 색 없이 서비스 색으로 하려는 사용자 요청과 부딪혔다.
- **알려진 한계**: 설이(슬픔)와 숨이(공포)가 둘 다 청록 계열이다(측정 6.6). D-048이 조건으로 적은 "슬픔 몸 색을 파랑 쪽으로"는 이번 채택에 반영되지 않았다.
- **되돌리는 조건**: 사용자가 이름·매핑을 다시 바꿀 때(D-051).
- **등급**: 사용자 결정 + 측정 + 해석·디자인 판단.

### 3.6 오늘 화면과 한 줄 질문 (D-056)

> → D-061~D-067이 대체·수정(아래는 당시 근거). 오늘 화면은 D-062·D-067이 어두운 숲과 가운데 돌 하나로 바꿨다. 큰 질문은 '오늘은 어떤 마음이 머물렀나요?'(D-061 ③, D-067 ⑥의 타이포그래픽 배치)이고 무대·시작 버튼·이번 주 길·한 줄 질문 카드·친구는 화면에서 빠졌다. 한 줄 질문의 작성 원칙은 BRAND_STORY §10에 남아 있다.

- **결정** (사용자 결정): 흰 바탕 + 숲색 무대(오늘 고른 조약돌·친구) + hero 질문 + 시작 버튼 + 이번 주 길 + 오늘의 한 줄 질문.
- **이유**: 사용자 QA — 오늘 화면의 요소가 적고 감정 동물이 줄 맞춰 딱딱하다. 하나의 "나의 노트" 같은 밀도를 원했다.
- **이번 주 길**: 기존 기록 상태로 만드는 것이라 PRD 밖의 새 기능이 아니다. streak 압박 문구는 쓰지 않는다.
- **한 줄 질문** (사용자 결정 + 에이전트 제안): 에이전트의 권고안(사람이 쓴 목록, 날짜로 정해 보여 줌, 답 저장 없음)으로 가고, 사용자가 **"질문 내용은 철학적 서적을 바탕으로, 너무 어렵지 않게, 모든 연령층이 쉽게. 지금 하지 말고 추후 계획으로"**를 더했다. 답을 저장하지 않으므로 데이터 모델·내보내기·삭제·개인정보 문서가 바뀌지 않는다. 참고 전통은 스토아·아리스토텔레스·실존철학·동양 고전 네 가지를 모두 골랐다. 저작권이 존속하는 저서는 문장 인용 없이 개념만 재서술하고 출처는 책 단위로만 적는다.
- **고르지 않은 것**: 답을 저장하는 안(원형 일기 6영역 밖의 확장 — MVP 범위를 넓힘), "다시 만난 조약돌(일주일 전 오늘)"(앱이 과거 기록을 대신 골라 보이면 무거운 시기의 기록이 예고 없이 나올 위험 — 사용자가 선택하지 않았다), 요소 추가 없이 장면만.
- **되돌리는 조건**: 질문 목록을 쓰게 될 때 사용자가 검수한다. 질문이 처방·정답 유도로 읽히면 그 질문을 뺀다.
- **등급**: 제품 원칙 + 사용자 결정.

### 3.7 타이포와 웹폰트 (D-057)

- **결정** (사용자 결정): 큰 제목 hero를 44/52·굵기 800으로 쓰고 Pretendard Variable을 self-host 웹폰트로 도입한다. D-034(d)의 "웹폰트를 싣지 않는다"를 번복한다.
- **이유**: 세 번째 무드 글 — "타이포는 설명이 아니라 그래픽 오브젝트, 굵은 산세리프 + 큰 크기 + 짧은 문장". 시스템 글꼴은 기기마다 굵기와 자모 모양이 달라 포스터 느낌이 안정적이지 않다.
- **사실 확인** (공식 저장소): SIL OFL 1.1, v1.3.9(2023-11-05), 가변 woff2 2,057,688 bytes(GitHub API와 내려받은 파일이 같음), 동적 서브셋 92조각·CSS 55.7KB. 라이선스는 사본과 저작권 고지를 함께 두면 self-host·재배포가 허용된다(조건 이행: `design/fonts/PRETENDARD-LICENSE.txt`).
- **위험과 규칙화**: ① 굵기 한 벌만 선언하면 본문이 그 굵기로 그려진다 — 가변 범위 하나로 선언한다. ② 약 2.0MB는 모바일 첫 로드에 무겁다 — 시안에서는 감수하고 Phase 1에서 동적 서브셋으로 바꾼다. ③ 200% 글자 확대에서 44px는 넘친다 — `clamp()`로 줄이고 360px·200% 가로 넘침 0을 검증한다.
- **고르지 않은 것**: 36/44·700을 큰 제목에만(시스템 글꼴 유지 안), 현재 28/36 유지. 사용자가 44/52·800과 웹폰트를 골랐다.
- **되돌리는 조건**: 실기기에서 첫 로드가 느리거나 굵은 글자가 답답할 때 36/44·700으로 낮춘다.
- **등급**: 사용자 결정 + 사실 확인.

### 3.8 이름·로고, 브랜드 문구, 그 밖의 범위 결정

- **이름·로고 (D-058)** (사용자 결정): "이름은 나중에 정한다." 문서에는 미정으로 적는다. 그때까지 임시로 '감정일기'를 쓰고 로고·워드마크는 만들지 않는다(D-036). 큰 타이포가 화면에 크게 나오므로 별도 로고 없이도 인상이 생긴다는 것이 현재 판단이다.
- **브랜드 문구** (사용자 결정): "잘 설명하지 못해도 괜찮아요. 오늘의 마음을, 처음 이름 붙이듯 적어 보세요."를 온보딩과 직접 작성 시작 안내에 쓴다. 이유 — 유년기의 시각 언어는 "판단 없는 기록"이며, "아이들은 더 솔직하다"는 주장은 쓰지 않는다.
- **시안까지 이번에 재구성** (사용자 결정): 문서·토큰·전시장에 더해 `web/` 시안도 새 언어로 다시 짠다. 캐릭터 이미지가 확정돼 크레용 자산 임시 사용 부담은 없어졌다.
- **TASK-DS-REF를 재개하지 않음** (사용자 결정): 이번 개편은 사용자의 브랜드 방향에서 나온 자체 규칙이다. TDS를 참고하면 확정 결정을 되돌리자는 후보가 나올 위험이 있다(그 작업의 불변 목록 원칙).
- **PRD §6.3 최소 수정** (사용자 결정): 화면 배경을 물들이는 감정 테마를 담도록 둘째 줄을 고친다. 흰색 기본과 비판정 원칙 문장은 그대로 둔다.

### 3.9 작성 흐름 재설계 — 세부 감정·강도 (D-059)

> → D-065·D-068이 일부 수정(아래는 당시 근거). 세부 감정의 검색창을 삭제했고(③) 화면 말에서 '강도'를 '크기'로 통일했다(②). 조약돌을 담는 자리는 친구 발치의 더미에서 바구니로 바뀌었다(D-068, §3.10.9).

- **결정** (사용자 결정 + 에이전트 판단): 사용자가 "하나의 감정을 선택하면 하나의 화면에서 그 감정의 세부 감정을 선택하고, 다음으로 넘어가서 또 다른 감정의 세부 감정을 선택할 수 있게", "세부 감정 선택 때 배경은 그 색상으로, 선택하면 조약돌이 자연스럽게 모이는 애니메이션", "강도는 대표 감정 강도가 메인이고 그 밑에 '세부 감정도 강도를 선택하고 싶어요'를 눌러 세부 감정도 고르게"라고 지시했다. 사용자는 30분 이상 자리를 비우며 질문 없이 "최고의 판단"으로 진행하라고 했다.
- **이유**: 한 번에 한 계열에 집중하고 고른 계열의 색·친구를 화면 전체에 쓰는 감정 테마(D-053)와 맞는다. 강도는 "이 마음이 얼마나 컸나"가 계열 단위의 질문이고, 세부 감정별 강도는 선택이어야 부담이 준다.
- **에이전트 판단 — 저장 계약은 바꾸지 않는다**: 대표 강도를 새로 저장하지 않는다. PRD §6.2는 세부 감정마다 독립된 정수 강도를 저장하라고 하고 DATA_MODEL의 `intensity` 컬럼이 그 단위다. 그래서 대표 강도는 **입력 편의**이고, 세부 강도를 따로 정하지 않은 세부 감정에는 대표 강도를 저장한다(fan-out). 데이터 모델·PRD·통계 정의(평균 강도 = 선택 행의 산술평균)가 그대로다. 고르지 않은 안: 계열 강도를 따로 저장하는 안(스키마·내보내기·삭제·통계 정의 변경 필요 — Phase 1 이전에 사용자 결정이 필요하다).
- **에이전트 판단 — pill 구름**: D-037은 한글 단어 길이가 들쭉날쭉해 격자·chip을 피하고 1열 리스트를 골랐다. 계열별 화면으로 나뉘어 한 화면의 감정이 3~53개가 되고 레퍼런스(Suntera)의 pill 칩 방향과도 맞으므로, 줄 바꿈으로 흐르는 flex-wrap pill 구름을 골랐다(격자가 아니라 정렬 문제가 없다). 24개를 넘는 계열(슬픔 53·기쁨 32)에만 검색을 둔다.
- **D-050과의 관계**: 조약돌 모임 애니메이션은 사용자 지시다. "돌 하나 = 그날 고른 계열 하나"는 **기록에 남는 돌**에 해당하고, 세부 감정을 고르는 화면의 돌 더미는 저장하지 않는 일시 피드백이다. 개수 글자·누적 표시·던지기는 여전히 금지한다.
- **위험**: 계열이 셋이면 작성 단계가 10개가 된다(날짜·사건, 계열, 세부 감정×3, 강도, 이유, 칭찬, 감사, 검토). 진행 표시와 `이 계열은 빼기`로 완화했고 써 본 뒤 줄일지 정한다. 감정이 53개인 슬픔 화면은 길다. 돌 더미가 수집·게임처럼 읽힐 위험은 개수 글자 금지와 일시 피드백으로 낮췄다. **QA에서 20개를 고르니 15슬롯 더미가 친구 몸통까지 올라와 친구가 돌에 파묻혔다** — 짐을 쌓는 것처럼 읽혀 D-050(짐 연출 금지)에 어긋나므로 보이는 돌을 최대 9개·높이 약 70px로 제한했다.
- **되돌리는 조건**: 사용자 눈 검수에서 단계 수가 부담이거나 돌 더미가 수집처럼 읽힐 때.
- **등급**: 사용자 결정 + 제품 원칙(PR-005·계약 유지) + 에이전트 판단.

### 3.10 무드 v4 — 흰 바탕의 큰 친구와 길과 노트(D-061·D-062·D-063·D-064·D-065·D-066·D-067·D-068·D-069·D-070·D-071·D-072)

2026-09-21~22에 사용자가 시안을 보고 고르고 뒤집으며 정한 것이다. 무드(D-061), 오늘 화면(D-062·D-067), 검토(D-063), 통계(D-064), 작은 화면(D-065), 마음 고르기(D-066), 세부 감정의 바구니(D-068), 작성 화면마다의 이야기 있는 배경(D-069), 달력·통계·설정의 밝은 탭(D-070), 세부 감정의 연한 배경(D-071), 오늘 화면의 숲 속 안(D-072)을 다룬다. 시안 검토 막바지에 사용자가 질문 없이 판단을 위임해(TASK-WEB-UI-02 QA 25행) 일부는 **사용자 위임**(에이전트 판단)이며 해당 항목에 적었다. 원본 시안은 세션 기록에만 있고 정본은 DESIGN_SYSTEM·BRAND_STORY·UX_SPEC이다(D-061 행). 아래 따옴표는 결정 행에서 옮긴 사용자의 말이다.

#### 3.10.1 무드 다섯 안의 반려와 흰 바탕 (D-061)

- **결정** (사용자 결정): 바탕은 흰색이고 그림자·굵은 윤곽이 없다. **친구를 상자·타일·다이컷 흰 테두리에 담지 않는다.** 색은 큰 면(오늘의 숲·세부 감정·완료의 언덕)과 ink 알약으로만 쓰고 소품(색 위 스티커·테이프 붙은 태그와 메모·줄 노트)은 한 화면에 세 곳 안팎으로 절제한다. 계열 고르기는 별자리 지도 대신 **친구 아홉을 한 화면에 박스 없이** 세우고 복수 선택한다(선택=이름이 ink 알약으로 채워지고 체크가 붙음, 문구 '여러 개여도 괜찮아요'). 큰 질문은 '오늘은 어떤 마음이 머물렀나요?', 화면 말투는 해요체 한 가지, 이야기는 '길과 노트'다. 완료는 흰 하늘·언덕·흰 길 위에 그날 고른 친구와 조약돌만 서고 친구 크기는 모두 같다. 작성 화면은 단계형 하나다.
- **사용자의 이유** (D-061 행): 네 번의 라운드 질문과 시안 반려로 수렴했다. 무드 다섯 안 가운데 스티커 노트에 큰 마스코트·색 면·장면을 섞은 안이 그림자·박스·유아틱함으로 반려됐다 — "그림자 빼고 배경은 흰색", "캐릭터를 박스 안에 넣지 마". 흰 바탕·납작한 면·박스 없음으로 다시 그린 열네 화면을 사용자가 이어서 수정하며 채택했다. 감정이 복수 선택이라는 점과 '오늘은 어떤 친구가 다녀갔나요?'의 반려가 문구에 반영됐다(반려 사유는 기록에 없다).
- **근거와 상태**: 친구의 사용처는 D-056의 네 곳 제한(§3.5)을 폐지하고 넓혔다 — 통계에서 캐릭터를 적극 쓰자는 사용자 요청(D-064)과 같은 방향이다. 안전 경계는 그대로다: 오늘 화면의 숲·위기 안내·AI 위기 전환·오류에는 친구가 나오지 않는다. 크기로 우열을 만들지 않는 원칙은 완료 화면(고른 수에 따라 전원이 함께 커지고 줄어든다)에서 지켜진다 — 온보딩 첫 쪽은 언덕의 줄에 따라 친구 폭이 달라 이 원칙과의 관계가 정해지지 않았다(§7). 시안(`web/`)에서 구현했고 실기기는 미검증이다.
- **고르지 않은 것**: 스티커 노트+큰 마스코트+색 면+장면을 섞은 안(반려), 별자리 지도의 유지(D-041·D-053이 골랐던 것), 긴 한 장 작성 화면(비교안에서 뺐다), 색 위 소품의 남발(세 곳 안팎으로 제한).
- **되돌리는 조건** (D-061 행): 2주 써 보고 흰 바탕이 밋밋하거나 친구가 어수선하게 읽힐 때, 상자 없는 친구 격자에서 조작 영역(44px)이 모자랄 때.
- **등급**: 사용자 결정 + 해석·디자인 판단.

#### 3.10.2 오늘 화면 — 어두운 숲과 돌 하나 (D-062)

- **결정** (사용자 결정): 오늘 화면에 한해 D-050의 '바탕은 흰색·무대는 풍경이 아님'을 대체한다. ink 계열의 납작한 층(하늘·먼 나무·중간 나무·가운데 길·가장자리 큰 나무)으로 그린 어두운 숲에 **버튼 대신 가운데 돌 하나**가 선다. 돌은 좌우로 천천히 흔들리고, 호버·누르는 중에는 흰빛으로 통통 뛴다. 누르면 돌에서 흰빛이 화면 전체로 퍼진 뒤 작성 첫 화면이 흰 화면에서 열린다. 하단 탐색은 이 화면에서 투명 입체 유리 알약에 청록 아이콘이고 베이지(크림빛)는 쓰지 않는다. 친구·시작 버튼·이번 주 길·한 줄 질문은 화면에 없다. 상태는 기록 없음·이어 쓰기·기록 있음·알림 배너·AI '지금은 쉬고 있어요'·로딩이다. 길 색·조약돌·큰 질문은 D-067이 고쳤다(§3.10.7).
- **사용자의 이유** (D-062 행): "어두운 청록으로, 길은 가운데, 나무는 뒷배경", "클릭하면 흰빛이 전체 화면으로 퍼지면서 일기 작성을 시작하는 느낌", "감정 캐릭터들은 빼자". 탐색은 처음에 "청록을 최대한 피해"라고 했고, 에이전트가 그린 크림 알약을 베이지라며 반려한 뒤 "메인화면에서 베이지색 사용하지 말고" 투명 입체 글래스모피즘 탐색에 청록 아이콘으로 하자고 다시 요청했다.
- **D-050이 밤 장면을 접은 이유와 지킨 방법**: D-050이 밤 장면 예외를 철회한 이유는 기록에 두 가지다 — 사용자가 흰 바탕을 요청했고 PRD §6.3의 '흰색/중립 배경 기본'과 같은 방향이었다는 것(§3.4), 수집·성취 장치가 위기 상황과 충돌할 수 있다는 설계 판단(D-062 행). 이 결정은 앞의 것을 오늘 화면 한 곳에 한해 사용자가 뒤집은 것이다. 뒤의 것은 다음으로 지킨다 — 개수·희귀도·보상 표시가 없고, 돌은 쌓이거나 세지지 않으며, 기록 있음·이어 쓰기 상태에서도 켜지는 것은 그날 고른 계열의 돌뿐이다. 친구·시작 버튼·이번 주 길·한 줄 질문 메모는 화면에 없다.
- **빛이 좋은 날 지도가 되지 않게**: D-055가 우려한 위험(빛이 기록으로 남으면 빛 있는 날과 없는 날이 좋은 날 지도가 된다)은 새 빛이 저장 값·달력 표시·통계와 무관한 순간 연출이라 생기지 않는다. 저장 뒤 완료 화면의 칭찬·감사 빛은 두지 않는다(D-062 ⑥).
- **PRD와의 관계**: PRD §6.3은 흰색/중립 배경을 '기본'으로 한다고 적어 오늘 화면의 어두운 숲과 문구상 양립하지만, D-062는 PRD를 고쳤는지 적지 않았다(§7).
- **측정** (§6, 2026-09-22 당시 — 하늘 한 색·유리 제거 뒤 값은 §6 갱신 줄): 흰 글자 on 숲 하늘(sky-mid) 13.76:1·on 회색 길(path-near) 6.72:1. 청록 탐색 아이콘 on 유리(뒤 숲 brightness .82 + 흰 채움 18%)는 숲 바닥 6.16·회색 길 3.48·큰 나무 7.15:1이다(아이콘은 3:1 기준). 유리 채움을 18% 이하로 제한한 것이 이 3:1을 지키는 조건이다.
- **움직임·환경**: 움직임 줄이기에서는 흔들림·반짝임·호버 애니메이션을 멈추고 흰빛 전환은 0.25초 페이드로 대신한다. 초당 3회를 넘는 깜빡임이 없다. 터치에는 호버가 없어 누르는 순간이 같은 흰빛이다. 유리를 못 쓰는 환경(backdrop-filter 미지원·투명도 줄이기)에서는 어두운 불투명에 가까운 면으로 대신한다. 시안(`web/`)에서 구현했고 실기기는 미검증이다.
- **고르지 않은 것**: 흰 바탕+ink 무대의 오늘 화면(D-050·D-056), ink 알약 탐색(ink 숲에 묻힌다), 크림 알약 탐색(베이지라 반려), 시작 버튼(가운데 돌이 대신한다), 저장 뒤 완료 화면의 칭찬·감사 빛, 옛 크림빛 빛(D-055).
- **되돌리는 조건** (D-062 행): 실제 기기에서 밤에 흰빛이 눈부시다는 반응이 있거나(밝기·시간 조정), 숲이 오늘 화면의 정보(알림·상태)를 가릴 때.
- **등급**: 사용자 결정 + 측정 + 해석·디자인 판단.

#### 3.10.3 검토는 나에게 쓰는 편지 (D-063)

- **결정** (사용자 결정 + 사용자 위임): UX_SPEC §4의 '검토: 원형 순서의 전체 요약과 수정 링크'를 **'나에게 쓰는 편지'**로 대체한다. 닫힌 봉투(민트 인장)를 열면 고른 조약돌이 나오고 카드가 올라온다. 봉투를 열지 않아도 '남기기'를 누를 수 있다. 카드 템플릿 셋 — 감정 카드(감정당 한 장: 그 계열 300 면·큰 이름·조약돌·세부 감정 알약·크기), 있었던 일과 이유(줄 노트 종이), 칭찬(큰 한 문장). 감사는 **채운 날에만** 같은 틀로 한 장 더 붙고, 칭찬·감사를 비운 날은 그 장을 건너뛴다. 카드는 옆으로 넘기되 이전·다음 화살표와 점을 함께 둔다. 각 카드의 '고치기' 태그(흰 태그+민트 테이프+연필, −3°)는 그 카드의 입력 단계로 보낸다. 기록 상세(달력)는 같은 편지의 읽기 모드다. 크기는 숫자와 열 점으로만 보인다.
- **사용자의 이유** (D-063 행): "나에게 쓰는 편지 느낌으로 봉투를 열어서, 열면 선택한 감정의 조약돌이 나오면서 인스타 카드뉴스처럼 스와이프". 템플릿은 "감정&세부감정&크기(감정당 한 장)·있었던 일과 이유·칭찬", 수정 버튼은 "이 무드에 맞게".
- **감사 카드를 채운 날에만 붙인 이유** (사용자 위임 → 에이전트 판단): 사용자가 감사를 언급하지 않았으나 PRD §5의 원형 6영역(기록일자·사건·감정과 강도·이유·칭찬·감사)을 잃지 않으려고 감사 카드를 넣었다. 채운 날에만 붙인 것은 D-055의 '빈 칸도 온전'을 지키기 위해서다 — 비운 칸의 빈 카드를 두면 채우지 않은 날이 눈에 띄는 빈 장으로 남는다(해석·디자인 판단). 그래서 칭찬도 비운 날은 건너뛴다.
- **근거와 상태**: 봉투를 열지 않고도 남길 수 있어 검토를 강제하지 않는다 — 자유는 앱의 행동으로 나타나야 한다는 원칙(BRAND_STORY §4)의 연장이다(해석). 스와이프만 두지 않고 화살표·점을 병행한다(코드 주석은 WCAG 2.5.1을 든다). 긴 글은 카드 안에서 세로로 스크롤하고 카드 크기는 늘지 않는다는 규칙이다(D-063 ③ — 있었던 일과 이유 카드는 글 자리를 고정값으로 놓아 긴 글에서 이 규칙대로인지 확인이 필요하다, §7). 크기를 조약돌 크기·색 농도로 그리지 않는다(D-050). 움직임 줄이기에서는 봉투 열림 연출 없이 카드가 바로 나온다. 봉투·카드·읽기 모드는 시안에서 구현했다. 밤의 책상 장면 배경은 이후 밝은 낮의 창가 책상으로 완성됐다(사용자의 '밝은 배경' 기준으로 D-069 ④가 정정, §3.10.10). 실기기 스와이프는 미검증이다.
- **측정** (§6): 감정 300 위 ink 글자 6.48~12.19:1(미움이 최저, D-063 행), 글자 on 종이 15.57·paper-ink on 종이 6.28·글자 on 크림빛 14.97·paper-ink on 크림빛 6.04·봉투 '나에게' 6.81:1. '고치기' 태그의 경계선은 크림 위 1.4:1로 낮아 글자가 버튼임을 알린다(D-063 행).
- **고르지 않은 것**: 옛 검토(원형 순서의 전체 요약과 수정 링크), 스와이프만 있는 카드, 비운 칭찬·감사의 빈 카드, 조약돌 크기·색 농도로 크기를 그리기.
- **되돌리는 조건** (D-063 행): 카드 스와이프가 실기기에서 세로 스크롤과 부딪히거나 검토를 건너뛰는 사용자가 많을 때(봉투를 열지 않고 남기는 비율).
- **등급**: 사용자 결정 + 측정 + 에이전트 판단(감사 카드).

#### 3.10.4 통계 — 친구와의 친밀도 (D-064)

- **결정** (사용자 결정 + 에이전트 제안): 통계에 '친구와의 친밀도'를 둔다. 친밀도 = 기간 안에 기록한 날 중 그 친구와 함께한 날의 비율이고, 친구가 '나'를 향한 길 위에서 서 있는 **위치로만** 보여 준다(친구는 모두 같은 크기, 가까울수록 비율이 높다). 함께한 날 수는 글자로 적는다. **머리말은 중립 요약**('이번 기간에는 여섯 친구가 다녀갔어요')이고, 기록이 5일 미만이면 친구를 나열하지 않고 '기록이 더 필요해요'로 두며, '많고 적음에 좋고 나쁨은 없어요'를 목록 아래에 고정한다. 다녀가지 않은 친구는 순위에서 빼고 '이번에는 오지 않았어요'로 모은다. 막대(자주 머문 마음)는 이 화면에서 뺀다. 레벨·점수·이름 붙은 단계·보상·연속 표시·줄어듦·잠금·순위 문장은 두지 않는다.
- **사용자의 이유** (D-064 행): "통계 부분에서 캐릭터를 적극 사용하자. 지금이랑 다르게 캐릭터와의 친밀도로 표현하자".
- **머리말을 고친 이유** (에이전트 제안 → 사용자 '진행'): 에이전트가 시안에서 머리말을 '타온과 가장 가까웠어요'로 그렸다가, 분노·미움·공포 친구가 1등일 때 평가로 읽힐 위험을 근거로 중립 요약으로 고쳤다. 이 위험은 D-050이 수집·성취 장치를 막은 이유와 같다.
- **근거와 상태**: D-050은 수집·도감·개수·누적 표시와 레벨·연속 기록 보상을 금지했다. 이 화면의 수는 기간 통계일 뿐 모으는 것이 아니고 위치는 비율일 뿐 단계가 아니어서 경계를 지킨다. 기록이 5일 미만이면 나열하지 않는 것은 적은 데이터에서 추세를 과장하지 않는다는 UX_SPEC §9의 원칙과 같은 방향이다. 기쁨 줄만 700(`#B08A00`)을 쓴다 — 500은 흰 바탕 1.77:1이라 토큰의 accent-override 규칙을 따랐다. 차트·막대 색은 계열의 정체일 뿐 좋고 나쁨이 아니다(PR-010). 예시 데이터로 시안을 구현했고(저장 없음), '나' 표식은 오늘 화면의 가운데 돌을 작게 쓰는 '나의 돌'로 바뀌었다(D-070, §3.10.11). 위치 설명 문구('함께한 날이 많을수록 나와 가까이 서 있어요')가 '가까워지는 것이 목표'로 읽히는지는 열린 문제다(BRAND_STORY §12).
- **고르지 않은 것**: 순위 머리말('타온과 가장 가까웠어요'), 레벨·점수·단계 이름·연속 표시, 막대 그래프(자주 머문 마음)를 이 화면에 두는 것.
- **되돌리는 조건** (D-064 행): 친밀도 위치가 '더 가까워지는 것이 목표'로 읽히거나 위기 시기에 부담이 된다는 반응이 있을 때, 기록이 적은 사용자에게 위치 차이가 의미 없어 보일 때.
- **등급**: 사용자 결정 + 제품 원칙(PR-010) + 에이전트 제안.

#### 3.10.5 작은 화면 결정 여섯 — 안전 문구 삭제 등 (D-065)

- **결정** (사용자 결정 + 사용자 위임): ① 위기 안내의 제목 '지금 안전이 먼저예요'를 삭제하고 남은 첫 문장 '혼자 견디지 않아도 돼요'를 제목으로 올린다. ② 화면 말에서 '강도'를 '크기'로 통일한다(PRD·데이터 이름은 intensity·강도 그대로). ③ 세부 감정 화면의 검색창을 없앤다(D-059의 '24개 초과 계열에 검색' 조항 폐지). ④ 완료 기록의 기간 표기 'streak'는 화면 말로 '이어서 쓴 날'이다. ⑤ 감사를 편지 앞의 정식 단계로 그린다(칭찬과 같은 틀, 비워도 오류 없음). ⑥ 하단 탐색 아래 안전영역·44px 목표는 그대로다.
- **사용자의 이유** (D-065 행): "안전이 먼저예요는 삭제하자", "세부 감정은 검색 창이 없어도 돼", 감정의 정도를 '크기'라고 불렀다. ①의 삭제 이유는 사용자가 밝히지 않았다(요청만 기록). ②는 사용자 말('크기')에 화면 어휘를 맞춘 것이다. 행에는 '사용자 요청·시안 검토와 에이전트 판단(위임)'이라고만 적혀 있고 어느 항목이 에이전트 판단인지는 나누어 적지 않았다 — ①·③은 사용자의 말이 인용돼 있다.
- **① 안전 문구 삭제가 안전 규칙을 바꾸지 않는 이유**: 위기 안내의 친구·색·움직임 없음, 연락처는 검수 전이라 번호를 적지 않는 규칙은 그대로다(코드: 제목 '혼자 견디지 않아도 돼요', '아래에서 지금 바로 도움을 받을 수 있어요.', danger 테두리의 '도움받을 수 있는 곳' 상자, '이 앱은 진단이나 위기 대응 서비스가 아니에요.'). SAFETY_POLICY에는 삭제한 제목을 요구하는 조항이 없다(저장소 검색). 다만 안전을 직접 말하던 문구가 줄어 위기 화면의 신호가 약해질 수 있어 사용자 눈 검수 항목으로 둔다(해석·디자인 판단).
- **③ 검색 삭제의 위험과 완화**: 세부 감정이 53개인 슬픔에서 검색이 없으면 찾기 어렵다. pill 구름을 가나다순으로 두고 첫 화면에 여러 줄이 보이게 해 완화했다(D-065 행).
- **고르지 않은 것**: 위기 안내에 옛 제목을 유지하기, 24개 초과 계열의 검색창 유지, 화면 말에 '강도' 유지.
- **되돌리는 조건** (D-065 행): 검색이 없어 슬픔·기쁨 계열에서 원하는 말을 못 찾는다는 반응이 있을 때, 통계의 '이어서 쓴 날'이 작성 streak 정의(PRD §8)와 어긋난다고 판단될 때.
- **등급**: 사용자 결정 + 제품 원칙(SAFETY_POLICY) + 에이전트 판단.

#### 3.10.6 마음 고르기 — 초록 언덕 위의 자유 배치 (D-066, provisional)

- **결정** (사용자 요청 → 시안, **사용자 확인 대기**): D-061 ②의 '박스 없이 세우는 3×3 격자'를 이 화면에 한해 대체하는 시안이다. 배경은 프로젝트 초록(`land` 토큰) 한 계열이다 — 하늘=먼 언덕색, 언덕 셋, 옅은 초록 길, 나무 몇 그루. 해·구름·조약돌은 없다. 친구 아홉은 같은 크기의 블록(그림+이름+계열 이름)을 쓰고 위치·기울기(±7° 이내)만 손으로 정한 자리에 선다. 블록은 겹치지 않고 선언 순서 그대로 위에서 아래로, 같은 높이대는 왼쪽부터 놓여 Tab 순서가 읽는 순서와 같다(심리 축 배치 금지). 조작·상태는 격자와 같다(토글 버튼 `aria-pressed`, 선택=이름이 ink 알약+체크+8% 커짐, 켤 때 한 번 통통). 친구가 5초 안팎으로 2% 남짓만 떠올랐다 가라앉고 움직임 줄이기에서는 정지한다.
- **사용자의 이유** (D-066 행): "친구들이 좀 자유분방하게 있고 첨부 이미지처럼 배경에 애들이 있되, 배경은 초록색 우리 프로젝트 컬러 계열로만. 그리고 조약돌은 없게 해서 시안 보여줘봐".
- **앞뒤 크기 차를 고르지 않은 이유** (에이전트 판단, 사용자 확인 전): 첨부 이미지(옛 시안: 복숭아색 하늘·해·구름·조약돌·앞뒤 크기 차)에서 초록 언덕·길·나무·자유 배치만 가져왔다. 앞은 크고 뒤는 작게 하는 깊이감은 쓰지 않았다 — 크기가 감정마다 달라 보이면 우열로 읽힌다(D-053·PR-010). 사용자가 '첨부 이미지처럼'이라고 했으므로 깊이감을 원했을 수 있다. 시안을 보여 주고 확인받기 전이라 provisional이다(D-066 행). *(이전: 오늘 화면 숲의 원근 조약돌과 결론이 다른 것은 "조약돌은 계열당 셋이라 깊이를 돌려 쓸 수 있다"고 적었으나, D-067이 조약돌도 계열마다 하나(아홉 개)로 되돌려 그 구분은 더 이상 성립하지 않는다 — 지금은 친구·조약돌 둘 다 계열마다 하나뿐이고, 조약돌 쪽에만 원근에 따른 고정 크기 차가 있다는 점이 다르다, §3.10.7·§3.10.8.)*
- **측정** (§6): 언덕 세 단계(far·mid·near) 위 ink 글자 12.75 / 9.77 / 6.56:1. 초록 위 초점 링은 ink 3px다 — 기본 파랑 초점 링은 가장 짙은 언덕(near) 위에서 2.1:1로 3:1에 못 미친다(D-066 행, 재계산 2.07:1). 오류 문구는 `danger` 원색이 초록 하늘(먼 언덕색) 위에서 4.38:1로 본문 기준 4.5:1에 약간 못 미쳐 ink를 25% 섞은 색으로 바꿨고 6.2:1이다(D-066 행 — 처음 손으로 계산해 6.5:1로 적었으나 `check-contrast`로 다시 재 보니 틀린 계산이었다).
- **고르지 않은 것**: 앞뒤 크기 깊이감, 첨부 이미지의 복숭아색 하늘·해·구름·조약돌, 이전 3×3 격자(`#/write?pick=grid`로 비교할 수 있게 남겼다).
- **되돌리는 조건** (D-066 행): 사용자가 시안을 보고 앞뒤 크기 깊이감을 원하거나 격자로 돌아가길 원할 때, 실기기 320px 폭에서 아홉 블록이 겹칠 때.
- **과정에서 나온 결함**: 새 컴포넌트의 클래스 `.field`가 폼 필드(`base.css`)와 겹쳐 장면이 24px 어긋났고 `.meadow`로 바꿨다(D-066 행). 같은 종류의 이름 충돌이 D-067에서 또 났다(§3.10.7).
- **등급**: 사용자 요청 + 측정 + 에이전트 판단.

#### 3.10.7 원근 조약돌 — 아홉 개 (D-067) *(이전 제목·본문은 "계열당 셋·27개"로 적었으나 사용자가 시안을 보고 정정해 D-067 행이 아홉 개로 바꿨다 — §3.10.8에 그 정정의 근거를 따로 적는다.)*

- **결정** (사용자 결정): 오늘 화면(D-062)을 고친다. ① 길은 회색이다(`forest.path-far #383F40`·`path-near #565D5E`, 청록 길 폐지). ② 감정 조약돌은 **계열마다 하나씩 아홉 개**다 — 크기는 원근 세 단계(먼 곳 22px·중간 30px·가까운 곳 42px, 상자 폭 360 기준, `web/js/components/forest.js`의 `BAND_SIZE`가 정본)이고, 먼 곳(희망·분노·혐오)·중간(슬픔·기쁨·미움)은 나무 뿌리 옆 식물 사이에, 가까운 곳(사랑·공포·즐거움)은 가장자리 큰 나무 밑에 놓인다. 위치는 고정 씨앗이라 볼 때마다 같고 가운데 돌·문구 자리는 비워 둔다. ③ 평소에는 빛나지 않는다 — 채도·밝기를 낮춰 숲에 묻혀 있고 **호버한 돌 하나만** 자기 계열 색으로 켜진다(터치는 호버가 없어 누르기 전에는 모두 어둡다). 기록 있음·이어 쓰기 상태에서만 그날 고른 계열의 돌이 켜져 있다. ④ 가운데 돌을 누르면 조약돌이 돌에서 가까운 것부터 차례로 모두 켜지고(약 0.5초) 0.62초 뒤 흰빛이 화면 전체로 퍼진다. ⑤ 가운데 돌을 호버할 때 나오던 별 모양을 뺀다. ⑥ 큰 질문은 타이포그래픽 배치다 — '오늘은 어떤'(작게)·**'마음'**(가장 크게, 굵기 900)+'이'(작게)·'머물렀나요?'(중간, 오른쪽으로 물러남), 흰색 한 색, 그림자·획 없음, 한 번 아래에서 차례로 올라온다. 읽는 글은 그대로 '오늘은 어떤 마음이 머물렀나요?'다.
- **사용자의 이유** (D-067 행): "길을 나타내는 컬러가 회색이었으면 좋겠고", "배경에 흩어져 있는, 배경에 자연스럽게 녹아들어가 있는 느낌(원근법도 사용)", "호버하지 않은 상태에서는 빛나지 않게", "가운데 조약돌을 클릭했을 때 전체가 다 빛나게", "타이포그래픽 디자인을 사용해서 더 강조", "별 모양들은 다 빼".
- **D-050·PR-010과 부딪히는 문제**: 원근을 쓰면 계열마다 돌의 크기가 달라 보일 수 있고, 크기가 감정마다 달라 보이면 우열로 읽힌다. D-050은 크기·개수·위치로 감정의 무게를 표현하지 않는다고 했고 PR-010은 감정 색·그림이 좋고 나쁨을 뜻하지 않게 한다. 처음에는 한 계열을 셋으로 나눠 먼·중간·가까운 곳에 하나씩 놓아 이 문제를 피했으나(§3.10.8), 사용자가 개수를 줄이라고 정정하며 계열마다 하나만 남아 **각 계열이 고정된 한 밴드(크기)에 묶이게 됐다** — 이 문제가 다시 열려 있다는 뜻이고 RISK_REGISTER RK-025에 있다. 크기는 깊이 표현일 뿐 감정의 무게를 뜻하려는 것은 아니다. D-062 ①의 '아홉이 모두 같은 크기'를 이것으로 대체한다.
- **측정** (§6): 흰 글자 on 숲 하늘 13.76:1·회색 길 6.72:1. 청록 탐색 아이콘 on 유리는 숲 바닥 6.16·큰 나무 7.15:1에 비해 회색 길 위 3.48:1로 여유가 가장 적다 — 길이 회색이 되며 숲에서 가장 밝은 자리가 됐기 때문이고, 유리 채움 상한 18%를 그대로 둔다(`check-contrast`).
- **고르지 않은 것**: 계열마다 셋(모두 27개, 최초 시안 — 사용자가 "너무 많다"고 정정), 원근 없이 모두 같은 크기(D-062 ①, 사용자가 원근을 요청), 평소에도 반짝이는 조약돌(D-062 ①, 사용자가 '빛나지 않게'), 호버 때의 별 모양.
- **되돌리는 조건** (D-067 행): 회색 길이 숲 안에서 눈에 튀거나(밝기 조정), 근경 조약돌이 하단 탐색 위 문구와 겹쳐 읽기 어려울 때, 호버가 없는 터치 기기에서 '어둡기만 하다'는 반응이 있을 때, 계열이 고정된 크기로 우열처럼 읽힌다는 관찰이 있을 때(RK-025).
- **과정에서 나온 결함**: 타이포 조각의 클래스 `.t1`~`.t3`이 편지 카드 클래스와 겹쳐 베이지 상자가 보여 `.ty1`~`.ty3`으로 바꿨다(D-067 행).
- **등급**: 사용자 결정 + 측정 + 해석·디자인 판단.

#### 3.10.8 조약돌 아홉 개로 되돌림 (D-067 개정)

- **무엇을**: 오늘 화면 조약돌 개수를 처음 시안의 27개(계열마다 셋)에서 **계열마다 하나씩 아홉 개**로 되돌렸다(§3.10.7이 최종 값을 담는다). 크기는 원근 세 단계(먼 22px·중간 30px·가까운 42px, 상자 폭 360 기준)이고 아홉 계열은 세 밴드에 셋씩 고정 배정된다(먼 곳 희망·분노·혐오 / 중간 슬픔·기쁨·미움 / 가까운 곳 사랑·공포·즐거움).
- **왜**: 27개로 만든 시안을 본 사용자가 "너무 많다"고 정정했다(D-067 행). 처음 27개를 고른 이유(계열마다 셋을 세 밴드에 하나씩 나눠 놓아 어느 계열도 늘 크거나 늘 작지 않게 하려는 것, D-050·PR-010)는 유효했지만, 사용자는 개수 자체를 줄이길 원했다.
- **측정**: 흰 글자 on 숲 하늘 13.76:1·회색 길 6.72:1은 개수와 무관하게 그대로다. 구현은 `web/js/components/forest.js`의 `BAND_SIZE = [22, 30, 42]`로 확인했다.
- **기각한 대안**: 27개(계열마다 셋) 유지 — 사용자가 시안을 보고 명시적으로 정정했다.
- **남은 문제** (해석·디자인 판단): 계열마다 하나뿐이라 이제 각 계열이 고정된 한 밴드(크기)에 묶인다 — "어느 계열도 늘 크거나 늘 작지 않다"던 원래 방어가 약해졌다는 뜻이다. 이는 RISK_REGISTER RK-025(원근 조약돌이 우열로 읽힘)의 열린 위험과 같은 자리이고, 화면에서 눈으로 계속 판단한다.
- **등급**: 사용자 결정 + 측정 + 해석·디자인 판단.

#### 3.10.9 세부 감정 화면의 바구니 (D-068)

- **무엇을**: 세부 감정을 켜면 조약돌이 친구 발치의 더미(D-059 ②) 대신 **친구 옆 바구니 하나**(112×104px)에 담긴다. pill을 켜면 조약돌(32px, 모두 같은 크기)이 480ms 미끄러져 200ms 내려앉아 담기고, 끄면 180ms 동안 12px 올라오며 사라진다. 보이는 돌은 최대 9개이고 개수 글자·누적 표시는 없다.
- **왜**: 사용자가 "세부 감정을 선택하면 옆에 바구니 하나 둬서 바구니에 조약돌이 담기게" 요청했다. 직선으로 미끄러져 담기는 연출이라 D-050이 막은 포물선 던지기가 아니고, 돌을 세지 않아 수집·보상 금지 원칙을 지킨다.
- **측정**: 바구니 색(`--paper-ink` 72%에 `--text`를 섞음)은 배경 대비 혐오 3.47:1~기쁨 6.53:1이다(봉투의 꿀색만 쓰면 아홉 계열 300 배경과 1.0~1.6:1이라 보이지 않았다).
- **기각한 대안**: 봉투 꿀색 그대로(배경 위에서 보이지 않음), 포물선으로 던져 담기(D-050의 짐 연출 금지에 어긋남).
- **되돌리는 조건** (D-068 행): 혐오 계열에서 바구니 대비 3.47:1이 눈에 어둡거나 모자랄 때, 친구마다 폭이 달라 바구니와의 간격(4~42px)이 고르지 않은 것이 거슬릴 때, 실기기에서 개별 `translate`/`rotate` 속성(Safari 14.1+)이 안 통할 때.
- **등급**: 사용자 결정 + 측정.

#### 3.10.10 작성 화면마다 다른 이야기의 배경 (D-069)

- **무엇을**: 크기·이유·오늘 있었던 일·칭찬·감사·이대로 남길까요(편지) 여섯 화면 모두에 **화면마다 다른 이야기의 밝은 배경**을 둔다 — 크기 = '길 위의 친구'(회색 길이 슬라이더 트랙, 손잡이는 그 계열의 친구), 이유 = 줄 종이 노트 아래 '곁에 있는 친구들'(초록 언덕에 고른 친구들이 섬), 오늘 있었던 일 = '아침 길의 들머리'(막 뜨는 해·흰 길·시작하는 돌), 칭찬 = '쪽지와 해'(쪽지 셋과 높이 뜬 해, 고른 계열의 조약돌이 언덕에 놓임), 감사 = '노을과 등불'(끈에 꿴 카드 셋과 노을·등불, 조약돌 없음), 편지 = '낮의 창가 책상'. 어두운 장면은 오늘 화면 하나로 한정한다(D-061·D-062).
- **왜**: 사용자가 "얼마나 컸나요·이유도 스토리텔링 형식으로 UI/UX를 적용시키되 이유에서는 하단에 고른 캐릭터들이", "이대로 남길까요 화면은 좀 더 스토리텔링 형식으로 배경 등을 디자인", "나머지 화면들에서도 너무 정적이지 않게"를 요청했고, 이어서 "나머지 화면은 배경이 밝은 색이어야 해"라고 정정했다.
- **측정**: `check-contrast` 331건 통과(언덕·편지·편지 책상·이유 노트 검사 포함). 책상 위 ink 캡션 13.2:1, 안 켜진 페이저 점(ink 50%) 3.06:1(비텍스트 3:1 기준).
- **기각한 대안**: 편지 배경은 처음 **밤의 책상**, 다음 **황토빛 나무 책상**이었으나 둘 다 사용자의 '밝은 배경' 기준에 화면 절반이 어두워 **옅은 민트 책상**(`land.hill-far`와 흰색을 섞은 색)으로 정정했다. 감사 화면에도 조약돌을 놓는 안은 칭찬 다음 화면에 또 놓이면 '쌓인다'로 읽힐 위험(D-050)이 있어 기각했다.
- **되돌리는 조건** (D-069 행): 크기 화면의 '길'이 슬라이더임을 못 알아보는 관찰이 있을 때, 칭찬 화면의 조약돌을 '누적'으로 읽는 사용자가 있을 때(D-050), 옅은 민트 책상에서 봉투가 '눌러 열 수 있는 것'으로 안 읽힐 때, 360×640에서 편지 묶음이 89px 스크롤되는 것이 문제가 될 때.
- **등급**: 사용자 결정 + 측정 + 에이전트 판단.

#### 3.10.11 달력·통계·설정은 밝은 탭 (D-070)

- **무엇을**: 달력·통계·설정 세 화면은 **밝은 바탕과 원래 하단 탐색**(ink 알약+민트 blob)을 쓴다. 어두운 숲+유리 탐색은 오늘 화면 한 곳뿐이다. 무드 통일은 색이 아니라 짜임으로 한다 — 달력의 큰 제목 짜임, 통계 친구 길 끝의 '나의 돌'(오늘 화면 가운데 돌의 쉬는 모습, 34px, 정적), 진입 연출 1회(달력·설정 섹션 240ms, 통계는 친구가 400ms 걸어옴, 반복 움직임 없음).
- **왜**: 사용자가 처음 "달력과 통계 화면도 메인화면에 맞게"라고 했고, 작업자가 이를 오늘 화면과 같은 어두운 숲+유리 탐색으로 확장해 시안을 만들었다. 사용자가 "나머지 화면은 배경이 밝은 색이어야 해. 네비게이션도 원래 것 쓰게"라며 흰 바탕 통계 시안을 첨부해 바로 정정했다.
- **측정**: 이 결정은 기존 밝은 화면의 토큰·탐색을 그대로 재사용해 새 대비 수치가 없다.
- **기각한 대안**: 달력·통계·설정을 오늘 화면과 같은 **어두운 숲+유리 탐색**으로 옮긴 안(작업자 시안) — 사용자 정정으로 기각했다.
- **되돌리는 조건** (D-070 행): 나의 돌이 흰 바탕에서 옅어 보일 때, 달력 칸이 320px 폭에서 39.7px로 좁을 때(설계 최소 폭은 360px).
- **등급**: 사용자 결정(정정).

#### 3.10.12 세부 감정 화면의 연한 배경 (D-071)

- **무엇을**: 세부 감정 화면 배경을 계열 300 하나(D-053)에서 **그 계열 100과 50을 6:4로 섞은 더 연한 색**으로 바꾼다. pill은 300을 흰색에 45% 섞은 색+안쪽 윤곽선 1px. 오류 문구는 중립 글자+'!' 표지로 바꾼다. 편지의 감정 카드는 그대로 300이다(D-063).
- **왜**: 사용자가 "감정 선택 화면에서는 각 감정 캐릭터의 메인색보단 살짝 연하게 배경 색을 함으로써 캐릭터가 잘 보이게" 요청했다.
- **측정**: 친구 몸 색과 배경의 색차(ΔE)가 300 배경에서는 최소 8.6(공포)이었는데 연한 배경에서는 최소 16.6(희망)으로 벌어졌다. ink 글자 대비 12.5:1 이상, pill 위 11.2:1 이상(`check-contrast`). `danger` 원색은 감정 배경 위 2.2~4.2:1이라 오류 문구에 원색을 그대로 쓰지 않는다.
- **기각한 대안**: 계열 300 그대로 유지(친구 몸 색이 배경에 묻힘), 100 단독(6:4 혼합보다 검증이 부족해 택하지 않았다).
- **되돌리는 조건** (D-071 행): 색 존재감이 너무 약해 계열을 알아보기 어렵다는 반응이 있을 때(6:4 혼합을 100 쪽으로 옮긴다), 특정 계열에서 친구가 여전히 묻힐 때.
- **등급**: 사용자 결정 + 측정.

#### 3.10.13 오늘 화면 — 숲 속 안 (D-072)

### 3.12 2026-09-24 피드백 묶음에서 에이전트가 판단한 것 (D-084·D-085·D-086)

사용자가 13건(D-077~D-083)에 이어 오후에 세 가지를 더 요청했고, 셋 다 "질문하지 말고 판단"하는 범위로 맡겼다. 요청별 사용자 선택은 각 결정 행에 있고, 여기에는 에이전트가 고른 방식과 버린 대안만 적는다.

#### 3.12.1 오늘 숲 — 한 색 하늘과 세 겹 앞뒤 (D-084)

- **무엇을**: 하늘을 `forest.sky` #0B1228 한 색으로 칠한다(세 정지점·빛줄기·지평선 흰 번짐·민트 안개 띠를 걷는다). 숲을 먼·가운데·가까운 세 겹 SVG로 나누고 조약돌을 자기 깊이의 겹 사이에 끼운다. 길은 먼 땅선에서 멈추고 작은 나무 둘 뒤로 사라진다. 가장자리 큰 소나무는 가지를 올려 발치가 보이게 하고 길 밖에 세운다. 조약돌 아홉은 그 깊이의 땅이 실제로 보이는 자리에 손으로 둔다.
- **왜(진단)**: 사용자가 네모 친 길 끝의 밝은 사각형은 y 300~410에 가로로 깔린 민트 안개 띠와 지평선 흰 번짐이 겹친 것이었다(직사각형 안개라 모서리가 그대로 보였다). 길 끝은 먼 나무 위에 덧칠돼 하늘로 솟아 보였다. 조약돌은 모든 나무 위의 한 층이라, 원근으로 뒤에 있어야 할 돌이 앞쪽 큰 소나무 잎 위에 떠 있었다. 평면 그림에서 앞뒤를 알려 주는 단서는 가림(occlusion)과 바닥 위치뿐이다. 둘이 서로 어긋나면 돌이 나무에 붙은 스티커처럼 읽힌다.
- **판단**: 겹침 자체는 허용하되 **가림의 방향이 원근과 맞는 겹침만** 남겼다. 가운데 돌이 가운데 나무 줄기 앞에 서는 것처럼, 바닥이 더 아래(가까이)인 것이 앞에 온다. 그 기준으로 조약돌마다 '그 깊이의 땅이 실제로 보이는 곳'을 계산해 자리를 정했다. 가장자리 큰 소나무의 발치에는 땅이 보이지 않아 가지를 올렸다. 오래된 소나무의 높은 첫 가지는 자연스럽다. 그 소나무가 길 위에 서지 않도록 길 밖으로 옮겼다.
- **기각한 대안**: 조약돌을 모두 길 위로 옮기기 — 돌이 가운데 돌과 경쟁하고 "숲에 묻혀 있다"(D-067)는 뜻이 사라진다. 가까운 조약돌을 크게 키워 화면 가장자리 앞에 두기(전경 액자) — 크기 우열처럼 읽히고 글로시 돌이 화면을 지배한다. 가장자리 소나무 없애기 — 숲 속 안(D-072)의 액자가 사라진다. 하늘 그라데이션 유지 — 사용자가 '단색으로만'이라고 했다.
- **측정**: check-contrast PASS — 하늘 한 색이 감정 색 700·900과 ΔE ≥7(가장 가까운 미움900 8.1), 먼 나무와 ΔE ≥10, 흰 글자 18.56:1. 로딩·오류·이어 쓰기·어제 글·기록 있음 상태의 안내 글이 숲 겹 위에 뜨는지 elementFromPoint로 확인했다. 375×740·375×812·360×640 캡처로 비교했다.
- **비용**: 가까운 조약돌이 화면 아래 모서리로 내려가 이전보다 작게 느껴질 수 있다. 360×640에서는 먼 조약돌이 큰 질문 글자 옆에 붙는다(가리지는 않는다).
- **되돌리는 조건** (D-084 행): 가까운 조약돌이 잘 안 보인다는 반응, 숲이 더 어둡게 느껴진다는 반응.
- **등급**: 사용자 요청 + 진단 측정 + 디자인 판단.

#### 3.12.2 편지 배경 — 마음의 숲 속 빈터 (D-085)

- **무엇을**: 편지 화면(이대로 남길까요·기록 상세)의 창가 책상 장면(D-069)을 '마음의 숲 속 빈터에서 나에게 보내는 편지를 열기 직전'으로 바꾼다. 흰빛에서 민트로 이어지는 한 장면이고, 네 모서리의 낮은 대비 둥근 나무가 빈터를 둘러싼다. 봉투 뒤 흰빛과 가장자리 비네트가 시선을 봉투로 모은다. 그날 고른 계열의 감정 조약돌은 캡션 아래 땅에 좌우 대칭의 얕은 호로 무광으로 놓는다.
- **왜**: 사용자는 배경에 '의미'를 요구했고, 이어서 '심리적으로 안정적이고 몰입감 있게, 저자극적이고 차분하게, 특정 감정을 강하게 유도하지 않게'를 요구했다. 기록의 마지막 장면은 자기 성찰의 자리다. 그래서 사물(해·길·나비·연필)을 빼고 빛과 여백으로 둘러싸인 빈 곳을 만들었다. 시선은 봉투 하나에 모이고, 조약돌은 그날 다녀간 마음이 발치에 조용히 놓인 모습이다. 계열 색이 화면을 물들이지 않게 조약돌은 채도를 낮춘 작은 돌로만 둔다(D-053·D-071).
- **기각한 대안**: '오늘 걸어온 길의 끝, 언덕 위의 편지'(1차 시안) — 흰 길이 깔때기처럼 시선을 끌고, 땅 패널의 가로 이음매와 흰 옆면이 생겼다. 사용자가 방향을 '숲 속 빈터'로 바꿨다. 창가 책상에 조약돌 두기 — 카드를 열면 창턱이 가려 뜻이 사라진다. 그날 감정 색의 번짐(오라) — 감정 카드의 색과 겨룬다.
- **비용·주의**: 원본 조약돌 그림이 광택 있는 그림이라, 필터만으로는 '장난감' 인상이 완전히 빠지지 않는다(원본 불변 제약). 나무 실루엣은 저자극을 위해 옅게 두어 작은 화면에서는 거의 그러데이션으로 읽힌다. 조약돌이 모으는 물건처럼 읽히지 않게 그날 고른 것만 놓는다(BRAND_STORY §5).
- **측정**(2026-09-25, Sub-A A5 + 메인 재측정):
  - 장면 밝기의 표준편차가 51.5에서 24.8로 내려갔다.
  - 흐림 처리한 밝기 최댓값이 봉투 중심에서 수평 7.5px 안쪽에 있다.
  - 가장자리 흰 띠가 없고(차 1.9~8.9), 행 사이 급격한 선이 없다.
  - 조약돌 무늬가 알파 밖을 칠하지 않는다(네 모서리 ΔE 0.000).
  - 조약돌과 캡션·봉투·버튼 줄의 겹침이 0이다.
  - 360~1280폭에서 가로 넘침이 0이다.
  - 숫자↔카드 간격 20px과 A1 28조합 회귀가 모두 통과했다.
  - 메인 재측정에서 1차의 결함 셋을 잡아 고쳤다: 잔결의 네모 상자, 떠 있는 그림자, 캡션을 감싸는 목걸이 배치.

#### 3.12.3 통계 크기 추세 — 감정마다 따로, 이견 없는 통계만 (D-086)

- **무엇을**: 모든 감정을 한데 평균 낸 '평균 크기' 칸과 전체 추세선을 없앤다. 계열마다 작은 차트 한 줄(small multiples)에 날마다의 크기, 평균(n≥3), 범위, n을 보인다. 지난 같은 길이 기간과는 규칙에 맞을 때만 '높아요/낮아요/비슷해요'로 비교한다. 규칙은 두 기간 n≥3이고, 차이가 1.0 이상이면서 Welch t 95% 기준으로 흔들림보다 클 때다. '읽는 법'을 접어 둔다.
- **왜**: 사용자는 "심리학적 요소를 넣되 거의 공통적으로 쓰이는 의심의 여지 없는 것들로, 냉철하게"를 요구했다. 그래서 해석이 갈리는 지표를 빼고 **이견 없는 원칙만** 남겼다.
  - ① 서로 다른 구성개념은 한데 평균 내지 않는다(기쁨 7과 슬픔 3의 평균 5는 어느 마음의 크기도 아니다). 한 숫자로 된 전체 평균은 기분 점수처럼 읽히는데, 이는 DESIGN_SYSTEM §6.10과 SERVICE_WHY §12가 금지한다.
  - ② 기록 없는 날은 0이 아니다(PRD §10, DATA_MODEL §7).
  - ③ 적은 표본을 과하게 읽는 경향이 있으니(작은 수의 법칙) n을 늘 보이고 평균은 3일부터 보인다.
  - ④ 감정 동학 연구에서 가장 기본적이고 이견 없는 기술치는 수준(평균)과 변동(범위·표준편차)이다. 관성(자기상관)·세분화 지수 같은 복합 지표는 해석이 갈리고, 평균·변동 이상의 정보를 거의 더하지 않는다는 보고도 있어 쓰지 않는다(SERVICE_WHY §19.9).
  - ⑤ 하루를 돌아보며 매긴 크기는 회고 자기보고라, 절정과 끝에 끌린다(peak-end). '읽는 법'에 이 한계를 적는다.
  - ⑥ 유난히 높거나 낮았던 기간 다음에는 평소 쪽으로 돌아오기 쉽다(평균으로의 회귀). 그래서 방향을 말하는 문턱을 두 겹으로 둔다: 통계적 문턱은 Welch t 95%, 실제적 문턱은 차이 1.0이다. 날마다의 값은 서로 독립이 아니어서 표준오차가 작게 잡히는데, 1.0 문턱이 이를 보완한다.
  - 기간 평균을 날 단위로 내는 것은, 세부 감정을 많이 고른 날(낱말 수)이 크기 평균에 더 무겁게 들어가지 않게 하려는 것이다. DATA_MODEL §7의 '해당 category 선택 행의 산술평균'을 이렇게 정밀화한다.
- **기각한 대안**: 전체 평균 유지 — 위 ①. 한 차트에 아홉 선 겹치기 — 읽을 수 없다(스파게티 차트). 작은 차트를 나란히 두는 것이 여러 계열 비교의 표준이다. 기간 안 추세 기울기(회귀·Theil–Sen) — 7일에 점 3~7개로는 기울기가 흔들리고 사용자에게 설명하기 어렵다. 가장 컸던 날 링크 — 힘든 날로 돌아가 곱씹게 만들 수 있어 넣지 않았다(SERVICE_WHY §11). 변동을 표준편차 숫자로 보이기 — 사용자에게 추상적이라 범위로 대신했다.
- **비용**: 비교 문장이 '비슷해요'로 자주 나올 수 있다(보수적인 문턱의 의도된 결과). 계열이 많으면 줄이 길어진다.
- **되돌리는 조건** (D-086 행): 비교 문장이 거의 늘 '비슷해요'라 쓸모없다는 반응, 줄이 길어 끝까지 보지 않는다는 관찰.
- **등급**: 사용자 요청(위임) + 통계 원칙 + 해석·디자인 판단. 참고한 문헌은 이번 결정에서 원문을 다시 확인하지 않았다 — Tversky & Kahneman(1971, 작은 수의 법칙), Kahneman 외(1993)·Redelmeier & Kahneman(1996, peak-end), Kuppens & Verduyn(2017, 감정 동학 개관), Dejonckheere 외(2019, 복합 감정 동학 지표의 추가 설명력), Barnett 외(2005, 평균으로의 회귀), Welch(1947). 외부 발표·문서에 인용하려면 원문을 먼저 확인한다(SERVICE_WHY §19).

### 3.13 2026-09-24 오후 피드백 — 오늘·완료·작성 흐름·달력·설정 (D-077~D-083)

사용자가 2026-09-24 오후에 열세 건(D-077~D-083)을 한 번에 요청했다. §3.12(D-084~D-086)와 달리 이 열세 건은 대부분 사용자가 화면을 짚어 직접 고른 것이다. 요청 원문과 전체 측정은 각 결정 행에 있고, 여기에는 왜 그 형태를 골랐는지와 기각한 대안만 요약한다. D-079의 이유 화면 자유 배치(②)는 이번 절에 넣지 않는다 — 화면 반영이 진행 중이라 DESIGN_SYSTEM·UX_SPEC에는 "반영 중" 표시만 남겼다.

#### 3.13.1 오늘 화면 — 밤하늘과 알림 한 줄로 합치기 (D-077)

- **무엇을**: 하늘을 짙은 남색으로 바꾸고, 가운데 돌을 누르면 조약돌이 은은하게만 켜지게 하며, 흰빛 확산을 1500→1200ms로 줄이고, 위쪽 유리 알림 배너를 없애 돌 위 한 줄('오늘 마음을 아직 남기지 않았어요')로 합친다.
- **왜**: 사용자 요청 넷 — "숲의 밤하늘이 왜 초록색인지 모르겠어. 밤하늘 색으로 바꿔", "가운데 돌을 클릭하면 뒤에 감정 돌들이 좀 더 연하게 빛나게", "흰색 화면으로 넘어가는 속도 조금만 더 빠르게", "오늘 마음을 아직 남기지 않았어요… 없어도 되지 않는지 생각해봐". 하늘이 초록으로 보인 원인을 진단하니 하늘과 나무의 색차가 ΔE 1~3에 불과해 하늘이 숲에 묻혔기 때문이었다. 밝은 남색(#101A3A)은 미움900과 ΔE 3.6이라 감정 색으로 읽힐 위험이 있어 후보에서 뺐고, 사용자가 짙은 남색(미움900과 ΔE 8.1)을 골랐다. 배너는 PR-011의 유일한 MVP 인앱 알림이라 지우지 않고 돌 안내에 흡수했다(사용자 선택) — 알림을 완전히 없애자는 요청이 아니라 "없어도 되지 않는지 생각해 보라"는 위임이었기 때문이다.
- **측정**: 흰 글자 on 하늘 18.56:1, 하늘 대 아홉 계열 700·900의 최소 ΔE 7.70(미움900), 하늘-먼 나무 ΔE 21.6(check-contrast에 두 검사 추가). 돌 클릭부터 작성 화면까지 1596ms(이전 1820ms).
- **기각한 대안**: 밝은 남색(#101A3A) — 미움과 너무 가까워 감정 색으로 읽힘. 알림을 완전히 삭제 — 유일한 MVP 인앱 알림이라 남기되 형태만 바꿈.
- **되돌리는 조건** (D-077 행): 밤하늘이 어두워 숲 윤곽·큰 질문이 묻힌다는 반응, 하늘이 미움 계열로 읽힌다는 반응, 알림 문구를 놓친다는 관찰.
- **등급**: 사용자 결정(네 차례 요청) + 측정.

#### 3.13.2 완료 화면 — 자유 배치와 두 버튼 (D-078)

- **무엇을**: 완료 화면의 친구를 마음 고르기처럼 인원마다 손으로 정한 자리에 자유롭게 세우고(4~9명 88px, ±7° 기울기, 줄마다 엇갈림), 제목 아래 글자 링크와 '오늘로 돌아가기'를 없애고 아래 [달력 보기(보조)][통계 보기(주)] 두 버튼으로 바꾼다.
- **왜**: 사용자 요청 — "완료화면에서 캐릭터들이 3*3으로 정직하게 배치되는 거 같은데 자유롭게 배치되게 해줘. 오늘은 어떤 마음이 머물렀나요? 화면을 참고하되 캐릭터 크기는 조금 키워서", "오늘로 돌아가기 버튼을 빼고 달력 보기랑 통계 보기를 하단 버튼으로". 크기(4명 이상 88px)와 버튼 위계는 사용자가 직접 골랐다.
- **1차 배치를 되돌린 이유**: 1차 배치는 겹침이 0이었지만 6~9명일 때 같은 세로줄로 연달아 서서 **기울어진 3×3 격자**처럼 읽혔고, **9명일 때 조약돌이 하늘에 떠 보였다** — 둘 다 사용자가 없애 달라고 한 "정직한 3×3"의 다른 얼굴이라 되돌려, 줄을 엇갈리게 하고 조약돌을 항상 땅 위 자기 친구 발치로 고정했다.
- **측정**(그림 픽셀 기준): n=1~9 × 375×812·360×740 18개 조합 모두에서 친구끼리 6px·친구↔조약돌 3px 이상 떨어짐, 해 고리·버튼 줄 침범 0, 조약돌 모두 땅 위·자기 친구 발치 한도 안.
- **기각한 대안**: 3×3 고정 격자 유지 — 사용자가 "정직하다"며 반려. 4명 이상을 계속 104px로 줄이며 세 칸씩 정렬 — 1차 배치에서 이미 이 방식이 겹침 문제를 낳아 88px 고정+자유 배치로 바꿨다.
- **되돌리는 조건** (D-078 행): 9명일 때 빽빽하다는 반응, 버튼 둘 중 한쪽만 쓰인다는 관찰.
- **등급**: 사용자 결정(두 요청) + 측정.

#### 3.13.3 작성 흐름 — 크기 미정 시트와 편지 카드 (D-079 ①③)

- **무엇을**: 대표 크기를 정하지 않은 계열이 있으면 시트로 알리고(①), 편지 카드를 화면 높이에 맞춰 376~448px로 키우며 세부 감정 알약은 36px(1~4개, 한 열)·32px(5~8개, 두 열) 두 단으로 고정하고 9개 이상은 8개씩 이어지는 카드로 넘긴다(③).
- **왜**: 사용자 요청 — "감정 크기 정하는 칸에서 크기 정하지 않았다면 팝업으로 어디 감정의 크기가 정해지지 않았다고", "이대로 남길까요 화면에서는 각 카드들의 크기가 더 커도 좋을 거 같고, 세부 감정이 많아지면 1열로 쭉 길게 하고 너무 작아서 보이지도 않아… 기준을 명확하게". "행을 늘리고"가 여러 열로 나눈다는 뜻임을 되물어 확인했다.
- **측정**: 4계열·알약 25개인 편지를 375×812·360×740·360×640에서 확인 — 카드 수=점 수, 알약 최소 14px, 카드 밖·겹침·구분선 넘김 0, 812·740에서 세로 스크롤 0. 360×640 작성 모드의 89px 겹침은 그대로 남는다(RK-030 — 알약 36px 최소 높이 때문에 카드를 376px 밑으로 줄이지 않기로 했다).
- **기각한 대안**: D-074 ①의 "개수에 따라 다 같이 줄어드는" 공식 — 계열이 9개 이상으로 늘면 글자를 읽을 수 없어지는 것을 감수하고 스크롤 없음을 우선했던 안이다. 이번에 "기준을 명확하게"라는 요구에 맞춰 두 단 고정+이어지는 카드로 바꿨다.
- **되돌리는 조건** (D-079 행): 이어지는 카드를 넘기지 않고 남기는 비율이 높을 때, 좁은 화면에서 알약이 넘친다는 관찰.
- **등급**: 사용자 결정(두 요청) + 측정.

#### 3.13.4 달력 — 주 접기와 인라인 편지 (D-080)

- **무엇을**: 날짜를 누르면 시트 대신 그 주 한 줄로 접히고 편지가 인라인으로 열리게 하며, 통계 친구 걸음을 느리게 한 번만 걷게 하고, 활성 탭 아이콘의 실루엣 결함을 고친다.
- **왜**: 사용자 요청 — "달력에서 날짜를 클릭하면 밑에 남은 화면에서 그 일기를 편지 형식으로 볼 수 있게", "통계 화면으로 들어가면 각 감정들이 그래프에서 우측으로 이동하는 속도가 너무 빨라", "달력 네비게이션이 선택될 때 실루엣만 보이는 현상". 시트 대신 인라인을 고른 것은 사용자의 요구를 그대로 구현하며 발견한 제약 때문이다 — 달력 아래 빈자리가 125~160px뿐이라 편지(376px)가 시트 없이는 들어가지 않아, 한 주로 접어 자리를 만드는 방식을 택했다.
- **측정**: 375×812 접힌 상태에서 스크롤 0, id 중복 0, 고른 날 `aria-pressed` 1개, region 이름 "9월 11일의 편지". 활성 달력 머리띠 줄 mint 102/170px(2배 크기).
- **기각한 대안**: 시트를 유지하고 안에 편지를 축소해 넣기 — 빈자리 부족으로 편지가 읽기 어려운 크기까지 줄어들어 기각했다.
- **되돌리는 조건** (D-080 행): 접힌 주에서 주를 자주 넘겨 스와이프가 필요하다는 관찰, 걸음이 느려졌다는 반응.
- **등급**: 사용자 결정(세 요청) + 측정.

#### 3.13.5 하루 기준 시각과 알림 조건 (D-081)

- **무엇을**: 설정에 PRD 필수인데 빠진 자리(알림 시각·시간대·개인정보·백업 지연 고지·위기 연락처 자리·내보내기 범위·접근 끊기)를 채우고, 하루 기준 시각(기본 새벽 4시, 0~6시에서 선택)을 더한다. 알림 문구는 켜짐+설정 시각 이후+오늘 기록·쓰던 글 없음일 때만 보인다.
- **왜**: 사용자가 "설정에는 추가적으로 더 설정에 있어야 하는 것들이 뭐가 있는지 생각해줘"라고 위임했다 — PRD 필수 항목과 대조해 빠진 자리를 찾고, 자정을 넘겨 쓰는 사람에게 "오늘"이 어제 밤이 되는 문제를 막을 하루 기준 시각을 새 범위로 제안해 사용자가 받아들였다. 알림 표시 조건도 사용자가 골랐다 — 아침부터 "아직 안 남겼다"고 재촉하지 않는다는 것이 SERVICE_WHY 원칙 4(기록은 의무가 아니다)와 맞는다.
- **기각한 대안**: 하루 기준 시각을 자정으로 고정 — 사용자별로 잠자리 습관이 달라 0~6시 범위를 허용했다. 알림을 기록 없음 여부와 무관하게 항상 표시 — 이미 기록·쓰던 글이 있으면 그 상태 자체가 알림이라 중복을 피했다.
- **되돌리는 조건** (D-081 행): 하루 기준 시각을 바꾸는 사용자가 거의 없을 때, 새벽 기록의 날짜가 헷갈린다는 반응.
- **등급**: 사용자 위임(설정 항목 선정) + 사용자 결정(알림 조건).

#### 3.13.6 새 기록은 그날만 — 소급 작성 폐지 (D-082)

- **무엇을**: 작성 첫 단계의 날짜 칸과 달력의 "이 날 쓰기"를 없애 새 기록은 그날만 쓰게 한다. 그날 시작한 임시저장은 기한 없이 이어 써서 마무리할 수 있고, 쓰던 글 지우기는 2단계로 확인하며, 저장 실패·연결 끊김에는 탭이 열린 동안만 sessionStorage에 임시 보관한다.
- **왜**: 사용자가 "그 날 쓰지 못한 일기는 못쓰게 하는거 어떻게 생각해?"라고 물었고, 그날의 마음을 그날 붙잡는 제품 초점(지난 날을 떠올려 쓰는 회고 편향을 줄인다)에 동의해 소급 작성을 없앴다. 시작한 글의 무기한 마무리 허용, 지우기 2단계, 임시 보관 범위는 위임된 세부 결정이다.
- **치르는 값**: 벤치마크 자료(`docs/research/benchmark-2026-09-analysis.md`)는 지난 날짜 입력을 시장의 기본 기대(P0)로 본다. 이 기대를 알면서도 포기한 것이다 — 회고 편향을 줄이는 제품 초점이 시장 관행보다 우선한다고 판단했다. 대신 SERVICE_WHY 원칙 4("기록하지 못한 날은 실패가 아니다")를 지키기 위해 빈 날에 "못 썼다"·"놓쳤다"는 말을 쓰지 않는다.
- **측정**: 달력에서 시작해 편지를 남긴 뒤 뒤로 가기 1번이면 달력, 2번이면 그 앞 화면으로 돌아감을 확인. 지난 날 마무리 경로의 화면 글자에 "오늘" 0개. 새로고침 뒤 복구 확인.
- **기각한 대안**: 소급 작성 유지 — 벤치마크의 P0 기대와 맞지만 회고 편향 문제를 그대로 둔다. 제한적 소급 허용(예: 3일 이내) — 사용자가 "그 날 쓰지 못한 일기는 못쓰게"라고 명확히 그날만으로 요청해 절충안을 쓰지 않았다.
- **되돌리는 조건** (D-082 행): 지난 날을 쓰고 싶다는 요청이 반복될 때, 이 규칙 뒤 기록 이탈이 늘 때.
- **등급**: 사용자 결정 + 벤치마크 근거를 명시적으로 포기(치르는 값).

#### 3.13.7 로딩·오류·연결 끊김과 없는 기록 주소 (D-083)

- **무엇을**: 오늘·달력(인라인 편지 포함)·통계·기록 상세에 불러오기·오류·연결 끊김 상태를 두고(오늘 기록을 확인 못 하면 가운데 돌을 누를 수 없다), 작성 흐름에는 "저장 안 됨" 띠와 연결 끊김 표시를 둔다. 없는·미래 날짜의 기록 주소는 "이 날의 편지가 없어요"를, 빈 달력은 짧은 안내 한 줄을 보인다. 글자가 125% 이상이거나 실측 겹침이 생기면 자유 배치를 격자로 바꾼다(③, 반영 중).
- **왜**: 사용자가 "모든 화면에서의 예외처리도 생각해야 해. 어떤 예외를 처리해야할지 생각하고 결정 필요한 것들 모두 질문해"라고 요청했다 — 로딩·오류를 둘 화면의 범위(주요 화면 전부)와 큰 글자에서의 격자 전환을 사용자가 골랐다. 오늘 화면에서 돌을 막는 이유는 확인 없이 새로 시작하면 하루 하나 규칙을 어길 수 있기 때문이다(에이전트 판단, 데이터 무결성 우선).
- **기각한 대안**: 명시적으로 검토해 기각한 대안은 결정 행에 없다 — 질문형 요청에 대해 예외 상태의 범위 자체를 답으로 제안하고 사용자가 승인한 흐름이었다.
- **되돌리는 조건** (D-083 행): 로딩이 길어 뼈대가 오래 보인다는 관찰, 격자 전환이 너무 이르거나 늦다는 반응.
- **등급**: 사용자 위임(질문에 답하는 형태) + 데이터 무결성 판단(돌 비활성화).

### 3.14 2026-09-25 — 달력 한 달 + 편지 미리보기, 이어지는 전환 (D-088·D-089)

#### 3.14.1 달력: 한 달을 접지 않고 미리보기 종이로 (D-088)

- **무엇을**: 날짜를 눌러도 한 달은 그대로 두고, 달 아래 남는 자리에 그날의 줄 노트 미리보기를 둔다. `펼쳐 읽기`를 누르면 그 자리에서 종이가 편지 카드로 바뀌고 달은 그 주 한 줄로 접힌다.
- **왜**: 사용자가 '달력이 한번에 다 보였으면', '아래 빈 공간을 왜 안 쓰나'라고 지적했다. 빈 자리의 원인은 두 결정이 겹친 것이다. 편지 카드의 높이 상한(376~448px, D-079)과 375×812 기준으로 정한 '항상 한 주로 접기'(D-080)가 화면 높이를 보지 않았다. 질문 세 개로 방향을 정했고, 사용자는 세 질문 모두 추천안을 골랐다. 근거는 넷이다.
  - 개요 먼저·세부는 원할 때(Shneiderman): 한 달은 늘 보이고, 편지는 원할 때 펼친다.
  - 공간 기억: 달의 모양이 유지돼 어느 날이 어디 있었는지 잃지 않는다.
  - 정보 냄새: 미리보기가 조약돌·감정·첫 줄로 누를 가치를 먼저 알려 준다.
  - 연속 전환: 같은 종이가 모양을 바꿔 맥락이 끊기지 않는다.
- **기각한 대안**:
  - 화면 높이에 따라 자동 — 휴대폰(812)에서는 여전히 접혀 기기마다 동작이 달라진다.
  - 끌어올리는 시트 — D-080에서 시트를 쓰지 않기로 했고, 끄는 동작을 모르면 놓친다.
  - 닫힌 봉투 미리보기 — 세계관은 강하지만 열기 전에는 무엇을 썼는지 보이지 않는다.
  - 감정 카드 축소판 — 작아지면 알약과 점이 빽빽해진다.
- **1차 시안에서 고친 것**: 첫 구현은 빈 공간을 테두리 친 카드 안으로 옮겼을 뿐이었다(네 상태 모두 가운데가 텅 빔). 그래서 모든 상태를 이유·사건 화면과 같은 **줄 노트 종이**로 통일하고, 남는 높이를 빈 줄로 채웠다. 기록 없는 날은 '비워 둔 종이'로 보인다(SERVICE_WHY §11: 기록하지 않은 날은 실패가 아니다). 펼침 전환 중 옛 글자가 새 카드 위에 겹쳐 보이던 것도 고쳤다.
- **측정**(메인 재측정 포함):
  - 375×812·360×740·1280×900에서 한 달 6줄이 다 보이고 탐색과 겹치지 않는다. 375×812는 스크롤 0이다.
  - 카드 안에서 줄도 글도 없는 빈 구간은 13~21px(줄 간격 32px 미만)이다.
  - 펼침·닫기·뒤로 가기·주소 직접 열기가 모두 기대 상태이고, 콘솔 오류 0, 가로 넘침 0이다.
  - 오늘 칸의 모양과 aria-current가 전과 같다.
- **비용·주의**: 360×640에서는 줄 노트 자리가 한 줄보다 작아 완료한 날에도 글이 안 보일 수 있다(스크롤로 미리보기까지 이동한다). 미리보기의 첫 줄이 옆 사람에게 보이는 상황은 사용 반응을 보고 숨김 설정을 검토한다.
- **등급**: 사용자 요청 + 질문으로 확정.

#### 3.14.2 한 편의 영화처럼 — 이어지는 전환 (D-089)

- **무엇을**: 전환은 세 곳이다.
  - 작성 단계끼리: 제목과 장면만 옆으로 밀리며 바뀐다.
  - 남기기 뒤 봉인: 카드 → 봉투 → 뚜껑 → 인장 → 흰빛 → 완료.
  - 완료 → 달력: 오늘 칸에 조약돌이 잠깐 내려앉는다.
- **왜**: 사용자가 '자연스러운 하나의 영화처럼, 편지 열고 편지지 사라지는 것처럼'을 요청했다. 전환을 모두 편지를 여는 연출(D-063)과 같은 사물로만 만들어 새 은유를 들이지 않았다. 기록이 '남았다'는 결과는 봉인과 돌 한 개로만 보여 주고 쌓지 않는다(BRAND_STORY §5 '수집품이 아니다').
- **측정**: 전체 약 1.02초(2초 안), 저장 실패면 연출 없음, 연타 1회, 뒤로 가기 함정 회귀 없음, 오늘 칸 배경·테두리가 0~2500ms 모든 시점에서 기준과 같다, 움직임 줄이기 즉시.
- **재작업에서 잡은 것**:
  - 봉인 뒤 완료 화면이 작게 그려졌다. 원인은 큰 글자 격자 판단의 켜짐/꺼짐 반복이었다.
  - 흰빛이 남아 있었다.
  - 조약돌이 오늘 칸의 완료 표시(`::after`)를 가로채 칸 모양이 뒤바뀌었다. 조약돌을 별도 고정 요소로 분리해 고쳤다.
- **등급**: 사용자 요청 + 디자인 판단(사용자 위임).

## 4. 사용자가 제공한 근거와 이 저장소에서의 상태

| 대화에서 사용된 근거 | 브랜드에 연결된 방식 | 근거 상태 |
| --- | --- | --- |
| 감정을 더 정확한 말로 알아차리고 기록·성찰하게 한다는 제품 목적 | "기록의 빛", 판단 없는 감정 선택, 기록을 통한 자기 이해 | PRD의 제품 원칙 |
| 행복은 즐거움뿐 아니라 만족·의미·관계·성장을 포함 | 빛을 단순 보상이 아니라 삶의 만족과 가능성의 상징으로 설정 | 사용자 제공 현대 행복심리학 요약 |
| 쾌락적 행복(Hedonia)과 실현적 행복(Eudaimonia)의 구분 | "기분이 좋아야만 행복한 건 아니다"라는 브랜드 태도 | 사용자 제공 철학·심리학 요약 |
| 자유는 선택권·자율성·행동 가능성·억압으로부터의 해방 | 숲의 길·여백·열린 공간을 자유의 메타포로 설정 | 사용자 제공 자유 개념 요약 |
| 자유는 행복의 조건일 수 있지만 행복 그 자체는 아님 | 자유=길과 공간, 행복=빛과 충만함으로 분리 | 사용자 제공 해석 |
| 자율성은 자신의 가치와 판단에 따라 결정하는 능력 | 앱·AI·친구가 사용자의 감정을 대신 정의하지 않음 | 사용자 제공 개념 + 제품 안전 원칙 |
| 직접 작성 글은 읽거나 스캔하지 않음 | 친구가 글에 반응하는 척하지 않고, AI 안내자도 글쓰기 화면에서 배제 | 제품 개인정보·안전 원칙 |
| 사람은 컴퓨터에도 사회적 규칙을 적용함 | 표정 있는 안내자를 AI의 얼굴처럼 두지 않음 | 대화에서 언급됐으나 원 논문은 이번 세션에서 재확인하지 않음 |
| 표현적 글쓰기는 혼자·비공개·피드백 없이 쓰는 맥락을 중요하게 봄 | 직접 작성 화면을 조용하게 하고 친구의 공감 연출을 제거 | 대화에서 언급됐으나 원문 검증 기록 없음 |
| 자연 장면의 회복 효과는 과장하면 안 됨 | 숲을 "치유 장치"가 아니라 세계관·여백의 메타포로 제한 | 대화에서 효과가 작고 단기적이라고 언급됐으나 원문 재확인 없음 |
| 표정의 보편성은 학계에서 논쟁적 | 감정을 화난 눈썹·울음·땀방울 같은 이모지 표정에 고정하지 않음 | Barrett 2019가 언급됐으나 이번 세션 원문 검증 없음 |
| 색각 이상에서 감정 색 구분이 무너질 수 있음 | 색만으로 감정·기록 상태·선택 상태를 전달하지 않음 | Machado 2009 시뮬레이션과 토큰 측정 기록 있음(§6) |
| 감정 색은 좋고 나쁨을 뜻하지 않음 | 분노·혐오도 같은 가치의 조약돌·친구·기록으로 남김 | PR-010 제품 원칙 |
| 스트릭·수집·성취 장치는 위기 상황과 충돌할 수 있음 | 조약돌은 컬렉션·레벨·희귀도·보상이 아니라 기록의 흔적 | 제품 안전 원칙 + 대화의 설계 판단 |

브랜드 문서에서 심리학적 사실처럼 단정해도 되는 것은 **제품 안전 원칙, 자율성·행복의 넓은 정의, 접근성 원칙** 정도다. "유년기로 돌아가면 감정을 더 잘 표현한다", "숲이 회복시킨다", "캐릭터가 표현적 글쓰기를 방해한다" 같은 문장은 현재로서는 브랜드의 해석·디자인 판단으로 써야 정확하다(BRAND_STORY §9).

## 7. 알려진 한계와 열린 문제

- 민트·하늘색 판단은 숫자와 화면 조각으로 했다. 실기기와 사용자 눈 검수가 남았다.
- 설이(슬픔)·숨이(공포)의 색 근접. 이름·실루엣으로 구분하며 색 조정은 후속 후보다.
- 글로시 조약돌과 평면 친구의 톤이 화면에서 어긋나 보이는지 미검증.
- 흰빛 연출(가운데 돌, D-062)의 반복 재생·reduced-motion·저사양 기기 동작은 미검증. *(이전: 크림빛 연출 — D-062가 흰빛으로 대체했다.)*
- 웹폰트 2.0MB의 첫 로드 영향(실기기·느린 네트워크)은 미검증. Phase 1에서 동적 서브셋으로 바꾼다.
- 오늘의 한 줄 질문 목록은 추후 계획이며 철학서 원문 대조는 하지 않는다.
- 이 개편 중 다른 세션이 같은 저장소에서 D-051(친구 확정)을 동시에 기록했다. 문서 번호(D-050, D-052~D-058)는 그 사이에서 이 개편이 잡은 것이다.

**무드 v4(§3.10)에서 남은 것**

- **D-066은 사용자 확인 대기(provisional)다.** 앞뒤 크기 깊이감을 원하는지, 격자(`#/write?pick=grid`)로 돌아갈지, 실기기 320px 폭에서 아홉 블록이 겹치지 않는지 정해지지 않았다.
- **근경 조약돌과 하단 탐색 문구의 겹침.** 오늘 화면의 가까운 조약돌이 하단 탐색 위 문구와 겹칠 수 있다. 가운데 돌과 문구·상태 칩 자리는 조약돌을 비워 두지만(코드 `blocked`), 글자 확대나 긴 문구(이어 쓰기 칩의 단계 이름 등)에서는 가장자리 돌과 닿을 수 있다(D-067의 재검토 조건, 화면으로 재현하지 않았다).
- ~~유리 탐색의 뒤 배경 의존~~ — D-076으로 오늘 화면의 탐색이 없어져 해소됐다. 남은 유리는 위쪽 알림 배너 하나다(글자는 흰색·청록 '나중에'). 이 배너도 D-077 ⑤로 돌 아래 글자 한 줄이 되어, 이제 화면에 유리는 없다.
- **마음 고르기 오류 문구의 대비 — 해결됨.** `danger` 원색은 초록 하늘 위에서 4.38:1로 4.5:1에 못 미쳐 ink 25% 혼합(6.2:1)으로 바꿨고 `check-contrast`가 이 쌍을 검사한다(§6).
- **PRD와의 관계 — 재확인.** PRD §6.3은 '흰색/중립 배경을 기본으로 하고 정해진 몇 화면만 예외로 색·장면을 넓게 쓴다(UX_SPEC §8)'고 이미 일반화해 적어 두어, 오늘 화면의 어두운 숲도 그 예외 하나로 문구상 포함된다 — 별도 PRD 수정은 필요하지 않다고 판단한다(2026-09-23 재확인, docs 작업자 D3). 다만 UX_SPEC §8 자체는 조약돌 개수·구현 중 표기가 낡아 있어 갱신이 필요하다(UX_SPEC은 이 작업자의 소유 파일이 아니다).
- **온보딩 첫 쪽 친구의 크기.** 언덕의 줄에 따라 폭이 54~116px(설계 상자 360 기준)로 다르다. D-061 ④의 '크기 모두 같다'는 완료 화면에 대한 규칙이고 온보딩은 명시가 없다 — '크기로 우열을 만들지 않는다'(D-066)와의 관계를 정해야 한다.
- **편지의 있었던 일과 이유 카드.** 글 자리를 고정값으로 놓고 넘침을 그대로 보이게 둔 코드라 긴 글에서 겹칠 수 있다. 코드 읽기로만 확인했고 화면으로 재현하지 않았다. D-063 ③의 '카드 안 세로 스크롤'과 맞는지 확인이 필요하다.
- **클래스 이름 충돌.** 새 부품의 클래스가 기존 것과 겹쳐 화면이 어긋난 일이 두 번 있었다(D-066 `.field`, D-067 `.t1`~`.t3`). 두 번 다 화면에서 눈으로 발견했다.
- **실기기 미검증.** iPhone Safari·Android Chrome에서 유리(backdrop-filter), 호버 없는 터치의 조약돌, 카드 스와이프, 흰빛의 눈부심은 확인하지 않았다.
