## 1. 만드는 방식

원자료(`references/source/*.jpg`)의 손그림 캐릭터를 **자르거나 그대로 쓰지 않고**, 같은 무드로 다시 생성한다. 생성기는 **codex imagegen**이고 프롬프트 정본은 [prompts.json](prompts.json)이다.

생성 경로는 **codex imagegen 직접 호출 하나뿐이다.** 별도의 이미지 생성 스킬·플러그인이나 외부 이미지 API는 도입하지 않는다. `prompts.json`의 공통 프롬프트로 캐릭터별 최종 프롬프트를 먼저 만들고, 그 묶음을 codex imagegen에 **한 번에** 넘겨 생성한다.

- 공통 스타일 프롬프트(`common_style_prompt`)와 금지 프롬프트(`negative_prompt`)는 7종에 **똑같이** 붙인다. 여기에 각 캐릭터의 `subject_prompt`만 이어 붙인다.
- **7종을 한 번에, 같은 seed로 생성한다.** 한 개만 나중에 다시 만들면 선 굵기와 채도가 어긋나 카테고리 토글에 나란히 놓았을 때 티가 난다. 한 개를 고쳐야 하면 7종을 다시 만든다.
- 프롬프트를 고치면 `prompts.json`의 `version`을 올리고 7종을 다시 생성한다.

## 2. 파일 규격

| 위치 | 크기 | 용도 |
| --- | --- | --- |
| `src/<key>-1024.png` | 1024×1024 | 생성 원본. 검수와 재생성 기준으로 저장소에 보관한다 |

크기를 줄일 때(예: ImageMagick):

```bash
magick design/characters/src/enjoyment-1024.png -resize 120x120 -strip design/characters/enjoyment.png
```

## 3. 검수 기준

`node scripts/check-characters.mjs`가 파일 유무·크기·투명 배경·PNG 형식을 검사한다(quick 하네스에 포함). 자산이 아직 없으면 `pending`으로 통과하고, 하나라도 생기면 7종 전부를 요구한다.

스크립트가 잡지 못하는 것은 눈으로 본다:

- [ ] 40px로 줄였을 때 무엇인지 알아볼 수 있는가 — 이게 가장 자주 실패하는 항목이다
- [ ] 7종을 나란히 놓았을 때 선 굵기·채도·크기·시선 방향이 한 벌로 보이는가
- [ ] 글자·서명·테두리·바닥 그림자가 들어가지 않았는가
- [ ] 표정이 무섭거나 공격적이지 않은가 (특히 분노·미움)
- [ ] 흑백으로 바꿔도 서로 구별되는가 — 색은 이미 계열이 맡고 있으므로 아이콘까지 색에만 기대면 안 된다

## 4. 쓰는 자리와 쓰지 않는 자리

쓰는 자리는 **카테고리 토글**과 **기록 카드의 카테고리 표시** 두 곳뿐이다. 강도 선택기, 평가·순위 표시, 위기 안내 화면에는 쓰지 않는다(DESIGN_SYSTEM §8·§11, SAFETY_POLICY).

이미지가 없어도 화면은 이름만으로 동작해야 한다. 각 아이콘은 `prompts.json`의 `alt` 값을 그대로 `alt`에 쓰고, 세부 감정 chip처럼 작은 자리에서는 아이콘 대신 8px 카테고리 색 점을 쓴다.

## 5. 알려진 판단

- **분노**: 원자료에는 버섯구름(폭발)이 있으나, 40px에서 알아보기 어렵고 일기 앱 아이콘으로는 연상이 좋지 않아 **어두운 고양이 + 부드러운 주황 번짐**으로 대체했다. 원자료의 어두운 고양이도 같은 분노 칸에 있으므로 계열의 의미(PR-010)는 바뀌지 않는다. 되돌리려면 `prompts.json`의 `anger.subject_prompt`와 `negative_prompt`의 폭발 금지 항목을 함께 고친다.
- **크기**: 손으로 그린 수채 질감은 24px에서 뭉개진다. 그래서 카테고리 토글의 아이콘을 24px에서 **40px**로 올렸다(DESIGN_SYSTEM §6.2).
