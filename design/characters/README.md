# 캐릭터 자산

taxonomy v2의 9개 상위 감정 카테고리를 찾기 쉽게 돕는 보조 자산이다. 정본 규칙은 [../../docs/DESIGN_SYSTEM.md](../../docs/DESIGN_SYSTEM.md) §8, 스타일 결정은 `docs/DECISIONS.md` D-045, 동물 매핑은 D-044다.

스타일 기준은 [mood-preview-v2.png](mood-preview-v2.png)다. [mood-preview-v1.png](mood-preview-v1.png)는 비교 이력으로 보존하며 둘 다 최종 개별 자산으로 세지 않는다.

## 1. 만드는 방식

생성기는 **Codex 내장 imagegen**이고 프롬프트 정본은 [prompts.json](prompts.json)이다. 외부 이미지 API나 무승인 CLI fallback을 쓰지 않는다.

- 공통 스타일·일관성 잠금·금지 프롬프트는 모든 캐릭터와 포즈에 동일하게 붙인다.
- 내장 도구는 seed를 노출하지 않으므로 동일 seed를 계약으로 삼지 않는다. v2 참조 이미지, 잠긴 프롬프트, 1024×1024 캔버스, 크기·중심·얼굴 비율·종 식별 요소·색·무늬를 고정한다.
- 최종 idle은 승인된 v2 합본의 9개 alpha 연결 영역을 분리해 만든다. 단순한 3×3 좌표 crop은 캐릭터가 셀 경계를 넘는 부분에 이웃 조각을 섞으므로 금지한다.
- 새 포즈는 해당 캐릭터 idle을 참조한 별도 imagegen 호출로 만든다. 한 호출의 여러 칸을 서로 다른 최종 포즈로 간주하지 않는다.
- 먼저 공포=토끼를 `pilot/`에 생성해 정적 포즈와 애니메이션 파이프라인을 검증한다. pilot은 최종 9종 일부가 아니므로 최종 경로에 복사하지 않는다.
- pilot 통과 후 v2에서 분리한 9종 idle과 그 정적 fallback을 만든다. 한 캐릭터의 국소 해부 문제는 승인된 base를 참조한 편집으로 고치되, 둘 이상의 캐릭터에서 선·색·비율이 함께 무너지면 전체 스타일 잠금을 다시 검토한다.
- 프롬프트 계약을 바꾸면 `prompts.json.version`을 올리고 영향받는 자산 범위를 기록한다.

## 2. 포즈와 동작

모든 캐릭터는 다음 6개 포즈를 가진다.

| pose | 역할 |
| --- | --- |
| `idle` | 기본 대기 자세이자 reduced-motion 대표 프레임 |
| `breathe` | 중심을 고정한 최소한의 들숨 극점 |
| `blink` | 얼굴의 다른 부분을 움직이지 않는 느린 한 번의 눈 깜빡임 |
| `tilt` | 몸을 고정한 2~3° 고개 기울임 |
| `emotion` | 종과 감정에 맞는 작은 몸짓 |
| `acknowledge` | 선택·기록 완료에 쓰는 짧은 반응, idle로 복귀 |

idle loop는 120×120, 12fps, 24프레임, 약 2초다. 끝 프레임을 처음 프레임과 중복 저장하지 않고 시간축에서 자연스럽게 이어지게 한다. acknowledge는 12~16프레임을 한 번 재생하고 idle로 끝낸다. 120px에서 알파 가중 중심 이동은 최대 1px다.

허용 동작은 느린 호흡, 한 번의 느린 깜빡임, 귀·꼬리·수염·깃털의 작은 움직임, 2~3° 이내 고개 움직임뿐이다. 점프·회전·큰 이동·화면 흔들기·빠른 탄성·과장된 squash/stretch는 금지한다.

### 9종 동작 설계

| 감정·동물 | `emotion` | `acknowledge` |
| --- | --- | --- |
| 즐거움·양 | 꼬리 끝과 편안한 귀 하나가 아주 조금 움직임 | 눈을 부드럽게 감고 작은 끄덕임 |
| 희망·거북이 | 등껍질을 고정한 채 목을 몇 픽셀 내밈 | 턱을 아주 조금 들었다 복귀 |
| 슬픔·기니피그 | 귀를 조금 더 모으고 시선을 살짝 올림 | 앞발을 모으고 입 모양이 잠깐 풀림 |
| 분노·고양이 | 꼬리 끝과 귀 하나만 절제해 움직임 | 눈썹이 잠깐 풀리고 한 번 깜빡임 |
| 기쁨·쥐 | 수염과 귀 하나가 아주 조금 움직임 | 한쪽 앞발을 살짝 들었다 내림 |
| 사랑·개 | 늘어진 귀와 꼬리 끝이 작게 움직임 | 작은 고개 기울임과 느린 눈웃음 |
| 미움·까마귀 | 시선과 목깃이 미세하게 움직임 | 고개를 2~3° 정면 쪽으로 돌렸다 복귀 |
| 공포·토끼 | 귀 끝과 모은 앞발이 아주 조금 이완됨 | 느린 깜빡임 뒤 귀가 몇 픽셀 풀렸다 복귀 |
| 혐오·침팬지 | 한 손을 작은 거부 동작으로 올림 | 손을 내리고 입 모양이 잠깐 중립으로 완화됨 |

## 3. 파일 규격

| 위치 | 크기 | 용도 |
| --- | --- | --- |
| `src/<key>-1024.png` | 1024×1024 | 최종 정적 생성 원본 |
| `poses/<key>--<pose>-1024.png` | 1024×1024 | 등록된 포즈 원본 |
| `<key>.png` | 120×120 | 앱 정적 파일·reduced-motion fallback |
| `motion/<key>--idle-loop.<webp\|apng>` | 120×120 | 약 2초 무한 반복 |
| `motion/<key>--acknowledge-once.<webp\|apng>` | 120×120 | 한 번 재생 후 idle 종료 |
| `ui-poses/<key>--expressive-static-1024.png` | 1024×1024 | 사용자 제공 전신·감정 표현의 UI용 정적 원본 |
| `ui-poses/<key>--expressive-static-120.png` | 120×120 | UI용 정적 출력. 애니메이션하지 않음 |
| `motion/manifest.json` | - | 형식·프레임·지연·크기·checksum 기록 |
| `pilot/*` | 규격별 | 공포=토끼 시범. 최종 세트로 세지 않음 |

`<key>`는 `enjoyment` `wish` `sadness` `anger` `joy` `love` `hate` `fear` `disgust` 순서다. 정적 원본과 앱 파일은 RGBA 8-bit sRGB 투명 PNG다. 프레임은 1024에서 작업하고 앱 출력 120px로 한 번만 축소한다. `ui-poses/`는 사용자가 제공한 전신·감정 포즈 시트를 칸별로 분리한 보조 세트다. 하트·감정 기호처럼 해당 포즈와 함께 그려진 표식도 보존하되, 대표 아이콘·카테고리 토글·reduced-motion fallback·애니메이션 프레임에는 사용하지 않는다.

애니메이션 형식은 D-046에 따라 lossless animated WebP를 쓴다. 토끼의 동일 24프레임 비교에서 WebP는 261,298 bytes, APNG는 389,709 bytes였고 Chromium에서 질감·알파 차이가 보이지 않았다. APNG는 `pilot/` 비교 이력으로만 보존하며 정적 PNG fallback은 유지한다.

## 4. 검수 기준

`node scripts/check-characters.mjs`는 최종 경로의 파일 유무·크기·형식·실제 투명 픽셀과, 형식 확정 후 애니메이션 프레임·지연·루프 계약을 검사한다. 최종 자산이 없으면 `pending`으로 통과하며 `pilot/`은 이 all-or-nothing 판정에 포함하지 않는다.

눈 검수는 다음을 모두 수행한다.

- [x] 40px에서 label 없이도 9종 실루엣이 구별되고 눈·입이 뭉개지지 않는다(2026-09-18 Chromium `qa.html`)
- [x] 120px에서 크레용 선·납작한 색면·종이결과 표정이 유지된다(2026-09-18 Chromium `qa.html`)
- [x] 9종의 선 굵기·채도·크기·시선 방향이 한 벌로 보인다(v2 직접 분리)
- [x] 흰색, `#121211`, 체크보드 배경에서 흰 matte·halo·색 번짐이 없다. 중립색·계열 50은 토끼 pilot에서 확인했다.
- [x] 중심 이동은 자동 검사에서 1px 이하이고 loop 첫·끝의 튐은 Chromium에서 관찰되지 않았다.
- [ ] 글자·서명·테두리·배경·바닥 그림자·광택·과한 그라데이션이 없다
- [ ] 분노·미움·공포·혐오가 무섭거나 공격적·조롱·진단적으로 보이지 않는다
- [ ] 회색조에서도 색에 기대지 않고 서로 구별된다
- [ ] 후속 웹 구현 뒤 iPhone Safari와 Android Chrome에서 투명도·속도·loop가 같은지 확인한다
- [ ] 후속 웹 구현 뒤 실제 OS `prefers-reduced-motion: reduce`에서 애니메이션 대신 같은 캐릭터의 정적 PNG가 보이는지 확인한다

## 5. 쓰는 자리와 쓰지 않는 자리

쓰는 자리는 **카테고리 토글**과 **기록 카드의 카테고리 표시** 두 곳뿐이다. 카테고리 토글에서는 별자리 점을 바꾸지 않고 지도 바로 아래 "고른 친구들" 줄에 둔다(D-047, `docs/DESIGN_SYSTEM.md` §8). 강도 선택기, 평가·순위 표시, 위기 안내 화면에는 쓰지 않는다.

이미지가 없어도 이름만으로 동작해야 한다. alt는 `prompts.json`의 값을 사용한다. 40px보다 작은 세부 감정 chip에는 캐릭터 대신 8px 카테고리 색 점을 쓴다. reduced-motion에서는 `<picture>` 또는 동등한 소스 선택으로 정적 `<key>.png`를 우선하고, 형식 미지원 때도 정적 PNG로 fallback한다.

## 6. 알려진 판단

- **스타일**: D-045로 v2를 확정했다. D-035의 수채 중심 설명과 동일 seed 약속은 이 결정으로 대체되지만, 손그림 정체성·투명 자산·40px 기준은 유지된다.
- **분노**: 버섯구름·폭발·불은 쓰지 않고 어두운 고양이의 심술난 표정과 절제된 귀·꼬리로 표현한다.
- **동물 선택**: 상세 근거는 `docs/research/character-animal-evidence.md`, 결정은 D-043·D-044다. 9종은 양·거북이·기니피그·고양이·쥐·개·까마귀·토끼·침팬지이며 임의로 바꾸지 않는다.
- **희망=거북이**: 동물 행동 문헌 근거가 없는 순수 창작 선택이라는 제한을 유지한다.
- **크기**: 손그림 질감은 24px에서 뭉개지므로 카테고리 아이콘은 40px, 앱 파일은 3x인 120px를 쓴다.

## 7. 현재 완료 범위와 남은 게이트

- 완료: v2 기준 9종 `src/*-1024.png`와 120px 정적 fallback, 9종 `idle`·`breathe`·`tilt`·`emotion` 원본, 열린 눈 5종의 `blink` 원본, 24프레임 idle WebP, 12~16페이지 acknowledge WebP, checksum manifest, 40px/120px Chromium QA, 자동 alpha·크기·프레임·delay·loop·총 길이·중심 이동 검사.
- 제한: `tilt`는 중심과 알파 가장자리를 보존하는 1.8° 전신 미세 기울임이다. 머리만 분리한 리깅은 현 원본에서 이음선이 생겨 채택하지 않았다. 눈을 이미 감고 있는 양·쥐·개·침팬지는 의도적으로 별도 blink 포즈를 만들지 않고, idle의 느린 호흡을 쓴다.
- 완료: 종별 `acknowledge`는 `motion_spec.emotion_rigs`의 국소 워프를 왕복시켜 만든다. 전체 imagegen 포즈 간 crossfade는 종이결이 깜빡여 사용하지 않았고, 원본 픽셀을 부드럽게 재표본화해 지정 부위의 외곽선이 4~6px 움직인 뒤 3프레임 머무른다. blink는 눈 동작만 부각하지 않도록 acknowledge가 아닌 idle loop에 둔다. 모두 1.33초 뒤 idle로 끝난다.
- 후속 보류: iPhone Safari·Android Chrome 실기기, 실제 OS `prefers-reduced-motion: reduce`, 회색조/label 없음 사용자 판독은 웹 구현 뒤의 확장 검수다. 2026-09-19 사용자 지시에 따라 이 항목들은 #26 자산 이슈 종료를 막지 않는다.
- 생성 실패 기록: 토끼 2×2 포즈 시트는 `tilt`와 귀·앞발 이완 칸이 idle과 사실상 같아 탈락했다. 단일 `tilt` 재시도도 머리만 2~3° 움직인다는 조건을 분명히 충족하지 못했다. 같은 원인으로 두 번 실패했으므로 프롬프트 덧붙이기를 중단하고, 포즈별 마스크/리깅 또는 수동 보정 경로를 다시 결정했다. 사랑 개의 첫 emotion 편집은 원본에 없던 꼬리를 추가해 `pilot/love--emotion-donor-v1-rejected-extra-tail.png`으로 보존·탈락했고, 꼬리 없이 귀만 고정한 두 번째 편집을 채택했다.
- 미검증(후속 웹 확장): iPhone Safari, Android Chrome 실기기, 실제 OS `prefers-reduced-motion: reduce`, 회색조/label 없음 사용자 판독. 자산 계약과 Chromium 검증은 완료했으며 이 항목들은 다음 웹 구현 작업의 게이트다.

## 8. 실패와 재시도

- 일시적 생성 실패는 최대 두 번만 재시도한다.
- 한 번에 귀 위치·눈 간격처럼 한 가지 결함만 고친다.
- 같은 원인 가설로 두 번 실패하면 프롬프트를 계속 덧붙이지 않고 원인을 다시 진단한다.
- 얼굴 비율, 머리 실루엣, 귀·주둥이·부리·등껍질, 눈·코 위치, 색·무늬, 선 굵기, 캔버스·중심 중 하나가 흔들리면 해당 포즈는 탈락이다.
- 내장 imagegen이 실패해도 CLI/API로 자동 전환하지 않는다. fallback은 사용자 별도 승인이 필요하다.
